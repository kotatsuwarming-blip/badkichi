## 調査1: バドミントン動画AI解析のOSS

**実施日時**: 2026-03-28
**目的**: AI による自動ショット検出の実現可能性を調査

### 調査方法
- GitHub の badminton-analysis, shuttlecock-detection トピックを検索
- 主要リポジトリの README を分析

### 調査結果

| プロジェクト | 検出内容 | 技術 | 成熟度 |
|---|---|---|---|
| Badminton-hit-detection | 打ったタイミング + 誰が打ったか（near/far player） | GRU + TrackNetV2 + ポーズ推定 | 研究レベル（論文付き） |
| badminton-ai-vision | 選手の動き・距離・速度 | YOLOv8 ポーズ推定 | 開発中 |
| Badminton_Shot_Detection | ショット種別分類 | Python（仏バドミントン連盟共同） | 初期段階 |

### Badminton-hit-detection の詳細
- **入力**: カメラ1台のベースライン映像（単眼）
- **出力**: 各フレームの "no hit" / "hit by near player" / "hit by far player"
- **精度**: プロシングルスで最も高い。アマチュアダブルスでもある程度汎化
- **技術詳細**:
  1. 特徴抽出: コート座標 + プレーヤーポーズ + シャトル位置
  2. シーケンス処理: 14フレーム連続をGRUに入力
  3. 分類: ヒット/ノーヒット + プレーヤー割当

## 調査2: 「誰が打ったか」の自動判定レベル

**実施日時**: 2026-03-31
**目的**: ダブルスにおける個人レベルのショット判定可能性を調査

### 判定レベルの整理

| レベル | 内容 | 技術 | 難易度 |
|--------|------|------|--------|
| 1 | どちらのチームが打ったか | GRU + シャトル追跡（既存OSS） | ★★☆ |
| 2 | ダブルス2人のうち誰か | ポーズ推定 + インパクト地点 + 腕の伸び検出 | ★★★ |
| 3 | 4人の個人識別を維持 | Re-ID（外見特徴）+ 動き追跡（Kalmanフィルタ） | ★★★★ |

### レベル2の技術的アプローチ
1. YOLOポーズ推定で4人の体・腕の位置を常時トラッキング
2. TrackNetV2でシャトルのインパクト地点を特定
3. インパクト地点に最も近い腕（ラケット腕）の選手 = 打った人

### 精度向上のための撮影条件
- カメラ位置: コートの横（ベースライン側）から固定
- チームごとにウェアの色を分ける
- カメラの画角に4人全員が収まる

### 結論
- 「どちらのチームが打ったか」は既存技術で実現可能
- 「ダブルスの2人のうち誰か」は技術的に可能だがインテグレーション工数大
- 「ショット種別」は教師データ不足が課題（外部データセット活用が必要）

## 技術検証サマリー

### 実現可能性
- **MVP（手動入力 + ルールエンジン + ダッシュボード）**: 高
- **AI打ったタイミング検出（Phase 2）**: 中〜高（OSSあり + MVPデータで学習）
- **AIチーム判定（Phase 3）**: 中（既存OSSを活用）
- **AI個人判定（Phase 4）**: 中（ポーズ推定 + シャトル追跡の組合せ）
- **AIショット種別（Phase 5）**: 低〜中（教師データ不足。外部データセット必要）

### リスク
1. 動画再生とデータ入力のリアルタイム連携 → HTML5 Video API / YouTube IFrame API
2. ルールエンジンの正確性 → ユニットテスト充実
3. YouTube API の制約（再生位置取得の精度）→ 事前検証必要
4. AI学習用データの品質（撮影条件のばらつき）→ 撮影ガイドライン策定

### 推奨アプローチ
- MVP: Nuxt 3 + Supabase + ルールエンジン（TypeScript）+ YouTube連携
- Phase 2以降: Python バックエンド追加 → AI検出API
