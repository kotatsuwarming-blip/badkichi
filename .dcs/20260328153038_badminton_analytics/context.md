## アイデアの概要

バドミントンの試合動画を再生しながら、ラリー中のショットタイミングとポイント結果を手動入力。バドミントンのルール（得点者が次のサーブ権を持つ）を活用し、最小限の入力から「誰がサーバー/レシーバーの時に得点率が高いか」等の戦術分析を自動算出する。

---

## ユーザーストーリー

### As a バドミントンチームのメンバー
I want to 試合動画を見ながらラリーデータを記録し、サービス/レシーブの得点率を分析したい
So that ペアの組み合わせや戦術の改善に活かせる

## 要件定義

### 機能要件（MVP）

#### 1. 試合・選手管理
- ダブルスの試合を作成（4人の選手を登録）
- 試合 > セット > ラリー > ショット の階層構造
- 最初の立ち位置（左右）を設定
- 試合中にダブルスの左右入れ替わりが発生した場合に修正できる

#### 2. 動画再生 + データ入力画面
- ローカル動画ファイルの再生（一時停止・シーク対応）
- ラリー中の各ショットタイミングを「打った」ボタンで記録（動画内の時間を自動記録）
- ラリー終了時に「どちらがポイントを取ったか」を記録
- ラリー開始時の動画内タイムスタンプが自動記録される
- サーバー/レシーバーはルールエンジンが自動推論

#### 3. ルールエンジン
- バドミントンのダブルスルールに基づいて自動推論：
  - 得点者が次のサーブ権を持つ
  - サーバーの立ち位置（得点が偶数=右、奇数=左）
  - 最初の立ち位置 + 得点経過 → 各ラリーのサーバー/レシーバーを自動特定

#### 4. 統計ダッシュボード
- **最重要**: サービス時 vs レシーブ時の得点率（選手別）
- **次に重要**: ラリー本数と得点率の関係
- ラリー一覧表示 → ワンクリックで該当ラリーの動画再生位置にジャンプ

### 将来構想（設計に反映、実装はしない）
- Phase 2: AI による打ったタイミングの自動検出（Badminton-hit-detection 等を参考）
- Phase 3: AI による誰が打ったかの自動判定
- Phase 4: ショット種別の自動分類
- Phase 5: クラウド動画保存・ストリーミング再生
- Phase 6: リアルタイム分析（試合中ライブ入力・表示）
- シングルス対応、トリプルス対応

### 非機能要件
- **パフォーマンス**: 動画再生中のデータ入力にラグがないこと
- **セキュリティ**: 未定（チーム内利用のため最低限）
- **保守性**: AI 検出の入力元を「手動」「AI」で切り替え可能な設計

- **Charts**: Apache ECharts (vue-echarts)

## データモデル（概念レベル）

```
Match（試合）
├── players: Player[4]（ダブルス）
├── initial_positions: { left/right for each player }
├── Sets: Set[]
│   ├── score: { teamA, teamB }
│   └── Rallies: Rally[]
│       ├── server: Player（ルールエンジンが自動推論）
│       ├── receiver: Player
│       ├── video_timestamp: number（動画内の開始時間）
│       ├── point_winner: TeamA | TeamB
│       ├── rally_length: number（ショット数）
│       └── Shots: Shot[]
│           ├── timestamp: number（動画内の時間）
│           └── player: Player（将来: AI判定）
```

## ユーザーインターフェース

### 画面一覧
1. **試合管理画面** — 試合一覧、新規作成、選手登録
2. **動画再生 + データ入力画面** — メイン画面。動画再生しながらショット入力
3. **統計ダッシュボード画面** — サービス得点率、ラリー分析、ラリージャンプ

### データフロー
動画再生 → ショットタイミング入力 → ポイント結果入力 → ルールエンジン推論 → データ保存 → 統計算出 → ダッシュボード表示
