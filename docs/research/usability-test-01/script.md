## 1. 導入 (読み上げ)

> **>> 今日はこのアプリの「分かりやすさ」をテストさせてください。テストしているのはアプリの方で、**

> **>> お願いしたいのは「今、何を考えているか・何を探しているか」を声に出しながら触ること。**

> **>> なくて、あなたがどう感じるかを見たいからです。途中でやめたくなったらいつでも言ってください。**

## 2. Phase 0 — 理解度テスト (タスクの前 / 約5分)

> **今回の割り切り**: 川島・あすかは概要を事前共有済み(汚染)なので Phase 0 は**参考**。clean な理解度は
> **峻さんのみ**(実質 n=1)。汚染2人でも「コピー狙い撃ち質問」は語の理解度として軽く取る。
> LP コピーの本判定は初見を集めた別機会(usability-test-02)で行うので、ここは時間をかけすぎない。

### これで何を見たいか (観察者の心構え)

**入口の LP の文章だけで「何のアプリか」が伝わるか**を見る。あなたは**一切説明しない**。
被験者が正しく言えなくても、それは**被験者の失敗ではなくコピーの発見**。淡々と聞いて、淡々と記録する。
リアクション(「そうそう!」等)も**しない** — 正解/不正解を匂わせると次の答えが誘導される。

### 進め方

1. LP(badkichi.vercel.app のトップ)を見せた状態にする。**まだ何も言わない**
2. 下の質問を順に。被験者の**言葉そのまま**を results.md に書く(要約しない)
3. 答えに**反応しない・訂正しない・補足しない**。「なるほど」程度でOK

> **>> この画面、ぱっと見て何のアプリだと思いますか? 声に出してみてください。**
>
> **>> 誰向けっぽいですか? 何ができそう?**
>
> **>> もしこれを使うとしたら、最初に何をすると思いますか?**

続けて、**画面の文言を指さして**狙い撃ちで:

> **>> ここに「強みと課題を“数字”で分析」とありますが、具体的に何が分かりそうだと思いますか?**
>
> **>> 「得点に効く要素を分析」って、何を指してると思いますか?**
>
> **>> この「Google で始める」ボタンを押したら、何が起きると思いますか?**

### (任意) 5秒テスト版

最初の自由質問の代わりに使ってもよい:

> **>> これから画面を5秒だけ見せます。じっくり読まなくていいので、見てください。**

→ 5秒見せて**隠す**(PC なら画面を伏せる / スマホなら裏返す)→

> **>> 今ので、何のアプリだと思いましたか? 印象に残った言葉はありますか?**

5秒で何が残るか = ヘッドラインの強さが分かる。

### 転び方の例 (これでイメージを掴む)

| 被験者の反応 | 判定 | 意味 |
|---|---|---|
| 「バドの試合を記録して、選手ごとの得点率とか強み弱みを分析するやつ。チームで使う感じ」 | ✅ 伝わった | コピーは機能している |
| 「バドの動画を見る/編集するアプリ?」 | ❌ 発見 | 「分析」より「映像」が前に出すぎ → 見出しの修正候補 |
| 「“得点に効く要素”…何だろ、点の取り方?」と曖昧 | △ 一部 | 語が抽象的。サービス/立ち位置等の具体に届いていない |
| 「Google で始める」=「いきなり登録/課金される?」とためらう | ❌ 発見 | CTA が不安を生む → 文言 or 補足の修正候補 |

→ **複数人が同じ誤解**をしたら、それが説明文修正の最優先。

### コンティンジェンシー

全く伝わらず Phase 1 に進めなくても、口頭で文脈を補って操作データは取る(セッションを無駄にしない):

> **>> 「チームのコーチが、試合を記録して選手ごとの得点率を分析するアプリ」だと思って、使ってみてください。**

## 3. Phase 1 — タスク (T1〜T5)

各タスクは**ゴールだけ読む。手順は言わない**。詰まっても **2〜3分は黙って待つ**。完全に手が止まったら次へ。
「自力完了 / ヒント後 / 失敗」を results.md に。T3a は**所要時間**も。

> **>> ① まず、このアプリを始めて、ログインしてください。**

(LP の CTA → Google ログインへ辿り着けるか)

> **>> ② あなたのチームを作って、選手を何人か登録してください。**

(onboarding → グループ作成 → 選手登録。招待 URL の案内で迷わないか)

> **>> ③ では、この試合を記録してみてください。1ゲーム分、ラリーを記録して保存するところまで。**

(**最重要**。試合作成 → ラリー記録 → 保存。所要時間を計る)

> **>> ④ 試合の途中で、◯◯側の選手の左右が入れ替わりました。それをアプリに記録してください。**
> **>> …(操作後)…はい、そのあと元の位置に戻りました。それも記録してください。**

(**Position Override**。`[A入替]`/`[B入替]` を**ボタン名を言わずに**自力で見つけられるか / 記録中に押せるか。
 素材に入れ替わりが無い被験者は、この口頭シナリオで発生させる)

> **>> ⑤ ◯◯選手の得点率を調べてください。**

(stats のドリルダウン)

> **>> ⑥ さっきの試合で気になった場面の動画を、見返してみてください。**

(統計 → 動画ジャンプ)

## 4. Phase 1.5 — 振り返り (全タスク後 / 意見)

**ここから意見を聞いてOK**(タスク中はNGだった)。

> **>> 全体を通して、一番迷った/分かりにくかったのはどこでしたか?**
>
> **>> もしどこか変えるなら、何がどうなってたら楽でしたか?**
>
> **>> さっきの「左右入れ替わり」の記録、ボタンはすぐ分かりましたか? 記録しながら押すのは大変じゃなかった?**

> **>> お金を払ってでも欲しい、と思う場面はありそうですか?**

## 観察者の鉄則 (常に手元に置く)

- **助けない・誘導しない・先回りして説明しない**
- 詰まっても **2〜3分待つ**
- 答えに**正解/不正解のリアクションをしない**
- 「次どうすれば?」→ **>> 「どうすればいいと思いますか?」** と聞き返す
- 迷い・誤操作・「えっどこ?」の発話は**全部メモ**(後で録画の頭出し用に時刻も)
