**振り返り (debrief / 全タスク後)**

打ち込みの手間 (61:30〜):
- 「前提手間はかかるが、**1.5倍速とかでやればそこまで手間すぎない**。1日2〜3試合なら振り返り含めてささっと、操作が慣れればそこまでではない」 → **コアの実用性自体は許容範囲** (慣れ前提)。問題は「慣れるまで」の壁。

操作で分からなかった点 (本人の言葉):
- **コート図が何を示すか分からなかった** (サーブ/レシーブの表示はあるが気づけず)。入れ替えやコート図を直接いじろうとした。
- **1ラリーではなく「打った回数」をカウントするのが分からなかった** (記録モデルの核心)。
- 「タイムスタンプを記録するのは分かったが、**何のタイミングで何を記録するのかが分からなかった**」(動画再生中、その秒数で「打った」を押す、が伝わらなかった)。
- 他の画面 (T2/T4/T5) はある程度わかった → **詰まりは記録画面に集中**。

本人が望む解決策 (重要):
- 「**?マークで説明が出てくる**とか、チュートリアルor補足説明がないと分からなかった」 → **アプリ内の文脈ヘルプ (インライン説明)** を本人が要望。= U-01 の方針 (初回ガイド+説明) と一致。

本人からの機能改善提案:
- **サーバー/レシーバーの文言**があった方が分かりやすい (サーブ表示が黄色/マークで不明瞭だった)
- ラリー行に**スコア (何対何)・時間**の表示があるとベター
- ラリー本数を **1・2 (サーブ/サーブレシーブで決着) と 3以上 (ラリー継続) で切り分け**た方が示唆が出る
- 記録は「打った」の意味・記録モデルが最初分からない、**慣れが必要**

その他気づき:
- **記録中バグ (High)**: 「打った」を取り消して0にすると以降カウント不可 / 記録中に押せなくなる。**作者の実演すらバグで失敗**し試合再作成を要した = 機能の安定性がコアブロッカー
- 対比が明確: **記録 (T3a/T3b) は大苦戦だが、統計 (T4/T5) は概ね自力**。詰まりは記録フローに集中

### 参考: プロダクト方向の議論 (川島 / 素材提供者・需要シグナルとしては弱い → ③backlog)

> 川島は需要メモ表 (n=2) の対象外。以下はセッション後の雑談で出たプロダクト方向の参考メモ。
> UI 修正の優先度には混ぜない (ADR-015 §3)。③需要・収益検証フェーズの入力として残す。

**収益・ペルソナ**
- チーム/実業団向けの方が課金しやすい点に同意。個人プラン/チームプランの分割 (Claude Code 的) もアリという反応。

**AI による差別化 (重要シグナル)**
- WBC のアナリストが投手/打者のヒートマップを AI で出していた例を引き、「**AI で自動化できると金を払えるサービス**。そこまで払えない層にマニュアル版」という整理。
- 「AI で簡単にできるならマニュアル版は要らないのでは」に極論同意 → **AI 自動化が本命で、現状のマニュアル記録は過渡期** という見方。作者の戦略 (汚い草の根映像を対象に、綺麗データのモデルをファインチューニング) は理解された。
- 現状の Gemini 等への動画入力での自動抽出は「今は無理」、今のアプリは「**データベース的な立ち位置**」という評価。

**現状機能への率直な評価 + 機能要望 (③backlog)**
- 「今のところ個人のサーブ/レシーブの得点率を見れるだけ」。強み/課題は **ショット種別** (スマッシュで得点 / スマッシュレシーブで失点) で見たい。サーブ/レシーブ限定の理由を質問 (→ ショット種別抽出は研究段階、得点率は記録だけでできるミニマムと回答)。
- ショット種別のマニュアル入力は「**面倒すぎる**」(一回一回止める)。現状は慣れれば試合時間程度で入力できるのが利点。
- 欲しかったもの (具体):
  1. **サーブミスが得点に繋がっているか** (本人はサーブミスが多かった)
  2. **どの場所で失点したか** (右前が弱い等のコート位置 → ヘアピン/ドロップ等に絞り込める。「どこから打っているか」が分かると良い)
  3. **1ラリーの時間** (スタミナ分析)。打数でも可だが、ラリーの長さ・連続する長ラリーも見たい
