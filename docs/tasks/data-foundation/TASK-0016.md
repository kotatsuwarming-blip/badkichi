## タスク概要

data-foundation 単位の検証目的で、Google OAuth ログインフローが「dev 環境で動く」ことを最小限のスタブで確認する。本格的なログイン UI / オンボーディング画面は auth-onboarding 単位で実装するため、本タスクでは以下のみを行う:

- `app/pages/confirm.vue` を作成（OAuth callback のランディング先となる最小ページ）
- ファイル冒頭に「auth-onboarding 単位で置換」というコメントを明記
- `pnpm dev` 起動 → Google ログイン → `/confirm` 着地 → ホーム遷移 → `useSupabaseUser()` 値持ち、までを手動スモークテストで確認

**自動テストは対象外**（E2E は auth-onboarding 単位以降）。スモークテスト結果は実装記録ディレクトリに残す。

**配置先**:

- `app/pages/confirm.vue`
- `docs/implements/data-foundation/TASK-0016/verification-log.md`（手動スモークテスト記録）

## 実装詳細

### 1. `app/pages/confirm.vue` 作成 🔵

**信頼性**: 🔵 *スキーマレビュー ⑬ C-15*

```vue
<!-- app/pages/confirm.vue
     data-foundation 単位の最小スタブ。auth-onboarding 単位で本実装（オンボーディング画面・エラー
     ハンドリング・初回 Group 参加導線）に置換する。
     現状の責務: Google OAuth callback 後の認証成立を待ってホームへリダイレクトするだけ。 -->
<script setup lang="ts">
const user = useSupabaseUser()

watch(
  user,
  (u) => {
    if (u) {
      navigateTo('/')
    }
  },
  { immediate: true }
)
</script>

<template>
  <div>Signing in...</div>
</template>
```

> **設計意図**: `@nuxtjs/supabase` モジュールは OAuth callback 後に Supabase のセッション cookie を確立する。`useSupabaseUser()` はそのセッションを購読する composable で、null → user オブジェクトに変化する瞬間を `watch` で捕まえてホームへ遷移させる。`immediate: true` により既にログイン済みの状態で `/confirm` を直接踏んだ場合も即座にホームへ飛ばせる。

### 2. ファイル冒頭コメントの方針 🔵

**信頼性**: 🔵 *スキーマレビュー ⑬ C-15*

- 「auth-onboarding 単位で置換」を必ず明記
- 「最小スタブ」「責務はリダイレクトのみ」を明記
- これにより、後続の auth-onboarding 単位担当者が「ここを書き換えるべき」と即座に認識できる

### 3. スモークテスト実施 🔵

**信頼性**: 🔵 *REQ-002, スキーマレビュー ⑬*

**実施手順**:

1. `.env.development` に dev プロジェクトの `SUPABASE_URL` / `SUPABASE_KEY` が設定されていることを確認（TASK-0003 / TASK-0009 完了状態）
2. `pnpm dev` で開発サーバ起動 → http://localhost:3000 にアクセス
3. `@nuxtjs/supabase` のデフォルトログインフロー（`/login` ページ or `signInWithOAuth({ provider: 'google' })` を呼ぶボタンを一時的に追加）を経由
4. Google アカウントで認可
5. `https://{dev-ref}.supabase.co/auth/v1/callback` → `http://localhost:3000/confirm` にリダイレクトされる
6. `/confirm` で `Signing in...` が一瞬表示され、即座に `/` にリダイレクトされる
7. `/` でブラウザの DevTools コンソールから `useSupabaseUser().value` または同等の方法で user が確定していることを確認

> ステップ 3 のログインボタンは確認用に一時的に追加して良い。コミット前に削除する。または、`@nuxtjs/supabase` の自動リダイレクト機能で `/login` に飛ばされた状態から手動で OAuth URL を踏む方法でも可。

## 注意事項

- **自動テスト化はしない**: E2E テストは auth-onboarding 単位以降のスコープ。本タスクはあくまでスモークテスト（手動）で「経路成立」のみ確認する 🔵
- **スタブの寿命**: 本ファイルは auth-onboarding 単位で本実装に置換されるため、本タスクで凝った実装をしない。エラーハンドリング・ローディング UI・初回 Group 参加導線等は全て後続単位の責務 🔵
- **`useSupabaseUser` の Nuxt SSR 挙動**: `@nuxtjs/supabase` はサーバ側でも cookie からセッションを復元するため、`/confirm` への直接アクセス時も `immediate: true` で適切に動く想定。万一 SSR で動かない場合は `<ClientOnly>` でラップする 🟡
- **prod での動作確認は TASK-0017 で実施**: 本タスクは dev のみ。prod での動作確認は TASK-0017 で行う 🔵
- **prep.md §7（本番ドメイン）未確定でも本タスクは進められる**: localhost のみで完結するため、本番ドメイン未確定でも問題ない 🔵
- **後続タスク (auth-onboarding) への引き継ぎ**:
  - 本ファイル冒頭コメントに「置換対象」と明示してあるため、auth-onboarding 担当者は迷わず手を入れられる
  - 必要なら ADR-004 に「`/confirm` の本実装は auth-onboarding 単位で行う」を明記し、責務境界を残しておく 🟡
