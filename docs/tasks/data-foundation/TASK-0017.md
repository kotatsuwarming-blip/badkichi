### 4. TypeScript 型再生成 + 差分確認 🔵

**信頼性**: 🔵 *REQ-006, NFR-301*

**手順**:

1. CLI のリンク先を prd に切り替え: `supabase link --project-ref {prd-ref}`
2. 型生成: `pnpm db:types`
3. 生成された `types/supabase.ts`（または同等パス）が、dev で生成した版と diff で完全一致することを確認

```bash
# dev で生成した版を一時保存
git stash
pnpm db:types  # prd で再生成
git diff types/supabase.ts  # 期待: 差分なし
git stash pop  # 元に戻す
```

> 差分があった場合は dev と prd のスキーマ不整合 → マイグレーション漏れがあるため要調査。

**重要**: 確認完了後、必ず CLI リンクを dev に戻す:

```bash
supabase link --project-ref {dev-ref}
```

> prd リンク状態で `pnpm db:reset` を誤実行すると壊滅的なので、TASK-0011 のガード（リンク先名が `prd` の場合 exit 1）が機能していることもこの機会に動作確認しておく 🔵

## 注意事項

- **prd 適用前の dev 全テスト通過必須**: TASK-0014 / 0015 / 0016 が dev で緑になっていない状態で prd 適用に進まない。CI 側でも main protection rule で前提テストを必須化することを推奨 🔵
- **CLI リンクの取り違え**: prd リンク状態で `pnpm db:reset` を実行すると prd が破壊される。TASK-0011 のガードが効くはずだが、念のためリンク切り替え時は `supabase status` で確認する習慣をつける 🔵
- **NFR-001 が 30 秒を超えた場合**: 失敗扱いではなく「現状値として記録し、将来の改善対象」とする。MVP リリース判定への影響は、要件定義書 NFR-001 を再評価して決定 🟡
- **Free プラン制限**: prd プロジェクトの DB 容量（Free プランは 500MB）の現在値も同時に記録しておくと、将来の有料プラン移行判断に役立つ 🟡
- **prep.md §7（本番ドメイン）が未確定の場合**: localhost を暫定登録した状態で本タスクは完了扱いにできるが、auth-onboarding 単位開始前に必ず確定させる必要があるため、ADR-004 に申し送りとして記録 🟡
- **Supabase 日次バックアップは UTC 基準**: ローカル時刻と混同しないように、検証ログには UTC タイムスタンプも併記 🟡
- **ロールバック判断**: 適用後に重大障害が発覚した場合の判断フローは「① CI ログ確認 → ② 影響範囲評価 → ③ 必要ならバックアップから Restore」。Free プランのバックアップ保持は 7 日のため、発見から 7 日以内に対応する必要がある 🔵
- **MVP スコープ**: 「複数環境（staging）」「Blue/Green デプロイ」等は MVP 範囲外。本タスクの構成は MVP リリースまでの最小限と割り切る 🟡
