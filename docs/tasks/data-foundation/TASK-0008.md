## タスク概要 🔵

**信頼性**: 🔵 *REQ-006, NFR-301, architecture.md 行 270〜281「型生成パイプライン」*

`supabase gen types typescript` コマンドを使った TypeScript 型の自動生成パイプラインを整備する。
`pnpm db:push` でマイグレーションを適用したあと、`pnpm db:types` で `types/supabase.ts` を再生成し、
Nuxt アプリ側で型安全に Supabase クライアントを利用できるようにする。

**配置先**:
- `package.json` の `scripts` セクション
- `types/supabase.ts`（自動生成、コミット対象）

`pnpm db:reset` スクリプト（REQ-008 / REQ-009 関連、prd ガード付き）は **本タスクには含まない**。`db:reset` は別途 TASK-0010 で実装する。

## 実装詳細

### ステップ 1: package.json scripts の編集 🔵

**信頼性**: 🔵 *architecture.md 行 265〜267 で確定*

`package.json` の `scripts` セクションに以下を追加する:

```json
{
  "scripts": {
    "db:push": "supabase db push --linked",
    "db:types": "supabase gen types typescript --linked > types/supabase.ts"
  }
}
```

注意:
- 既存の scripts（`dev` / `build` / `lint` / `typecheck` 等）は **改変しない**
- 末尾 comma の方針はリポジトリの既存 `package.json` に揃える（ESLint 規約: no comma dangle だが JSON は別ルール）

### ステップ 2: types/ ディレクトリ作成 + 初回生成 🔵

**信頼性**: 🔵 *Supabase CLI 標準*

```bash
mkdir -p types
# TASK-0009 で dev DB にマイグレーションが適用されている前提
pnpm db:types
# → types/supabase.ts が生成される
```

なお、初回 `pnpm db:push` の実行は TASK-0009 と統合してもよい（順序: push → types）。

### ステップ 3: .gitignore 確認 🔵

**信頼性**: 🔵 *型再生成をコミットして CI で `tsc` が通る前提*

`.gitignore` で `types/` または `types/supabase.ts` が除外されていないことを確認する。除外されている場合は除外を解除する。

### ステップ 4: pnpm typecheck 通過確認 🔵

**信頼性**: 🔵 *Nuxt + TypeScript strict mode*

```bash
pnpm typecheck
```

`types/supabase.ts` の型に矛盾がなく、Nuxt 既存コードもエラーなく通ること。Supabase クライアントの使用箇所が未実装（TASK-0011 以降）の段階では、ファイル単体での `tsc` パス確認で十分。

## 注意事項 ⚠

- 🔵 型再生成を **忘れると drift する**（NFR-301 違反）。CI で `pnpm db:types` 相当を実行し、出力差分があれば失敗させる仕組みを後で導入する想定（TASK-0014 の CI で検討）
- 🔵 `supabase gen types --linked` は `supabase link` 済みのプロジェクトを参照する。dev プロジェクトを向いている前提（TASK-0004 で完了済み）
- 🟡 `types/supabase.ts` をコミットする方針は架空ではなく architecture.md 行 294「supabase gen types で自動生成」と整合。`.gitignore` の現状確認後に方針を確定する
- 🔵 `db:reset` スクリプト（prd ガード付き）は **本タスクには含めない**。REQ-008 / REQ-009 対応の `db:reset` は別タスク（TASK-0010）で実装する
- 🟡 `supabase gen types` の出力先パス（`> types/supabase.ts`）はシェルリダイレクト。Windows の cmd では動作しない可能性があるため、CI / 開発環境は POSIX シェル前提（既存リポジトリも同様）
