## タスク概要

`main` ブランチに `supabase/migrations/**` の変更が含まれる push が来た時点で、GitHub Actions が **自動で prd (`badkichi-prd`) にマイグレーションを適用する** ワークフロー (`migrate-prd.yml`) を整備する（スキーマレビュー ⑮ C-17 案 ii 最小構成）。

設計判断:

- **発火条件**: `on.push.branches: [main]` かつ `paths: ['supabase/migrations/**']`
- **適用方法**: `supabase/setup-cli` + `supabase db push --linked`
- **失敗時通知**: MVP は `gh issue create` で GitHub Issue を自動作成（Slack 連携は後付け可）
- **バックアップ**: 適用前バックアップは **追加しない**（Supabase 標準の日次バックアップに任せる、⑮ C-17 案 ii）

本タスクはワークフロー定義のみで、**初回 prd 適用は実施しない**（初回適用は TASK-0017）。Secrets 登録後の dry-run は手動 trigger でも可。

## 実装詳細

### 1. `.github/workflows/migrate-prd.yml` の作成 🔵

**信頼性**: 🔵 *REQ-003, REQ-004, ⑮ C-17, architecture.md "マイグレーション運用 → prd 適用"*

`.github/workflows/migrate-prd.yml` を以下の方針で作成する。

```yaml
name: migrate-prd

# 発火条件:
#   - main への push かつ supabase/migrations/ が変更された場合
#   - workflow_dispatch (手動 trigger) で dry-run / 緊急再実行も可能
#
# 注: スキーマレビュー ⑮ C-17 案 ii 最小構成。
#     適用前バックアップは追加せず、Supabase 標準の日次バックアップに任せる。

on:
  push:
    branches: [main]
    paths:
      - 'supabase/migrations/**'
  workflow_dispatch: {}

# 同時実行を抑止（連続 push 時のレース防止）
concurrency:
  group: migrate-prd
  cancel-in-progress: false

jobs:
  migrate:
    runs-on: ubuntu-latest

    # GITHUB_TOKEN に Issue 作成権限を付与（失敗通知用）
    permissions:
      contents: read
      issues: write

    env:
      SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}
      SUPABASE_PRD_DB_PASSWORD: ${{ secrets.SUPABASE_PRD_DB_PASSWORD }}
      SUPABASE_PRD_PROJECT_REF: ${{ secrets.SUPABASE_PRD_PROJECT_REF }}

    steps:
      - name: Checkout
        uses: actions/checkout@v6

      - name: Setup Supabase CLI
        uses: supabase/setup-cli@v1
        with:
          version: latest

      - name: Link to prd project
        run: |
          supabase link \
            --project-ref "${SUPABASE_PRD_PROJECT_REF}" \
            --password "${SUPABASE_PRD_DB_PASSWORD}"

      - name: Push migrations to prd
        run: supabase db push --linked

      - name: Notify on failure (create GitHub Issue)
        if: failure()
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          gh issue create \
            --title "prd マイグレーション失敗: ${{ github.sha }}" \
            --body "$(cat <<EOF
          prd 自動マイグレーション (migrate-prd.yml) が失敗しました。

          - Commit: ${{ github.sha }}
          - Actions run: ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}
          - Triggered by: ${{ github.actor }}

          手動で原因調査し、必要に応じてロールバック / 修正マイグレーションを追加してください。
          EOF
          )" \
            --label "prd-migration-failure"
```

> **コメント**: ファイル先頭のコメント（「⑮ C-17 案 ii 最小構成。適用前バックアップは追加せず、Supabase 標準の日次バックアップに任せる」）は **削除しないこと**。設計判断の根拠を YAML 内に残しておく目的。🔵

```markdown
## §N: GitHub Secrets 登録（TASK-0012 で利用）

`.github/workflows/migrate-prd.yml` が prd に自動でマイグレーションを適用するため、
以下の Secrets を GitHub リポジトリの Settings → Secrets and variables → Actions に登録する。

| Secret 名 | 値 | 取得元 |
|----------|----|--------|
| `SUPABASE_ACCESS_TOKEN` | Supabase Personal Access Token | https://supabase.com/dashboard/account/tokens |
| `SUPABASE_PRD_DB_PASSWORD` | badkichi-prd の DB password | TASK-0001 で設定したパスワード |
| `SUPABASE_PRD_PROJECT_REF` | badkichi-prd の Project Ref | Supabase Dashboard → Project Settings → General |

**注意**:
- これらは prd 環境への書き込み権限を持つため、漏洩厳禁
- リポジトリの Environment (例: `production`) を切って Environment Secrets として登録する選択肢もあり
- `SUPABASE_ACCESS_TOKEN` の Personal Access Token は所有者の退職等で revoke される可能性があるため、
  本番運用では Bot ユーザーで発行することを推奨（MVP では個人 token で OK）
```

## 注意事項

- **初回 prd 適用は TASK-0017 で実施**: 本タスクはワークフロー定義 + Secrets 登録までで止める。TASK-0017 で初回マイグレーションを main にマージし、自動発火させる。🔵
- **適用前バックアップを追加しない理由（⑮ C-17 案 ii）**: Supabase Free プランは標準で日次バックアップを取得しており、MVP 段階で個別バックアップを取る運用負荷に見合わない。失敗時は Issue 自動作成 + 手動ロールバックで対応する。将来マイグレーションが大規模化したら別タスクで `pg_dump` ステップを追加検討。🔵
- **失敗時通知の段階的拡張**: MVP は `gh issue create` のみ。Slack Webhook / メール通知は後付け可能（同じ `if: failure()` ステップに追加するだけ）。🟡
- **`supabase db push --linked` の挙動**: 既に prd に適用済みのマイグレーションはスキップされる（Supabase CLI が `supabase_migrations.schema_migrations` を見て差分のみ適用）。冪等性は CLI 側が担保。🔵
- **`concurrency` 設定の理由**: 連続 push（hotfix 連投など）で同時実行されると競合する可能性があるため、`group: migrate-prd` でシリアライズ。`cancel-in-progress: false` で進行中の適用を中断しない（中断するとスキーマが中途半端になる）。🔵
- **Personal Access Token のローテーション**: `SUPABASE_ACCESS_TOKEN` の token を発行した開発者がチームを抜けた場合、token を revoke し新規発行する必要がある。MVP では個人 token で OK だが、運用本格化時は Bot ユーザー化を検討。🟡
- **GitHub Environments の活用余地**: Repository Secrets ではなく `production` Environment Secrets として登録すれば、main ブランチ以外からの誤発火を防げる + Required reviewers での承認ゲートも追加可能。MVP では Repository Secrets で簡素に開始するが、将来選択肢として検討。🟡
- **後続タスクへの引き継ぎ**:
  - 本タスク完了後、TASK-0017 で初回 prd マイグレーションを main にマージし、自動発火を確認する
  - 失敗時通知の Slack 連携が必要になった時点で別タスクとして切り出す
- **MVP スコープ**: 本タスクは MVP の Phase 3 に必須。手動 prd 適用運用では誤操作リスク + 適用忘れリスクが高い。🔵
