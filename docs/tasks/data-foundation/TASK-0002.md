## タスク概要

Nuxt アプリから Supabase に接続するために必要な npm パッケージ（`@nuxtjs/supabase`, `zod`）を pnpm で追加し、`nuxt.config.ts` の `modules` 配列および `supabase` 設定ブロックを編集する。`@nuxtjs/supabase` の `redirectOptions.login` / `redirectOptions.callback` を本プロジェクトの URL 規約（`/login`, `/confirm`）に合わせて設定する。

`.env.*` の作成と内容の流し込みは別タスク（TASK-0003）の責務であり、本タスクではモジュール導入と設定のみを扱う。設定後に `pnpm install` および `pnpm typecheck` が通ることを確認する。

## 実装詳細

### 1. 依存パッケージのインストール 🔵

**信頼性**: 🔵 *REQ-005, REQ-007, architecture.md*

**変更ファイル**: `package.json`, `pnpm-lock.yaml`

**コマンド**:

```bash
pnpm add @nuxtjs/supabase
pnpm add zod
```

> `@nuxtjs/supabase` は Nuxt モジュールだが、本プロジェクトの方針（[ADR-003](../../decisions/003-harness-engineering-approach.md) 参照）では `devDependencies` ではなく `dependencies` に入れる。runtime で読み込まれるため。
>
> バージョン指定は `latest` を許容するが、`@nuxt/test-utils` と同様に `.nuxtrc` 経由でピンする運用が確立している場合はそちらに従う。

**期待される `package.json` の変化（抜粋）**:

```jsonc
{
  "dependencies": {
    "@nuxtjs/supabase": "^1.x.x",  // 1.x 系の最新安定版
    "zod": "^3.x.x",
    // ...
  }
}
```

### 2. `nuxt.config.ts` の編集 🔵

**信頼性**: 🔵 *architecture.md "Nuxt 側の接続設定", ヒアリング 2026-04-20 Q4*

**変更ファイル**: `nuxt.config.ts`

**変更内容**:

```typescript
// nuxt.config.ts (抜粋・追記箇所)
export default defineNuxtConfig({
  modules: [
    '@nuxt/eslint',
    '@nuxt/ui',
    '@nuxtjs/supabase',  // ← 追加
  ],
  supabase: {
    redirectOptions: {
      login: '/login',
      callback: '/confirm',
    },
  },
  // ... 既存設定
})
```

**ポイント**:

- `redirectOptions.login`: 未認証ユーザーがアクセスした際の遷移先。auth-onboarding 単位で `/login` ページを実装する想定。🔵
- `redirectOptions.callback`: OAuth リダイレクトの戻り先。architecture.md "Auth フロー: /confirm ページ" で定義された通り、data-foundation で最小スタブを置く。🔵
- `@nuxtjs/supabase` は自動で環境変数 `NUXT_PUBLIC_SUPABASE_URL` / `NUXT_PUBLIC_SUPABASE_KEY` を読む（TASK-0003 で設定）。本タスクでは明示的な URL/key 指定は行わない。🔵

### 3. 型定義の取り込み確認 🟡

**信頼性**: 🟡 *Nuxt モジュールの自動型生成挙動からの妥当な推測*

`@nuxtjs/supabase` を追加すると `.nuxt/types/` 配下に `useSupabaseClient()` / `useSupabaseUser()` 等の Composable 型が自動生成される。`pnpm typecheck` で参照可能か確認する。

```bash
pnpm dev  # 一度起動して .nuxt/ を再生成
# 別ターミナルで
pnpm typecheck
```

> この段階では `useSupabaseClient()` を呼ぶ Vue ファイルはまだ無いため、型エラーが出ないことを確認するだけでよい。

### 4. ESLint 整合性確認 🟡

**信頼性**: 🟡 *プロジェクト規約 (CLAUDE.md "Coding Conventions") からの推測*

`nuxt.config.ts` の編集で 1tbs / no comma dangle 等の lint ルールに違反していないか確認する。

```bash
pnpm lint
```

エラーが出る場合は ESLint の `--fix` で自動修正可能なものは修正し、残りは手動で整える。

## 注意事項

- **環境変数未設定時の挙動**: 本タスク完了時点では `.env.*` が未作成のため、`pnpm dev` 実行時に `@nuxtjs/supabase` が `NUXT_PUBLIC_SUPABASE_URL is not set` のような警告/エラーを出す可能性がある。実際の接続検証は TASK-0003 完了後に行う。🔵
- **`@nuxtjs/supabase` のバージョン選定**: 既存リポジトリの `@nuxt/test-utils` は `.nuxtrc` でバージョンピンされている（commit `562fb31` 参照）。同様の対応が必要なら `.nuxtrc` にも追記する。最新安定版 (1.x 系) で `redirectOptions` の API が変わっていないことを確認すること。🟡
- **`zod` のバージョン**: 3.x 系で問題なし。Phase 2 以降で rule-engine と DB スキーマの境界バリデーションに使用する想定（[note.md](../../spec/data-foundation/note.md) 参照）。🔵
- **`redirectOptions.exclude` などの追加オプション**: 認可不要ページのホワイトリスト等は auth-onboarding 単位で追加する想定。本タスクでは最小設定にとどめる。🟡
- **テストファイル不要**: DIRECT タスクのため `__tests__/` 配下のテストは作成しない。設定の正しさは TASK-0003 完了後の接続検証で確認する。🔵
- **コミット粒度**: 「依存追加」と「nuxt.config 編集」は同一コミットで OK（密結合）。.env.* 関連の変更は TASK-0003 で別コミットとする。🟡
