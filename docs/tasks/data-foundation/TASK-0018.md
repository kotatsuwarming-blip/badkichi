## タスク概要

ADR-006 で確定した「1 ユーザー = 1 Group 制約 (MVP)」を data-foundation に反映する。さらに、追記マイグレーションを **dev ブランチへの push で自動適用** する CI ワークフロー (`migrate-dev.yml`) を整備し、今後のスキーマ変更を手動 `pnpm db:push` 運用から脱却させる。

実施内容:

1. **追記マイグレーション**: `group_members` に `UNIQUE (user_id)` 制約を追加し、`join_group_with_code` RPC の冒頭に `already_in_group` 早期失敗ガードを `CREATE OR REPLACE` で挿入
2. **dev 自動マイグレーション CI**: `.github/workflows/migrate-dev.yml` を新規作成 (発火: `push` to `dev` branch + `paths: supabase/migrations/**`)
3. **進行中タスクの追補修正**:
   - TASK-0014 `rls.integration.test.ts` に「二重所属拒否」「`already_in_group` 早期失敗」テストを追加
   - TASK-0015 `tdd-testcases.md` / `tdd-requirements.md` に `already_in_group` 例外ケースを追加
4. **既存マイグレーションは変更禁止** (NFR-302): RPC 再定義は追記 migration 内で `CREATE OR REPLACE FUNCTION` のみ使用

App 識別子追加 (`app/types/error-codes.ts` の `ALREADY_IN_GROUP` 定数 / `locales/ja.json`) は ADR-005 §D2-D3 規約に従い **auth-onboarding 単位の管轄**。本タスクではスコープ外とする。

## 実装詳細

### 1. 追記 migration ファイル 🔵

**信頼性**: 🔵 *ADR-006 §決定 §DB 制約 / §RPC ガード*

ファイル名: `supabase/migrations/20260524150000_adr_006_single_group_per_user.sql` (timestamp は作成時刻に合わせる)

```sql
-- ADR-006: 1 ユーザー = 1 Group 制約 (MVP)
-- 既存 migration `20260519060000_initial_schema.sql` は NFR-302 により変更禁止のため、
-- 本ファイルで構造的制約 (UNIQUE) と RPC ガードを追加する。

-- 1. group_members に UNIQUE (user_id) 制約を追加
--    既存の UNIQUE (group_id, user_id) は同一 Group 内重複防止、本制約は別 Group も含めた
--    「ユーザは 1 Group のみ所属可能」を構造的に保証する。
ALTER TABLE group_members
  ADD CONSTRAINT group_members_user_id_unique UNIQUE (user_id);

-- 2. join_group_with_code を CREATE OR REPLACE で再定義し、冒頭に既所属チェックを追加
--    UNIQUE 違反 (PG 23505) を待つのではなく、識別可能な例外で早期失敗させる (ADR-006 §決定)
CREATE OR REPLACE FUNCTION join_group_with_code(invite_code text)
RETURNS uuid
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  invitation_record record;
  target_group_id uuid;
BEGIN
  -- ADR-006: 既所属チェック (構造的 UNIQUE 制約と二重ガード)
  IF EXISTS (
    SELECT 1 FROM group_members WHERE user_id = auth.uid()
  ) THEN
    RAISE EXCEPTION 'already_in_group';
  END IF;

  SELECT * INTO invitation_record
  FROM group_invitations
  WHERE code = invite_code AND deleted_at IS NULL;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'invitation_not_found';
  END IF;

  IF invitation_record.expires_at < now() THEN
    RAISE EXCEPTION 'invitation_expired';
  END IF;

  target_group_id := invitation_record.group_id;

  INSERT INTO group_members (group_id, user_id)
  VALUES (target_group_id, auth.uid());

  RETURN target_group_id;
END;
$$;
```

### 2. `.github/workflows/migrate-dev.yml` 🔵

**信頼性**: 🔵 *TASK-0012 既存 migrate-prd.yml をベース*

```yaml
name: migrate-dev

# 発火条件:
#   - dev ブランチへの push かつ supabase/migrations/ が変更された場合
#   - workflow_dispatch (手動 trigger) で再実行・dry-run も可能
#
# 注: main への push はリポジトリルールで禁止されており、prd は別ワークフロー
#     (migrate-prd.yml) で main マージ時に自動適用される。
#     本ワークフローは dev プレ環境用 (GitHub Flow + dev pre-prod ブランチ構造)。

on:
  push:
    branches: [dev]
    paths:
      - 'supabase/migrations/**'
  workflow_dispatch: {}

concurrency:
  group: migrate-dev
  cancel-in-progress: false

jobs:
  migrate:
    runs-on: ubuntu-latest

    permissions:
      contents: read
      issues: write

    environment: dev

    env:
      SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}
      SUPABASE_DB_PASSWORD: ${{ secrets.SUPABASE_DB_PASSWORD }}
      SUPABASE_PROJECT_REF: ${{ secrets.SUPABASE_PROJECT_REF }}

    steps:
      - name: Checkout
        uses: actions/checkout@v6

      - name: Setup Supabase CLI
        uses: supabase/setup-cli@v1
        with:
          version: latest

      - name: Link to dev project
        run: |
          supabase link \
            --project-ref "${SUPABASE_PROJECT_REF}" \
            --password "${SUPABASE_DB_PASSWORD}"

      - name: Push migrations to dev
        run: supabase db push --linked

      - name: Notify on failure (create GitHub Issue)
        if: failure()
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          gh issue create \
            --title "dev マイグレーション失敗: ${{ github.sha }}" \
            --body "$(cat <<EOF
          dev 自動マイグレーション (migrate-dev.yml) が失敗しました。

          - Commit: ${{ github.sha }}
          - Actions run: ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}
          - Triggered by: ${{ github.actor }}

          dev プレ環境のスキーマが整合しない可能性があります。原因を調査し、
          修正マイグレーションを追加するか dev ブランチを reset してください。
          EOF
          )" \
            --label "dev-migration-failure"
```

## 注意事項

- **App 識別子追加はスコープ外**: `app/types/error-codes.ts` の `ALREADY_IN_GROUP` 定数追加と `locales/ja.json` の文言追加は ADR-005 §D2-D3 規約により **auth-onboarding 単位**の管轄。本タスクでは DB / RPC / 統合テストのみ修正 🔵
- **既存マイグレーション変更禁止 (NFR-302)**: `20260519060000_initial_schema.sql` の RPC 定義を直接編集してはならない。必ず追記 migration 内で `CREATE OR REPLACE FUNCTION` を使う 🔵
- **GitHub Secrets `SUPABASE_DEV_*` の事前登録**: 本タスク完了前にユーザが GitHub Repository Secrets に `SUPABASE_DEV_DB_PASSWORD` / `SUPABASE_DEV_PROJECT_REF` を登録する必要がある (`SUPABASE_ACCESS_TOKEN` は prd と共用) 🔵
- **dev ブランチの存在前提**: 本タスクは dev branch が存在する前提。未作成の場合は `git checkout -b dev origin/main && git push -u origin dev` で先に作成する 🟡
- **型再生成の運用**: CI で自動 commit せず、開発者ローカルで `pnpm db:types` 実行 + dev branch に commit。理由は MVP では複雑性に見合わない 🟡
- **TASK-0014 完了マークの戻し**: ADR-006 由来の追加テストケース (TC-14-30/31) が未実装のまま overview の [x] を残すと不整合。本タスク開始時に [ ] に戻し、テスト追加後に再 [x] 化する 🔵
- **dev 適用と prd 適用のタイミング**: 本タスクで dev 適用までを完了させ、prd 適用は TASK-0017 (prd 初回マイグレーション適用) のタイミングで実施する。dev で TC-14-30/31 / TC-15-12 が全通過しないと prd 適用に進まないこと 🔵
- **MVP スコープ**: ADR-006 で Phase 2 で複数 Group 対応に拡張する可能性が言及されている。その際は本 migration の UNIQUE 制約と RPC ガードを DROP する別 migration を追加する 🟡
