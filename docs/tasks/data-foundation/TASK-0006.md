## タスク概要 🔵

**信頼性**: 🔵 *REQ-101, REQ-201, NFR-104, database-schema.sql の RLS セクション*

`docs/design/data-foundation/database-schema.sql` の RLS セクションを Supabase CLI マイグレーションとして転写する。
全 11 テーブルで Row Level Security を有効化し、`is_member_of()` ヘルパー関数を介して
「認証済みユーザーが自分の所属する Group のデータのみアクセス可能」というマルチテナント境界を
DB レベルで強制する。

**配置先**: 🔵 **TASK-0005 で作成した `{timestamp}_initial_schema.sql` に追記する** (B1 確定方針, 2026-05-13)。新規マイグレーションファイルは作成しない。

⑦ A-1 + A-2 の意思決定により、**`groups` および `group_members` の INSERT ポリシーは作成しない**。
両テーブルへの INSERT は `create_group_with_owner` / `join_group_with_code` RPC（TASK-0007）からの
SECURITY DEFINER 経由のみ許可する。

### ステップ 3: search_path 固定の必須対応 🔵

**信頼性**: 🔵 *B2 確定方針 (2026-05-13, ユーザ確認 + Supabase 公式ガイド準拠)*

`is_member_of()` の関数定義に **`SET search_path = public` を必ず付与する**。SECURITY DEFINER 関数で search_path 未固定だと search_path 攻撃 (悪意ある関数の優先解決) が成立するため、最初から正しく書く。

```sql
CREATE OR REPLACE FUNCTION is_member_of(target_group_id uuid)
RETURNS boolean
LANGUAGE sql
SECURITY DEFINER
STABLE
SET search_path = public  -- ← 必須 (B2)
AS $$
  SELECT EXISTS (
    SELECT 1 FROM group_members
    WHERE group_id = target_group_id
      AND user_id = auth.uid()
      AND deleted_at IS NULL
  );
$$;
```

database-schema.sql が `SET search_path` を含まない場合でも、**本タスクの追記時点で必ず付与する** (database-schema.sql との差分発生は許容)。CI の `supabase db lint` (TASK-0011) でも `function_search_path_mutable` として検出されるが、二重防御として最初から書く方針。

## 注意事項 ⚠

- 🔵 ポリシーの **USING と WITH CHECK の使い分け**:
  - SELECT / DELETE: `USING` のみ
  - INSERT: `WITH CHECK` のみ
  - UPDATE: **`USING` のみで十分**（database-schema.sql の方針）。ただし更新後の行も検証したい場合は `WITH CHECK` も併記する。本タスクでは database-schema.sql の記述に忠実に従う
- 🔵 ⑦ A-1 + A-2 により `groups` / `group_members` の INSERT ポリシーは **作成してはならない**。RPC（TASK-0007）が SECURITY DEFINER で代替する
- 🔵 マイグレーションファイルは **TASK-0005 で作成した `{timestamp}_initial_schema.sql` 1 本に統合する** (B1 確定方針, 2026-05-13)。新規 `_rls.sql` は作成せず、TASK-0005 のファイル末尾に追記する。理由: dev/prod の初回適用時のアトミック性 (全成功 or 全 rollback) を担保するため
- 🔵 **全 SECURITY DEFINER 関数で `SET search_path = public` 必須** (B2 確定方針, 2026-05-13)。search_path 攻撃の防御措置。本タスクの `is_member_of()` および TASK-0007 の 3 RPC すべてに付与する。CI の `supabase db lint` (TASK-0011) でも `function_search_path_mutable` として検出されるが、最初から正しく書く二重防御の方針
- 🔵 RLS の動作検証（実際に未所属ユーザーが SELECT して空集合が返ること等）は TASK-0015 の RLS 統合テストで行う。本タスクは **ポリシー定義の存在確認まで**
