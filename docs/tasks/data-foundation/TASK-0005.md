## タスク概要 🔵

**信頼性**: 🔵 *REQ-003, REQ-004, database-schema.sql に DDL 完全記載済み*

`docs/design/data-foundation/database-schema.sql` に確定済みの DDL を、Supabase CLI のマイグレーション機構（`supabase/migrations/` 配下の連番 SQL）として 1 ファイルに転写する。dev/prd 両 Supabase プロジェクトに同一スキーマを適用するための **初回マイグレーション** を構築するタスク。

**配置先**: `supabase/migrations/{timestamp}_initial_schema.sql`
（{timestamp} は `YYYYMMDDHHMMSS` 形式。例: `20260513120000_initial_schema.sql`）

**🔵 確定方針 (B1, 2026-05-13)**: マイグレーションファイルは **TASK-0005 / TASK-0006 / TASK-0007 を 1 ファイル (`{timestamp}_initial_schema.sql`) に統合する**。

- 採用理由:
  - NFR-302 により既存マイグレーションファイルの改変は禁止されているため、責務分割の review メリットが薄い
  - 1 ファイルにまとめることで初回 push のアトミック性（全成功 or 全 rollback）を担保できる
  - 後続タスク (TASK-0006: RLS / TASK-0007: RPC) では「TASK-0005 で作成した同じファイルに追記する」運用とする

本タスクの責務は **DDL（テーブル + 共通トリガー関数 + インデックス + 拡張機能）の転写** であり、RLS と RPC は後続タスクで同一ファイル末尾に追記される。

## 注意事項 ⚠

- 🔵 マイグレーションは **追記のみ**（NFR-302）。本ファイルを後続タスクで書き換えてはならない。後で修正が必要な場合は新規マイグレーションを追加する
- 🔵 RLS と RPC は **TASK-0005 と同一の `{timestamp}_initial_schema.sql` に追記する** (B1 確定方針, 2026-05-13)。初回 push のアトミック性 (全成功 or 全 rollback) を担保する。後続タスク (TASK-0006 / TASK-0007) は新規ファイルを作らず、本タスクのファイル末尾に追記する
- 🔵 ファイル名のタイムスタンプは UTC `YYYYMMDDHHMMSS` を Supabase CLI が自動採番する
- 🔵 transaction 境界は `supabase db push` がファイル全体を 1 トランザクションで実行するため明示的な `BEGIN/COMMIT` は **書かない**
- 🔵 `auth.users` への FK（`group_members.user_id`, `group_invitations.created_by`）は Supabase 標準。Supabase プロジェクトに既に存在するため CREATE 不要
