## タスク概要 🔵

**信頼性**: 🔵 *REQ-102, REQ-103, スキーマレビュー ⑦ ⑧, database-schema.sql の RPC セクション*

TASK-0006 で `groups` / `group_members` の直接 INSERT を禁止した代替手段として、3 種類の RPC（PostgreSQL 関数）を `SECURITY DEFINER` で実装する。クライアントは `supabase.rpc(...)` 経由で Group 作成・招待コード発行・招待コード参加を行う。

**配置先**: 🔵 **TASK-0005 で作成した `{timestamp}_initial_schema.sql` に追記する** (B1 確定方針, 2026-05-13)。新規マイグレーションファイルは作成しない。TASK-0006 で追記された RLS セクションの直後 (ファイル末尾) に挿入する。

実装する RPC:

| 関数名 | 用途 | 関連要件 |
|--------|------|---------|
| `create_group_with_owner(group_name text)` | Group 作成 + 自己の group_members 追加を原子化（⑦ A-1, A-2） | REQ-202 |
| `generate_invitation_code(target_group_id uuid)` | 招待コード発行（8 文字大文字 hex、7 日有効、UNIQUE 衝突リトライ最大 5 回） | REQ-102, NFR-103, EDGE-101, ⑧ B-12 |
| `join_group_with_code(invite_code text)` | 招待コードで Group 参加（期限検証、二重参加防止） | REQ-103, EDGE-001, EDGE-002 |

### generate_invitation_code 🔵

- [x] `generate_invitation_code(target_group_id uuid) RETURNS text` が定義されている
- [x] `LANGUAGE plpgsql`、`SECURITY DEFINER` 修飾子付き
- [x] 冒頭で `is_member_of(target_group_id)` をチェックし、NG なら `RAISE EXCEPTION 'not_a_member'`
- [x] `gen_random_uuid()` を CSPRNG 源として 8 文字大文字 hex を抽出（`upper(substring(replace(gen_random_uuid()::text, '-', '') from 1 for 8))`）

- [x] UNIQUE 衝突（`unique_violation` 例外）時に **最大 5 回までリトライ**
- [x] 5 回連続失敗時に `RAISE EXCEPTION 'invitation_code_collision_after_retry'`
- [x] 成功したら生成した 8 文字 code を返す

### join_group_with_code 🔵

- [x] `join_group_with_code(invite_code text) RETURNS uuid` が定義されている
  - **引数名は `invite_code`**（database-schema.sql の最終 DDL に準拠。タスク指示の `invitation_code` ではない。注意事項参照）🟡
- [x] `LANGUAGE plpgsql`、`SECURITY DEFINER` 修飾子付き
- [x] `group_invitations` から `code = invite_code AND deleted_at IS NULL` で検索
- [x] 該当なし時に `RAISE EXCEPTION 'invitation_not_found'`（EDGE-001 相当）

### ステップ 3: search_path 固定の必須対応 🔵

**信頼性**: 🔵 *B2 確定方針 (2026-05-13, ユーザ確認 + Supabase 公式ガイド準拠)*

**3 関数すべての定義に `SET search_path = public` を必ず付与する**。SECURITY DEFINER 関数で search_path 未固定だと search_path 攻撃が成立するため、最初から正しく書く。

```sql
-- 例: create_group_with_owner
CREATE OR REPLACE FUNCTION create_group_with_owner(group_name text)
RETURNS uuid
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public  -- ← 必須 (B2)
AS $$
  -- ...本体...
$$;

-- 同様に generate_invitation_code / join_group_with_code にも付与
```

database-schema.sql が `SET search_path` を含まない場合でも、**本タスクの追記時点で必ず付与する**。TASK-0006 の `is_member_of()` と方針を揃え、CI の `supabase db lint` (TASK-0011) との二重防御とする。

### 例外名と api-endpoints.md の整合 🔵

api-endpoints.md（行 327〜332）と本実装の例外名:

| 関数 | 例外メッセージ |
|------|--------------|
| create_group_with_owner | `not_authenticated`, `invalid_group_name` |
| generate_invitation_code | `not_a_member`, `invitation_code_collision_after_retry` |
| join_group_with_code | `invitation_not_found`, `invitation_expired`, PG code `23505`（二重参加） |

タスク指示書では `invalid_code` / `expired_code` / `already_member` という名前が挙げられていたが、**database-schema.sql / api-endpoints.md の確定値（`invitation_not_found` / `invitation_expired` / PG `23505`）を採用する**。理由は注意事項参照。

## 注意事項 ⚠

- 🔵 SECURITY DEFINER の関数は **関数所有者の権限で実行される**。Supabase では DB owner（典型的に `postgres`）所有なので、RLS をバイパスして `groups` / `group_members` に INSERT できる
- 🔵 **全 SECURITY DEFINER 関数で `SET search_path = public` 必須** (B2 確定方針, 2026-05-13)。本タスクの 3 RPC すべてに付与する。TASK-0006 の `is_member_of()` と方針を揃え、CI の `supabase db lint` (TASK-0011) でも `function_search_path_mutable` として検出されるが、最初から正しく書く二重防御とする
- 🔵 マイグレーションファイルは **TASK-0005 で作成した `{timestamp}_initial_schema.sql` 1 本に追記する** (B1 確定方針, 2026-05-13)。新規 `_rpc.sql` は作成しない
- 🟡 タスク指示書では例外名として `invalid_code` / `expired_code` / `already_member` が挙げられていたが、**database-schema.sql および api-endpoints.md（行 320〜332）の確定値である `invitation_not_found` / `invitation_expired` / PG code `23505` を採用する**。理由:
  - database-schema.sql が source of truth
  - api-endpoints.md にクライアント側のエラーハンドリングサンプルが既に確定値で記述されている
  - 例外名の差分は ADR-005 のエラー識別子集約で吸収可能
  - 仮に指示書の名前へ統一する場合は database-schema.sql / api-endpoints.md / 本ファイルの 3 か所を同時更新する必要があり、本タスク単独では実施しない
- 🔵 `auth.uid()` は Supabase の認証ヘッダーから取得する仕組み。クライアント側で未認証の場合は `auth.uid()` が NULL となり、`create_group_with_owner` の場合は `not_authenticated` 例外で拒否される
- 🔵 `generate_invitation_code` のリトライ 5 回上限値はスキーマレビュー ⑧ B-12 で確定済み。変更しない
- 🔵 `join_group_with_code` の二重参加時の挙動は **PostgrestError code `23505`** として伝播する仕様。クライアント側（auth-onboarding 単位）で「すでに参加済みです」と訳す（api-endpoints.md 行 346）
