## タスク概要
Group 作成画面を実装する (REQ-004/109)。Group 名フォーム (`<UForm>` + `<UFormField>`) を表示し、Zod スキーマ (`group-name`、1〜50 文字 / trim 後空白不可) で同期検証する (NFR-201、inline error)。送信で `useCreateGroup().create(name)` を呼び、成功時は `navigateTo('/')` する (dataflow.md §3)。RPC が `invalid_group_name` を返した場合は `useCreateGroup.fieldErrors` を `<UFormField>` の inline error として Group 名フィールド直下に表示する (REQ-109)。送信中は `useCreateGroup.pending` でボタンを disabled にし二重送信を防ぐ (EDGE-003)。`groups.name` に UNIQUE 制約はなく「同名重複」エラーは存在しない (architecture.md §既存 API マッピング 注1)。layout は無指定で `default.vue` を継承。

## 実装詳細
### 1. groups/new.vue 🔵
**信頼性**: 🔵 *REQ-004/109 + dataflow.md §3 + NFR-201/202 + EDGE-003*
Group 名入力フォームを `<UForm>` + `<UFormField>` で組む。`<UForm>` の schema に Zod `group-name` (TASK-0006) を渡し、送信前に同期検証する (1〜50 文字 / trim 後空白不可、NFR-201。EDGE-103/104/105 の境界は Zod 側で検証済)。送信で `useCreateGroup().create(name)` を呼ぶ。
- 成功 (`{ data: group_id, error: null }`) → `navigateTo('/')` (useCreateGroup が内部で `useCurrentGroup.refresh()` 済、dataflow.md §3)。
- `invalid_group_name` (RPC 側検証) → `useCreateGroup.fieldErrors['name']` を `<UFormField>` の inline error として表示 (REQ-109 / error-handling.md §6.3 #2)。page は context 文字列を持たない (error-handling.md §5.5)。
- 送信中は `useCreateGroup.pending` で送信ボタンを disabled にし二重送信を防ぐ (EDGE-003 / NFR-202)。

「同名グループ重複」エラーは存在しない (`groups.name` に UNIQUE 制約なし、architecture.md §既存 API マッピング 注1)。create のエラーは `invalid_group_name` のみ。layout は無指定で `default.vue` を継承。文言は locales 経由 (NFR-204)。
**実装ファイル**: `app/pages/groups/new.vue`
