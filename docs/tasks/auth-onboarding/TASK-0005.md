## 実装詳細
### 1. error.vue 🔵
**信頼性**: 🔵 *error-handling.md §8.4*
`app/error.vue` を作成。`defineProps<{ error: NuxtError }>()` で受け取り、`onMounted` で `Sentry.captureException(props.error)` を呼ぶ。全画面置換フォールバックとして `clearError()` による復帰動線を持たせ、表示文言は locales 経由 (`t('errors.generic')` 等) で取得する (NFR-204)。マークアップは Nuxt UI コンポーネントで組む (具体は kairo-implement で確定)。
**実装ファイル**: `app/error.vue`
```vue
<script setup lang="ts">
import * as Sentry from '@sentry/nuxt'
import type { NuxtError } from '#app'

const props = defineProps<{ error: NuxtError }>()

onMounted(() => {
  // グローバルフォールバック: 想定外例外 (undefined.foo / Hydration mismatch 等) のみここに到達する。
  // 想定エラー (INVITATION_* / NOT_A_MEMBER / ALREADY_IN_GROUP 等) は domain composable で
  // チャネル表示済のため error.vue には来ない → ここでの captureException は想定外のみ報告 (NFR-304)。
  Sentry.captureException(props.error)
})

// clearError() で復帰動線を提供 (テンプレートのボタンから呼ぶ)
</script>
```

### 2. Sentry 報告ポリシー 🔵
**信頼性**: 🔵 *NFR-304*
報告対象を「想定外例外 (error.vue 到達分)」と「unmapped 識別子」のみに限定する方針を確立する。`unmapped_error_code` の報告 (`tags: { reason: 'unmapped_error_code' }`) は `useErrorMessage` 側 (TASK-0007) の fallthrough で行うため、本タスクの error.vue では想定外例外のみを扱う。ユーザ操作起因の想定エラー (招待コード期限切れ等) は送らない。
**実装ファイル**: `app/error.vue` (コメントとして方針を明記)
