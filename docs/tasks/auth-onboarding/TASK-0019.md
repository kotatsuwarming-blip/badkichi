## タスク概要
Group 設定画面を実装する (REQ-006/007/110)。招待リンク一覧 (`useListInvitations`: 発行日 / 期限 / 状態を表示、**状態は `expires_at < now()` の派生値**で算出 — group_invitations に status 列は無い)、「招待リンクを発行」ボタン (`useGenerateInvitation().generate` → 返却 code を `${useRequestURL().origin}/join/{code}` 形式で組み立て、REQ-408)、URL コピーボタン (`useToast` で「コピーしました」を 2 秒表示、NFR-203)、メンバー一覧 (read only、Google アカウントの表示名 + avatar) を表示する。発行成功後は `useGenerateInvitation` が内部で `useListInvitations.refresh()` を呼び一覧が自動更新される (dataflow.md §5)。`not_a_member` は `useToast` で表示 (REQ-110)。`invitation_code_collision_after_retry` も toast + 再試行 (EDGE-008)。layout は無指定で `default.vue` を継承。

## 実装詳細
### 1. groups/[id]/settings.vue 🔵
**信頼性**: 🔵 *REQ-006/007/110/408 + dataflow.md §5 + NFR-203*
group id は route params (`id`) から取得する。
- **招待リンク一覧**: `useListInvitations` (`useAsyncData('invitations-list:{id}')`) の `Invitation[]` を一覧表示。各行に発行日 (`created_at`)・期限 (`expires_at`)・**状態**を表示。状態は **`expires_at < now()` で派生算出**する (group_invitations に status 列は無い、interfaces.ts 注 / EDGE-107)。
- **発行ボタン**: `useGenerateInvitation().generate(id)` を呼ぶ (pending=true)。
  - 成功 → 返却 8 hex code を `${useRequestURL().origin}/join/${code}` 形式で URL 組立 (REQ-408 / REQ-007。SSR 環境の host は `useRequestURL()`)。`useGenerateInvitation` が内部で `useListInvitations.refresh()` を呼ぶため一覧が自動更新 (dataflow.md §5)。成功 toast「招待リンクを発行しました」。
  - `not_a_member` → `useToast` で「このグループのメンバーではありません」(REQ-110 / error-handling.md §6.3 #5)。
  - `invitation_code_collision_after_retry` → `useToast` + 再試行ボタン (EDGE-008)。
- **URL コピー**: コピーボタン押下で `useToast` 「コピーしました」を 2 秒表示 (NFR-203)。
- **メンバー一覧**: read only。Google アカウントの表示名 + avatar を表示 (REQ-006)。

layout は無指定で `default.vue` 継承。文言は locales 経由 (NFR-204)。
**実装ファイル**: `app/pages/groups/[id]/settings.vue`

### 2. メンバー一覧取得 🟡
**信頼性**: 🟡 *architecture.md は members 一覧の具体 SELECT を明示していない (実装時クエリ確定)*
メンバー一覧の取得元 (`group_members` 結合 + Google identity の表示名 / avatar の取得元) は architecture.md / interfaces.ts に具体 SELECT が明示されていない。表示名 / avatar は `auth.users` の identity か、`useSupabaseUser()` の `user_metadata` 相当の値が候補だが、他メンバーの identity をクライアントから取得できるかは RLS と Supabase の identity 公開範囲に依存するため、実装時にクエリ (SELECT / 結合) を確定する。取得は domain composable 経由とし page から直接 `supabase.from(...)` を叩かない (REQ-406)。
**実装ファイル**: `app/pages/groups/[id]/settings.vue` (+ 必要なら member 取得 composable)

## 注意事項
- group_invitations に status 列は無い。「状態」(有効 / 期限切れ) は `expires_at < now()` で派生算出する (interfaces.ts 注。`expires_at == now()` の境界は EDGE-107)。
- メンバー一覧の取得クエリは 🟡 (実装時確定)。表示名 / avatar の取得元・RLS 公開範囲・結合方法を実装時に確定し、必ず domain composable 経由にする (REQ-406)。
- URL 組立は `${useRequestURL().origin}/join/${code}` (REQ-408。SSR 環境の host 取得に `useRequestURL()` を使う)。
- 該当 Group のメンバーのみアクセス可 (middleware で未認証 → `/login` / 未所属 → `/onboarding`、+ RLS)。MVP では削除 / 招待無効化は無い (REQ-404)、有効期限は固定 7 日 (REQ-405)。
