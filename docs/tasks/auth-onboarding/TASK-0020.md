## タスク概要
auth-onboarding の全画面 (TASK-0013〜0019) 結線後の統合・受入検証を行う。新規の DB / API は作らず、data-foundation の既存 3 RPC (`create_group_with_owner` / `join_group_with_code` / `generate_invitation_code`) + PostgREST + Supabase Auth を消費する UI 層の最終確認に限定する。

本タスクで実施すること:
- 既存の全 mock unit テスト (composables / middleware / schemas) を緑にして回帰を確認する (ADR-012 D1)
- i18n `ja.json` / `en.json` のキー構造一致チェック緑を確認する (NFR-303)
- 未ログイン招待リンク経由のリダイレクトチェーン全体 (EDGE-001) を手動確認する
- global middleware (`auth.global.ts`) による保護漏れゼロを全保護ページで確認する (NFR-104 / ADR-008)
- NFR-001 ログインフロー 5 秒以内を dev 環境で実測する (設計面は確定済、実測ゲートのみ)
- 招待発行 → URL コピー → 別ユーザ参加の手動シナリオを通す
- acceptance-criteria.md の受入項目を満たすことを検証ログに記録する

E2E (Playwright) は ADR-012 D10 で MVP 保留のため本タスクでは実施しない。Google OAuth の実フローテストも行わない (D10 / 採用しなかった選択肢 G、bot 検出リスク)。

## 実装詳細
### 1. 受入検証と検証ログ記録 🔵
**信頼性**: 🔵 *acceptance-criteria.md*
acceptance-criteria.md の受入項目 (REQ-001〜007 / 100s / 200s / 401, NFR-301〜304) を順に確認し、結果を検証ログに記録する。検証は次の手段で行う:
- 自動化済みの項目 (TC-001-01, TC-003-01〜04, TC-101〜104 系, TC-NFR-304 系など) は mock unit テスト緑で担保 (実装詳細 4 / 単体テスト要件)。
- 手動確認の項目はリダイレクトチェーン (③ / EDGE-001) と招待発行 → コピー → 別ユーザ参加 (⑥) のシナリオで担保する。
- EDGE-006 (別タブ同時 Group 作成 / 参加) の `already_in_group` 拒否は data-foundation 側 integration (TC-401-02) で検証済 (ADR-012 D2)、本タスクでは再実施しない。
検証ログは合否・実測値・気づきを残し、auth-onboarding 単位の完了判定の根拠とする。

### 2. NFR-001 ログインフロー 5 秒実測ゲート 🟡
**信頼性**: 🟡 *architecture.md §パフォーマンス。設計面は確定済 (1 ナビゲーション 1 クエリ = NFR-002 / ADR-008 D4) で不確実性なし、実測のみ未実施。OAuth ラウンドトリップは外部要因*
dev 環境で「Google でログイン」押下から行き先ページ表示完了までの合計時間を実測する (Google OAuth 画面表示〜承認のユーザ操作時間は除外)。設計レバーは `useCurrentGroup` の `useAsyncData('current-group', …)` による 1 ナビゲーション 1 クエリ保証で確定済 (NFR-002)。5 秒を超過した場合のみ個別チューニング (不要なクエリ・待機の特定) を行う。本項目が 🟡 なのは「未実測」であって「設計が曖昧」だからではない (architecture.md §パフォーマンス)。

### 3. middleware 保護漏れゼロ確認 🔵
**信頼性**: 🔵 *NFR-104 / ADR-008*
`auth.global.ts` が global middleware として全保護ページに適用され、保護漏れが構造的に起きないことを確認する。全保護ページ (`/` / `/onboarding` / `/groups/**` 等) を未認証で直アクセスし、いずれも `/login?redirect={path}` にリダイレクトされること、ログイン済 Group 未所属では `/onboarding` に強制リダイレクトされ本体がレンダリングされないこと (REQ-202) を確認する。分岐ロジック自体は mock unit (`tests/unit/middleware/auth.test.ts`) で網羅済 (ADR-008 D8 / ADR-012 D2)、本タスクは「新規ページに付け忘れがないか」の構造確認に focus する。
