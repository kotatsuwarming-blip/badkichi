## タスク概要
本プロジェクト初の `app/layouts/` を導入する (ADR-011)。認証前後で画面の外枠が根本的に異なるため、2 レイアウト構成を採用する。`auth.vue` は中央寄せ・ロゴのみ・ヘッダーなしで `/login`・`/confirm` が使用する。`default.vue` はヘッダー (ロゴ + ユーザアバター + ログアウト) + `<slot />` で、認証後の全 page が**無指定で自動適用**する。REQ-008 (ログアウト) は `default.vue` ヘッダーに 1 回だけ実装し、player-management 以降の page を足してもヘッダー + ログアウトが自動で付く「付け忘れゼロ」を構造的に保証する (ADR-008 の「保護漏れゼロ」と同じ事故防止思想)。ログアウトは `useLogin().logout()` 経由で呼ぶ (page/layout から `supabase.auth` を直接叩かない、REQ-406)。

## 実装詳細
### 1. auth.vue (認証前レイアウト) 🔵
**信頼性**: 🔵 *ADR-011 D1 + architecture.md §レイアウト戦略*
中央寄せ・ロゴのみ・ヘッダーなしの外枠。未ログイン画面のためユーザアバター / ログアウトは存在しえない (ADR-011 背景)。`<slot />` に page (`/login`, `/confirm`) を描画する。各 page 側で `definePageMeta({ layout: 'auth' })` を指定して切り替える (TASK-0015 で page 側に付与)。内部の具体マークアップ (どの Nuxt UI コンポーネントで組むか、ロゴ画像の配置等) は本タスクで確定する (ADR-011 D3「枚数・責務・ログアウトの所在のみ設計確定、マークアップは実装で確定」)。
**実装ファイル**: `app/layouts/auth.vue`

### 2. default.vue (認証後レイアウト) 🔵
**信頼性**: 🔵 *ADR-011 D1-D2 + REQ-008 + dataflow.md §2*
ヘッダー (ロゴ + ユーザアバター + ログアウト) + `<slot />`。認証後の全 page (`/onboarding`, `/groups/new`, `/join/[code]`, `/groups/[id]/settings` および後続単位の全 page) が**無指定で自動適用**する。ログアウト処理は `useLogin().logout()` を呼ぶ (`signOut()` → `/login` 遷移は useLogin が内包、ADR-011 D2 / REQ-406)。ユーザアバターは `useSupabaseUser()` の Google identity (表示名 / avatar_url) を表示する (read only、REQ-006 と整合)。ログアウトの実装はこの 1 箇所のみとし、後続単位で page を追加しても自動継承される (NFR-104 と同じ思想)。
**実装ファイル**: `app/layouts/default.vue`

1. **direct-setup**:

   - ヘッダーのログアウトが `useLogin().logout()` を呼び `/login` へ遷移することを確認。

## 注意事項
- レイアウト内部の具体マークアップ (どの Nuxt UI コンポーネント = `UContainer` / `UHeader` 等で組むか、ロゴ画像配置) は本タスクの実装時に確定する (ADR-011 D3 / architecture.md §レイアウト戦略)。設計は「枚数 2 枚・責務・ログアウトの所在」のみ確定済。
- player-management 以降の page は `definePageMeta({ layout })` を**指定しない**ことで `default.vue` を自動適用しヘッダー + ログアウトを継承する (ADR-011 後続 UI 単位への影響)。
- `/join/[code]` は public path (未ログインでも着地しうる) だが、レイアウトは `default.vue` を使う。未認証時の page 内リダイレクトはレイアウト分岐とは独立 (ADR-011 D1)。
- ログアウトは page/layout から `supabase.auth.signOut()` を直接呼ばず、必ず `useLogin` 経由 (REQ-406)。
