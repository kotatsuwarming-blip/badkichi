## タスク概要
REQ-001 / REQ-008。Google OAuth ログインとログアウトを内包する Write (Auth) composable。`login()` は `supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: '/confirm?redirect=...' } })` を呼び、A2 (redirect クエリ運搬) のため目的地を `/confirm` の `redirect` クエリに載せる。`logout()` は `supabase.auth.signOut()` 後に `navigateTo('/login')` する。Auth エラーは EDGE-002 のため `useNoticeErrors` チャネル (`notice`) に流して `<UAlert>` 表示に備える。二重送信防止 (EDGE-003) のため `pending` を持つ。戻り値は interfaces.ts `UseLoginReturn` (`{ login, logout, pending, notice }`)。page から `supabase.auth` を直叩きしない (REQ-406 / ADR-007 D9)。

## 実装詳細
### 1. useLogin 🔵
**信頼性**: 🔵 *REQ-001 / REQ-008 + dataflow.md §2 (sequence) + interfaces.ts UseLoginReturn + architecture.md §既存 API マッピング*
`useSupabaseClient<Database>()` から `auth.signInWithOAuth` / `auth.signOut` を呼ぶ。`useNoticeErrors()` の `notice` / `setNotice` を expose 用に取得。`login(redirect?)` では `redirectTo` に `/confirm?redirect=` + 目的地を組み立てて運搬する (A2)。`redirect` は引数で受けるか内部で `useRoute().query.redirect` を読むかは実装判断だが、本契約では引数で示す (interfaces.ts UseLoginReturn コメント)。`logout()` は `signOut()` 成功後に `navigateTo('/login')`。Auth エラー (両関数共通) は `setNotice(error)` で `<UAlert>` チャネルへ。`pending` は各関数の try/finally で制御する。
**実装ファイル**: `app/composables/useLogin.ts`
```ts
// app/composables/useLogin.ts
export function useLogin(): UseLoginReturn {
  const supabase = useSupabaseClient()
  const { notice, setNotice, clear } = useNoticeErrors()
  const pending = ref(false)

  async function login(redirect?: string) {
    clear()
    pending.value = true
    const redirectTo = `/confirm?redirect=${encodeURIComponent(redirect ?? '/')}`
    const { error } = await supabase.auth.signInWithOAuth({
      provider: 'google',
      options: { redirectTo }
    })
    if (error) setNotice(error)
    pending.value = false
  }

  async function logout() {
    pending.value = true
    const { error } = await supabase.auth.signOut()
    if (error) setNotice(error)
    else await navigateTo('/login')
    pending.value = false
  }

  return { login, logout, pending, notice }
}
```
> `redirectTo` の絶対 URL / 相対パス扱いは `@nuxtjs/supabase` / Supabase OAuth の仕様に合わせて実装時に確認 (リダイレクト許可リスト含む)。`/confirm` への着地後の遷移は TASK-0016 (confirm.vue) と middleware (§1) が担う。

## 注意事項
- page から `supabase.auth` を直叩きすることは禁止 (REQ-406 / ADR-007 D9)。ログイン・ログアウトは必ず `useLogin` 経由。

- Auth エラーは `<UAlert>` (notice チャネル) であり toast でない (EDGE-002, dataflow.md §6)。
