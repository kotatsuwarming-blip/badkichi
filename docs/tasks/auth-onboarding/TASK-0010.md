## タスク概要
REQ-004 / REQ-109。Group 作成を内包する Write (RPC) composable。`create(groupName)` は `rpc('create_group_with_owner', { group_name })` を呼び、成功で `useCurrentGroup().refresh()` を呼んで所属状態を最新化する (D5-4)。検証エラー `invalid_group_name` は `useFormErrors` チャネルで inline 表示 (REQ-109, `<UFormField>`)。二重送信防止 (EDGE-003) のため `pending` を持つ。戻り値は interfaces.ts `UseCreateGroupReturn` (`{ create, pending, fieldErrors }`)。`create` は `ActionResult<string>` (group_id) を返す。`groups.name` に UNIQUE 制約はないため「同名重複」エラーは存在せず、create のエラーは `invalid_group_name` のみ (architecture.md §既存 API マッピング 注1)。

## 実装詳細
### 1. useCreateGroup 🔵
**信頼性**: 🔵 *dataflow.md §3 (sequence) + architecture.md §既存 API マッピング 注1 + interfaces.ts UseCreateGroupReturn + error-handling.md §6.5*
`useSupabaseClient<Database>()` の `rpc('create_group_with_owner', { group_name })` を呼ぶ。引数名は生成済み型と適用済み migration を真とし `group_name` (architecture.md §既存 API マッピング)。`useFormErrors()` の `fieldErrors` / `setFieldError` / `clear` を取得。`useCurrentGroup()` の `refresh` を取得し成功時に呼ぶ。`create` 冒頭で `clear()`、`pending=true`、RPC 実行、エラーなら `setFieldError('name', error)`、成功なら `refresh()`。`pending` は try/finally で false に戻す。`{ data, error }` (ActionResult) を返し、page は `error` を成功/失敗の分岐にのみ使う (ADR-007 §補遺)。
**実装ファイル**: `app/composables/useCreateGroup.ts`
```ts
// app/composables/useCreateGroup.ts
export function useCreateGroup(): UseCreateGroupReturn {
  const supabase = useSupabaseClient<Database>()
  const { fieldErrors, setFieldError, clear } = useFormErrors()
  const { refresh } = useCurrentGroup()
  const pending = ref(false)

  async function create(groupName: string): Promise<ActionResult<string>> {
    clear()
    pending.value = true
    const { data, error } = await supabase.rpc('create_group_with_owner', {
      group_name: groupName
    })
    if (error) setFieldError('name', error) // invalid_group_name (REQ-109)
    else await refresh()
    pending.value = false
    return { data, error }
  }

  return { create, pending, fieldErrors }
}
```
> `groups.name` に UNIQUE 制約は無く (CHECK のみ) 「同名グループ重複」エラーは存在しない。ADR-007 D4-2 例の `GROUP_NAME_TAKEN` / `UNIQUE_VIOLATION` 分岐は不正確なため採用しない (architecture.md §既存 API マッピング 注1)。create のエラーは `invalid_group_name` のみ。Zod による事前検証 (1〜50 文字 / 空白不可) は page 側で TASK-0006 schema を使い、RPC 側 `invalid_group_name` は二重防御の inline 表示。
