## タスク概要
REQ-005 / 105 / 106 / 107。招待コードによる Group 参加を内包する Write (RPC) composable。`join(inviteCode)` は `rpc('join_group_with_code', { invite_code })` を呼び、成功で `useCurrentGroup().refresh()` (dataflow.md §4)。エラーは `useNoticeErrors` チャネル (`<UAlert>` 永続) に流す。重要な非自明点として、DB が返す `invitation_not_found` と App 識別子 `INVITATION_NOT_FOUND_BY_LINK` は **文字列が異なる**ため、`useJoinGroup` 内で DB メッセージ `invitation_not_found` を**明示判定**して `INVITATION_NOT_FOUND_BY_LINK` に変換する (素朴な `includes` では一致しない、注2 / EDGE-005)。`already_in_group`→`ALREADY_IN_GROUP` (REQ-105)、`invitation_expired`→`INVITATION_EXPIRED` (REQ-106)。`pending` を持つ (EDGE-003)。戻り値は interfaces.ts `UseJoinGroupReturn` (`{ join, pending, notice }`)。

## 実装詳細
### 1. useJoinGroup 🔵
**信頼性**: 🔵 *dataflow.md §4 (sequence) + architecture.md §既存 API マッピング 注2/注3/注4 + interfaces.ts UseJoinGroupReturn + error-handling.md §5.5 / §6.5*
`useSupabaseClient<Database>()` の `rpc('join_group_with_code', { invite_code })` を呼ぶ。`useNoticeErrors()` の `notice` / `setNotice` / `clear`、`useCurrentGroup()` の `refresh` を取得。`join` 冒頭で `clear()`、`pending=true`。エラー時はチャネルへ流すが、DB の `invitation_not_found` は App 識別子 `invitation_not_found_by_link` と文字列が違うため、`setNotice(error)` の素朴な `includes` では `INVITATION_NOT_FOUND_BY_LINK` 文言に解決できない (注2)。そこで DB メッセージを明示判定し、`INVITATION_NOT_FOUND_BY_LINK` 識別子相当のエラーに**詰め替えてから** `setNotice` する (または `errorToMessage` に詰め替え後のエラーを渡す)。`already_in_group` / `invitation_expired` は App 識別子と文字列一致するため `setNotice(error)` でそのまま解決される。成功時は `refresh()`。`{ data, error }` (ActionResult) を返す。
**実装ファイル**: `app/composables/useJoinGroup.ts`
```ts
// app/composables/useJoinGroup.ts
import { APP_ERROR_CODES } from '~/types/error-codes'

export function useJoinGroup(): UseJoinGroupReturn {
  const supabase = useSupabaseClient<Database>()
  const { notice, setNotice, clear } = useNoticeErrors()
  const { refresh } = useCurrentGroup()
  const pending = ref(false)

  async function join(inviteCode: string): Promise<ActionResult<string>> {
    clear()
    pending.value = true
    const { data, error } = await supabase.rpc('join_group_with_code', {
      invite_code: inviteCode
    })
    if (error) {
      // 注2: DB 'invitation_not_found' は App 'invitation_not_found_by_link' と文字列が異なる。
      // 素朴な includes では一致しないため明示判定し、App 識別子へ詰め替える (EDGE-005)。
      const msg = (error as { message?: string }).message ?? ''
      const mapped = msg.includes('invitation_not_found') && !msg.includes('invitation_not_found_by_link')
        ? { ...error, message: APP_ERROR_CODES.INVITATION_NOT_FOUND_BY_LINK }
        : error
      setNotice(mapped) // already_in_group / invitation_expired はそのまま一致
    } else {
      await refresh()
    }
    pending.value = false
    return { data, error }
  }

  return { join, pending, notice }
}
```
> `join_group_with_code` は ADR-006 migration で `already_in_group` を**最初に**チェックするため、1 user = 1 group 違反は識別可能な例外で早期失敗する (PG 23505 を待たない、注4)。`already_in_group` は本単位で `APP_ERROR_CODES` に追加済 (注3 / interfaces.ts §1)。明示判定のロジックは実装時に DB メッセージの厳密な値で調整してよいが、「素朴 includes に頼らない」原則は守る (注2)。

## 注意事項
- `isAppError(error, INVITATION_NOT_FOUND_BY_LINK)` (= `message.includes('invitation_not_found_by_link')`) では DB の `invitation_not_found` に一致しない。必ず明示判定して App 識別子へ詰め替えること (注2)。これが本タスクの最大の非自明点。
- `join_group_with_code` は `already_in_group` を最初にチェックする (ADR-006 / 注4)。1 user = 1 group 違反は PG 23505 ではなく `already_in_group` 例外で返る。
- `already_in_group` 識別子は本単位で `APP_ERROR_CODES` に追加済 (TASK-0003、注3 / interfaces.ts §1)。
- エラーチャネルは `<UAlert>` 永続 (`useNoticeErrors`)。招待リンク着地はフィールド特定不能のため inline でなく `<UAlert>` (error-handling.md §6.3 代表例 #3)。
