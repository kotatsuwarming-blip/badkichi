## タスク概要

選手を **ソフト削除**する Write composable `app/composables/useDeletePlayer.ts` を実装する。
`UseDeletePlayerReturn` 契約（`{ deletePlayer, pending }`）に従い、`deletePlayer(id)` で
`from('players').update({ deleted_at: new Date().toISOString() }).eq('id', id)` を実行する。

players テーブルには **hard DELETE ポリシーが存在せず物理削除は不可**（REQ-402）。削除は
`deleted_at` を `now()` 相当に設定する UPDATE のみ。`useCreateGroup.ts` の pending を try/finally で
制御するパターンを踏襲。戻りは `ActionResult<null>`。

**確認ダイアログは composable 責務外**（page 側でも出さない＝無警告ソフト削除、REQ-103）。
試合（matches）に参照中の選手でも単純 update で成功し、過去 matches は player.id 経由で維持される
（REQ-104 / EDGE-006）。

## 実装詳細

### 1. useDeletePlayer composable 🔵
**信頼性**: 🔵 *interfaces.ts UseDeletePlayerReturn / players に DELETE ポリシー無し / REQ-004 / REQ-402 / EDGE-006*

`useCreateGroup.ts` の Write パターン（pending → try で実行 → finally でリセット）を踏襲。
削除は `update({ deleted_at })` の単純 UPDATE。`.delete()` は使わない（DELETE ポリシー無し＝
RLS で拒否されるうえ要件違反、REQ-402）。`eq('id', id)` で対象行に限定し、RLS `players_update`
で自 Group に限定。確認ダイアログ・refresh は呼び出し側（page）の責務。試合参照中でも
FK は player.id を残すため単純 update で成功する（EDGE-006）。戻りは `ActionResult<null>`。

**実装ファイル**: `app/composables/useDeletePlayer.ts`

```typescript
/**
 * 【機能概要】: 選手をソフト削除する Write composable (deleted_at を now() に設定)
 * 【実装方針】: useCreateGroup.ts の pending/try-finally を踏襲。
 *             update({ deleted_at }).eq('id', id) のみ (物理削除不可 = REQ-402)。
 *             確認ダイアログは持たない (無警告 = REQ-103)。
 * 🔵 interfaces.ts UseDeletePlayerReturn / REQ-004 / REQ-402 / EDGE-006
 */
import type { Database } from '~/types/supabase'
import type { Player } from '~/types/player'

interface ActionResult<T> { data: T | null; error: unknown }

interface UseDeletePlayerReturn {
  deletePlayer: (id: Player['id']) => Promise<ActionResult<null>>
  pending: Ref<boolean>
}

export function useDeletePlayer(): UseDeletePlayerReturn {
  // 【pending 初期化】: 二重送信防止のため false で初期化 🔵
  const pending = ref(false)

  // 【型付きクライアント】: Database 型付きで型安全に update する 🔵
  const client = useSupabaseClient<Database>()

  async function deletePlayer(id: Player['id']): Promise<ActionResult<null>> {
    // 【pending 開始】: 実行中は pending=true 🔵
    pending.value = true

    try {
      // 【ソフト削除 update】: deleted_at を now() 相当 (ISO 文字列) に設定。
      //   .delete() は使わない (players に DELETE ポリシー無し = REQ-402)。
      //   試合参照中でも単純 update で成功する (EDGE-006)。 🔵
      const { error } = await client
        .from('players')
        .update({ deleted_at: new Date().toISOString() })
        .eq('id', id)

      // 【エラー処理】: RLS 拒否 / PostgREST / 通信エラーは ActionResult.error に詰めて返す 🔵
      if (error) return { data: null, error }

      // 【成功戻り値】: ActionResult<null> 契約に従い { data: null, error: null } を返す 🔵
      return { data: null, error: null }
    } finally {
      // 【pending リセット】: 成功・エラーを問わず必ず false に戻す 🔵
      pending.value = false
    }
  }

  return { deletePlayer, pending }
}
```

> テスト方針: 最小境界値 + 分岐網羅のみ。Supabase クライアントをモックし、update({ deleted_at }) と eq('id', id) を検証する。

### テストケース1: TC-004-01 deleted_at 設定の update を実行（物理削除しない） 🔵
**信頼性**: 🔵 *REQ-004 / REQ-402 / players に DELETE ポリシー無し*
**Given**: `deletePlayer('p1')`、update が `{ error: null }` を返す / **When**: 実行 / **Then**: `update` が `deleted_at` キー付きで呼ばれ、`eq('id', 'p1')` が呼ばれ、`.delete()` は呼ばれず、戻りが `{ data: null, error: null }`

**テストファイル**: `tests/unit/composables/useDeletePlayer.test.ts`

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'

const eq = vi.fn()
const update = vi.fn(() => ({ eq }))
const del = vi.fn()
const from = vi.fn(() => ({ update, delete: del }))
vi.stubGlobal('useSupabaseClient', () => ({ from }))
vi.stubGlobal('ref', (v: unknown) => ({ value: v }))

const { useDeletePlayer } = await import('~/composables/useDeletePlayer')

beforeEach(() => {
  eq.mockResolvedValue({ error: null })
})

describe('useDeletePlayer', () => {
  it('TC-004-01: deleted_at 設定の update を実行し物理削除しない (REQ-402)', async () => {
    const { deletePlayer } = useDeletePlayer()
    const r = await deletePlayer('p1')
    expect(update).toHaveBeenCalledWith(expect.objectContaining({ deleted_at: expect.any(String) }))
    expect(eq).toHaveBeenCalledWith('id', 'p1')
    expect(del).not.toHaveBeenCalled()
    expect(r).toEqual({ data: null, error: null })
  })
})
```

## 注意事項
- **`.delete()` を絶対に使わない**。players には DELETE ポリシーが無く物理削除は不可（REQ-402）。削除は `update({ deleted_at })` の UPDATE のみ。
- `deleted_at` は `new Date().toISOString()`（クライアント時刻の ISO 文字列）で設定する。DB の `now()` ではなくクライアント時刻だが、ソフト削除フラグとしての一致性は問題ない（一覧フィルタは `is('deleted_at', null)` で「NULL かどうか」のみを見るため）。
- **確認ダイアログのロジックを composable に持たせない**（無警告、REQ-103）。page 側でも出さない方針。
- `pending` は **必ず try/finally** で false に戻す。
- エラーは `ActionResult.error` に詰めて返す。表示チャネル（toast）の選択は page 側（ADR-007）。
- 成功後の一覧更新は **page 側で `usePlayers().refresh()`**。
