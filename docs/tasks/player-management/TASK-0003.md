## タスク概要

選手を `players` テーブルへ insert する **Write composable** `app/composables/useCreatePlayer.ts`
を実装する。`UseCreatePlayerReturn` 契約（`{ createPlayer, pending }`）に従い、
`createPlayer({ name, handedness })` で `group_id` を `useCurrentGroup` から付与し、
`from('players').insert({ group_id, name, handedness: handedness ?? 'unknown' }).select().single()`
を実行する。

`useCreateGroup.ts` の **pending を try/finally で制御**するパターン（二重送信防止）を踏襲する
（ただし RPC ではなく PostgREST insert）。戻りは `ActionResult<Player>`。
`handedness` 省略時は `'unknown'` を送信（EDGE-003）。同名でも成功する（REQ-102 / EDGE-004、
`name` 非 UNIQUE）。成功後の一覧更新は page 側で `usePlayers().refresh()` を呼ぶ。

name 検証（Zod / inline）は **フォーム側（Phase 2）の責務**で、本 composable は insert 実行に専念する
（RLS 拒否・PostgREST・通信エラーは `ActionResult.error` として返し、page 側で `useToast()` 表示）。

## 実装詳細

### 1. useCreatePlayer composable 🔵
**信頼性**: 🔵 *interfaces.ts UseCreatePlayerReturn / useCreateGroup.ts pending・try/finally / EDGE-003 / REQ-102*

`useCreateGroup.ts` の Write パターン（pending 初期化 → try で実行 → finally で pending リセット）を
踏襲する。ただし RPC ではなく PostgREST `insert`。`group_id` は `useCurrentGroup().data.value?.group_id`
から付与。`handedness` 未指定時は `?? 'unknown'`（DB DEFAULT と一致、EDGE-003）。
`.select().single()` で挿入行を取得し `Player` として返す。エラー時は `setFieldError` ではなく
`ActionResult.error` に詰めて返し、表示チャネル（toast）の選択は page 側に委ねる（ADR-007）。

**実装ファイル**: `app/composables/useCreatePlayer.ts`

```typescript
/**
 * 【機能概要】: players へ選手を insert する Write composable
 * 【実装方針】: useCreateGroup.ts の pending/try-finally を踏襲 (二重送信防止)。
 *             group_id は useCurrentGroup から付与、handedness 省略時は 'unknown'。
 * 🔵 interfaces.ts UseCreatePlayerReturn / REQ-002 / REQ-102 / EDGE-003
 */
import type { Database } from '~/types/supabase'
import type { CreatePlayerInput, Player } from '~/types/player'

interface ActionResult<T> { data: T | null; error: unknown }

interface UseCreatePlayerReturn {
  createPlayer: (input: CreatePlayerInput) => Promise<ActionResult<Player>>
  pending: Ref<boolean>
}

export function useCreatePlayer(): UseCreatePlayerReturn {
  // 【pending 初期化】: 二重送信防止のため false で初期化 🔵
  const pending = ref(false)

  // 【型付きクライアント】: Database 型付きで型安全に insert する 🔵
  const client = useSupabaseClient<Database>()

  // 【所属 Group】: group_id を useCurrentGroup から付与する (ADR-006: 1 user 1 group) 🔵
  const currentGroup = useCurrentGroup()

  async function createPlayer(input: CreatePlayerInput): Promise<ActionResult<Player>> {
    // 【pending 開始】: 実行中は pending=true で UI 側がボタン disabled を制御可能にする 🔵
    pending.value = true

    try {
      // 【group_id 取得】: 未取得時は insert 不可。error を返して page 側で toast 表示 🔵
      const gid = currentGroup.data.value?.group_id
      if (!gid) return { data: null, error: new Error('no_current_group') }

      // 【insert 実行】: handedness 省略時は 'unknown' を送信 (EDGE-003)。同名でも成功 (REQ-102/EDGE-004) 🔵
      const { data, error } = await client
        .from('players')
        .insert({ group_id: gid, name: input.name, handedness: input.handedness ?? 'unknown' })
        .select('id, name, handedness')
        .single()

      // 【エラー処理】: RLS 拒否 / PostgREST / 通信エラーは ActionResult.error に詰めて返す (表示は page 側 toast) 🔵
      if (error) return { data: null, error }

      // 【成功戻り値】: 挿入行を Player として返す 🔵
      return { data: data as Player, error: null }
    } finally {
      // 【pending リセット】: 成功・エラーを問わず必ず false に戻す (二重送信防止) 🔵
      pending.value = false
    }
  }

  return { createPlayer, pending }
}
```

## 単体テスト要件

> テスト方針: 最小境界値 + 分岐網羅のみ。Supabase クライアントと `useCurrentGroup` をモックし、insert 引数と戻りの分岐を検証する。

### テストケース1: TC-002-01 name のみ → handedness=unknown で insert（EDGE-003） 🔵
**信頼性**: 🔵 *EDGE-003 / DEFAULT 'unknown' / REQ-002*
**Given**: `group_id = 'g1'`、`createPlayer({ name: '田中' })`（handedness 省略） / **When**: 実行 / **Then**: `insert({ group_id: 'g1', name: '田中', handedness: 'unknown' })` が呼ばれ、`ActionResult.data` が挿入行になる

**テストファイル**: `tests/unit/composables/useCreatePlayer.test.ts`

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'

const single = vi.fn()
const selectAfterInsert = vi.fn(() => ({ single }))
const insert = vi.fn(() => ({ select: selectAfterInsert }))
const from = vi.fn(() => ({ insert }))
vi.stubGlobal('useSupabaseClient', () => ({ from }))
vi.stubGlobal('ref', (v: unknown) => ({ value: v }))

let groupData = { value: { group_id: 'g1' } as { group_id: string } | null }
vi.stubGlobal('useCurrentGroup', () => ({ data: groupData }))

const { useCreatePlayer } = await import('~/composables/useCreatePlayer')

beforeEach(() => {
  groupData = { value: { group_id: 'g1' } }
  single.mockResolvedValue({ data: { id: 'p1', name: '田中', handedness: 'unknown' }, error: null })
})

describe('useCreatePlayer', () => {
  it('TC-002-01: name のみ → handedness=unknown で insert する (EDGE-003)', async () => {
    const { createPlayer } = useCreatePlayer()
    const r = await createPlayer({ name: '田中' })
    expect(insert).toHaveBeenCalledWith({ group_id: 'g1', name: '田中', handedness: 'unknown' })
    expect(r.data).toEqual({ id: 'p1', name: '田中', handedness: 'unknown' })
    expect(r.error).toBeNull()
  })
})
```

### テストケース2: TC-002-02 同名でも成功（REQ-102 / EDGE-004） 🔵
**信頼性**: 🔵 *REQ-102 / EDGE-004 / name 非 UNIQUE*
**Given**: 既存と同名 `'田中'`、insert が正常に行を返す / **When**: `createPlayer({ name: '田中', handedness: 'left' })` / **Then**: `error` なしで成功し、`insert` の `handedness` が `'left'`

```typescript
it('TC-002-02: 同名でも成功する (REQ-102/EDGE-004)', async () => {
  single.mockResolvedValue({ data: { id: 'p2', name: '田中', handedness: 'left' }, error: null })
  const { createPlayer } = useCreatePlayer()
  const r = await createPlayer({ name: '田中', handedness: 'left' })
  expect(insert).toHaveBeenCalledWith({ group_id: 'g1', name: '田中', handedness: 'left' })
  expect(r.error).toBeNull()
  expect(r.data).toMatchObject({ name: '田中', handedness: 'left' })
})
```

### テストケース3: エラー時は ActionResult.error を返す 🔵
**信頼性**: 🔵 *REQ-401 / error-handling §6④ / ActionResult 契約*
**Given**: insert が `{ data: null, error: <RLS拒否> }` を返す / **When**: `createPlayer` / **Then**: `{ data: null, error }` を返し、`pending` が finally で false に戻る

```typescript
it('エラー時は ActionResult.error を返し pending を false に戻す', async () => {
  const err = { message: 'rls denied' }
  single.mockResolvedValue({ data: null, error: err })
  const { createPlayer, pending } = useCreatePlayer()
  const r = await createPlayer({ name: '田中' })
  expect(r.data).toBeNull()
  expect(r.error).toBe(err)
  expect(pending.value).toBe(false)
})
```

## 注意事項
- `pending` は **必ず try/finally** で false に戻す（成功・例外どちらでも、二重送信防止。useCreateGroup.ts と同方針）。
- 本 composable は **name の Zod 検証を行わない**。検証は Phase 2 フォーム側（`playerNameSchema` + `<UFormField>` inline）。composable は insert 実行と `ActionResult` 返却に専念する。
- エラーは `setFieldError` ではなく **`ActionResult.error`** に詰めて返す。表示チャネル（toast）の選択は page 側（ADR-007 補遺、useCreateGroup の inline とは方針が異なる点に注意）。
- 成功後の一覧更新は **page 側で `usePlayers().refresh()`**（同一固定キー）。composable 内では refresh しない（責務分離）。
- `handedness ?? 'unknown'` は列省略でも DB DEFAULT で 'unknown' になるが、テスト検証性のため明示送信する（EDGE-003）。
