## タスク概要

選手管理のルートページ `app/pages/groups/[id]/players.vue` を実装する。`usePlayers()`（TASK-0002）で
未削除選手一覧を取得・表示し、0 件時は**空状態の説明文 + 「選手を追加」CTA**（REQ-201）を出す。
各行に編集（`PlayerFormModal` を edit mode で開く）・削除ボタンを置き、削除は**確認ダイアログなしで**
`useDeletePlayer.deletePlayer`（TASK-0005）を即実行し `usePlayers().refresh()` する（REQ-103 / 機能4）。
「選手を追加」CTA は `PlayerFormModal` を create mode で開き、`saved` 後に refresh する。

`layout` は無指定（`default` 自動適用、ADR-011 D1）。保護は `auth.global.ts` が担い、本 page 到達時点で
「認証済み・Group 所属済み」が保証される。supabase 直叩き禁止・composable 経由（REQ-403）。全文言 i18n。

新規 DB スキーマ・API・エラーコードは作らない。

## 実装詳細

### 1. 一覧取得とローディング / 空状態分岐 🔵
**信頼性**: 🔵 *REQ-001 / REQ-201 / dataflow.md 機能1 / settings.vue ローディング pattern*

`usePlayers()` の `data` / `pending` / `refresh` を使う。`pending` 中は `USkeleton`、取得後 0 件なら
空状態（`t('players.empty')` + CTA）、1 件以上なら一覧。`error` は error チャネルへ（後述）。

**実装ファイル**: `app/pages/groups/[id]/players.vue`

```vue
<script setup lang="ts">
import type { Player } from '~/types/player'

const { t } = useI18n()

// 一覧取得（composable 経由・supabase 直叩き禁止, REQ-403）
const { data: players, pending, error, refresh } = usePlayers()
</script>

<template>
  <UContainer class="py-8">
    <div class="flex max-w-2xl flex-col gap-6 mx-auto">
      <div class="flex items-center justify-between">
        <h1 class="text-2xl font-bold">{{ t('players.title') }}</h1>
        <UButton :label="t('players.add')" icon="i-lucide-plus" @click="openCreate" />
      </div>

      <!-- ローディング -->
      <div v-if="pending">
        <USkeleton class="mb-2 h-12 w-full" />
        <USkeleton class="mb-2 h-12 w-full" />
        <USkeleton class="h-12 w-full" />
      </div>

      <!-- 空状態（REQ-201） -->
      <div
        v-else-if="!players || players.length === 0"
        class="rounded-lg border border-dashed border-gray-300 p-8 text-center text-gray-500"
      >
        <p class="mb-4">{{ t('players.empty') }}</p>
        <UButton :label="t('players.add')" icon="i-lucide-plus" @click="openCreate" />
      </div>

      <!-- 一覧 -->
      <ul v-else class="flex flex-col gap-2">
        <li
          v-for="player in players"
          :key="player.id"
          class="flex items-center justify-between rounded-lg border border-gray-200 p-3"
        >
          <span class="font-medium">{{ player.name }}</span>
          <div class="flex items-center gap-2">
            <span class="text-sm text-gray-500">
              {{ t(`players.handednessOptions.${player.handedness}`) }}
            </span>
            <UButton
              color="neutral" variant="ghost" size="sm" icon="i-lucide-pencil"
              :aria-label="t('players.edit')" :label="t('players.edit')"
              @click="openEdit(player)"
            />
            <UButton
              color="error" variant="ghost" size="sm" icon="i-lucide-trash-2"
              :aria-label="t('players.delete')" :label="t('players.delete')"
              :disabled="deletePending"
              @click="onDelete(player.id)"
            />
          </div>
        </li>
      </ul>
    </div>

    <PlayersPlayerFormModal
      v-model:open="modalOpen"
      :mode="modalMode"
      :player="editTarget"
      @saved="onSaved"
    />
  </UContainer>
</template>
```

### 2. モーダル開閉（create / edit）と saved 後 refresh 🔵
**信頼性**: 🔵 *architecture.md §UI / dataflow.md 機能2・機能3 / TASK-0007 emits*

`modalOpen` / `modalMode` / `editTarget` で `PlayerFormModal` を制御。CTA で create、行の編集ボタンで
edit（対象 player をセット）。`saved` を受けてモーダルを閉じ `refresh()` する。

```vue
<script setup lang="ts">
const modalOpen = ref(false)
const modalMode = ref<'create' | 'edit'>('create')
const editTarget = ref<Player | undefined>(undefined)

function openCreate() {
  modalMode.value = 'create'
  editTarget.value = undefined
  modalOpen.value = true
}
function openEdit(player: Player) {
  modalMode.value = 'edit'
  editTarget.value = player
  modalOpen.value = true
}
async function onSaved() {
  modalOpen.value = false        // 親がモーダルを閉じる（TASK-0007 注意事項）
  await refresh()                // 一覧再取得（機能2/3 成功後）
}
</script>
```

### 3. 削除（確認なし即実行 → refresh） 🔵
**信頼性**: 🔵 *REQ-103 / REQ-104 / dataflow.md 機能4 / TC-004-01 / EDGE-005*

`useDeletePlayer.deletePlayer(id)` を**確認ダイアログを出さず**即実行。`error` が無ければ `refresh()`
で一覧から消す（`deleted_at IS NULL` フィルタ、EDGE-005）。`error` なら toast。`deletePending` 中は
削除ボタン disabled で二重実行防止。

```vue
<script setup lang="ts">
const { deletePlayer, pending: deletePending } = useDeletePlayer()
const { showError } = useToastErrors()

async function onDelete(id: Player['id']) {
  // 確認ダイアログなし（REQ-103） / composable 経由（REQ-403）
  const { error } = await deletePlayer(id)
  if (error) {
    showError(error)             // 通信 / RLS → toast
    return
  }
  await refresh()                // 一覧から除外（EDGE-005）
}
</script>
```

### 4. 取得エラーのハンドリング 🔵
**信頼性**: 🔵 *error-handling §6④/⑦ / dataflow.md エラーフロー*

`usePlayers()` の `error`（取得失敗）は error チャネルへ委譲する。最小実装としては、Write 系と整合する
`useToastErrors` で通知するか、想定外は Nuxt の `error.vue` に委譲。本 page では一覧取得失敗時に
`showError(error)` を一度通知する方針（toast）とし、空状態と取得失敗を区別する。

```vue
<script setup lang="ts">
watch(error, (e) => {
  if (e) showError(e)            // 取得失敗を toast（§6④）
})
</script>
```
