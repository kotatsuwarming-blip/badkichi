## タスク概要

選手の**追加 / 編集を一覧画面上で行う `<UModal>` フォーム**コンポーネント
`app/components/players/PlayerFormModal.vue` を実装する。専用ページは作らず、一覧（TASK-0008）から
モーダルを開いて操作する（NFR-201 / ヒアリング2026-06-02）。

`mode`（`'create' | 'edit'`）prop で挙動を分岐し、`edit` 時は対象 `player` を prop で受けてフォームを
プリフィルする。name は `playerNameSchema`（TASK-0001）でクライアント検証し、エラーは `<UFormField>`
inline に表示する（EDGE-007 / error-handling §6①）。handedness は3択（right / left / unknown）で、
未選択時は `unknown` を既定送信する（NFR-202 / EDGE-003）。

保存時は `mode` に応じて `useCreatePlayer.createPlayer`（TASK-0003）/ `useUpdatePlayer.updatePlayer`
（TASK-0004）を呼び、成功で `emit('saved')`（親がモーダルを閉じ `usePlayers().refresh()`）、失敗は
`useToastErrors`（TASK-0006 文言）で toast 表示する（EDGE-008）。`pending` 中はボタンを
`loading` / `disabled` にして二重送信を防止する。全文言は i18n 経由（NFR-301）。

新規 DB スキーマ・API・エラーコードは作らない。

## 実装詳細

### 1. props / emits 契約 🔵
**信頼性**: 🔵 *architecture.md §UI / dataflow.md 機能2・機能3 / 型 player.ts*

`mode` で create / edit を分岐。`edit` 時のみ `player`（`Player`）を必須的に受けプリフィルする。
親（TASK-0008）が `v-model:open` でモーダル開閉を制御し、`saved` を受けて閉じ + refresh する。

**実装ファイル**: `app/components/players/PlayerFormModal.vue`

```vue
<script setup lang="ts">
import { playerNameSchema } from '~/schemas/player-name'
import type { Player, Handedness, CreatePlayerInput, UpdatePlayerInput } from '~/types/player'

const props = defineProps<{
  mode: 'create' | 'edit'
  player?: Player          // edit 時のプリフィル対象（create 時は undefined）
  open: boolean            // 親が v-model:open で開閉制御
}>()

const emit = defineEmits<{
  'update:open': [value: boolean]
  saved: []                // 保存成功 → 親がモーダル閉じ + usePlayers().refresh()
}>()

const { t } = useI18n()
</script>
```

### 2. フォーム state とプリフィル / handedness 既定 🔵
**信頼性**: 🔵 *NFR-202 / EDGE-003 / dataflow.md 機能3 プリフィル*

`name` は文字列、`handedness` は `Handedness`。create 時は `name=''` / `handedness='unknown'`、
edit 時は `props.player` で初期化。モーダルを開くたびに（`mode` / `player` 変化時）リセットする。
未選択 = `unknown` 既定により「name だけ入力」が EDGE-003（unknown 登録）を満たす。

```vue
<script setup lang="ts">
const name = ref('')
const handedness = ref<Handedness>('unknown')

function resetForm() {
  if (props.mode === 'edit' && props.player) {
    name.value = props.player.name
    handedness.value = props.player.handedness
  } else {
    name.value = ''
    handedness.value = 'unknown'     // NFR-202 未選択既定
  }
}
// 開いた瞬間 / 対象変更時にリセット
watch(() => [props.open, props.player, props.mode], () => {
  if (props.open) resetForm()
})

// handedness 3択の選択肢（i18n / TASK-0006 と 1:1）
const handednessItems = computed(() => (['right', 'left', 'unknown'] as const).map(v => ({
  value: v,
  label: t(`players.handednessOptions.${v}`)
})))
</script>
```

### 3. name 検証（inline）と保存ハンドラ 🔵
**信頼性**: 🔵 *EDGE-007 / EDGE-001 / EDGE-002 / dataflow.md 機能2 / error-handling §6①④*

保存時にまず `playerNameSchema.safeParse(name)` で検証。失敗なら `<UFormField>` の inline error に
`t('errors.invalid_player_name')` を出して **composable を呼ばない**（EDGE-007）。成功なら mode に応じて
`createPlayer` / `updatePlayer` を呼び、`error` が無ければ `emit('saved')`、あれば `showError`（toast）。

```vue
<script setup lang="ts">
const { createPlayer, pending: createPending } = useCreatePlayer()
const { updatePlayer, pending: updatePending } = useUpdatePlayer()
const { showError } = useToastErrors()
const pending = computed(() => createPending.value || updatePending.value)

const nameError = ref<string | null>(null)   // UFormField inline 用

async function onSubmit() {
  // name クライアント検証（DB CHECK と一致、EDGE-001/002）
  const parsed = playerNameSchema.safeParse(name.value)
  if (!parsed.success) {
    nameError.value = t('errors.invalid_player_name')   // inline（EDGE-007）
    return                                              // composable を呼ばない
  }
  nameError.value = null

  let error: unknown
  if (props.mode === 'edit' && props.player) {
    const input: UpdatePlayerInput = { name: parsed.data, handedness: handedness.value }
    ;({ error } = await updatePlayer(props.player.id, input))
  } else {
    const input: CreatePlayerInput = { name: parsed.data, handedness: handedness.value }
    ;({ error } = await createPlayer(input))
  }

  if (error) {
    showError(error)            // RLS / 通信 → toast（EDGE-008 / §6④）
    return
  }
  emit('saved')                 // 成功 → 親が閉じ + refresh
}
</script>
```

### 4. テンプレート（UModal + UForm + UFormField） 🔵
**信頼性**: 🔵 *NFR-201 Nuxt UI v4 / settings.vue i18n 利用パターン / error-handling §6①*

`<UModal v-model:open>` 内に `<UForm>` を置き、name は `<UFormField :error>`、handedness は
`<USelect>`（または `<URadioGroup>`）。保存ボタンは `:loading="pending"` `:disabled="pending"`。
タイトルは mode で `modalCreateTitle` / `modalEditTitle` を出し分ける。全文言 `t()` 経由。

```vue
<template>
  <UModal :open="open" @update:open="emit('update:open', $event)">
    <template #content>
      <UForm :state="{ name, handedness }" @submit.prevent="onSubmit">
        <h2 class="text-lg font-semibold mb-4">
          {{ mode === 'edit' ? t('players.modalEditTitle') : t('players.modalCreateTitle') }}
        </h2>

        <UFormField :label="t('players.nameLabel')" name="name" :error="nameError ?? undefined">
          <UInput v-model="name" :placeholder="t('players.namePlaceholder')" autofocus />
        </UFormField>

        <UFormField :label="t('players.handednessLabel')" name="handedness" class="mt-4">
          <USelect v-model="handedness" :items="handednessItems" />
        </UFormField>

        <div class="mt-6 flex justify-end gap-2">
          <UButton
            color="neutral"
            variant="ghost"
            :label="t('players.cancel')"
            :disabled="pending"
            @click="emit('update:open', false)"
          />
          <UButton
            type="submit"
            :label="t('players.save')"
            :loading="pending"
            :disabled="pending"
          />
        </div>
      </UForm>
    </template>
  </UModal>
</template>
```

**When**: 保存（submit）

```typescript
// @vitest-environment happy-dom
import { describe, it, expect, vi } from 'vitest'
import { mount } from '@vue/test-utils'

vi.mock('vue-i18n', () => ({ useI18n: () => ({ t: (k: string) => k }) }))
const createPlayer = vi.fn(() => Promise.resolve({ data: { id: '1', name: 'a', handedness: 'unknown' }, error: null }))
vi.mock('~/composables/useCreatePlayer', () => ({ useCreatePlayer: () => ({ createPlayer, pending: ref(false) }) }))
```

## 注意事項
- name 検証 NG 時は **composable を呼ばない**（無駄な insert / update を発生させない、EDGE-007）。
- `useCreatePlayer` / `useUpdatePlayer` は **Supabase native `{ data, error }`** を返す。`error` truthy を
  失敗分岐に使い、表示はチャネル（toast / inline）を見る（ADR-007 §補遺 / interfaces.ts §2）。
- handedness 未選択既定は **`unknown`**（空文字や null を送らない、NFR-202）。`handednessItems` のキーは
  `Handedness` union と 1:1（TASK-0006 の `handednessOptions` キーに完全一致）。
- supabase を直叩きしない（必ず composable 経由、REQ-403）。
- モーダル開閉は親が `v-model:open` 制御。`saved` 後の **閉じる責務は親**（本コンポーネントは emit のみ）。
- テストは happy-dom + i18n mock（`t` はキーをそのまま返す）。Nuxt UI は最小スタブ（既存
  `VideoPlayer.test.ts` の stubs パターン踏襲）。冗長ケースを作らない。
