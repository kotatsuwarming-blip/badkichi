## 統合テスト要件

### 統合テスト1: 一覧 → 追加 → 編集 → 削除 通しフロー（happy path 1 本） 🔵
**信頼性**: 🔵 *acceptance-criteria.md TC-002/003/004 / dataflow.md 機能1〜4*
**テストファイル**: `tests/unit/pages/groups/players.flow.test.ts`（結合スタブ・happy-dom）
**テスト内容**: `players.vue` をマウントし、composable は最小限の結合スタブ（in-memory 配列で
create / update / delete / list を連動）に差し替えたうえで、
1. 初期 0 件 → 空状態
2. 追加 CTA → モーダルで name 入力 → 保存 → 一覧 1 行
3. 編集 → name 変更 → 保存 → 行の値更新
4. 削除 → 確認なし → 行消失
を 1 シナリオで検証する。
**期待結果**: 各ステップで一覧 DOM が期待どおり更新される（refresh 連動）。冗長な異常系は別タスクの
単体テストに委ねるため、ここでは happy path のみ。

```typescript
// @vitest-environment happy-dom
// in-memory 結合スタブで usePlayers/useCreatePlayer/useUpdatePlayer/useDeletePlayer を連動させ、
// 追加→編集→削除で一覧 DOM が更新されることを 1 本で確認する（happy path）。
```

### 統合テスト2: RLS / 構造的保証の確認（非実行・点検） 🔵
**信頼性**: 🔵 *NFR-101 / NFR-001 / data-foundation integration test 既存*
**テスト内容**: NFR-101 の実 RLS 越境拒否は data-foundation の `rls.integration.test.ts` が既に担保済み。
本ユニットでは新規 integration test を**追加せず**、(a) 全クエリが composable 経由で group_id を伴うこと、
(b) `usePlayers` が `deleted_at IS NULL` を含むこと、をコードレビューで点検する。
**期待結果**: 越境クエリ経路が存在せず、一覧クエリが未削除フィルタを含む。
