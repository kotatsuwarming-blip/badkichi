## タスク概要

所属 Group の **未削除選手一覧を name 昇順で返す Read composable** `app/composables/usePlayers.ts`
を実装する。`useAsyncData<Player[]>('players', handler)` の固定キー（ADR-007 D4）でラップし、
`useCurrentGroup.ts` と同じ「Database 型付きクライアント + 固定キー共有」思想に揃える。

handler は `useCurrentGroup()` の `group_id` を読み、`from('players')` を
`select('id, name, handedness')` / `eq('group_id', gid)` / `is('deleted_at', null)` / `order('name')`
で取得する。RLS（`players_select = is_member_of(group_id)`）で自 Group のみが返るが、
クエリでも `eq('group_id', gid)` を明示し、部分インデックス `idx_players_group_id`
（`WHERE deleted_at IS NULL`、NFR-001）対象の `is('deleted_at', null)` フィルタを必ず含める。

`group_id` 未取得時はクエリを発行せず `[]`（空配列）を返す。0 件は空配列。

## 実装詳細

### 1. usePlayers composable 🔵
**信頼性**: 🔵 *interfaces.ts UsePlayersReturn / useCurrentGroup.ts 固定キーパターン / REQ-001 / NFR-001*

`useCurrentGroup.ts` の固定キー Read パターンを踏襲する。`useSupabaseClient<Database>()` で
型付きクライアントを取得し、`useCurrentGroup()` から `group_id` を読む。`useAsyncData` の
固定キー `'players'` で 1 ナビゲーション 1 クエリを保証する（重複クエリ防止、ADR-007 D4）。
`group_id` が未取得（未所属・未認証）なら空配列を返し、UI は空状態（REQ-201）を表示できる。
クエリ結果の `handedness` は生成型では `string` だが、`select` 列が CHECK 制約列のみのため
ドメイン `Player[]` へ素直にマップできる（必要なら `as Player[]` で narrow）。

**実装ファイル**: `app/composables/usePlayers.ts`

```typescript
/**
 * 【機能概要】: 所属 Group の未削除選手一覧を name 昇順で返す Read composable
 * 【実装方針】: useAsyncData<Player[]>('players', handler) 固定キー (ADR-007 D4)。
 *             useCurrentGroup の group_id を読み、deleted_at IS NULL でフィルタして取得する。
 * 🔵 interfaces.ts UsePlayersReturn / useCurrentGroup.ts / REQ-001 / NFR-001
 */
import type { Database } from '~/types/supabase'
import type { Player } from '~/types/player'

export function usePlayers() {
  // 【型付きクライアント】: useCurrentGroup.ts と同じ Database 型付きクライアントを共有 🔵
  const client = useSupabaseClient<Database>()

  // 【所属 Group 読取】: ADR-006 で 1 user = 1 group。group_id を AsyncData から読む 🔵
  const currentGroup = useCurrentGroup()

  // 【固定キー useAsyncData】: 'players' 固定で 1 ナビゲーション 1 クエリを保証 (ADR-007 D4) 🔵
  return useAsyncData<Player[]>('players', async () => {
    // 【group_id 取得】: useCurrentGroup の data から group_id を読む 🔵
    const gid = currentGroup.data.value?.group_id

    // 【未取得ガード】: group_id 未取得 (未所属/未認証) はクエリ未発行で空配列を返す (REQ-201) 🔵
    if (!gid) return []

    // 【players SELECT】: 自 Group・未削除のみを name 昇順で取得。
    //   eq('group_id', gid) を明示 (RLS と二重)、is('deleted_at', null) で部分インデックス対象 (NFR-001, EDGE-005)。 🔵
    const { data, error } = await client
      .from('players')
      .select('id, name, handedness')
      .eq('group_id', gid)
      .is('deleted_at', null)
      .order('name')

    // 【エラー処理】: クエリエラーは throw して error.vue グローバルフォールバックに委ねる 🔵
    if (error) throw error

    // 【結果返却】: 0 件は空配列。handedness を Handedness に narrow して Player[] を返す 🔵
    return (data ?? []) as Player[]
  })
}
```

## 単体テスト要件

> テスト方針: 最小境界値 + 分岐網羅のみ。Supabase クライアントと `useCurrentGroup` / `useAsyncData` をモックし、handler を即時実行してクエリビルダ呼び出しを検証する。

### テストケース1: TC-001-01 自 Group のみ取得（eq(group_id) 検証） 🔵
**信頼性**: 🔵 *REQ-001 / NFR-101 / players_select RLS*
**Given**: `useCurrentGroup().data.value = { group_id: 'g1' }`、`from('players')` チェーンがダミー行を返す
**When**: handler を実行
**Then**: `from('players')` が呼ばれ、`eq('group_id', 'g1')` が呼ばれ、返り値が取得行配列になる

**テストファイル**: `tests/unit/composables/usePlayers.test.ts`

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'

// useAsyncData は handler を即時実行して結果を返すスタブにする
const handlers: Array<() => unknown> = []
vi.stubGlobal('useAsyncData', (_key: string, h: () => unknown) => {
  handlers.push(h)
  return { data: { value: undefined }, pending: { value: false }, error: { value: null }, refresh: vi.fn() }
})

const order = vi.fn()
const isNull = vi.fn(() => ({ order }))
const eq = vi.fn(() => ({ is: isNull }))
const select = vi.fn(() => ({ eq }))
const from = vi.fn(() => ({ select }))
vi.stubGlobal('useSupabaseClient', () => ({ from }))

let groupData = { value: { group_id: 'g1' } as { group_id: string } | null }
vi.stubGlobal('useCurrentGroup', () => ({ data: groupData }))

const { usePlayers } = await import('~/composables/usePlayers')

beforeEach(() => {
  handlers.length = 0
  groupData = { value: { group_id: 'g1' } }
  order.mockResolvedValue({ data: [{ id: 'p1', name: 'A', handedness: 'right' }], error: null })
})

describe('usePlayers', () => {
  it('TC-001-01: 自 Group のみ eq(group_id) で取得する', async () => {
    usePlayers()
    const result = await handlers[0]!()
    expect(from).toHaveBeenCalledWith('players')
    expect(eq).toHaveBeenCalledWith('group_id', 'g1')
    expect(result).toEqual([{ id: 'p1', name: 'A', handedness: 'right' }])
  })
})
```

## 注意事項
- `useAsyncData` のキーは **必ず固定文字列 `'players'`**。動的キー（group_id を埋め込む等）は 1 ナビゲーション内で重複クエリを生むため禁止（ADR-007 D4 / useCurrentGroup.ts と同方針）。
- 追加・編集・削除（TASK-0003〜0005）後の一覧更新は **page 側で `usePlayers().refresh()`** を呼んで行う。同一固定キーのため refresh で再取得される。
- `eq('group_id', gid)` は RLS と二重になるが、部分インデックス `idx_players_group_id` を効かせる目的とテスト検証性のため明示する（NFR-001）。
- handler は `error` を throw して `error.vue` に委ねる（useToast 整形はしない、useCurrentGroup.ts と同方針）。
- `select` 列は `'id, name, handedness'` のみ（`group_id` / `deleted_at` 等の余分な列を取得しない）。
