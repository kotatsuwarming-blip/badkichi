## タスク概要

Phase 2 の UI（TASK-0007 `PlayerFormModal.vue` / TASK-0008 `players.vue`）が使う **全 UI 文言**を
`i18n/locales/ja.json` / `en.json` に `players` namespace として追加する。コードに文字列リテラルを
直書きせず、すべて `t('players.…')` 経由にするための前提タスク（NFR-301 / REQ-404）。

ja / en の **キー構造を完全一致**させる（CI のキー構造一致チェックの対象、NFR-301）。
name 検証エラー文言キー `invalid_player_name` は、`playerNameSchema`（TASK-0001）の `message` と
整合する **既存 `errors` namespace 配下**に置く（`invalid_group_name` と同じ階層・命名規約に合わせる）。

新規 DB スキーマ・API・エラーコードは作らない。i18n の JSON 追加のみの DIRECT タスク。

## 実装詳細

### 1. `players` namespace を ja.json に追加 🔵
**信頼性**: 🔵 *既存 groups.settings 構造 + REQ-201 / REQ-202 / NFR-201 / 受入 TC-001-03*

既存 `groups.settings`（一覧タイトル・空状態 `noInvitations` 文・操作ボタン）と同じ粒度で
`players` namespace を構成する。空状態は REQ-201 の「説明文 + CTA」を満たす2キー
（`empty`＝説明文 / `add`＝CTA）に分ける。handedness の3択ラベルは `handednessOptions` 配下に集約し、
TASK-0007 の select/radio が `right` / `left` / `unknown` をそのまま引けるようにする。

文言案（命名は妥当推測のため文言キーの一部は 🟡、構造は 🔵）:

**実装ファイル**: `i18n/locales/ja.json`

```jsonc
{
  // 既存 errors namespace に 1 キー追加（playerNameSchema の message と 1:1）
  "errors": {
    // …既存キー…
    "invalid_player_name": "選手名は 1〜50 文字で入力してください"
  },
  // 新規トップレベル namespace
  "players": {
    "title": "選手一覧",
    "empty": "まだ選手が登録されていません",          // REQ-201 空状態の説明文
    "add": "選手を追加",                              // REQ-201 CTA / 追加モーダルを開く
    "nameLabel": "選手名",
    "namePlaceholder": "例: 山田 太郎",
    "handednessLabel": "利き手",
    "handednessOptions": {
      "right": "右",
      "left": "左",
      "unknown": "未設定"
    },
    "edit": "編集",
    "delete": "削除",
    "save": "保存",
    "cancel": "キャンセル",
    "modalCreateTitle": "選手を追加",
    "modalEditTitle": "選手を編集",
    "createSuccess": "選手を追加しました",
    "updateSuccess": "選手を更新しました",
    "deleteSuccess": "選手を削除しました"
  }
}
```

> 🟡 *文言の日本語そのものは妥当推測*。ただし**キー構造**（namespace・キー名・ネスト）は
> 既存 `groups.settings` / `errors.invalid_group_name` の規約に厳密準拠のため 🔵。

### 2. `players` namespace を en.json に追加 🔵
**信頼性**: 🔵 *NFR-301 キー構造一致 / 既存 en.json 構造*

ja.json と **同一キー構造**で英語文言を追加する。キーの過不足は CI で落ちるため、
ja の追加分を 1:1 で対応させる。

**実装ファイル**: `i18n/locales/en.json`

### 3. errors namespace への配置判断 🔵
**信頼性**: 🔵 *既存 errors.invalid_group_name 規約 / TASK-0001 playerNameSchema.message*

`playerNameSchema`（TASK-0001）は `message: 'invalid_player_name'` を返す。表示は
`useErrorMessage`（`errorToMessage`）→ `t('errors.invalid_player_name')` の既存変換経路を通る想定。
したがってキーは `players` 配下ではなく **既存 `errors` namespace** に置き、`invalid_group_name` と
同階層に並べる（命名・配置を既存規約に合わせ、変換ロジックを再利用する）。

## 注意事項
- ja / en は**追記のみ**。既存キーの編集・削除・並べ替えをしないこと（CI 差分とキー一致を壊さない）。
- `invalid_player_name` は `players` 配下ではなく **`errors` namespace** に置く（`invalid_group_name`
  と同階層）。`playerNameSchema.message` の値と文字列を一致させること（TASK-0001 と整合）。
- `handednessOptions` のキーは `Handedness` union（`'right' | 'left' | 'unknown'`）と**完全一致**させる
  （TASK-0007 が union 値でキーを引くため、表記ゆれ厳禁）。
- 文言の日本語/英語そのものは仕様未確定の妥当推測（🟡）。レビューで文言調整があってもキー構造は変えない。
- JSON のため ESLint の no comma dangle はそのまま適用される。末尾カンマを付けないこと。
