## 実装詳細

### 1. ドメイン型 `app/types/player.ts` 🔵
**信頼性**: 🔵 *interfaces.ts §1 ドメイン型 / players.handedness CHECK / REQ-002・REQ-003*

`interfaces.ts §1` の契約をそのまま実装ファイルに落とす。`Handedness` は
`players.handedness CHECK (handedness IN ('right','left','unknown'))` と 1:1。
生成型では `handedness` は `string` になるため、ドメイン側で union に narrow する。
`Player` は一覧・表示が使う部分集合（`id` / `name` / `handedness`）。
`group_id` は composable が `useCurrentGroup` から付与するため `CreatePlayerInput` に含めない。

**実装ファイル**: `app/types/player.ts`

```typescript
import type { Database } from '~/types/supabase'

/** 利き手。players.handedness CHECK と 1:1。
 *  🔵 players.handedness CHECK (handedness IN ('right','left','unknown'))
 *  生成型では text (string) のため、ドメイン側でこの union に narrow する。 */
export type Handedness = 'right' | 'left' | 'unknown'

/** 一覧・表示が使う players の部分集合。
 *  🔵 interfaces.ts §1 Player。クエリ:
 *  from('players').select('id, name, handedness').eq('group_id', gid)
 *    .is('deleted_at', null).order('name') */
export interface Player {
  id: Database['public']['Tables']['players']['Row']['id']
  name: Database['public']['Tables']['players']['Row']['name']
  handedness: Handedness
}

/** 追加入力。group_id は composable が useCurrentGroup から付与するため含めない。
 *  🔵 REQ-002 / REQ-102。handedness 省略時は 'unknown' (DB DEFAULT)。 */
export interface CreatePlayerInput {
  name: string
  handedness?: Handedness
}

/** 編集入力。🔵 REQ-003。 */
export interface UpdatePlayerInput {
  name: string
  handedness: Handedness
}
```

### 2. Zod スキーマ `app/schemas/player-name.ts` 🔵
**信頼性**: 🔵 *interfaces.ts §4 / players_name_length_check (1〜50字, trim 後) / group-name.ts 同型*

`group-name.ts` と完全同型で、DB の `players_name_length_check`（trim 後 1〜50 字）と一致させる。
空白のみは trim 後 0 字となり `min(1)` で弾かれる（EDGE-001）。
`message` は locale キー `invalid_player_name` と整合させる（表示は呼び出し側で `t()`）。
UI inline（Phase 2 のフォーム）と各 Write composable で共有し、DB CHECK はすり抜け時の最終防衛。

**実装ファイル**: `app/schemas/player-name.ts`

```typescript
import { z } from 'zod'

// 選手名: trim 後 1〜50 文字 (REQ-101)。空白のみは trim 後 0 文字となり min(1) で弾かれる (EDGE-001)。
// message は locale キー (invalid_player_name) と整合させる (REQ-404、表示は呼び出し側で t())。
// UI inline (Phase 2) と Write composable で共有。DB players_name_length_check はすり抜け時の最終防衛。
export const playerNameSchema = z
  .string()
  .trim()
  .min(1, { message: 'invalid_player_name' })
  .max(50, { message: 'invalid_player_name' })

export type PlayerName = z.infer<typeof playerNameSchema>
```

## 単体テスト要件

> テスト方針: 最小境界値 + 分岐網羅のみ（冗長ケース禁止）。型はコンパイル時（`pnpm typecheck`）で保証されるため、ランタイムテストは `playerNameSchema` の境界のみ。

### テストケース1: trim 後 1 字は成功（下限境界） 🔵
**信頼性**: 🔵 *EDGE-001 / players_name_length_check 下限*
**Given**: `'a'`（前後空白なし 1 字） / **When**: `playerNameSchema.safeParse('a')` / **Then**: `success === true`、`data === 'a'`

**テストファイル**: `tests/unit/schemas/player-name.test.ts`

```typescript
import { describe, it, expect } from 'vitest'
import { playerNameSchema } from '~/schemas/player-name'

describe('playerNameSchema', () => {
  it('trim 後 1 字は成功する (EDGE-001 下限)', () => {
    const r = playerNameSchema.safeParse('a')
    expect(r.success).toBe(true)
    if (r.success) expect(r.data).toBe('a')
  })
})
```

### テストケース2: 空白のみ（trim 後 0 字）は拒否 🔵
**信頼性**: 🔵 *EDGE-001 / min(1)*
**Given**: `'   '`（空白のみ） / **When**: `safeParse` / **Then**: `success === false`、エラー message が `'invalid_player_name'`

```typescript
it('空白のみは trim 後 0 字で拒否される (EDGE-001)', () => {
  const r = playerNameSchema.safeParse('   ')
  expect(r.success).toBe(false)
  if (!r.success) expect(r.error.issues[0]?.message).toBe('invalid_player_name')
})
```

### テストケース3: trim 後ちょうど 50 字は成功（上限境界） 🔵
**信頼性**: 🔵 *EDGE-002 / players_name_length_check 上限*
**Given**: `'a'.repeat(50)` / **When**: `safeParse` / **Then**: `success === true`

```typescript
it('trim 後ちょうど 50 字は成功する (EDGE-002 上限)', () => {
  const r = playerNameSchema.safeParse('a'.repeat(50))
  expect(r.success).toBe(true)
})
```

### テストケース4: trim 後 51 字は拒否 🔵
**信頼性**: 🔵 *EDGE-002 / max(50)*
**Given**: `'a'.repeat(51)` / **When**: `safeParse` / **Then**: `success === false`、message が `'invalid_player_name'`

```typescript
it('trim 後 51 字は拒否される (EDGE-002)', () => {
  const r = playerNameSchema.safeParse('a'.repeat(51))
  expect(r.success).toBe(false)
  if (!r.success) expect(r.error.issues[0]?.message).toBe('invalid_player_name')
})
```

## 注意事項
- `Player.id` / `Player.name` は **生成型を真**とし、ハードコードした `string` 型を書かないこと（`Database['public']['Tables']['players']['Row']` 参照）。`handedness` のみ union に narrow する。
- `playerNameSchema` の `message` は文言そのものではなく **locale キー**（`invalid_player_name`）。表示は呼び出し側で `t()`。`locales/ja.json` / `en.json` へのキー追加は Phase 2 のフォームタスクで行う。
- `group-name.ts` と同型を厳守（`invalid_group_name` を流用コピペしてキー置換漏れしないこと）。
- DB CHECK は trim 後の `char_length` を見るため、Zod 側も必ず `.trim()` を `min/max` の前に置く。
