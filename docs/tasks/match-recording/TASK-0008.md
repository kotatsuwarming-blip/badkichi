## タスク概要

ショット記録（楽観 insert）と、undo の**物理削除（hard delete）** composable 3本を実装する。

- **`useCreateShot()`**: `shots` を**楽観 insert**（`shot_number` / `video_timestamp_ms` / `input_source='manual'`、`rally_id` 既知）。`.select('id').single()` で `shot_id` を返す（undo の削除対象、`ShotDraft.shotId` に保持）。`OptimisticWriteReturn` 準拠。
- **`useDeleteShot()`**: `shots` を**物理削除**（`delete().eq('id', shotId)`、undo、REQ-110a）。
- **`useDeleteRally()`**: 空（shot 0 件・point 未確定）になった**遅延生成 rally を物理削除**（`delete().eq('id', rallyId)`、undo、REQ-110a）。

物理削除は **TASK-0001 の DELETE RLS ポリシー additive migration**（`rallies`/`shots`/`position_overrides`、FK 経由 `is_member_of`）が前提。soft delete（`deleted_at`）は使わない（分析 SQL で deleted_at フィルタ不要、ユーザー方針2026-06-05）。`input_source` は `'manual'` 固定（MVP、将来 `'ai'` 拡張可、REQ-301）。

## 実装詳細

### 1. useCreateShot composable（楽観） 🔵
**信頼性**: 🔵 *interfaces.ts ShotDraft / REQ-005 / REQ-301 / shots スキーマ / NFR-001*

`rally_id`（遅延生成済み）+ `shot_number`（ラリー内連番）+ `video_timestamp_ms`（getCurrentTimeMs、NULL 許容）+ `input_source:'manual'` を insert。`.select('id').single()` で `shot_id` を返す（`ShotDraft.shotId` に保持し undo で削除）。`OptimisticWriteReturn`（`{ action }` のみ、即時痕跡反映は session）。

**実装ファイル**: `app/composables/useCreateShot.ts`

```typescript
/**
 * 【機能概要】: shots を楽観 insert する Write composable（shot_id を返す）
 * 【実装方針】: OptimisticWriteReturn。即時痕跡反映は session 側、本体は非同期 insert。
 *             input_source は 'manual' 固定（MVP、REQ-301）。video_timestamp_ms は ms（NULL 許容）。
 * 🔵 interfaces.ts ShotDraft / REQ-005 / shots スキーマ / shots_insert RLS
 */
import type { Database } from '~/types/supabase'

interface ActionResult<T> { data: T | null; error: unknown }
interface CreateShotInput {
  rallyId: string
  shotNumber: number
  videoTimestampMs: number | null
}
interface UseCreateShotReturn {
  createShot: (input: CreateShotInput) => Promise<ActionResult<string>>
}

export function useCreateShot(): UseCreateShotReturn {
  const client = useSupabaseClient<Database>()

  async function createShot(input: CreateShotInput): Promise<ActionResult<string>> {
    const { data, error } = await client
      .from('shots')
      .insert({
        rally_id: input.rallyId,
        shot_number: input.shotNumber,
        video_timestamp_ms: input.videoTimestampMs,
        input_source: 'manual'
      })
      .select('id')
      .single()

    if (error) return { data: null, error }
    // 【戻り】: undo の削除対象になる shot_id（ShotDraft.shotId に保持）
    return { data: data.id, error: null }
  }

  return { createShot }
}
```

### 2. useDeleteShot composable（物理削除・undo） 🔵
**信頼性**: 🔵 *useDeleteMatch.ts delete パターン / REQ-110a / DELETE RLS（TASK-0001）*

`delete().eq('id', shotId)` で**物理削除**（soft delete でない）。undo の最後の shot 取り消しで使う。RLS DELETE ポリシー（FK 経由）が無いと行が消えないため TASK-0001 が前提。

**実装ファイル**: `app/composables/useDeleteShot.ts`

```typescript
/**
 * 【機能概要】: shots を物理削除する Write composable（undo 用）
 * 【実装方針】: delete().eq('id', shotId)。物理削除（hard delete）。soft delete は使わない。
 * 🔵 interfaces.ts UseDeleteShotReturn / REQ-110a / shots_delete RLS（TASK-0001）
 */
import type { Database } from '~/types/supabase'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseDeleteShotReturn {
  deleteShot: (input: { shotId: string }) => Promise<ActionResult<true>>
}

export function useDeleteShot(): UseDeleteShotReturn {
  const client = useSupabaseClient<Database>()

  async function deleteShot(input: { shotId: string }): Promise<ActionResult<true>> {
    // 【物理削除】: DELETE RLS（FK 経由 is_member_of）で自 Group のみ。soft delete しない
    const { error } = await client
      .from('shots')
      .delete()
      .eq('id', input.shotId)

    if (error) return { data: null, error }
    return { data: true, error: null }
  }

  return { deleteShot }
}
```

### 3. useDeleteRally composable（物理削除・空 rally の undo） 🔵
**信頼性**: 🔵 *REQ-110a / rallies_delete RLS（TASK-0001）*

`delete().eq('id', rallyId)` で**遅延生成された空 rally**（shot 0 件・point 未確定）を物理削除。shot を全 undo してラリーが空になったとき session が呼ぶ。

**実装ファイル**: `app/composables/useDeleteRally.ts`

```typescript
/**
 * 【機能概要】: 空（shot 0 件・point 未確定）の遅延生成 rally を物理削除する Write composable（undo 用）
 * 【実装方針】: delete().eq('id', rallyId)。物理削除（hard delete）。
 * 🔵 interfaces.ts UseDeleteRallyReturn / REQ-110a / rallies_delete RLS（TASK-0001）
 */
import type { Database } from '~/types/supabase'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseDeleteRallyReturn {
  deleteRally: (input: { rallyId: string }) => Promise<ActionResult<true>>
}

export function useDeleteRally(): UseDeleteRallyReturn {
  const client = useSupabaseClient<Database>()

  async function deleteRally(input: { rallyId: string }): Promise<ActionResult<true>> {
    const { error } = await client
      .from('rallies')
      .delete()
      .eq('id', input.rallyId)

    if (error) return { data: null, error }
    return { data: true, error: null }
  }

  return { deleteRally }
}
```

## 注意事項
- delete は **物理削除（`delete()`）** であり soft delete（`update({ deleted_at })`）ではない（ユーザー方針2026-06-05、分析 SQL で deleted_at フィルタ不要）。テストで `delete()` 呼び出しを明示検証する。
- 物理削除は **TASK-0001 の DELETE RLS ポリシー** が前提。ポリシーが無いと delete が空振り（0 行影響）するため、統合テストで「実際に消えること」を確認する。
- `createShot` の `input_source` は **'manual' 固定**（MVP）。`'ai'` 拡張は将来（REQ-301）、本タスクでは渡さない。
- `shot_number` の採番（ラリー内連番）・`video_timestamp_ms` の取得は session（TASK-0010）の責務。本 composable は値を insert するのみ。
- 楽観 insert がまだ未解決のまま undo が来た場合の「insert 解決を待ってから delete」（REQ-110d、delete が insert を追い越さない）は **session（TASK-0011）が `ShotDraft.shotId` の確定を待って delete を呼ぶ** ことで実現。本 composable は id を受け取って delete するだけ。
- delete 失敗は `ActionResult.error` で返し、toast は session 側。
