## タスク概要

左右入れ替わり（override）の楽観記録と、undo の物理削除 composable 2本を実装する。

- **`useCreateOverride()`**: `position_overrides` を**楽観 insert**（`rally_id` / `team` / `override_type`）。`override_type`（`'swapped'` / `'restored'`）は **`decideOverrideType`（TASK-0003 の純関数）出力**を受け取って insert（偶数回目=swapped / 奇数回目=restored、REQ-105）。`.select('id').single()` で `override_id` を返す（undo の削除対象）。`OptimisticWriteReturn` 準拠。
- **`useDeleteOverride()`**: `position_overrides` を**物理削除**（`delete().eq('id', overrideId)`、undo、REQ-110c）。

engine の `applyOverride(state, team)` 呼び出し（ステートレストグル）と `override_type` の偶奇判定（`decideOverrideType`）は session（TASK-0011）/ TASK-0003 の責務で、本 composable は **意味ラベルを受け取って DB に書く / 消す**ことに専念する（DB は意味ラベルを保存、engine はトグル、という REQ-105 の不整合解消方針）。物理削除は TASK-0001 の DELETE RLS ポリシーが前提。

## 実装詳細

### 1. useCreateOverride composable（楽観） 🔵
**信頼性**: 🔵 *interfaces.ts DecideOverrideType / REQ-105 / EDGE-008 / position_overrides スキーマ*

`rally_id`（遅延生成済み）+ `team` + `override_type`（`decideOverrideType` 出力）を insert。偶奇判定は composable では行わず**呼び出し側から `override_type` を受け取る**（DB は意味ラベルを保存、engine はトグル）。`.select('id').single()` で `override_id` を返す（undo 削除対象）。

**実装ファイル**: `app/composables/useCreateOverride.ts`

```typescript
/**
 * 【機能概要】: position_overrides を楽観 insert する Write composable（override_id を返す）
 * 【実装方針】: OptimisticWriteReturn。override_type は decideOverrideType（TASK-0003）出力を受け取る
 *             （偶奇判定は composable で行わない）。DB は意味ラベル保存、engine はトグル（REQ-105）。
 * 🔵 interfaces.ts DecideOverrideType / REQ-105 / position_overrides スキーマ / RLS
 */
import type { Database } from '~/types/supabase'
import type { Team } from '~/utils/rule-engine/types'

type OverrideType = Database['public']['Tables']['position_overrides']['Row']['override_type']

interface ActionResult<T> { data: T | null; error: unknown }
interface CreateOverrideInput {
  rallyId: string
  team: Team
  overrideType: OverrideType // decideOverrideType 出力（'swapped' | 'restored'）
}
interface UseCreateOverrideReturn {
  createOverride: (input: CreateOverrideInput) => Promise<ActionResult<string>>
}

export function useCreateOverride(): UseCreateOverrideReturn {
  const client = useSupabaseClient<Database>()

  async function createOverride(input: CreateOverrideInput): Promise<ActionResult<string>> {
    const { data, error } = await client
      .from('position_overrides')
      .insert({
        rally_id: input.rallyId,
        team: input.team,
        override_type: input.overrideType
      })
      .select('id')
      .single()

    if (error) return { data: null, error }
    // 【戻り】: undo の削除対象になる override_id
    return { data: data.id, error: null }
  }

  return { createOverride }
}
```

### 2. useDeleteOverride composable（物理削除・undo） 🔵
**信頼性**: 🔵 *useDeleteMatch.ts delete パターン / REQ-110c / position_overrides_delete RLS（TASK-0001）*

`delete().eq('id', overrideId)` で**物理削除**（soft delete でない）。undo の override 取り消しで使う。engine 状態の復元（snapshot）は session の責務、本 composable は行削除のみ。

**実装ファイル**: `app/composables/useDeleteOverride.ts`

```typescript
/**
 * 【機能概要】: position_overrides を物理削除する Write composable（undo 用）
 * 【実装方針】: delete().eq('id', overrideId)。物理削除（hard delete）。soft delete は使わない。
 * 🔵 interfaces.ts UseDeleteOverrideReturn / REQ-110c / position_overrides_delete RLS（TASK-0001）
 */
import type { Database } from '~/types/supabase'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseDeleteOverrideReturn {
  deleteOverride: (input: { overrideId: string }) => Promise<ActionResult<true>>
}

export function useDeleteOverride(): UseDeleteOverrideReturn {
  const client = useSupabaseClient<Database>()

  async function deleteOverride(input: { overrideId: string }): Promise<ActionResult<true>> {
    // 【物理削除】: DELETE RLS（FK 経由 is_member_of）で自 Group のみ
    const { error } = await client
      .from('position_overrides')
      .delete()
      .eq('id', input.overrideId)

    if (error) return { data: null, error }
    return { data: true, error: null }
  }

  return { deleteOverride }
}
```

## 注意事項
- `override_type` の **偶奇判定は本 composable の責務外**（TASK-0003 の `decideOverrideType` 純関数）。composable は出力ラベルを受け取って insert するだけ（DB は意味ラベル保存、engine はトグル、REQ-105 の不整合解消）。
- delete は **物理削除（`delete()`）** であり soft delete ではない（REQ-110c、テストで明示検証）。**TASK-0001 の DELETE RLS ポリシー** が前提（無いと空振り）。
- `rally_id` は遅延生成済み（override は進行中ラリーに紐づく）。ラリー行未生成時の扱い（ensureRallyRow）は session の責務。
- 楽観 insert が未解決のまま undo が来た場合の「insert 解決を待ってから delete」（REQ-110d）は session が `override_id` の確定を待って delete を呼ぶことで実現。本 composable は id を受け取って delete するのみ。
- engine 状態の巻き戻し（snapshot 復元）は session（TASK-0011）の責務。本 composable は DB 行の作成 / 削除に専念。
- insert/delete 失敗は `ActionResult.error` で返し、toast + 未同期マークは session 側。
