## タスク概要

`useRecordingSession` の**第2段**を実装する。スコープは ①左右入替（`recordOverride`） ②統一 undo スタックと
`undoLast` / `undoLabelKey` ③セット/試合遷移（`advanceToNextSet` / `setWinner` / `matchWinner`）。TASK-0010 が
所有する `gameState` / `currentRally` / Write composable 群に**追記する形**で同一ファイルに実装する。

override は `decideOverrideType(existingCount)`（純関数、TASK-0008）で `swapped` / `restored` を決め
`createOverride`（楽観）→ `applyOverride(state, team)`（rule-engine）→ 必要なら現ラリー行の server 系を
楽観 update する（REQ-105 / EDGE-008）。2回連続で元の表示に戻る（DB は2行、engine は元の state）。

統一 undo は **記録操作ごとに `UndoStep`（kind + 直前 GameState スナップショット + DB 行参照）を push** し、
`undoLast()` が pop して逆操作する（REQ-110、現在セット内・linear）。kind 別逆操作：shot=`useDeleteShot`（空に
なった遅延生成 rally は `useDeleteRally` も）、point/let=`useUpdateRally` で reopen + GameState スナップショット
復元、override=`useDeleteOverride` + 復元。**全て物理削除（hard delete）**。楽観 insert 未解決の行は insert
解決（id 確定）を待ってから削除（delete が insert を追い越さない、REQ-110d）。`undoLabelKey` は次に取り消す
対象の i18n キー（UI 文脈ラベル）、スタック空で `null`（no-op）。

`advanceToNextSet()` は `setWinner` を前セット勝者として `firstServingTeam` 既定に carry し、状態をリセットして
次セットの設定入力（再度 `configureAndStartSet`）に進ませる（REQ-107）。`matchWinner` は先取セット数到達で確定
（**先取数ルールは実装時にプロトタイプで確定 🟡**、EDGE-011 で試合終了後の新規セット追加を抑止）。

新規 DB スキーマ・RPC は作らない。undo の物理削除に必要な DELETE RLS ポリシーは DIRECT タスク（TASK-0009）で
追加済を前提とする。

## 実装詳細

### 1. recordOverride（type 決定 + applyOverride + 現ラリー反映） 🔵
**信頼性**: 🔵 *dataflow.md 機能5 / REQ-105 / EDGE-008 / rule-engine applyOverride / interfaces.ts DecideOverrideType*

当該チームの既存 override 回数（現在セット内）の偶奇で `decideOverrideType` が `swapped`（偶数回目）/ `restored`
（奇数回目）を返す。`createOverride`（楽観）で `position_overrides` に意味ラベルを残し、`applyOverride(state, team)`
で当該チームの左右トグル後 state に差し替える。現在ラリー行が既に生成済なら、その `server` / `receiver` /
`server_position` を新 state で楽観 update する（rule-engine: 当該ラリーに反映、dataflow §機能5 ステップ3）。

**実装ファイル**: `app/composables/useRecordingSession.ts`（TASK-0010 に追記）

```typescript
const overrideCounts: Record<Team, number> = { A: 0, B: 0 }

async function recordOverride(team: Team): Promise<void> {
  if (gameState.value === null || currentRally.value === null) return
  const prev = gameState.value // 復元用スナップショット

  // 【type 決定（純関数）】: 偶数回目=swapped / 奇数回目=restored 🔵 REQ-105
  const overrideType = decideOverrideType(overrideCounts[team])
  overrideCounts[team] += 1

  // 【楽観 insert】: rally_id は遅延生成済の場合のみ。意味ラベルを保存 🔵
  const rallyId = currentRally.value.rallyId ?? await ensureRallyRowWithoutShot()
  const p = createOverride({ rallyId: rallyId!, team, overrideType })

  // 【engine トグル】: applyOverride で左右入替 → state 差し替え 🔵 EDGE-008
  const next = applyOverride(gameState.value, team)
  gameState.value = next

  // 【現ラリー行に反映】: server 系を update（当該ラリーに反映）🔵 dataflow §機能5-3
  if (rallyId) {
    updateRallyServer({ rallyId, server: next.server, receiver: next.receiver, serverPosition: next.serverPosition })
  }

  // 【undo push】: override 取り消しは行物理削除 + state 復元 🔵 REQ-110c
  pushUndo({ kind: 'override', prevGameState: prev, rallyId, rowId: null, deletesEmptyRally: false, pendingInsert: p })
}
```

### 2. undo スタックと pushUndo / undoLabelKey 🔵
**信頼性**: 🔵 *architecture.md §undo スタック / interfaces.ts UndoStep / ui-design.md §統一「取り消し」/ REQ-110*

`UndoStep[]` を持ち、各記録操作（TASK-0010 の recordShot / finalizeRally / skipRally + 本タスクの recordOverride）の
末尾で `pushUndo` する。`pendingInsert` には楽観 insert の Promise を保持（未解決なら解決待ち、REQ-110d）。
`undoLabelKey` は末尾 step の kind を i18n キーへ写す computed（空なら `null`）。

```typescript
const undoStack = ref<UndoStep[]>([])

function pushUndo(step: UndoStep): void {
  undoStack.value.push(step)
}

// 【文脈ラベル】: 次に取り消す対象の kind を i18n キーへ。空なら null（no-op）🔵 REQ-110
const undoLabelKey = computed<string | null>(() => {
  const top = undoStack.value.at(-1)
  return top ? `recording.undo.${top.kind}` : null
})
```

### 3. undoLast（kind 別逆操作 + 物理削除 + state 復元） 🔵
**信頼性**: 🔵 *ui-design.md §統一「取り消し」/ REQ-110a/b/c/d / architecture.md（巻き戻し = snapshot 復元）*

`undoLast()` はスタックを1つ pop。`pendingInsert` があれば**先に await**（delete が insert を追い越さない、REQ-110d）。
kind 別：
- **shot**: 末尾 shot を `useDeleteShot`（物理削除）+ メモリ除去。空（shot 0・point 未確定）かつ遅延生成行なら `useDeleteRally`（REQ-110a）。GameState は不変（`prevGameState=null`）。
- **point / let**: `useUpdateRally` で `point_winner=null` / `is_point_confirmed=false` に戻し（reopen）、`gameState` を `prevGameState` へ復元、`currentRally` を当該ラリーへ戻す（REQ-110b）。
- **override**: `useDeleteOverride`（物理削除）+ `gameState` を `prevGameState` へ復元、`overrideCounts[team]` をデクリメント（EDGE-008 の整合）（REQ-110c）。

```typescript
async function undoLast(): Promise<void> {
  const step = undoStack.value.pop()
  if (!step) return // 【空 no-op】🔵 REQ-110

  // 【楽観未解決待ち】: insert 解決後に削除（追い越し防止）🔵 REQ-110d
  if (step.pendingInsert) await step.pendingInsert

  if (step.kind === 'shot') {
    if (step.rowId) await deleteShot({ shotId: step.rowId })          // 物理削除 REQ-110a
    currentRally.value?.shots.pop()
    if (step.deletesEmptyRally && step.rallyId) {
      await deleteRally({ rallyId: step.rallyId })                    // 空 rally 物理削除 REQ-110a
      if (currentRally.value) currentRally.value.rallyId = null
    }
  } else if (step.kind === 'point' || step.kind === 'let' || step.kind === 'skip') {
    if (step.rallyId) {
      updateRally({ rallyId: step.rallyId, pointWinner: null, isLet: false, isPointConfirmed: false }) // reopen REQ-110b
    }
    if (step.prevGameState) gameState.value = step.prevGameState      // state 復元
    setWinner.value = null                                            // 決着取り消し
    restoreCurrentRallyTo(step.rallyId)
  } else if (step.kind === 'override') {
    if (step.rowId) await deleteOverride({ overrideId: step.rowId })  // 物理削除 REQ-110c
    if (step.prevGameState) gameState.value = step.prevGameState      // state 復元
    decrementLastOverrideCount()
  }
}
```

> 注: shot/override の `rowId` は楽観 insert 解決時に確定するため、`pushUndo` 時点で `null` の場合は `pendingInsert`
> await 後に draft / override 参照から id を解決して削除する。`shot_number` の再採番（歯抜け許容 or 詰め）は実装時に確定 🟡。

### 4. advanceToNextSet（前勝者を先攻 carry） 🔵
**信頼性**: 🔵 *dataflow.md 状態遷移 / REQ-107 / rule-engine REQ-009*

`setWinner` 確定後の CTA で呼ぶ。前セット勝者を次セットの `firstServingTeam` 既定として持ち越し、`gameState` /
`currentRally` / `undoStack` / `overrideCounts` をリセットして次セット設定（`configureAndStartSet` 再呼び）へ進ませる。
自動でセットを作らず、設定入力を経由する（REQ-107）。

```typescript
const nextSetDefaultFirstServingTeam = ref<Team | null>(null)

function advanceToNextSet(): void {
  if (setWinner.value === null) return
  // 【先攻 carry】: 前勝者を次セットの既定先攻に 🔵 REQ-107 / rule-engine REQ-009
  nextSetDefaultFirstServingTeam.value = setWinner.value
  // 【リセット】: 設定入力（SetSetupForm）へ。engine は configureAndStartSet で再初期化 🔵
  gameState.value = null
  currentRally.value = null
  undoStack.value = []
  overrideCounts.A = 0
  overrideCounts.B = 0
  setWinner.value = null
}
```

### 5. matchWinner（先取セット数到達 + 追加抑止） 🟡
**信頼性**: 🟡 *REQ-011 / EDGE-011（先取数ルールは実装時プロトタイプで確定）*

セット決着の累積から各チームの取得セット数を数え、先取セット数（3セットマッチなら2先取等、**具体ルールは
実装時確定 🟡**）到達で `matchWinner` を確定する。確定後は `advanceToNextSet` / `configureAndStartSet` を抑止し
（新規セット追加不可、EDGE-011）、UI は試合終了表示にする。

```typescript
const setWins = ref<Record<Team, number>>({ A: 0, B: 0 })
const matchWinner = computed<Team | null>(() => {
  // 🟡 先取数は実装時に SetConfig 由来で確定（暫定 2 先取）
  const need = 2
  if (setWins.value.A >= need) return 'A'
  if (setWins.value.B >= need) return 'B'
  return null
})
```

## 注意事項
- undo は **物理削除（hard delete）**。`.delete()` を使い、DELETE RLS ポリシー（TASK-0009）に依存する。soft delete は使わない（REQ-110a/c）。
- 楽観 insert が**未解決の行は insert 解決を待ってから削除**（delete が insert を追い越さない、REQ-110d）。`pendingInsert` を必ず await。
- engine は前方関数（applyRally/applyOverride）のみ。巻き戻しは**保存済み GameState スナップショットの復元**で行う（REQ-106 の再計算機構を共用）。
- override の `overrideCounts` は undo 時に**必ずデクリメント**して整合を保つ（EDGE-008 の偶奇判定が崩れない）。
- `advanceToNextSet` は**自動でセットを作らない**。前勝者を先攻既定に carry し、`configureAndStartSet` の再入力を経由（REQ-107）。
- `matchWinner` の**先取セット数ルールは実装時にプロトタイプで確定**（🟡 REQ-011）。確定後はセット追加を抑止（EDGE-011）。
- Supabase は直叩きしない（必ず Write/Delete composable 経由、REQ-402）。
