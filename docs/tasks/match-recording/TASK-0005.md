## タスク概要

録画画面の2つの Read composable を実装する。

- **`useSets(matchId)`**: 当該 match のセット一覧を `set_number` 昇順で読む（セット番号採番・録画再開用）。未削除（`is('deleted_at', null)`）に限定。`{ id, setNumber, winner, ... }` の最小射影。
- **`useSetRallies(setId)`**: 現在セットのラリー履歴一覧（`RallyHistoryItem`: `rallyNumber` / `servingTeam` / `serverPlayerId` / `pointWinner` / `isLet` / `isPointConfirmed` / `shotCount`）を `rally_number` 昇順で読む。`shotCount` は `shots` の件数を **PostgREST 埋め込み COUNT**（`shots(count)`）で取得。`is_point_confirmed=false`（スキップ未確定、EDGE-003）を区別できるよう `isPointConfirmed` を射影に含める。

両 composable とも `useMatches.ts` の Read パターン（`useAsyncData` 固定キー + camelCase マッピング）を踏襲する。RLS は FK 経由 `is_member_of(matches.group_id)` で担保（sets→matches、rallies→sets→matches）。

## 実装詳細

### 1. useSets composable 🔵
**信頼性**: 🔵 *useMatches.ts Read パターン / sets スキーマ / REQ-201（再開・採番）*

`sets` を `match_id` で読み `set_number` 昇順。採番（`useSets().data.length + 1`）と再開（既存セット・winner 状態）を session 側が使う。

**実装ファイル**: `app/composables/useSets.ts`

```typescript
/**
 * 【機能概要】: match のセット一覧を set_number 昇順で読む Read composable（採番・再開用）
 * 【実装方針】: useMatches.ts 踏襲。useAsyncData 固定キー（matchId 含む）+ camelCase。
 * 🔵 useMatches.ts / sets スキーマ / REQ-201
 */
import type { Database } from '~/types/supabase'
import type { Team } from '~/utils/rule-engine/types'

interface SetSummary {
  id: string
  setNumber: number
  winner: Team | null
}

export function useSets(matchId: string) {
  const client = useSupabaseClient<Database>()

  return useAsyncData<SetSummary[]>(`sets-${matchId}`, async () => {
    const { data, error } = await client
      .from('sets')
      .select('id, set_number, winner')
      .eq('match_id', matchId)
      .is('deleted_at', null)
      .order('set_number', { ascending: true })

    if (error) throw error
    return (data ?? []).map((row): SetSummary => ({
      id: row.id,
      setNumber: row.set_number,
      winner: row.winner as Team | null
    }))
  })
}
```

### 2. useSetRallies composable 🔵
**信頼性**: 🔵 *interfaces.ts RallyHistoryItem / REQ-009 / EDGE-003 / rallies・shots スキーマ*

`rallies` を `set_id` で読み `rally_number` 昇順。`shots(count)` 埋め込みで各ラリーのショット数を取得（PostgREST は `[{ count: N }]` 形式で返すため `row.shots[0]?.count ?? 0` で取り出す）。`is_point_confirmed=false` の未確定ラリー（スキップ、EDGE-003）も一覧に含め、`isPointConfirmed` で UI が「未確定」を明示できるようにする。

**実装ファイル**: `app/composables/useSetRallies.ts`

```typescript
/**
 * 【機能概要】: 現在セットのラリー履歴一覧を rally_number 昇順で読む Read composable
 * 【実装方針】: useMatches.ts 踏襲。shotCount は shots(count) 埋め込み COUNT。
 *             is_point_confirmed=false（スキップ未確定）を区別できるよう射影に含める。
 * 🔵 interfaces.ts RallyHistoryItem / REQ-009 / EDGE-003 / rallies・shots スキーマ
 */
import type { Database } from '~/types/supabase'
import type { RallyHistoryItem } from '~/types/match-recording'
import type { Team } from '~/utils/rule-engine/types'

export function useSetRallies(setId: string) {
  const client = useSupabaseClient<Database>()

  return useAsyncData<RallyHistoryItem[]>(`set-rallies-${setId}`, async () => {
    // 【埋め込み COUNT】: shots(count) で各ラリーのショット件数を取得（[{ count: N }] 形式）
    const { data, error } = await client
      .from('rallies')
      .select('rally_number, serving_team, server_player_id, point_winner, is_let, is_point_confirmed, shots(count)')
      .eq('set_id', setId)
      .is('deleted_at', null)
      .order('rally_number', { ascending: true })

    if (error) throw error
    return (data ?? []).map((row): RallyHistoryItem => ({
      rallyNumber: row.rally_number,
      servingTeam: row.serving_team as Team,
      serverPlayerId: row.server_player_id,
      pointWinner: row.point_winner as Team | null,
      isLet: row.is_let,
      isPointConfirmed: row.is_point_confirmed,
      // 【shotCount】: 埋め込み集約は配列で返るため [0].count を取り出す（未取得は 0）
      shotCount: (row.shots as unknown as { count: number }[])[0]?.count ?? 0
    }))
  })
}
```

## 注意事項
- `shots(count)` 埋め込み集約は **配列**（`[{ count: N }]`）で返るため、`[0]?.count ?? 0` で取り出す（直接 number ではない）。
- `useSetRallies` は **未確定ラリーも除外しない**（スキップを一覧表示するため、EDGE-003）。`deleted_at` 除外は物理削除（undo）方針のため実質効かないが一貫性のため付与。
- `useSets` は採番（`length + 1`）・再開判定（`winner` 確定数）の材料を返すだけで、採番ロジック自体は session（TASK-0010）の責務。
- 両キーは `matchId` / `setId` を含めて分離する（セット切替時に `refresh()` ではなく key 切替で再取得できる粒度）。
- RLS は FK 経由（rallies→sets→matches）で自 Group に限定。composable は `group_id` を持たない（REQ-401）。
