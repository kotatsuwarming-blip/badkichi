## タスク概要

ラリー行の**遅延生成（同期）** と **得点確定/スキップ/修正（楽観）** の Write composable 2本を実装する。

- **`useCreateRally()`**: `rallies` を**遅延生成**（初ショット時 / 得点時に1回、**同期 insert**）。denorm 列（`map-game-state.ts` 出力 = `serving_team` / `server_position` / `server_player_id` / `receiver_player_id` / `camera_near_team`）+ `rally_number` + `video_start_timestamp_ms`（初ショット ms）を書き、`.select('id').single()` で `rally_id` を返す（shots / position_overrides の FK 親、id 確定が必須）。
- **`useUpdateRally()`**: `point_winner` / `is_let` / `is_point_confirmed` を **楽観 update**（ホットパス、NFR-001）。得点確定（REQ-006/007）・スキップ（REQ-103）・直前修正（REQ-106）で使用。`OptimisticWriteReturn` 準拠（`{ action }` のみ、即時ローカル反映は session 側）。

`useCreateRally` は **同期**（FK 親）、`useUpdateRally` は **楽観**（write-behind）。両者とも `group_id` を持たず FK 経由 RLS で自 Group に限定。

## 実装詳細

### 1. useCreateRally composable（同期・遅延生成） 🔵
**信頼性**: 🔵 *useCreateMatch.ts pending / interfaces.ts RallyDenorm / REQ-007 / REQ-410 / rallies スキーマ*

`setId` + `rallyNumber` + `RallyDenorm`（`map-game-state.ts` 出力）+ `videoStartTimestampMs` を insert。`video_start_timestamp_ms` は初ショット ms（NULL 許容、得点先行時は null）。`.select('id').single()` で `rally_id` を返す（shots / position_overrides の FK 親）。denorm 列は写像出力を**そのまま**写し二重管理しない（REQ-410）。

**実装ファイル**: `app/composables/useCreateRally.ts`

```typescript
/**
 * 【機能概要】: rallies を遅延生成する同期 Write composable（rally_id を返す）
 * 【実装方針】: useCreateMatch.ts pending/try-finally。同期 await（shots/override の FK 親）。
 *             denorm 列は map-game-state.ts（TASK-0003）出力をそのまま insert（二重管理しない）。
 * 🔵 interfaces.ts RallyDenorm / REQ-007 / REQ-410 / rallies スキーマ / rallies_insert RLS
 */
import type { Database } from '~/types/supabase'
import type { RallyDenorm } from '~/types/match-recording'

interface ActionResult<T> { data: T | null; error: unknown }
interface CreateRallyInput {
  setId: string
  rallyNumber: number
  denorm: RallyDenorm
  videoStartTimestampMs: number | null
}
interface UseCreateRallyReturn {
  createRally: (input: CreateRallyInput) => Promise<ActionResult<string>>
  pending: Ref<boolean>
}

export function useCreateRally(): UseCreateRallyReturn {
  const pending = ref(false)
  const client = useSupabaseClient<Database>()

  async function createRally(input: CreateRallyInput): Promise<ActionResult<string>> {
    pending.value = true
    try {
      const { denorm } = input
      // 【insert】: denorm（写像出力）+ rally_number + video_start_timestamp_ms。
      //   point_winner/is_let/is_point_confirmed は既定（NULL/false/false）で開始 → 後で update。
      const { data, error } = await client
        .from('rallies')
        .insert({
          set_id: input.setId,
          rally_number: input.rallyNumber,
          serving_team: denorm.servingTeam,
          server_position: denorm.serverPosition,
          server_player_id: denorm.serverPlayerId,
          receiver_player_id: denorm.receiverPlayerId,
          camera_near_team: denorm.cameraNearTeam,
          video_start_timestamp_ms: input.videoStartTimestampMs
        })
        .select('id')
        .single()

      if (error) return { data: null, error }
      // 【戻り】: shots/override の FK 親になる rally_id
      return { data: data.id, error: null }
    } finally {
      pending.value = false
    }
  }

  return { createRally, pending }
}
```

### 2. useUpdateRally composable（楽観） 🔵
**信頼性**: 🔵 *interfaces.ts UseUpdateRallyReturn・UpdateRallyInput / REQ-006/103/106 / OptimisticWriteReturn*

`UpdateRallyInput`（`rallyId` / `pointWinner` / `isLet` / `isPointConfirmed`）を `update().eq('id', rallyId)` で更新。楽観のため `pending` は持たず `{ action }` のみ（即時ローカル反映 + 失敗時 toast は session 側）。得点確定（`pointWinner=team, isPointConfirmed=true`）・スキップ（`null, false`）・直前修正（`pointWinner` 差し替え）・undo の得点戻し（`null, false`、REQ-110b）すべてこの1本で表現する。

**実装ファイル**: `app/composables/useUpdateRally.ts`

```typescript
/**
 * 【機能概要】: rallies の point_winner/is_let/is_point_confirmed を update する楽観 Write composable
 * 【実装方針】: OptimisticWriteReturn（{ action } のみ）。即時ローカル反映と toast は session 側。
 *             得点確定/スキップ/直前修正/undo の得点戻し（REQ-110b）を1本で表現。
 * 🔵 interfaces.ts UseUpdateRallyReturn / REQ-006/103/106 / rallies_update RLS
 */
import type { Database } from '~/types/supabase'
import type { UpdateRallyInput } from '~/types/match-recording'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseUpdateRallyReturn {
  updateRally: (input: UpdateRallyInput) => Promise<ActionResult<string>>
}

export function useUpdateRally(): UseUpdateRallyReturn {
  const client = useSupabaseClient<Database>()

  async function updateRally(input: UpdateRallyInput): Promise<ActionResult<string>> {
    // 【update】: point_winner/is_let/is_point_confirmed を eq('id', rallyId) で更新（楽観）
    const { error } = await client
      .from('rallies')
      .update({
        point_winner: input.pointWinner,
        is_let: input.isLet,
        is_point_confirmed: input.isPointConfirmed
      })
      .eq('id', input.rallyId)

    if (error) return { data: null, error }
    return { data: input.rallyId, error: null }
  }

  return { updateRally }
}
```

## 注意事項
- `useCreateRally` は **同期**（FK 親）、`useUpdateRally` は **楽観**（write-behind、`pending` を持たない）。永続化戦略の使い分けを守る（architecture.md）。
- `createRally` の denorm 列は **TASK-0003 の `map-game-state.ts` 出力をそのまま**写す（二重管理禁止、REQ-410）。本 composable は写像を呼ばず、受け取った `RallyDenorm` を insert するだけ。
- `rally_number` の採番・`video_start_timestamp_ms` の取得（getCurrentTimeMs）は session（TASK-0010）の責務。本 composable は値を受け取り insert/update するのみ。
- `updateRally` は得点確定 / スキップ / 直前修正 / **undo の得点戻し（REQ-110b、`null/false`）** を1本で表現する（専用 composable を増やさない）。
- 楽観 update の失敗は `ActionResult.error` で返し、toast + 未同期マーク + 再試行は session 側（error-handling §2.A）。
- `is_let=true`（レット）は `recordLet` から `updateRally({ pointWinner:null, isLet:true, isPointConfirmed:true })` の形で呼ばれる（REQ-102、session 側の組み立て）。
