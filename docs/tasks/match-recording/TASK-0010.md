## タスク概要

録画セッションの集約オーケストレータ `app/composables/useRecordingSession.ts` の**第1段**を実装する。
本タスクのスコープは ①rule-engine `GameState` の reactive 所有 ②`getCurrentTimeMs` 注入の受け口
③セットアップ（`configureAndStartSet`） ④ラリー記録のホットパス（`recordShot` / `recordPoint` /
`recordLet`） ⑤スキップ保留（`skipRally` / `confirmSkipped`）。override・統一 undo・セット/試合遷移は
**TASK-0011** に分離する。

`useRecordingSession(matchId, { getCurrentTimeMs })` は `getCurrentTimeMs: () => number | null` を**注入**で
受け、実プレーヤーなしでフェイク時計により単体テスト可能にする（NFR-303 / [[feedback_test_coverage]]）。
内部状態（`gameState` / `currentRally` / `currentSetNumber` 等）は `ref` で持ち、公開は `readonly` で行う
（interfaces.ts `UseRecordingSessionReturn`）。

永続化はハイブリッド（architecture.md）。セット作成・初期立ち位置・ラリー行の遅延生成は**同期 await**、
ショット追加・得点 update は**楽観**（メモリ即反映 + 非同期 write-behind）。rule-engine（`createInitialState`
/ `applyRally` / `determineSetWinner`）は純関数として呼び、DB は触らせない（REQ-403）。GameState → rallies の
denormalize 写像は `map-game-state.ts`（別タスク TASK-0008 で実装済の純関数）を利用する。

新規 DB スキーマ・RPC は作らない。Write/Read composable（TASK-0003〜0008）を組み合わせるのみ。

### 1. 集約 composable のシグネチャと注入 🔵
**信頼性**: 🔵 *architecture.md §Composable 層 / interfaces.ts UseRecordingSessionReturn / NFR-303*

`useRecordingSession` は第2引数で `{ getCurrentTimeMs }` を受ける。page は `useVideoPlayer().controls.getCurrentTimeMs`
を束縛して渡し、テストはフェイク関数を渡す。内部状態は `ref`、公開は `readonly`。Write/Read composable は
内部で生成（直叩き禁止、REQ-402）。

**実装ファイル**: `app/composables/useRecordingSession.ts`

```typescript
/**
 * 【機能概要】: 録画セッションの集約オーケストレータ（第1段）。GameState を所有し、
 *               セットアップ + ラリー記録ホットパス + スキップ保留を担う。
 * 【実装方針】: getCurrentTimeMs を注入で受け、フェイク時計でテスト可能にする（NFR-303）。
 *               セット/ラリー行は同期 await、ショット/得点は楽観。rule-engine は純関数として呼ぶ。
 * 🔵 architecture.md §Composable / interfaces.ts UseRecordingSessionReturn
 */
import { readonly, ref } from 'vue'
import { createInitialState, applyRally, determineSetWinner } from '~/utils/rule-engine'
import type { GameState, SetConfig, Team } from '~/utils/rule-engine/types'
import { mapGameStateToRallyDenorm } from '~/utils/match-recording/map-game-state'
import type {
  SetSetupInput,
  SetPositionInput,
  CurrentRally,
  ActionResult
} from '~/types/match-recording'

interface RecordingSessionDeps {
  getCurrentTimeMs: () => number | null
}

export function useRecordingSession(matchId: string, deps: RecordingSessionDeps) {
  // 【engine 状態】: null = セット未設定。reactive 所有・readonly 公開 🔵 REQ-008
  const gameState = ref<GameState | null>(null)
  const currentRally = ref<CurrentRally | null>(null)
  const currentSetNumber = ref<number | null>(null)
  const setWinner = ref<Team | null>(null)

  // 【SetConfig 退避】: applyRally 後の determineSetWinner で使う 🔵
  let activeConfig: SetConfig | null = null
  let activeSetId: string | null = null
  let cameraNearTeam: Team | null = null

  // 【Write/Read composable（直叩き禁止）】 🔵 REQ-402
  const { action: createSet } = useCreateSet()
  const { action: createSetPositions } = useCreateSetPositions()
  const { action: createRally } = useCreateRally()
  const { action: updateRally } = useUpdateRally()
  const { action: createShot } = useCreateShot()

  // ... configureAndStartSet / recordShot / recordPoint / recordLet / skipRally / confirmSkipped（以下節）

  return {
    gameState: readonly(gameState),
    currentRally: readonly(currentRally),
    currentSetNumber: readonly(currentSetNumber),
    setWinner: readonly(setWinner)
    // configureAndStartSet, recordShot, recordPoint, recordLet, skipRally, confirmSkipped
  }
}
```

### 2. configureAndStartSet（同期セットアップ） 🔵
**信頼性**: 🔵 *dataflow.md 機能1 / REQ-002/003/201 / EDGE-002 / rule-engine createInitialState*

`sets` → `set_player_positions` を**同期 await** で順に insert（後続 FK 親のため整合性優先）。`set_number` は
`useSets` の既存数 +1（setup に含めて渡す）。立ち位置重複（`(team, position)`）の UNIQUE 違反は `createSetPositions`
の error として返り、page が inline error で扱う（EDGE-002、検証は SetSetupForm でも事前に行う TASK-0016）。
成功したら `createInitialState(config, positions)` で `gameState` を初期化し、`currentRally` を rallyNumber=1 で開始。

```typescript
async function configureAndStartSet(
  setup: SetSetupInput,
  positions: SetPositionInput[]
): Promise<ActionResult<string>> {
  // 【sets 同期生成】: 後続 FK 親。失敗時は中断（FK 親未確定で続行不可）🔵 dataflow §エラー E
  const setRes = await createSet({ ...setup, matchId })
  if (setRes.error || !setRes.data) return setRes
  activeSetId = setRes.data

  // 【立ち位置 4行 同期生成】: UNIQUE(set_id, team, position) 違反は error で返す（EDGE-002）🔵
  const posRes = await createSetPositions({ setId: setRes.data, positions })
  if (posRes.error) return { data: null, error: posRes.error }

  // 【engine 初期化】: 純関数で第1ラリーの server/receiver/score を得る 🔵 REQ-002/003
  const config: SetConfig = {
    targetPoints: setup.targetPoints,
    enableDeuce: setup.enableDeuce,
    deucePointCap: setup.deucePointCap,
    firstServingTeam: setup.firstServingTeam
  }
  activeConfig = config
  cameraNearTeam = setup.cameraNearTeamAtStart
  gameState.value = createInitialState(config, positions)
  currentSetNumber.value = setup.setNumber
  setWinner.value = null
  currentRally.value = { rallyNumber: 1, rallyId: null, shots: [], isPending: false }

  return { data: setRes.data, error: null }
}
```

### 3. ensureRallyRow + recordShot（遅延生成 + 楽観） 🔵
**信頼性**: 🔵 *dataflow.md 機能2 / REQ-005/101 / EDGE-001 / NFR-001 / architecture.md ラリー行ライフサイクル*

`recordShot()` はまず `deps.getCurrentTimeMs()` を取得し `null` なら**何もせず return**（未ロード/バッファ、EDGE-001）。
ms が取れたら `ensureRallyRow(ms)`：`currentRally.rallyId == null` のときだけ `createRally`（同期）で1行 insert し
（denormalize は `mapGameStateToRallyDenorm(gameState, cameraNearTeam)` + `video_start_timestamp_ms = ms`）、rallyId を
確定する。以降 shot をメモリに楽観追加（`shots` 配列 + 痕跡用、UI <16ms）し、`createShot` を**非同期 fire**する。

```typescript
async function ensureRallyRow(firstShotMs: number): Promise<string | null> {
  // 【遅延生成】: 既に行があれば再利用。無ければ同期生成（shots の FK 親）🔵
  if (currentRally.value?.rallyId) return currentRally.value.rallyId
  const denorm = mapGameStateToRallyDenorm(gameState.value!, cameraNearTeam)
  const res = await createRally({
    setId: activeSetId!,
    rallyNumber: currentRally.value!.rallyNumber,
    videoStartTimestampMs: firstShotMs,
    ...denorm
  })
  if (res.error || !res.data) return null
  currentRally.value!.rallyId = res.data
  return res.data
}

async function recordShot(): Promise<void> {
  // 【未ロード no-op】: getCurrentTimeMs() が null なら記録しない（EDGE-001 / REQ-101）🔵
  const ms = deps.getCurrentTimeMs()
  if (ms === null || gameState.value === null || currentRally.value === null) return

  const rallyId = await ensureRallyRow(ms)
  if (rallyId === null) return // 親生成失敗は子を書かない（FK 整合）

  // 【楽観追加】: メモリ即反映（痕跡 + カウント）→ 非同期 insert 🔵 NFR-001
  const shotNumber = currentRally.value.shots.length + 1
  currentRally.value.shots.push({ shotId: null, shotNumber, videoTimestampMs: ms, synced: false })
  const draft = currentRally.value.shots[shotNumber - 1]
  createShot({ rallyId, shotNumber, videoTimestampMs: ms })
    .then((r) => { if (!r.error && r.data) { draft.shotId = r.data; draft.synced = true } })
  // 失敗時の toast + 未同期マークは page 側 / TASK-0011 の楽観失敗処理に委譲
}
```

### 4. recordPoint / recordLet（applyRally + 勝者判定 + 前進） 🔵
**信頼性**: 🔵 *dataflow.md 機能3 / REQ-006/007/102/410 / EDGE-010 / rule-engine applyRally・determineSetWinner*

得点は楽観 update（`point_winner=team` / `is_point_confirmed=true`）。`applyRally` で次 GameState を導出し
`gameState` を差し替え。`determineSetWinner(next.score, config)` が勝者を返したら `setWinner` をセットし**前進しない**
（次セット遷移は TASK-0011 `advanceToNextSet`、自動遷移しない REQ-107）。null なら `currentRally` を次ラリーへ。
`recordLet()` は `is_let=true` / `point_winner=null` で記録し、`applyRally` はレットでスコア不変・サーバー据え置きの
state を返す（rule-engine 実装）。ショット0件で得点された場合も `ensureRallyRow` で行を確保してから update する。

```typescript
async function finalizeRally(pointWinner: Team | null, isLet: boolean): Promise<void> {
  if (gameState.value === null || currentRally.value === null || activeConfig === null) return
  if (setWinner.value !== null) return // セット決着後は追加不可（EDGE-006 / REQ-203）

  // 【行確保】: ショット0件得点でも行が要る（FK 親 / denormalize 保存）🔵
  const rallyId = currentRally.value.rallyId ?? await ensureRallyRowWithoutShot()
  if (rallyId === null) return

  // 【楽観 update】: 得点/レット確定（ホットパス）🔵 NFR-001
  updateRally({ rallyId, pointWinner, isLet, isPointConfirmed: true })

  // 【engine 前進】: applyRally → 次 state（レットはスコア不変）🔵 REQ-007/102
  const next = applyRally(gameState.value, { pointWinner, isLet })
  gameState.value = next

  // 【勝者判定】: 勝者なら setWinner にセットし前進しない（手動遷移 REQ-107）🔵
  const winner = determineSetWinner(next.score, activeConfig)
  if (winner !== null) {
    setWinner.value = winner
    return // セット決着 CTA は TASK-0011 / UI（PositionControls）
  }

  // 【次ラリーへ】🔵
  currentRally.value = {
    rallyNumber: currentRally.value.rallyNumber + 1,
    rallyId: null,
    shots: [],
    isPending: false
  }
}

const recordPoint = (team: Team) => finalizeRally(team, false)   // REQ-006/007
const recordLet = () => finalizeRally(null, true)                // REQ-102 / EDGE-010
```

### 5. skipRally / confirmSkipped（未確定保留 → 後確定） 🔵
**信頼性**: 🔵 *dataflow.md 機能4 / REQ-103/104 / EDGE-003 / rule-engine REQ-403（pointWinner 必須）*

スキップは `ensureRallyRow` で行を確保し `is_point_confirmed=false` / `point_winner=null` で楽観 update。engine は
`pointWinner` 必須のため**前進させず**、`currentRally.isPending=true` にして保留する（UI で未確定明示、EDGE-003）。
後から `confirmSkipped(team)` で `is_point_confirmed=true` に update し、`applyRally(state, {team})` で前進する。

```typescript
async function skipRally(): Promise<void> {
  if (gameState.value === null || currentRally.value === null) return
  const rallyId = currentRally.value.rallyId ?? await ensureRallyRowWithoutShot()
  if (rallyId === null) return
  // 【未確定 update】: engine は前進させない（pointWinner 必須 REQ-403）🔵 EDGE-003
  updateRally({ rallyId, pointWinner: null, isLet: false, isPointConfirmed: false })
  currentRally.value.isPending = true
}

async function confirmSkipped(team: Team): Promise<void> {
  if (currentRally.value === null || !currentRally.value.isPending) return
  // 【後確定 → engine 前進】🔵 REQ-104
  await finalizeRally(team, false) // is_point_confirmed=true で update + applyRally
}
```

## 注意事項
- `getCurrentTimeMs` は**必ず注入**で受ける（`useVideoPlayer` を composable 内で生成しない）。テスト容易性の核（NFR-303）。
- rule-engine は**純関数**。`createInitialState` / `applyRally` / `determineSetWinner` のみ呼び、DB には触らせない（REQ-403）。
- セット作成・立ち位置・ラリー行は**同期 await**（FK 親の id 確定）。ショット/得点は**楽観**（NFR-001、押下→記録 100ms）。
- denormalize は `map-game-state.ts` の純関数を**唯一の写像**として使う（修正/override でも同じ写像、二重管理しない、REQ-410）。
- 勝者検知後は**自動でセット遷移しない**（`setWinner` を立てて CTA に委ね、advance は TASK-0011）。
- スキップ中（`isPending`）は engine を**前進させない**（pointWinner 必須、EDGE-003）。
- `recordShot` の `null` 分岐は早期 return（副作用ゼロ）。Supabase は直叩きしない（REQ-402）。
