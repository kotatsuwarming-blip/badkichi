## タスク概要

`docs/design/match-recording/interfaces.ts` の型契約を実装ファイル `app/types/match-recording.ts`
へ移植する。本ユニットの全 composable（Phase 2）と page/component が共有する**型契約の基盤**。

rule-engine の公開型（`Team` / `CourtSide` / `PlayerId` / `SetConfig` / `SetPlayerPosition` /
`GameState`）は `~/utils/rule-engine/types` から import して**再定義しない**。録画系テーブルの行型は
data-foundation 生成の `~/types/supabase`（`Database['public']['Tables']['sets'|'rallies'|
'shots'|'position_overrides']['Row']`）を参照し、ドメイン型は camelCase、DB I/O 時に snake_case へ
マッピングする方針（既存 `useCreateMatch`/`useMatches` 準拠）に揃える。

新規 DB スキーマ・新規 API・新規エラーコードは作らない。`app/types/match.ts` と同じく
`app/types/` 直下フラットに集約する。

## 実装詳細

### 1. ドメイン型 `app/types/match-recording.ts` 🔵
**信頼性**: 🔵 *interfaces.ts 全体 / rule-engine types.ts / supabase.ts Row 型*

interfaces.ts の各 export をそのまま実装ファイルへ落とす。import は次の2系統のみ：
- `import type { Database } from '~/types/supabase'`（行 alias 用）
- `import type { Team, CourtSide, PlayerId, SetConfig, SetPlayerPosition, GameState } from '~/utils/rule-engine/types'`

行 alias は interfaces.ts のとおり：

```typescript
type SetRow = Database['public']['Tables']['sets']['Row'] // 🔵 sets 定義
type RallyRow = Database['public']['Tables']['rallies']['Row'] // 🔵 rallies 定義
type OverrideType = Database['public']['Tables']['position_overrides']['Row']['override_type'] // 🔵 'swapped' | 'restored'
```

ドメイン入力型・状態型・戻り型は interfaces.ts L41-239 を移植する（`SetSetupInput` /
`SetPositionInput` / `RallyDenorm` / `MapGameStateToRallyDenorm` / `DecideOverrideType` /
`CurrentRally` / `ShotDraft` / `RallyHistoryItem` / `UndoStep` / `UseRecordingSessionReturn` /
`ActionResult` / `SyncWriteReturn` / `OptimisticWriteReturn` / `UseCreateSetReturn` /
`UseUpdateRallyReturn` / `UseDeleteShotReturn` / `UseDeleteRallyReturn` / `UseDeleteOverrideReturn` /
`UpdateRallyInput` / `MatchForRecording`）。

**実装ファイル**: `app/types/match-recording.ts`

> 移植時の注意（型が真であること）:
> - `OverrideType` は文字列リテラルをハードコードせず、必ず `position_overrides` Row から導出する。
> - `MapGameStateToRallyDenorm = (state: GameState, cameraNearTeam: Team | null) => RallyDenorm`、
>   `DecideOverrideType = (existingOverrideCount: number) => OverrideType`（純関数の TASK-0003 が実装）。
> - `UndoStep.kind` は `'shot' | 'point' | 'let' | 'skip' | 'override'`（REQ-110a/b/c）。
> - `UseRecordingSessionReturn` の各 Ref は `Readonly<Ref<...>>`。`Ref` は Nuxt auto-import（明示 import 不要）。

## 注意事項
- rule-engine 型（`Team`/`CourtSide`/`PlayerId`/`SetConfig`/`SetPlayerPosition`/`GameState`）と Supabase Row 型は **再定義禁止**。必ず import して参照する（型を真とする）。
- `OverrideType` は `'swapped'|'restored'` をハードコードせず `position_overrides` Row から導出する（スキーマ変更追従のため）。
- ESLint 規約: セミコロンなし・no comma dangle・1tbs。interfaces.ts は既にこの規約で書かれているため、移植時もコメント含めそのまま踏襲する。
- `app/types/match-recording.ts` に集約（`app/types/match.ts` と同じフラット配置）。`utils/match-recording/` の純関数（TASK-0003）はこの型を import して実装する。

- `Ref` / `Readonly` は Nuxt auto-import 対象（明示 import 不要だが typecheck が通ることを確認）。
