## タスク概要

セットアップ・決着の**同期 Write composable** 3本を実装する。いずれも `useCreateMatch.ts` の `{ action, pending }` + `ActionResult<T> = { data, error }` パターンを踏襲し、**同期 await**（後続 FK 親 / トランザクション境界のため確実性優先、architecture.md 永続化戦略）。

- **`useCreateSet()`**: `sets` を1行 insert（`set_number` / `target_points` / `enable_deuce` / `deuce_point_cap` / `first_serving_team` / `camera_near_team_at_start`）。`match_id` を付与し、`.select('id').single()` で `set_id` を返す（REQ-002）。
- **`useCreateSetPositions()`**: `set_player_positions` に4行を一括 insert（`set_id` / `player_id` / `team` / `position`）。`(set_id, team, position)` UNIQUE 制約違反（EDGE-002）は `ActionResult.error` で返し拒否。
- **`useUpdateSet()`**: `sets.winner` を `update().eq('id', setId)` で更新（REQ-010、セット決着確定）。

`group_id` は付与しない（`match_id` 経由 / `id` 指定 + FK 経由 RLS `is_member_of(matches.group_id)` で自 Group に限定、REQ-401）。

## 実装詳細

### 1. useCreateSet composable 🔵
**信頼性**: 🔵 *useCreateMatch.ts pending/try-finally / interfaces.ts UseCreateSetReturn / REQ-002 / sets スキーマ*

`SetSetupInput & { matchId }` を受け、camelCase → snake_case マッピングで insert。`.select('id').single()` で `set_id` を返す（後続の `set_player_positions` / `rallies` の FK 親、id 確定が必須）。

**実装ファイル**: `app/composables/useCreateSet.ts`

```typescript
/**
 * 【機能概要】: sets を1行 insert する同期 Write composable（set_id を返す）
 * 【実装方針】: useCreateMatch.ts の pending/try-finally + ActionResult。同期 await（FK 親）。
 * 🔵 interfaces.ts UseCreateSetReturn / REQ-002 / sets スキーマ / sets_insert RLS
 */
import type { Database } from '~/types/supabase'
import type { SetSetupInput } from '~/types/match-recording'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseCreateSetReturn {
  createSet: (input: SetSetupInput & { matchId: string }) => Promise<ActionResult<string>>
  pending: Ref<boolean>
}

export function useCreateSet(): UseCreateSetReturn {
  const pending = ref(false)
  const client = useSupabaseClient<Database>()

  async function createSet(input: SetSetupInput & { matchId: string }): Promise<ActionResult<string>> {
    pending.value = true
    try {
      // 【insert】: camelCase → snake_case。RLS sets_insert = is_member_of(matches.group_id)
      const { data, error } = await client
        .from('sets')
        .insert({
          match_id: input.matchId,
          set_number: input.setNumber,
          target_points: input.targetPoints,
          enable_deuce: input.enableDeuce,
          deuce_point_cap: input.deucePointCap,
          first_serving_team: input.firstServingTeam,
          camera_near_team_at_start: input.cameraNearTeamAtStart
        })
        .select('id')
        .single()

      if (error) return { data: null, error }
      // 【戻り】: 後続 FK 親になる set_id
      return { data: data.id, error: null }
    } finally {
      pending.value = false
    }
  }

  return { createSet, pending }
}
```

### 2. useCreateSetPositions composable 🔵
**信頼性**: 🔵 *interfaces.ts SyncWriteReturn / REQ-003 / EDGE-002 / set_player_positions UNIQUE*

4行を**一括 insert**（配列）。`(set_id, team, position)` UNIQUE 違反（同一スロット2選手、EDGE-002）は PostgREST が error を返すため `ActionResult.error` で拒否する（inline error 表示は page 側）。`.select('id')` で挿入行を返す（必須ではないが一貫性のため）。

**実装ファイル**: `app/composables/useCreateSetPositions.ts`

```typescript
/**
 * 【機能概要】: set_player_positions に4行を一括 insert する同期 Write composable
 * 【実装方針】: useCreateMatch.ts pending/try-finally。同期 await。UNIQUE 違反は error 素通し（EDGE-002）。
 * 🔵 interfaces.ts SyncWriteReturn / REQ-003 / EDGE-002 / spp UNIQUE
 */
import type { Database } from '~/types/supabase'
import type { SetPositionInput } from '~/types/match-recording'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseCreateSetPositionsReturn {
  createSetPositions: (setId: string, positions: SetPositionInput[]) => Promise<ActionResult<true>>
  pending: Ref<boolean>
}

export function useCreateSetPositions(): UseCreateSetPositionsReturn {
  const pending = ref(false)
  const client = useSupabaseClient<Database>()

  async function createSetPositions(setId: string, positions: SetPositionInput[]): Promise<ActionResult<true>> {
    pending.value = true
    try {
      // 【一括 insert】: 4行。UNIQUE(set_id, team, position) 違反は error で拒否（EDGE-002）
      const { error } = await client
        .from('set_player_positions')
        .insert(positions.map((p) => ({
          set_id: setId,
          player_id: p.playerId,
          team: p.team,
          position: p.position
        })))

      if (error) return { data: null, error }
      return { data: true, error: null }
    } finally {
      pending.value = false
    }
  }

  return { createSetPositions, pending }
}
```

### 3. useUpdateSet composable 🔵
**信頼性**: 🔵 *useUpdatePlayer.ts update パターン / REQ-010 / sets.winner*

`winner` を `update().eq('id', setId)` で更新（セット決着の同期確定）。`group_id` は不要（id 指定 + RLS）。

**実装ファイル**: `app/composables/useUpdateSet.ts`

```typescript
/**
 * 【機能概要】: sets.winner を update する同期 Write composable（セット決着確定）
 * 【実装方針】: update({ winner }).eq('id', setId)。同期 await。id 指定 + RLS で自 Group。
 * 🔵 REQ-010 / sets.winner / sets_update RLS
 */
import type { Database } from '~/types/supabase'
import type { Team } from '~/utils/rule-engine/types'

interface ActionResult<T> { data: T | null; error: unknown }
interface UseUpdateSetReturn {
  updateSet: (setId: string, winner: Team) => Promise<ActionResult<true>>
  pending: Ref<boolean>
}

export function useUpdateSet(): UseUpdateSetReturn {
  const pending = ref(false)
  const client = useSupabaseClient<Database>()

  async function updateSet(setId: string, winner: Team): Promise<ActionResult<true>> {
    pending.value = true
    try {
      const { error } = await client
        .from('sets')
        .update({ winner })
        .eq('id', setId)
      if (error) return { data: null, error }
      return { data: true, error: null }
    } finally {
      pending.value = false
    }
  }

  return { updateSet, pending }
}
```

## 注意事項
- 3本とも **同期 await**（楽観ではない）。set / spp / winner は FK 親・トランザクション境界のため確実性優先（architecture.md 永続化戦略）。
- `createSet` の `.select('id').single()` で **必ず set_id を返す**（後続 spp / rallies の FK 親）。
- `createSetPositions` は4行を**一括 insert**（1リクエスト）。部分成功を避けるため individual insert にしない。
- UNIQUE 違反（EDGE-002）は composable では検証せず **error 素通し**（DB が最終防衛、inline 表示は page 側）。立ち位置重複の事前検証はフォーム側の責務。
- `group_id` を付与しない（`match_id` / `id` 経由 + FK RLS で自 Group に限定、REQ-401）。
- `pending` は必ず try/finally で false に戻す（useCreateMatch.ts 方針）。
- `set_number` の採番（既存数 +1）は session（TASK-0010）の責務で、本 composable は受け取った値を insert するのみ。
