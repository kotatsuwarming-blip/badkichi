## タスク概要

match-recording の中核となる**2つの純関数**を `app/utils/match-recording/` に実装する。
副作用なし・DB に触れない・reactive に依存しない純粋写像で、単体テスト最優先（NFR-303 /
feedback_test_coverage）。

1. `map-game-state.ts` — `mapGameStateToRallyDenorm(state, cameraNearTeam) → RallyDenorm`。
   rule-engine の `GameState` を `rallies` の denormalize 列へ写像する（REQ-410）。
   `servingTeam → serving_team`（`RallyDenorm.servingTeam`）/ `serverPosition → server_position` /
   `server → server_player_id`（`RallyDenorm.serverPlayerId`）/
   `receiver → receiver_player_id`（`RallyDenorm.receiverPlayerId`）/
   `cameraNearTeam → camera_near_team`（sets から carry、`null` 許容）。
   ドメイン型は camelCase のため `RallyDenorm`（camelCase）を返し、snake_case 変換は Write composable
   側の責務とする（interfaces.ts の `RallyDenorm` 定義に一致）。

2. `decide-override-type.ts` — `decideOverrideType(existingOverrideCount) → OverrideType`。
   当該チームの既存 override 回数の偶奇で `position_overrides.override_type` ラベルを決める
   （REQ-105: 偶数回目＝`'swapped'` / 奇数回目＝`'restored'`）。engine へは `applyOverride(state, team)` を
   別途渡すため、本関数は DB 保存ラベルの決定のみを担う（DB＝意味ラベル / engine＝トグルの両立）。

新規 DB スキーマ・新規 API は無し。型は TASK-0002 の `app/types/match-recording.ts` から import する。

## 実装詳細

### 1. map-game-state.ts 🔵
**信頼性**: 🔵 *architecture.md GameState→rallies マッピング表（L87-98）/ interfaces.ts RallyDenorm・MapGameStateToRallyDenorm / REQ-410*

`GameState`（`server`/`receiver`/`servingTeam`/`serverPosition`/`positions`/`score`）のうち、
denormalize に使う4項目 + 引数 `cameraNearTeam` を `RallyDenorm` へ写す。`score` / `positions` は
`rallies` には保存しない（スコアは `point_winner` の COUNT で導出、② B-7）。写像は1対1で分岐なし。

**実装ファイル**: `app/utils/match-recording/map-game-state.ts`

```typescript
/**
 * 【機能概要】: rule-engine GameState を rallies の denormalize 列（RallyDenorm）へ写像する純関数
 * 【実装方針】: 副作用なし。引数のみに依存。snake_case 変換は呼び出し側 (Write composable) の責務。
 * 🔵 architecture.md GameState→rallies マッピング / interfaces.ts MapGameStateToRallyDenorm / REQ-410
 */
import type { Team } from '~/utils/rule-engine/types'
import type { GameState } from '~/utils/rule-engine/types'
import type { MapGameStateToRallyDenorm } from '~/types/match-recording'

// GameState → rallies denormalize 列（REQ-410）。cameraNearTeam は sets から carry（MVP セット単位、NULL 許容）。
export const mapGameStateToRallyDenorm: MapGameStateToRallyDenorm = (
  state: GameState,
  cameraNearTeam: Team | null
) => ({
  servingTeam: state.servingTeam, // → serving_team
  serverPosition: state.serverPosition, // → server_position
  serverPlayerId: state.server, // → server_player_id
  receiverPlayerId: state.receiver, // → receiver_player_id
  cameraNearTeam // → camera_near_team（sets.camera_near_team_at_start を carry）
})
```

> 注: `RallyDenorm` のフィールド名（`serverPlayerId`/`receiverPlayerId`）は GameState の
> `server`/`receiver` から名前が変わる点に注意。snake_case（`server_player_id` 等）への最終変換は
> Write composable が行う。

### 2. decide-override-type.ts 🔵
**信頼性**: 🔵 *REQ-105（偶数回目=swapped / 奇数回目=restored）/ EDGE-008（2回連続で元に戻る）/ interfaces.ts DecideOverrideType*

当該チームの既存 override 行数（`existingOverrideCount`）の偶奇でラベルを決める。0 回目（偶数）＝
最初の入替＝`'swapped'`、1 回目（奇数）＝戻し＝`'restored'`、2 回目（偶数）＝再入替＝`'swapped'`。
EDGE-008（同一チームへ2回連続で元の表示状態に戻る）と整合する。engine のステートレストグルとは独立に、
DB に残す意味ラベルのみを決定する。

**実装ファイル**: `app/utils/match-recording/decide-override-type.ts`

```typescript
/**
 * 【機能概要】: 当該チームの既存 override 回数の偶奇で position_overrides.override_type を決める純関数
 * 【実装方針】: 偶数回目=swapped / 奇数回目=restored（REQ-105）。engine へは applyOverride(team) を別途渡す。
 * 🔵 REQ-105 / EDGE-008 / interfaces.ts DecideOverrideType
 */
import type { DecideOverrideType } from '~/types/match-recording'

// 偶数回目（0,2,4...）= swapped（入れ替わった）/ 奇数回目（1,3,5...）= restored（戻った）。REQ-105 / EDGE-008。
export const decideOverrideType: DecideOverrideType = (existingOverrideCount: number) =>
  existingOverrideCount % 2 === 0 ? 'swapped' : 'restored'
```

### テストケース1: mapGameStateToRallyDenorm が各列を写像する 🔵
**信頼性**: 🔵 *REQ-410 / architecture.md マッピング表*
**Given**: `state = { servingTeam: 'A', serverPosition: 'right', server: 'p1', receiver: 'p3', score: {...}, positions: {...} }`、`cameraNearTeam = 'A'`
**When**: `mapGameStateToRallyDenorm(state, 'A')`
**Then**: `{ servingTeam: 'A', serverPosition: 'right', serverPlayerId: 'p1', receiverPlayerId: 'p3', cameraNearTeam: 'A' }` を返す（`score`/`positions` は含まれない）

**テストファイル**: `tests/unit/utils/match-recording/map-game-state.test.ts`

```typescript
import { describe, it, expect } from 'vitest'
import { mapGameStateToRallyDenorm } from '~/utils/match-recording/map-game-state'
import type { GameState } from '~/utils/rule-engine/types'

const baseState: GameState = {
  score: { teamA: 0, teamB: 0 },
  servingTeam: 'A',
  server: 'p1',
  receiver: 'p3',
  serverPosition: 'right',
  positions: { teamA: { left: 'p2', right: 'p1' }, teamB: { left: 'p4', right: 'p3' } }
}

describe('mapGameStateToRallyDenorm', () => {
  it('GameState の各列を RallyDenorm へ写像する (REQ-410)', () => {
    const r = mapGameStateToRallyDenorm(baseState, 'A')
    expect(r).toEqual({
      servingTeam: 'A',
      serverPosition: 'right',
      serverPlayerId: 'p1',
      receiverPlayerId: 'p3',
      cameraNearTeam: 'A'
    })
  })
})
```

## 注意事項
- 両関数は**純関数**を厳守（reactive・DB・getCurrentTimeMs に依存しない）。これにより engine 連携の分岐ロジックを composable 層から分離し、単体テストを容易にする（NFR-303）。
- `RallyDenorm` のフィールド名は GameState と一部異なる（`server`→`serverPlayerId`、`receiver`→`receiverPlayerId`）。写像漏れ・取り違えに注意。
- `RallyDenorm` は camelCase。snake_case（`server_player_id` 等）への変換は Write composable の責務であり、本関数では行わない（責務分離）。
- `decideOverrideType` は DB の意味ラベル決定のみ。engine の状態更新は `applyOverride(state, team)`（rule-engine）が担う。両者を混同しない（note.md §5 の論点）。
- 修正/override 時も同じ `mapGameStateToRallyDenorm` で rallies を上書きし、denormalize の二重管理を避ける（interfaces.ts MapGameStateToRallyDenorm コメント）。
- 型は TASK-0002 の `~/types/match-recording` から import（`MapGameStateToRallyDenorm` / `DecideOverrideType`）。GameState/Team は rule-engine から import。
