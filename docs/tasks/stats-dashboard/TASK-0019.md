## タスク概要

record → stats フロー全体を結合確認し、acceptance-criteria.md の受け入れ基準（TC）と突き合わせて
MVP（stats-dashboard、ひいては全8ユニット）の完成を確定する最終タスク。

dataflow.md の機能1〜4 シーケンス（①初期表示 ②クロスフィルタ ③ラリー再生 ④ペア/選手フィルタ導出）を
代表ケースで結合検証する。具体的には「記録済み試合 → 統計画面表示 → クロスフィルタ（グラフ選択で
テーブル連動）→ ラリー行選択で該当 ms 再生」の一連を、選手 / ペア × 役割（serve/receive）の絞り込み、
ラリー長ビンの複数選択、空状態（REQ-103/201）、母数併記（NFR-201）、他 Group 遮断（NFR-101）まで含めて
確認する。テストは ADR-012 の 2 層に従い、**RPC は integration（CI 専用）**、**UI フローは
component / 結合**で検証する。

新規 DB スキーマ・新規 RPC・新規ロジックは原則追加しない（結合確認と受け入れ突き合わせが主目的）。
不整合が見つかった場合のみ、責務境界（読み取り専用 REQ-401 / スキーマ不変 REQ-402）を守って最小修正する。

## 実装詳細

### 1. 結合フローのスモーク（機能1〜3 の連結）🔵
**信頼性**: 🔵 *dataflow.md 機能1/2/3 + acceptance-criteria.md TC-003-01・TC-010-01・TC-007-01 + 状態管理フロー*

dataflow.md の「初期表示 → 絞り込み中 → 再生中」の状態遷移を 1 本の結合テストでなぞる。試合単位
ダッシュボードを mount し、(a) チャート + テーブル + プレーヤーが描画される（機能1）、(b) チャートの棒
クリックで `useStatsFilter` 更新 → `filter-rallies` でテーブルが連動絞り込み（機能2、per-match は
クライアント側）、(c) 絞り込み後の行選択で `StatsVideoPane` の `seekToMs(video_start_timestamp_ms)` が
呼ばれる（機能3）、を順に検証する。

**検証ファイル（結合）**: `app/pages/groups/[id]/matches/[matchId]/stats.*.test.ts`（component 結合、happy-dom）
- RPC / video-playback は mock（`useVideoPlayer` の `controls.seekToMs` を spy）。

### 2. 絞り込み次元の網羅（選手 / ペア × 役割 / ラリー長ビン複数）🔵
**信頼性**: 🔵 *REQ-010/004/012 + dataflow.md 機能2 詳細1（ラリー長ビン複数選択は和集合 / ペア・選手は役割と連動）+ acceptance-criteria TC-010-01/02・TC-004-01/02*

`useStatsFilter` + `filter-rallies` の結合で、次の絞り込み次元を代表ケースで検証する:
- **選手 × 役割**: 「選手 P のサーブ」で P がサーバーのラリーのみに絞られる（TC-010-01）。
- **ペア × 役割**: 「ペア X のサーブ時」= ペア X が serving 側のラリーに絞られる（player_id で集計、A/B 非依存・TC-004-02）。
- **ラリー長ビン複数選択**: 1〜3 と 4〜6 を選ぶと和集合 1〜6 で絞られる（`rally-length-bins` の binsToRanges、dataflow 機能2 詳細1）。
- **解除**: フィルタ解除でテーブルが全件に戻る（TC-010-02）。

### 3. 再生・エッジケース 🔵
**信頼性**: 🔵 *REQ-007/011/104/102 + EDGE-103/002 + acceptance-criteria TC-007-01/E01/E02・TC-104-01*

- **再生**: 絞り込み後の行選択で `seekToMs(ms)` が呼ばれる（TC-007-01）。
- **EDGE-103**: `video_start_timestamp_ms IS NULL` の行は非リンク・再生不可（TC-007-E01）。
- **REQ-102 / EDGE-002**: `local` 動画 URL 失効で再選択を促す（`needsReselect`、TC-007-E02）。
- **REQ-104（Group 横断）**: 別試合の行選択で `currentSource` を当該試合のソースに切替（`:key` 再生成、TC-104-01）。

### 4. 空状態・母数併記 🔵
**信頼性**: 🔵 *REQ-103/201/202 + NFR-201 + acceptance-criteria TC-103-01・TC-101-B01・TC-201-01*

- **空状態**: 確定ラリー 0 件（記録 0 / 全件レット・未確定）で `StatsEmptyState` を表示し例外を投げない（TC-103-01 / TC-101-B01・EDGE-101）。
- **母数併記**: 得点率に母数を併記（`67%（n=3）`、NFR-201・TC-201-01）。母数 0 は「-」（REQ-202 / TC-202-01）。

### 5. 集計 RPC の integration 検証（CI 専用）🔵
**信頼性**: 🔵 *REQ-408/403 + NFR-101 + ADR-012 / [[feedback_test_layer_separation]] + acceptance-criteria TC-408-01・TC-NFR-101-01・TC-401-01*

集計の本体（`stats_player_rates` / `stats_pair_rates` / `stats_rally_length` / `stats_rallies`）は
**integration テスト（CI 専用、`*.integration.test.ts`、共有 DB のため `fileParallelism: false`）**で検証する:

- **確定ラリー除外（REQ-101）**: レット・未確定が母数・分子から除外される（SQL 側）。

- **ペア導出（機能4 / REQ-012）**: 試合のチーム構成から無向ペアを導出し serving_team 基準で集計される。

## 統合テスト要件

dataflow.md の機能1〜4 シーケンスを代表ケースで検証する（境界値 + 分岐のみ）。RPC は integration（CI 専用）、

### 結合（component、happy-dom + i18n mock + video-playback mock）

#### 結合フロー（機能1→2→3）🔵
- **Given**: 確定ラリー・レット・未確定が混在し、`video_start_timestamp_ms` を持つラリーを含む記録済み試合
- **When**: stats 画面を開き、チャートで「選手 P のサーブ」を選択し、絞り込まれた行を選択する
- **Then**: チャート + テーブル + プレーヤーが描画され、テーブルが P サーブのラリーに連動絞り込みされ、行選択で `seekToMs` が当該 ms で呼ばれる 🔵 *TC-003-01 / TC-010-01 / TC-007-01*

#### クロスフィルタ解除 / 複数ビン 🔵
- **Given**: 絞り込み中のテーブル
- **When**: フィルタを解除する / ラリー長ビン 1〜3 と 4〜6 を選ぶ
- **Then**: 解除で全件に戻る / 複数ビンは和集合 1〜6 で絞られる 🔵 *TC-010-02 / dataflow 機能2 詳細1*

#### 再生エッジ 🔵
- **Given**: `video_start_timestamp_ms IS NULL` の行 / `local` 動画 URL 失効
- **When**: 当該行を選択
- **Then**: NULL 行は非リンク・再生不可 / URL 失効は再選択を促す 🔵 *TC-007-E01 / TC-007-E02・EDGE-103/002*

#### 空状態 / 母数併記 🔵
- **Given**: 確定ラリー 0 件（記録 0 / 全件レット・未確定）/ 母数 3 の得点率
- **When**: stats 画面を開く
- **Then**: 空状態が表示され例外を投げない / 得点率が `(n=3)` 併記で表示される 🔵 *TC-103-01 / TC-101-B01 / TC-201-01*

### integration（CI 専用、`*.integration.test.ts`、`fileParallelism: false`）

#### 他 Group 遮断（RLS）🔵
- **Given**: 別 Group の試合に紐づく録画データ
- **When**: 他 Group の `p_match_id` / `p_group_id` で集計 RPC を呼ぶ
- **Then**: データは 0 件で返り、他 Group のデータを集計・返却しない 🔵 *TC-NFR-101-01 / TC-408-01・REQ-403/408*

#### 確定ラリー除外 / 読み取り専用 🔵
- **Given**: レット・未確定を含むラリー群
- **When**: 集計 RPC を呼ぶ / stats 操作を行う
- **Then**: レット・未確定が母数・分子から除外され、録画系テーブルへの書き込みが発生しない 🔵 *REQ-101 / TC-401-01*

## 注意事項
- **テスト 2 層の厳守（ADR-012 / [[feedback_test_layer_separation]]）**: 集計 RPC の本体検証は integration（CI 専用、`*.integration.test.ts`）に置く。UI の連動・再生・空状態は component / 結合で mock を使って検証し、RPC を component テストから直叩きしない。
- **共有 DB の integration（[[feedback_vitest_file_parallelism]]）**: integration テストは `fileParallelism: false` を守り、cross-file の `beforeAll`/`afterAll` 干渉を避ける。DB パスワードはローカルで使わず CI 一本化（[[feedback_db_password_ci_only]]）。
- **読み取り専用・スキーマ不変（REQ-401/402）**: 結合中に修正が要る場合も、録画系テーブルへの書き込み・既存スキーマ変更は禁止。集計は既存の読み取り専用 RPC で完結させる。
- **A/B 非依存（REQ-004/012）**: 絞り込み・集計のキーは player_id / ペアであることを結合でも確認する。チーム A/B が試合ごとに入れ替わっても同一選手・同一ペアとして集計されること（TC-004-02）。
- **依存方向（REQ-405 / ADR-002）**: stats → video-playback の一方向。再生検証は `useVideoPlayer` の契約（`seekToMs` / `needsReselect`）を mock/spy し、video-playback にドメイン概念を持ち込まない。
- **CSR 限定（REQ-404 / ADR-010）**: チャートは `<ClientOnly>`。component テストは happy-dom + vue-i18n auto-import mock 方針（[[project_video_playback_progress]]）に揃える。
- **TC 突き合わせの記録**: acceptance-criteria.md の各 TC がどの結合 / integration テストで満たされるかの対応を残し、未充足 TC が無いことを最終確認する（MVP 完成判定）。
