## タスク概要

設計の `docs/design/stats-dashboard/interfaces.ts` で確定した型を、アプリの
`app/types/stats-dashboard.ts` へ配置（同期）する。後続のほぼ全タスク（composable / util /
コンポーネント / RPC 呼び出し）が参照する型基盤であり、設計 interfaces.ts を**正**として一致させる。

RPC 生返却型（snake_case）/ クライアント派生型（camelCase）/ クロスフィルタ型 / composable 戻り値型 /
コンポーネント props 型 / 定数（`RALLY_LENGTH_BINS`）を含む。`VideoSource` は既存の
`~/types/video-playback` から import する（依存方向 stats → video-playback、REQ-405）。

新規 DB スキーマ・新規 API・新規ロジックは無い。純粋な型配置のため DIRECT タスクとする。

## 注意事項
- **設計 interfaces.ts を正とする**: 命名・構造・コメントを設計に一致させる。アプリ側で独自拡張しない（同期方向は設計 → アプリ）。
- **ESLint 規約**: セミコロンなし / no comma dangle / 1tbs。interfaces.ts は既にこの規約準拠のため、原則そのまま転記すれば lint を通る。
- **`supabase.ts` 生成型との重複に注意**: RPC 行型（`PlayerRateRow` 等）は本ファイルでアプリ用に定義するが、`app/types/supabase.ts` は gen-types CI が migration から自動再生成する別物。RPC 呼び出し時の型は用途に応じて使い分ける（生 RPC の戻りは supabase 型、UI 受け渡しは本ファイルの型）。設計が本ファイルを「同期配置」と位置づけているため、本タスクでは interfaces.ts の型を配置する。
- **依存方向（REQ-405 / ADR-002）**: `VideoSource` は import のみ。stats 側の型を video-playback へ逆流させない。
- 本ファイルは後続ほぼ全タスクの前提。型の欠落・名称ずれは広範な型エラーを招くため、完了条件のリストを漏れなく満たすこと。
