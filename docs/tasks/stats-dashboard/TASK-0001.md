## タスク概要

stats-dashboard のチャート描画基盤を整備する。PRD §6 / REQ-406 で指定された **echarts + vue-echarts**
を依存追加し、CSR 限定（REQ-404）で動かすため **client plugin**（`app/plugins/echarts.client.ts`）で
必要モジュールのみを `use()` 登録（ツリーシェイク）して `VChart` コンポーネントを Nuxt にグローバル登録する。

得点率（棒）/ ラリー長（棒 + 線コンボ）に必要な `BarChart` / `LineChart`、および軸・凡例・ツールチップ・
データセット・Canvas レンダラーの component を登録する。NFR-001（初期表示 3 秒以内）のため全部入りの
`echarts` ではなく `echarts/core` から必要分のみ import する。

新規 DB スキーマ・新規 API・新規ロジックは無い。本タスクは描画基盤の整備のみで、チャート
コンポーネント（StatsRateChart / StatsRallyLengthChart）の実装は後続フェーズで行う。

## 実装詳細

### 1. 依存追加 🔵
**信頼性**: 🔵 *REQ-406（vue-echarts 指定）/ architecture.md「チャート: echarts + vue-echarts」*

`pnpm add echarts vue-echarts` で 2 パッケージを追加する。`echarts` は core + 必要モジュールの
ツリーシェイク登録に用い、`vue-echarts` は Vue コンポーネント（`VChart`）を提供する。`@types` の
追加は不要（両パッケージとも型を同梱）。

### 2. CSR client plugin 🔵
**信頼性**: 🔵 *REQ-404（CSR 限定）/ NFR-001（必要モジュールのみ import で転送量最小化）/ architecture.md「client plugin でツリーシェイク登録」*

CSR 限定のため `.client.ts` サフィックスで plugin を作る。`echarts/core` の `use()` に
必要モジュールのみ渡す（得点率の棒 = `BarChart`、ラリー長の本数棒 + 勝率線 = `BarChart` + `LineChart`、
軸 = `GridComponent`、凡例 = `LegendComponent`、ツールチップ = `TooltipComponent`、データセット =
`DatasetComponent`、描画 = `CanvasRenderer`）。`VChart` をグローバルコンポーネント登録し、ページ/
コンポーネント側では `<ClientOnly>` でラップして使う（CSR 限定の徹底）。

**実装ファイル**: `app/plugins/echarts.client.ts`

```typescript
import { use } from 'echarts/core'
import { BarChart, LineChart } from 'echarts/charts'
import {
  GridComponent,
  TooltipComponent,
  LegendComponent,
  DatasetComponent
} from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'
import VChart from 'vue-echarts'
import { defineNuxtPlugin } from '#app'

// 【機能概要】: CSR 限定（REQ-404）で vue-echarts をツリーシェイク登録するプラグイン
// 🔵 REQ-406 / REQ-404 / NFR-001 / architecture.md「チャート」節
export default defineNuxtPlugin((nuxtApp) => {
  use([
    BarChart,
    LineChart,
    GridComponent,
    TooltipComponent,
    LegendComponent,
    DatasetComponent,
    CanvasRenderer
  ])
  nuxtApp.vueApp.component('VChart', VChart)
})
```

> 注: モジュール集合は得点率（棒）/ ラリー長（棒 + 勝率線コンボ）の MVP チャートに必要十分なもの。
> 将来チャート種が増えた場合（例: ScatterChart）は本 plugin の `use()` に追記して一元管理する。

## 注意事項
- **CSR 限定（REQ-404）**: plugin は必ず `.client.ts` サフィックスにする。チャート利用側は `<ClientOnly>` でラップし、SSR でのチャート描画を避ける（ADR-010 SSR/CSR 境界）。
- **ツリーシェイク厳守（NFR-001）**: `import * as echarts from 'echarts'`（全部入り）は使わない。`echarts/core` + 個別モジュールの `use()` 登録に限定し、バンドルサイズと初期表示時間を抑える。
- **登録漏れに注意**: ラリー長チャートは「本数（棒）+ 勝率（線）」のコンボのため `BarChart` と `LineChart` の両方が必要。軸（`GridComponent`）・ツールチップ・凡例・データセット・レンダラーのいずれかが欠けると実行時に空描画/エラーになる。
- **依存方向（REQ-405 / ADR-002）**: 本 plugin はドメイン非依存（汎用チャート登録のみ）。stats ドメイン概念を持ち込まない。
- このタスクはチャートコンポーネント実装の前提であり、ここで `VChart` が解決できないと後続が進まないため、direct-verify を確実に通すこと。
