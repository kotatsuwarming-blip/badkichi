## タスク概要

stats-dashboard の集計層の中核となる**読み取り専用 RPC を新規 migration で 1 本作成**し、その中に
**選手別得点率（`stats_player_rates`）とペア別得点率（`stats_pair_rates`）**を実装・検証する。

集計は Postgres 側で完結させ（NFR-002）、クライアントへは集計済みの母数・分子を返す。全関数は
`SECURITY INVOKER` + `STABLE` + `SET search_path = public` で、RLS（`rallies`/`sets`/`matches` の
FK 経由 `is_member_of`）を継承して他 Group のデータを返さない（REQ-403 / NFR-101）。スコープは
`p_match_id` / `p_group_id` の**いずれか一方のみ**必須で、両 NULL / 両指定は `invalid_scope` を `RAISE`。

得点率の集計対象は**確定ラリーのみ**（REQ-101）:
`r.deleted_at IS NULL AND r.is_let = false AND r.is_point_confirmed = true AND r.point_winner IS NOT NULL`
（`sets` / `matches` も `deleted_at IS NULL`）。ペアは試合のチーム構成（`matches.team_*_player*`）から
`LEAST` / `GREATEST` で無向正規化し、同じ 2 人が別試合・別チーム（A/B）で組んでも同一ペアとして累計する
（A/B ラベル非依存、ヒアリング2026-06-09）。

既存テーブルのスキーマは変更しない（additive、関数 + GRANT のみ）。適用は CI 経由（`db:push`、
ローカル不可、[[feedback_db_password_ci_only]]）。検証は integration テスト（CI 専用）で行う。

### 2. stats_player_rates（選手別 母数・分子） 🔵
**信頼性**: 🔵 *database-schema.sql 関数 1 / REQ-003 / REQ-101 / REQ-202*

database-schema.sql の関数 1 を忠実に実装する。`confirmed` CTE で確定ラリーに絞り、`serve` CTE
（`server_player_id` で GROUP BY、`count(*)` = serve_total、`FILTER (WHERE point_winner = serving_team)`
= serve_won）、`receive` CTE（`receiver_player_id` で GROUP BY、won は `point_winner <> serving_team`）
を作り、`player_id` で `FULL OUTER JOIN`。出力は `COALESCE` で 0 埋め。母数 0 の選手は 0 のまま返し、
得点率の 0 除算回避はクライアント（`computePlayerRate`）が行う（EDGE-001 / REQ-202）。

```sql
CREATE OR REPLACE FUNCTION stats_player_rates(
  p_match_id uuid DEFAULT NULL,
  p_group_id uuid DEFAULT NULL
)
RETURNS TABLE (
  player_id uuid, serve_total bigint, serve_won bigint, receive_total bigint, receive_won bigint
)
LANGUAGE plpgsql SECURITY INVOKER STABLE SET search_path = public
AS $$
BEGIN
  IF (p_match_id IS NULL) = (p_group_id IS NULL) THEN
    RAISE EXCEPTION 'invalid_scope';
  END IF;
  RETURN QUERY
  WITH confirmed AS (
    SELECT r.serving_team, r.server_player_id, r.receiver_player_id, r.point_winner
    FROM rallies r
    JOIN sets s ON s.id = r.set_id AND s.deleted_at IS NULL
    JOIN matches m ON m.id = s.match_id AND m.deleted_at IS NULL
    WHERE r.deleted_at IS NULL AND r.is_let = false
      AND r.is_point_confirmed = true AND r.point_winner IS NOT NULL
      AND (p_match_id IS NULL OR m.id = p_match_id)
      AND (p_group_id IS NULL OR m.group_id = p_group_id)
  ),
  serve AS (
    SELECT c.server_player_id AS pid, count(*) AS total,
           count(*) FILTER (WHERE c.point_winner = c.serving_team) AS won
    FROM confirmed c GROUP BY c.server_player_id
  ),
  receive AS (
    SELECT c.receiver_player_id AS pid, count(*) AS total,
           count(*) FILTER (WHERE c.point_winner <> c.serving_team) AS won
    FROM confirmed c GROUP BY c.receiver_player_id
  )
  SELECT COALESCE(sv.pid, rc.pid), COALESCE(sv.total, 0), COALESCE(sv.won, 0),
         COALESCE(rc.total, 0), COALESCE(rc.won, 0)
  FROM serve sv FULL OUTER JOIN receive rc ON rc.pid = sv.pid;
END;
$$;
```

> 完全な本体は database-schema.sql（L29-86）を参照し、列名・CTE 構造・COALESCE を一致させる。

### 3. stats_pair_rates（ペア別 母数・分子） 🔵
**信頼性**: 🔵 *database-schema.sql 関数 2 / REQ-012 / ヒアリング2026-06-09（A/B 非依存・無向ペア累計）*

database-schema.sql の関数 2 を忠実に実装する。`match_pairs` CTE で各試合の team A / team B を
`LEAST`/`GREATEST` で無向ペア `(p1, p2)` に正規化（A / B を UNION ALL）。`confirmed` CTE で確定ラリー
（`match_id` / `serving_team` / `point_winner`）を抽出。`serve` CTE は `match_pairs.team = serving_team`
で JOIN しペア単位で集計、`receive` CTE は `team <> serving_team`。`(p1, p2)` で FULL OUTER JOIN し
COALESCE 0 埋め。**同じ 2 人が別試合で team A と B でも `(p1,p2)` が一致するため同一ペアとして累計**される。

```sql
-- 要点（全体は database-schema.sql L93-166 を正とする）
WITH match_pairs AS (
  SELECT m.id AS match_id, 'A'::text AS team,
         LEAST(m.team_a_player1_id, m.team_a_player2_id) AS p1,
         GREATEST(m.team_a_player1_id, m.team_a_player2_id) AS p2
  FROM matches m WHERE m.deleted_at IS NULL
  UNION ALL
  SELECT m.id, 'B'::text,
         LEAST(m.team_b_player1_id, m.team_b_player2_id),
         GREATEST(m.team_b_player1_id, m.team_b_player2_id)
  FROM matches m WHERE m.deleted_at IS NULL
)
-- confirmed → serve (mp.team = serving_team) / receive (mp.team <> serving_team) → FULL OUTER JOIN on (p1,p2)
```

### TC-003-01: 確定ラリーの選手別 serve 得点率（正常系・母数/分子） 🔵
**信頼性**: 🔵 *REQ-003 / database-schema.sql confirmed/serve CTE*
**Given**: User A の Group に試合 M を作成し、選手 P がサーバーの**確定**ラリー 4 件（うち 3 件は `point_winner = serving_team`＝サーブ側得点、1 件は相手得点）を seed
**When**: User A クライアントで `client.rpc('stats_player_rates', { p_match_id: M })` を呼ぶ
**Then**: P の行が `serve_total = 4` / `serve_won = 3` を返す

### TC-101-01: レット・未確定の除外（分岐） 🔵
**信頼性**: 🔵 *REQ-101 / EDGE-101*
**Given**: 同一選手 P のラリーに `is_let = true` 1 件、`is_point_confirmed = false` 1 件、`point_winner IS NULL` 1 件を追加 seed（いずれも確定条件を満たさない）
**When**: `stats_player_rates(p_match_id: M)`
**Then**: これら 3 件は母数・分子の双方から除外され、TC-003-01 と同じ `serve_total = 4` のまま（増えない）

### TC-003-02: 母数 0（行が出ない / 0 を返す）（境界値） 🔵
**信頼性**: 🔵 *EDGE-001 / EDGE-101 / REQ-202*
**Given**: 全ラリーがレット / 未確定で確定ラリー 0 件の試合 M2
**When**: `stats_player_rates(p_match_id: M2)`
**Then**: 集計対象 0 件として行が返らない（または該当選手が 0/0 で出ない）。0 除算エラーにならない（rate=null 変換はクライアント責務）

### TC-012-01: ペア導出（A/B ラベル非依存の同一ペア累計） 🔵
**信頼性**: 🔵 *REQ-012 / ヒアリング2026-06-09 / database-schema.sql match_pairs（LEAST/GREATEST）*
**Given**: 選手 X・Y が、試合 Ma では team A、試合 Mb では team B として同じペアを組み、各試合に確定ラリーを seed
**When**: `stats_pair_rates(p_group_id: G)`
**Then**: X・Y は `(player1_id, player2_id) = (LEAST, GREATEST)` の**単一行**に累計される（Ma/Mb の A/B ラベルに依存せず合算される）

### TC-403-01: RLS（他 Group は 0 件）（セキュリティ分岐） 🔵
**信頼性**: 🔵 *REQ-403 / NFR-101 / SECURITY INVOKER で RLS 継承*
**Given**: User B の Group のみに確定ラリーを seed（User A は非所属）
**When**: User A クライアントで `stats_player_rates(p_group_id: G_userB)` / `stats_pair_rates(p_group_id: G_userB)`
**Then**: いずれも空（0 件）を返す（他 Group のデータは集計・返却されない）

### TC-408-01: invalid_scope（引数分岐） 🔵
**信頼性**: 🔵 *REQ-408 / database-schema.sql スコープガード*

## 注意事項
- **migration はローカル適用しない**: `db:push` / `db:reset` は CI 一本化（`SUPABASE_DB_PASSWORD` ローカル不使用、[[feedback_db_password_ci_only]]）。ローカルでは SQL の記述と integration テストの記述に留め、適用は CI に委ねる。
- **既存 migration を編集しない**: additive で新規ファイルを 1 本追加（REQ-402）。TASK-0004 が同じファイルへ追記するため、ファイル名・ヘッダコメントを TASK-0004 と共有する前提で作る。
- **SECURITY INVOKER 厳守**: `SECURITY DEFINER` にしない。INVOKER で呼び出しユーザーの RLS を継承するのが本単位の他 Group 遮断（REQ-403 / NFR-101）の要。`SET search_path = public` も必須（search_path 攻撃防御、既存 SECURITY 関数と方針統一）。
- **STABLE / 読み取り専用厳守**: `SELECT` のみ。INSERT/UPDATE/DELETE/DDL を含めない（REQ-401 / REQ-408）。
- **ペアの無向正規化**: 必ず `LEAST`/`GREATEST` で `(p1,p2)` を作る。A/B ラベルや入力順に依存させない（ヒアリング2026-06-09: 大事なのは A/B ではなく選手が誰か）。
- **母数 0 の扱い**: SQL は 0/0 を返す（または行を出さない）に留め、`rate=null`（「-」表示）への変換はクライアント `computePlayerRate` の責務（EDGE-001 / REQ-202）。SQL 側で除算しない。
- **integration テストの seed**: Admin/service client で Group / matches / sets / rallies を直接作成し、`afterAll` で削除（clean state、ADR-012 D8）。`fileParallelism: false`（共有 DB の cross-file 干渉対策）。
