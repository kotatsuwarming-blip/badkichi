## タスク概要

チャート選択に連動する **クロスフィルタ状態**と適用ロジックを保持する composable を実装する。

- **`filter: Ref<StatsFilter>`**: 現在のフィルタ状態（選手 / ペア / 役割 / ラリー長ビン）。
- **`setFilter(patch)`**: チャート選択でフィルタを部分更新。**同一選択の再クリックでトグル解除**（同じ値を渡されたらその次元を `null` / `[]` に戻す）。
- **`clear()`**: 全フィルタを初期状態（未指定）へ。
- **`apply(rows)`**: per-match 用。`filterRallies`（TASK-0007）へ委譲してクライアント絞り込み。
- **`toQueryArgs()`**: group 横断用。`StatsFilter` → `RallyQueryArgs` 変換（ペア + role → `pairPlayer1Id` / `pairPlayer2Id` + `role`、選択ビン → `binsToRanges` → `shotRanges`、選手 + role → `serverPlayerId` / `receiverPlayerId`）。

## 実装詳細

### 1. useStatsFilter composable 🔵
**信頼性**: 🔵 *interfaces.ts UseStatsFilterReturn / StatsFilter / RallyQueryArgs / REQ-010 / REQ-012*

`setFilter` のトグル解除は「patch のキーごとに、現在値と等価なら null / [] へ戻す」方針。`shotBinKeys` は配列のため、同一キー集合の再選択でクリア、差分があれば置き換え（またはトグル追加）とする。`toQueryArgs` では `role` に応じて選手 id を server / receiver いずれかへ振り分ける（role 未指定時は両方 null とし、サーバー側で OR 評価 or 行は絞らない）。

**実装ファイル**: `app/composables/useStatsFilter.ts`

```typescript
/**
 * 【機能概要】: チャート選択に連動するクロスフィルタ状態 + 適用ロジック。
 * 【実装方針】: ローカル ref（グローバルストアなし）。setFilter は同一選択でトグル解除。
 *             apply は filterRallies 委譲（per-match）、toQueryArgs は RallyQueryArgs 変換（group）。
 * 🔵 interfaces.ts UseStatsFilterReturn / StatsFilter / RallyQueryArgs / REQ-010 / REQ-012
 */
import { ref } from 'vue'
import type { StatsFilter, RallyRow, RallyQueryArgs, UseStatsFilterReturn } from '~/types/stats-dashboard'
import { filterRallies } from '~/utils/stats-dashboard/filter-rallies'
import { binsToRanges } from '~/utils/stats-dashboard/rally-length-bins'

function emptyFilter(): StatsFilter {
  return { playerId: null, pair: null, role: null, shotBinKeys: [] }
}

export function useStatsFilter(): UseStatsFilterReturn {
  const filter = ref<StatsFilter>(emptyFilter())

  function setFilter(patch: Partial<StatsFilter>) {
    const next = { ...filter.value }
    for (const key of Object.keys(patch) as (keyof StatsFilter)[]) {
      const value = patch[key]
      // 【トグル解除】: 同一選択の再クリックは当該次元を初期値へ戻す
      const isSame = JSON.stringify(next[key]) === JSON.stringify(value)
      if (isSame) {
        next[key] = (key === 'shotBinKeys' ? [] : null) as never
      } else {
        next[key] = value as never
      }
    }
    filter.value = next
  }

  function clear() {
    filter.value = emptyFilter()
  }

  function apply(rows: RallyRow[]): RallyRow[] {
    return filterRallies(rows, filter.value)
  }

  function toQueryArgs(): RallyQueryArgs {
    const f = filter.value
    const args: RallyQueryArgs = {}
    if (f.pair) {
      args.pairPlayer1Id = f.pair.player1Id
      args.pairPlayer2Id = f.pair.player2Id
      args.role = f.role
    } else if (f.playerId) {
      // 【役割連動】: serve → server、receive → receiver。role 未指定は両方 null（サーバー側で評価）
      if (f.role === 'serve') args.serverPlayerId = f.playerId
      else if (f.role === 'receive') args.receiverPlayerId = f.playerId
      args.role = f.role
    }
    if (f.shotBinKeys.length > 0) {
      args.shotRanges = binsToRanges(f.shotBinKeys)
    }
    return args
  }

  return { filter, setFilter, clear, apply, toQueryArgs }
}
```

## 注意事項
- 状態はローカル `ref`（グローバルストアなし、architecture.md §状態管理）。ページごとにインスタンス化し、試合単位 / Group 横断で共有しない。
- `apply`（per-match）と `toQueryArgs`（group）は同じ `filter` 状態から異なる消費経路を提供する。per-match は往復なし（クライアント）、group はサーバー側再フェッチ（TASK-0010）。
- トグル解除の等価判定は `JSON.stringify` で十分（小さなフィルタ値のみ）。pair は `{player1Id, player2Id}` の順序を呼び出し側で正規化（小さい uuid を player1）しておくと再選択判定が安定する。
- `role` 未指定の選手フィルタを `toQueryArgs` する場合、server / receiver を絞らず `role: null` のみ渡す（サーバー側で「いずれか関与」を評価、api-endpoints.md §4）。
- ビン → 範囲変換は `binsToRanges`（TASK-0006）を再利用（二重実装しない）。
