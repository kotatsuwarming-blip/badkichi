## タスク概要

選手別／ペア別の **サービス時得点率 / レシーブ時得点率** を vue-echarts の棒グラフで可視化する読み取り専用チャートコンポーネント。母数（対象ラリー数）を必ず併記（NFR-201）し、母数 0 は「-」表示（REQ-202）。棒（または項目）をクリックすると、その選手／ペア・役割（serve/receive）を `emit('select', ...)` でクロスフィルタへ通知する（REQ-010 連動の起点）。

集計値は上位 composable（useMatchStats / useGroupStats）が `compute-player-rate` で算出した `PlayerRate[]` / `PairRate[]` を props で受け取るのみ。本コンポーネントは算出・取得を行わず、描画 + 選択 emit に専念する。CSR 限定（REQ-404）のため `<ClientOnly>` でラップする（REQ-406 / ADR-010）。

## 実装詳細

### 1. props / emits 契約 🔵
**信頼性**: 🔵 *interfaces.ts（PlayerRate / PairRate / StatsRole）/ REQ-004 / REQ-012*

**実装ファイル**: `app/components/stats/StatsRateChart.vue`

```typescript
import type { PlayerRate, PairRate, StatsRole } from '~/types/stats-dashboard'

const props = defineProps<{
  rates: PlayerRate[] | PairRate[]
  mode: 'player' | 'pair'
}>()

// mode='player' は { playerId, role } / mode='pair' は { pair, role }
const emit = defineEmits<{
  select: [payload:
    | { playerId: string, role: StatsRole }
    | { pair: { player1Id: string, player2Id: string }, role: StatsRole }]
}>()
```

- `mode` で `rates` の実体を判別する（player=`PlayerRate[]`、pair=`PairRate[]`）。判別は型ガード util（`isPlayerRate`）か `mode` で行い、`as` の濫用を避ける 🟡。
- 軸ラベルは `mode='player'` → `playerName`、`mode='pair'` → `pairLabel`（「田中 / 佐藤」）を用いる 🔵 *interfaces.ts*。

### 2. 母数併記 + 母数 0 の「-」表示 🔵
**信頼性**: 🔵 *NFR-201（母数併記必須）/ REQ-202 / EDGE-001（0 除算回避）*

- 各バーのラベル/ツールチップは `RateValue` を `formatRate(rate)` で `67%（n=3）` 形式へ整形する。
- `rate === null`（母数 0）は数値を描かず「-」を表示し、バーは 0 高さ or 非表示にする（チャートをエラーにしない, REQ-103 整合）。
- 整形は純関数（`app/utils/stats-dashboard/` の `formatRate` 等。TASK-0002/0003 系で用意される想定。無ければ本タスクで util を切り出し単体テスト可能にする, REQ-407）🟡。

```typescript
// 例: 母数併記の整形（純関数として分離）
function formatRate(v: { rate: number | null, denominator: number }): string {
  if (v.rate == null) return '-'
  return `${Math.round(v.rate * 100)}%（n=${v.denominator}）`
}
```

### 3. serve / receive の表現 🔵
**信頼性**: 🔵 *REQ-003（サービス時 / レシーブ時）*

- serve / receive を 2 系列の棒（グループ化）として並べる。凡例（LegendComponent, TASK-0001 で登録済）で切替可能にする。
- クリック時、押された系列から `role`（'serve' | 'receive'）を判定して emit する。

### 4. クリックで選択 emit（クロスフィルタ起点） 🔵
**信頼性**: 🔵 *REQ-010 / dataflow.md 機能2*

- vue-echarts の `@click`（params.dataIndex / params.seriesName）から、対象の選手 or ペアと role を解決して `emit('select', ...)`。
- 同一選択の再クリックでのトグル解除は `useStatsFilter.setFilter`（上位）が担う。本コンポーネントは選択内容を通知するのみ 🔵 *interfaces.ts UseStatsFilterReturn*。

### 5. `<ClientOnly>` ラップ（CSR 限定） 🔵
**信頼性**: 🔵 *REQ-406 / REQ-404 / ADR-010*

- `VChart`（TASK-0001 で登録）を `<ClientOnly>` 内に置く。SSR 時の echarts 実行を避ける。

## UI/UX要件
- **ローディング**: 取得中はチャートを描かず、上位ページが `pending` でスケルトン/ローディングを出す（本コンポーネントは描画専念）🔵 *NFR-001*。
- **空状態**: `rates` が空（確定ラリー0件）の場合はチャートを描かず、上位が `StatsEmptyState` を出す（REQ-103）。本コンポーネントは空配列でも例外を投げない 🔵。
- **母数併記**: 全得点率に母数を併記し、少数サンプルの過大評価を防ぐ（NFR-201）🔵。
- **レスポンシブ**: コンテナ幅に追従（vue-echarts `autoresize`）。PC / スマホ両対応（NFR-202）🔵。
- **アクセシビリティ**: ツールチップだけに依存せず、テキストでも得点率・母数を読めるようにする（凡例ラベル・aria）🟡。

## 注意事項
- **算出は持たない（責務分離）**: 得点率の算出は composable / util（compute-player-rate）の責務。本コンポーネントは `PlayerRate[]` / `PairRate[]` を受け取り描画 + emit するのみ（REQ-407）🔵。
- **チーム A/B を軸にしない**: 集計・選択キーは選手（player_id）／ペア。A/B ラベルは使わない（ヒアリング2026-06-09）🔵。
- **CSR 限定**: `<ClientOnly>` 必須。SSR で echarts を実行しない（REQ-404 / ADR-010）🔵。
- **整形の純関数化**: `formatRate` 等の派生整形は util に切り出し単体テスト可能にする（REQ-407）🔵。
- **0 除算回避**: 母数 0 は `rate=null` を前提に「-」へ分岐（NaN/Infinity を描かない, EDGE-001）🔵。
