## タスク概要

Group 横断ダッシュボード `/groups/[id]/stats` を実装する。複数試合を跨いだ **選手別 / ペア別**（同一の 2 選手の組, REQ-012）の累計分析。`useGroupStats`（集計）+ `useGroupRallies`（絞り込み後のラリー行をサーバー側取得）+ `useStatsFilter` を結線し、TASK-0011〜0015 のコンポーネントを再利用する。

per-match との最大の差分: ① **初期はチャートのみ**表示し、絞り込み確定後に `useGroupRallies` が `stats_rallies` を **サーバー側フィルタ + LIMIT** で取得してテーブル表示（大量ロード回避, architecture.md パフォーマンス）。② **別試合のラリー選択時はソース切替**（`StatsVideoPane` の `source` を当該試合の動画に切替、`:key` 再生成で再 attach, REQ-104。`local` は方式 A 再選択, REQ-102）。③ 選手別/ペア別の切替 UI（REQ-004/012）。

## 実装詳細

### 1. ルート + composable 結線 + 選手/ペア切替 🔵
**信頼性**: 🔵 *REQ-002/004/012 / interfaces.ts / dataflow.md 機能4*

**実装ファイル**: `app/pages/groups/[id]/stats.vue`

```typescript
import { computed, ref, watch } from 'vue'
import { useRoute } from 'vue-router'
import type { RallyRow } from '~/types/stats-dashboard'

const route = useRoute()
const groupId = route.params.id as string

const { data: stats, pending: statsPending } = useGroupStats(groupId)
const { filter, setFilter, clear, toQueryArgs } = useStatsFilter()
const { data: rallies, pending: ralliesPending, refresh: refreshRallies } = useGroupRallies(groupId)

const mode = ref<'player' | 'pair'>('player')        // REQ-004/012 切替
const chartRates = computed(() =>
  mode.value === 'pair' ? stats.value?.pairRates ?? [] : stats.value?.playerRates ?? [])
```

### 2. 初期チャートのみ → 絞り込み後にサーバー側取得 🔵
**信頼性**: 🔵 *architecture.md パフォーマンス（横断は初期チャートのみ）/ dataflow.md 機能2（group 分岐）/ interfaces.ts RallyQueryArgs*

```typescript
// フィルタが「未指定（絞り込みなし）」かどうか
const hasFilter = computed(() =>
  filter.value.playerId != null || filter.value.pair != null || filter.value.shotBinKeys.length > 0)

// 絞り込み確定で stats_rallies をサーバー側フィルタ + LIMIT 取得（大量ロード回避）
watch(() => filter.value, () => {
  if (hasFilter.value) refreshRallies(/* toQueryArgs() を useGroupRallies へ反映 */)
}, { deep: true })
```

- 初期（フィルタ無し）は **テーブル非表示**、チャートのみ。フィルタ確定で `toQueryArgs()`（serverPlayerId / pair / role / shotRanges / limit）を `useGroupRallies` に渡しサーバー側評価 + `LIMIT`（既定 200）で取得 🔵 *interfaces.ts RallyQueryArgs / dataflow.md*。
- フィルタ解除でテーブル非表示へ戻る 🔵。

### 3. 別試合ラリーのソース切替再生（REQ-104） 🔵
**信頼性**: 🔵 *REQ-104 / dataflow.md 機能3 / TASK-0014 StatsVideoPane（:key 再生成）*

```typescript
const currentSource = ref<VideoSource | null>(null)
const videoPane = ref<{ seekToMs: (ms: number) => void } | null>(null)

function onSelectRally(rally: RallyRow): void {
  if (rally.video_start_timestamp_ms == null) return // EDGE-103
  const next = toVideoSource(rally) // match_id の video_source_type/url から構築（youtube|local）
  if (!sameSource(currentSource.value, next)) {
    currentSource.value = next       // :key 再生成 → StatsVideoPane が再 attach（REQ-104）
    // local は方式A 再選択（VideoPlayer needsReselect, REQ-102）
  }
  videoPane.value?.seekToMs(rally.video_start_timestamp_ms)
}
```

- `RallyRow.video_source_type` / `video_source_url` / `match_id` から `VideoSource` を構築（`youtube`=url、`local`=再選択要）🔵 *interfaces.ts RallyRow*。
- ソースが現在と異なれば `currentSource` 更新 → `StatsVideoPane` の `:key`（source 由来）が変わり再 attach。同一試合なら `seekToMs` のみ 🔵。
- `local` で File 未供給/失効は VideoPlayer の `needsReselect` UI → `reselectFile` を上位で受け currentSource を更新（REQ-102）🔵。

### 4. 空状態 / ローディング 🔵
**信頼性**: 🔵 *REQ-103 / interfaces.ts StatsAggregate.isEmpty*

- `statsPending` 中はチャートスケルトン。`stats.value?.isEmpty`（Group に確定ラリー0件）で `StatsEmptyState`（variant='no-data'）🔵。
- 絞り込み後 `rallies` が 0 件なら「該当ラリーなし」（テーブル空状態）。チャートはエラーにしない 🔵。

## 注意事項
- **横断はサーバー側絞り込み**: per-match と違い大量データのためクライアント全ロードしない。絞り込み確定で `stats_rallies`（filter + LIMIT）を取得（architecture.md / dataflow.md 機能2 group 分岐）🔵。
- **初期テーブル非表示**: フィルタ未指定では `useGroupRallies` を呼ばずチャートのみ（性能, NFR-001）🔵。
- **ソース切替の :key（REQ-104）**: `StatsVideoPane` の再生成は source 由来 key で。別試合に切り替わらない不具合に注意。同一試合は seekToMs のみ 🔵。
- **A/B ではなく選手/ペア**: 集計・絞り込みキーは player_id / ペア。チーム A/B は軸にしない（ヒアリング2026-06-09 / dataflow.md 機能4）🔵。
- **EDGE-103 / REQ-102**: NULL 行はジャンプ不可、local URL 失効は再選択（VideoPlayer 委譲）🔵。
- **toVideoSource は util へ**: RallyRow → VideoSource 変換は純関数で分離し単体テスト可能に（REQ-407）🔵。
