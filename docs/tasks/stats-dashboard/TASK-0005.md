## タスク概要

得点率（サービス時 / レシーブ時）を算出する **純関数ユーティリティ**を実装する。

- **`computePlayerRate(total, won): RateValue`**: 母数（`total`）と分子（`won`）から得点率を算出する。母数 0 のときは 0 除算を回避し `{ rate: null, denominator: 0, numerator: 0 }` を返す（EDGE-001 / REQ-202）。母数を必ず併記する（NFR-201）。
- **RPC 行 → 派生型のマッピング関数**: `stats_player_rates` の行（`PlayerRateRow`）を `PlayerRate`（`serve` / `receive` の `RateValue`）へ、`stats_pair_rates` の行（`PairRateRow`）を `PairRate` へマッピングする。`computePlayerRate` を serve/receive それぞれに適用する。**選手名（`playerName` / `pairLabel`）は呼び出し側（composable）でマスタ解決**するため、本関数では埋めない（空文字または引数で受け取る方針）。

集計本体は RPC（SQL 側）で行うため、本ユーティリティは「RPC が返した母数・分子を表示用の率へ整形する」責務に限定される（NFR-002）。

## 実装詳細

### 1. computePlayerRate（純関数） 🔵
**信頼性**: 🔵 *interfaces.ts RateValue / EDGE-001 / REQ-202 / NFR-201*

母数 0 を `null` に変換することで「-」表示（REQ-202）を可能にし、母数を必ず併記（NFR-201）する。

**実装ファイル**: `app/utils/stats-dashboard/compute-player-rate.ts`

```typescript
/**
 * 【機能概要】: 母数・分子から得点率（0..1）を算出する純関数。母数 0 は 0 除算回避で rate=null。
 * 【実装方針】: RPC が返す total/won を表示用 RateValue へ整形。母数併記必須（NFR-201）。
 * 🔵 interfaces.ts RateValue / EDGE-001 / REQ-202 / NFR-201
 */
import type { RateValue, PlayerRate, PlayerRateRow, PairRate, PairRateRow } from '~/types/stats-dashboard'

export function computePlayerRate(total: number, won: number): RateValue {
  // 【0 除算回避】: 母数 0 は rate=null（UI は「-」表示, EDGE-001 / REQ-202）
  if (total <= 0) {
    return { rate: null, denominator: 0, numerator: 0 }
  }
  return { rate: won / total, denominator: total, numerator: won }
}

/** PlayerRateRow → PlayerRate（playerName は呼び出し側でマスタ解決） 🔵 */
export function toPlayerRate(row: PlayerRateRow, playerName = ''): PlayerRate {
  return {
    playerId: row.player_id,
    playerName,
    serve: computePlayerRate(row.serve_total, row.serve_won),
    receive: computePlayerRate(row.receive_total, row.receive_won)
  }
}

/** PairRateRow → PairRate（pairLabel は呼び出し側でマスタ解決） 🔵 */
export function toPairRate(row: PairRateRow, pairLabel = ''): PairRate {
  return {
    player1Id: row.player1_id,
    player2Id: row.player2_id,
    pairLabel,
    serve: computePlayerRate(row.serve_total, row.serve_won),
    receive: computePlayerRate(row.receive_total, row.receive_won)
  }
}
```

### テストケース1: TC-202-01 母数 0 → rate=null（0 除算回避） 🔵

**Given**: `total=0`, `won=0`

### テストケース2: TC-202-02 4 件中 3 件 → 0.75・母数 4 🔵
**信頼性**: 🔵 *NFR-201（母数併記）*
**Given**: `total=4`, `won=3`
**When**: `computePlayerRate(4, 3)`
**Then**: `{ rate: 0.75, denominator: 4, numerator: 3 }`

### テストケース3: TC-202-B01 全勝 → 1.0 / 全敗 → 0.0（境界） 🔵
**信頼性**: 🔵 *境界値*
**Given**: `(2, 2)` および `(2, 0)`
**When**: `computePlayerRate`
**Then**: 全勝 = `rate 1.0`（母数 2）/ 全敗 = `rate 0.0`（母数 2）。いずれも `rate` は非 null

**信頼性**: 🔵 *interfaces.ts PlayerRate / PairRate*

**Then**: `serve.rate=0.75`（母数 4）・`receive.rate=null`（母数 0）。`playerName`/`pairLabel` は引数省略で空文字、`player1Id`/`player2Id` が保持される

## 注意事項
- 集計（除外・カウント）は RPC（SQL 側）の責務（REQ-101 / NFR-002）。本関数は **率の整形のみ**を行い、レット・未確定の除外ロジックを二重実装しない。
- `rate` は 0..1 の小数で返す（パーセント化・丸めは表示層）。母数は必ず `denominator` で併記（NFR-201）。
- `playerName` / `pairLabel` の解決は composable（TASK-0009 / TASK-0010）が `players` マスタを引いて埋める。本関数に解決責務を持たせない（純関数性を保つ）。
