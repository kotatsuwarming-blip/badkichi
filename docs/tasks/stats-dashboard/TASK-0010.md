## タスク概要

Group 横断の **集計 RPC** と、**絞り込み後のサーバー側ラリー取得（遅延）** の Read composable を 2 本実装する。

- **`useGroupStats(groupId)`**: `stats_player_rates` / `stats_pair_rates` / `stats_rally_length` を **`{ p_group_id }`** で取得し、選手別 `PlayerRate[]` / ペア別 `PairRate[]`（REQ-012）を含む `StatsAggregate` を組む。名前解決・isEmpty は useMatchStats と同方針。戻り値は `UseStatsReturn`。
- **`useGroupRallies(groupId)`**: **フィルタ確定時のみ** `stats_rallies({ p_group_id, ...toQueryArgs, p_limit })` を発行する**遅延取得**（大量ロード回避、ヒアリング2026-06-08）。初期は未取得（`data=null`）。`refresh(args)`（または `setArgs` + `refresh`）でサーバー側フィルタ付き再取得。戻り値は `UseRalliesReturn` 準拠（`refresh` で再フェッチ）。

### 1. useGroupStats composable 🔵
**信頼性**: 🔵 *api-endpoints.md §1-3 / REQ-002 / REQ-012 / useMatchStats（TASK-0009）と同型*

`{ p_group_id }` でスコープ違いの同形処理。選手別 + **ペア別**（REQ-012：同じ 2 人が複数試合で組めば累計）を `StatsAggregate` に含める。名前解決・isEmpty は TASK-0009 と同方針（共通化してもよい）。

**実装ファイル**: `app/composables/useGroupStats.ts`

```typescript
/**
 * 【機能概要】: Group 横断の集計 RPC（選手別/ペア別 rates + rally_length）を StatsAggregate へ。
 * 【実装方針】: useMatchStats と同型でスコープを p_group_id に。ペア別は REQ-012（横断累計）。
 * 🔵 api-endpoints.md §1-3 / REQ-002 / REQ-012 / NFR-002
 */
import type { Database } from '~/types/supabase'
import type {
  StatsAggregate, UseStatsReturn,
  PlayerRateRow, PairRateRow, RallyLengthRow, RallyLengthPoint
} from '~/types/stats-dashboard'
import { toPlayerRate, toPairRate } from '~/utils/stats-dashboard/compute-player-rate'

export function useGroupStats(groupId: string): UseStatsReturn {
  const client = useSupabaseClient<Database>()

  return useAsyncData<StatsAggregate>(`group-stats-${groupId}`, async () => {
    const arg = { p_group_id: groupId }
    const [playerRes, pairRes, lengthRes, playersRes] = await Promise.all([
      client.rpc('stats_player_rates', arg),
      client.rpc('stats_pair_rates', arg),
      client.rpc('stats_rally_length', arg),
      client.from('players').select('id, name')
    ])
    if (playerRes.error) throw playerRes.error
    if (pairRes.error) throw pairRes.error
    if (lengthRes.error) throw lengthRes.error
    if (playersRes.error) throw playersRes.error

    const nameMap = new Map((playersRes.data ?? []).map(p => [p.id, p.name]))
    const playerRates = ((playerRes.data ?? []) as PlayerRateRow[])
      .map(r => toPlayerRate(r, nameMap.get(r.player_id) ?? ''))
    const pairRates = ((pairRes.data ?? []) as PairRateRow[])
      .map(r => toPairRate(r, `${nameMap.get(r.player1_id) ?? ''} / ${nameMap.get(r.player2_id) ?? ''}`))
    const rallyLength: RallyLengthPoint[] = ((lengthRes.data ?? []) as RallyLengthRow[])
      .map(r => ({ shotCount: r.shot_count, rallies: r.rallies, serveWinRate: r.rallies > 0 ? r.serve_won / r.rallies : null }))

    const totalDenom = playerRates.reduce((s, p) => s + p.serve.denominator + p.receive.denominator, 0)
    const isEmpty = totalDenom === 0 && rallyLength.length === 0
    return { playerRates, pairRates, rallyLength, isEmpty }
  }) as unknown as UseStatsReturn
}
```

### 2. useGroupRallies composable（遅延取得） 🔵
**信頼性**: 🔵 *api-endpoints.md §4 / ヒアリング2026-06-08（絞り込み後取得）/ architecture.md §パフォーマンス*

初期はフェッチしない（`immediate: false`）。フィルタ確定時に `toQueryArgs`（TASK-0008）の結果 + `p_limit` で `stats_rallies` を発行。`refresh(args)` を呼ぶと最新引数で再取得する。snake_case 引数（`p_server_player_id` 等）へのマッピングをここで行う。

**実装ファイル**: `app/composables/useGroupRallies.ts`

```typescript
/**
 * 【機能概要】: Group 横断のラリー行を「絞り込み確定時のみ」サーバー側フィルタで取得する遅延 Read。
 * 【実装方針】: immediate:false。toQueryArgs（camelCase）→ RPC snake_case 引数へマップ。p_limit 既定 200。
 *             初期は data=null（未取得）。refresh で最新 args 再取得（大量ロード回避, ヒアリング2026-06-08）。
 * 🔵 api-endpoints.md §4 / REQ-010 / REQ-012 / architecture.md §パフォーマンス
 */
import { ref } from 'vue'
import type { Database } from '~/types/supabase'
import type { RallyRow, RallyQueryArgs, UseRalliesReturn } from '~/types/stats-dashboard'

export function useGroupRallies(groupId: string) {
  const client = useSupabaseClient<Database>()
  const currentArgs = ref<RallyQueryArgs>({})

  const state = useAsyncData<RallyRow[]>(`group-rallies-${groupId}`, async () => {
    const a = currentArgs.value
    const { data, error } = await client.rpc('stats_rallies', {
      p_group_id: groupId,
      p_server_player_id: a.serverPlayerId ?? null,
      p_receiver_player_id: a.receiverPlayerId ?? null,
      p_pair_player1_id: a.pairPlayer1Id ?? null,
      p_pair_player2_id: a.pairPlayer2Id ?? null,
      p_role: a.role ?? null,
      p_shot_ranges: a.shotRanges ?? null,
      p_limit: a.limit ?? 200,
      p_offset: a.offset ?? 0
    })
    if (error) throw error
    return (data ?? []) as RallyRow[]
  }, { immediate: false }) as unknown as UseRalliesReturn

  // 【絞り込み確定で再取得】: 最新引数をセットしてから refresh
  async function fetchWith(args: RallyQueryArgs) {
    currentArgs.value = args
    await state.refresh()
  }

  return { ...state, fetchWith }
}
```

## 注意事項
- **遅延取得**（`immediate: false`）が肝（ヒアリング2026-06-08）。Group 横断は大量データのため、フィルタ未確定では `stats_rallies` を発行しない。初期はチャート（`useGroupStats`）のみ。
- `useGroupStats` は `useMatchStats`（TASK-0009）とスコープ引数（`p_group_id` vs `p_match_id`）以外ほぼ同形。整形・名前解決・isEmpty ロジックを共通ヘルパーへ切り出してもよい（リファクタ時に判断）。
- `toQueryArgs`（camelCase、TASK-0008）→ RPC（snake_case `p_*`）のマッピングは本 composable の責務。`null` 明示で「絞らない」を表現（api-endpoints.md §4 の既定 null）。
- `p_shot_ranges` は jsonb（`[{min,max}]`、`max=null` 可）。`binsToRanges`（TASK-0006）の出力をそのまま渡せる。
- composable test の auto-import mock は `useMatches.test.ts` 参照。`immediate:false` を扱うため、mock 側で `refresh` を実 handler 呼び出しに接続する（または `useAsyncData` mock を `immediate` オプション対応に拡張）。
- RLS は RPC の `SECURITY INVOKER` で担保（REQ-403 / NFR-101）。他 Group は空配列（エラーにしない）。
