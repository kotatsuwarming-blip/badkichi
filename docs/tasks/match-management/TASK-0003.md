## タスク概要

所属 Group の未削除試合を `match_date` 降順 → `created_at` 降順で返す **Read composable**
`app/composables/useMatches.ts` を実装する。`usePlayers.ts` の `useAsyncData<T>('key', handler)`
固定キーパターンを踏襲し、`useAsyncData<MatchListItem[]>('matches', …)` 固定キー（ADR-007 D4）で
1 ナビゲーション 1 クエリを保証する。`useCurrentGroup` の `group_id` を読み、
`eq('group_id', gid).is('deleted_at', null)` でフィルタする。

本タスク固有の論点は **4 選手名の解決**。一覧では 4 選手名が必要で、削除済 player も名前表示を
維持する要件（EDGE-007）があるため、未削除のみを返す `usePlayers` では解決できない。よって
`useMatches` 内で **PostgREST resource embedding** により `players(name)` を結合して取得する。
ただし `matches → players` は **複合 FK `(group_id, player_id)`** のため、単一列ヒントの埋め込みが
解決できるかを **実装時に実地検証**する（本タスク唯一の残🟡。検証で🔵へ昇格）。

## 実装詳細

### 1. 【最初のステップ】複合 FK 埋め込みの実地検証 🟡→🔵
**信頼性**: 🟡 *architecture.md §選手名の解決（実装時に実地検証）→ 検証完了で🔵*

実装に入る前に、最小スクリプト or 一時クエリで以下を実地検証する（この小ステップを最初に行う）：

```
from('matches').select('id, ta1:players!team_a_player1_id(name)').eq('group_id', gid).limit(1)
```

- **解決できる場合**: 推奨の埋め込み select を採用する（下記 §2 の推奨クエリ）。
- **解決できない場合（複合 FK のため単一列ヒントで解けない）**: フォールバックを採用する。
  当該 Group の `players` を **`deleted_at` フィルタなし**で `(id, name)` だけ別取得し、
  クライアントで `id → name` マップを作って 4 選手 ID を名前解決する（削除済 player も
  名前維持＝EDGE-007 を満たす）。

**どちらを採用したかを本セクションに明記する**（採用クエリ / フォールバックの別、検証日、根拠）。

#### ✅ 実地検証結果（2026-06-05、🟡→🔵 昇格）

dev PostgREST に実クエリを投げて検証（publishable key、anon。埋め込み parse エラーは RLS 行フィルタ前に出るため anon でも判定可）：

| 検証 | クエリ | 結果 |
|---|---|---|
| 単一列ヒント | `players!team_a_player1_id(id,name)` | **400 PGRST200**「no matches found using the hint 'team_a_player1_id'」= 解決不可 |
| 制約名ヒント | `players!matches_group_id_team_a_player1_id_fkey(id,name)` | **200**（`[]`＝RLS フィルタ、embed parse 成功）= **解決可** |
| 4選手 full embed | 4 制約名ヒント同時 | **200** = 全て解決可 |

**採用 = 埋め込み方式（制約名ヒント）**。フォールバック不要。生成型 `supabase.ts` の matches Relationships に
4 複合 FK（制約名・`columns:[group_id, team_*_id]`・`referencedRelation:'players'`）が含まれ、
supabase-js は to-one 埋め込みとして単一オブジェクト推論する。**注意**: select 文字列は `+` 連結すると
型が `string` に広がり推論が `GenericStringError` になるため、**単一文字列リテラル**で渡すこと（実装で対応済）。

### 2. useMatches composable 🔵
**信頼性**: 🔵 *usePlayers.ts パターン / interfaces.ts UseMatchesReturn / REQ-001 / NFR-203*

`usePlayers.ts` と同型。固定キー `'matches'`、`group_id` 未取得ガード（空配列）、
`is('deleted_at', null)` で部分インデックス対象（NFR-001）、`order('match_date', {ascending:false})`
→ `order('created_at', {ascending:false})` で安定ソート（NFR-203 / EDGE-013）。取得行を
`MatchListItem[]` へマッピングする（snake_case 列 → camelCase ドメイン、埋め込み名 → teamA/teamB）。

**実装ファイル**: `app/composables/useMatches.ts`

```typescript
/**
 * 【機能概要】: 所属 Group の未削除試合を match_date 降順→created_at 降順で返す Read composable
 * 【実装方針】: useAsyncData<MatchListItem[]>('matches', handler) 固定キー (ADR-007 D4)。
 *             usePlayers.ts と同型。4 選手名は PostgREST 埋め込みで解決 (EDGE-007)。
 * 🔵 interfaces.ts UseMatchesReturn / REQ-001 / REQ-201 / NFR-001 / NFR-203
 */
import type { Database } from '~/types/supabase'
import type { MatchListItem, VideoSourceType } from '~/types/match'
import { useCurrentGroup } from '~/composables/useCurrentGroup'

export function useMatches() {
  const client = useSupabaseClient<Database>()
  const currentGroup = useCurrentGroup()

  return useAsyncData<MatchListItem[]>('matches', async () => {
    const gid = currentGroup.data.value?.group_id
    // 【未取得ガード】: group_id 未取得 (未所属/未認証) はクエリ未発行で空配列 (REQ-201) 🔵
    if (!gid) return []

    // 【推奨: 埋め込み select】複合 FK 検証 (§1) で解決可なら採用。
    //   解決不可ならフォールバック (players を deleted_at フィルタ無しで別取得し id→name マップ)。
    const { data, error } = await client
      .from('matches')
      .select(
        'id, name, match_date, created_at, video_source_type, video_source_url,'
        + ' ta1:players!team_a_player1_id(id, name),'
        + ' ta2:players!team_a_player2_id(id, name),'
        + ' tb1:players!team_b_player1_id(id, name),'
        + ' tb2:players!team_b_player2_id(id, name)'
      )
      .eq('group_id', gid)
      .is('deleted_at', null)
      .order('match_date', { ascending: false })
      .order('created_at', { ascending: false })

    if (error) throw error

    // 【マッピング】: snake_case 列 + 埋め込み → MatchListItem[] 🔵
    return (data ?? []).map((row): MatchListItem => ({
      id: row.id,
      name: row.name,
      matchDate: row.match_date,
      teamA: [{ id: row.ta1.id, name: row.ta1.name }, { id: row.ta2.id, name: row.ta2.name }],
      teamB: [{ id: row.tb1.id, name: row.tb1.name }, { id: row.tb2.id, name: row.tb2.name }],
      videoSourceType: row.video_source_type as VideoSourceType,
      videoSourceUrl: row.video_source_url
    }))
  })
}
```

> 注: 埋め込みの戻り形状（`ta1` が単一オブジェクトか配列か）は PostgREST のリレーション基数で
> 変わる。§1 の検証結果に合わせてマッピングを確定する。フォールバック採用時は select を
> `matches` 単体（4 player ID 列）+ `players` 別取得に置き換え、マップで名前解決する。
