## タスク概要

既存試合の **全項目（4 選手構成・動画ソース・試合名・試合日付）** を update する **Write composable**
`app/composables/useUpdateMatch.ts` を実装する（REQ-003）。`useUpdatePlayer.ts` の **pending を
try/finally で制御**するパターンを踏襲し、`updateMatch(id, input)` で
`from('matches').update({…}).eq('id', id).select().single()` を実行する。

戻りは `ActionResult<MatchListItem>`。`group_id` は update 引数に含めない（id 指定 + RLS
`matches_update = is_member_of(group_id)` で自 Group に限定）。入力検証（name 境界 / 4 選手相異 /
動画ソース）は編集フォーム側（Phase 2）+ TASK-0002 の Zod の責務で、本 composable は update 実行に専念する。
RLS / 通信 / 制約違反は `ActionResult.error` で返し、表示（toast）は page 側（ADR-007、EDGE-010）。

## 実装詳細

### 1. useUpdateMatch composable 🔵
**信頼性**: 🔵 *useUpdatePlayer.ts pending・try-finally / interfaces.ts UseUpdateMatchReturn / REQ-003 / matches_update RLS*

`useUpdatePlayer.ts` の Write パターン（pending → try → finally）を踏襲。`UpdateMatchInput`
（= `CreateMatchInput` と同形状、全項目）を `matches` の snake_case 列へマッピングし、
`eq('id', id)` で対象行に限定して update する。`.select(...).single()` で更新後行を取得する。

**実装ファイル**: `app/composables/useUpdateMatch.ts`

```typescript
/**
 * 【機能概要】: 既存試合の全項目を update する Write composable (REQ-003)
 * 【実装方針】: useUpdatePlayer.ts の pending/try-finally を踏襲。
 *             update({…}).eq('id', id).select().single() を実行する。
 * 🔵 interfaces.ts UseUpdateMatchReturn / REQ-003 / matches_update RLS
 */
import type { Database } from '~/types/supabase'
import type { UpdateMatchInput, MatchListItem } from '~/types/match'

interface ActionResult<T> { data: T | null; error: unknown }

interface UseUpdateMatchReturn {
  updateMatch: (id: MatchListItem['id'], input: UpdateMatchInput) => Promise<ActionResult<MatchListItem>>
  pending: Ref<boolean>
}

export function useUpdateMatch(): UseUpdateMatchReturn {
  const pending = ref(false)
  const client = useSupabaseClient<Database>()

  async function updateMatch(id: MatchListItem['id'], input: UpdateMatchInput): Promise<ActionResult<MatchListItem>> {
    pending.value = true
    try {
      // 【update 実行】: 全項目を eq('id', id) で対象行に限定。
      //   RLS matches_update = is_member_of(group_id) で自 Group のみ更新可。group_id は送らない 🔵
      const { data, error } = await client
        .from('matches')
        .update({
          name: input.name ?? null,
          match_date: input.matchDate,
          team_a_player1_id: input.teamAPlayer1Id,
          team_a_player2_id: input.teamAPlayer2Id,
          team_b_player1_id: input.teamBPlayer1Id,
          team_b_player2_id: input.teamBPlayer2Id,
          video_source_type: input.videoSourceType,
          video_source_url: input.videoSourceUrl
        })
        .eq('id', id)
        .select('id, name, match_date')
        .single()

      // 【エラー処理】: RLS 拒否 / 複合FK / distinct CHECK / 通信は ActionResult.error に詰める (EDGE-010) 🔵
      if (error) return { data: null, error }

      // 【成功戻り値】: 更新後行の最小射影を返す (選手名解決は page 側 refresh に委ねる) 🔵
      return {
        data: { id: data.id, name: data.name, matchDate: data.match_date } as unknown as MatchListItem,
        error: null
      }
    } finally {
      // 【pending リセット】: 成功・エラーを問わず必ず false に戻す 🔵
      pending.value = false
    }
  }

  return { updateMatch, pending }
}
```

> 注: TASK-0004 と同様、`ActionResult<MatchListItem>` の戻りで teamA/teamB 名前まで埋めるかは任意。
> 表示の正は `useMatches().refresh()` 後の一覧。最小射影方針は TASK-0004 と揃える。

## 単体テスト要件

> テスト方針: 最小境界 + 分岐網羅のみ。Supabase クライアントをモックし、update 引数（snake_case
> マッピング・group_id 非送信）と `eq('id', id)`、分岐（成功 / エラー）を検証する。

**テストファイル**: `tests/unit/composables/useUpdateMatch.test.ts`

### テストケース1: 全項目更新が反映（update 引数 + eq(id) 検証） 🔵
**信頼性**: 🔵 *REQ-003 / matches_update RLS*
**Given**: valid な `UpdateMatchInput`、update が更新後行を返す / **When**: `updateMatch('m1', input)` /
**Then**: `update` に全項目 snake_case が渡り（`group_id` を含まない）、`eq('id', 'm1')` が呼ばれ、`error` が null

### テストケース2: RLS / 通信エラーは ActionResult.error で返す 🔵
**信頼性**: 🔵 *REQ-401 / EDGE-010 / ActionResult 契約*
**Given**: update が `{ data: null, error }` を返す / **When**: `updateMatch('m1', input)` /
**Then**: `{ data: null, error }` を返し `pending` が finally で false に戻る

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'

const single = vi.fn()
const selectAfterEq = vi.fn(() => ({ single }))
const eq = vi.fn(() => ({ select: selectAfterEq }))
const update = vi.fn(() => ({ eq }))
const from = vi.fn(() => ({ update }))

vi.stubGlobal('useSupabaseClient', () => ({ from }))
vi.stubGlobal('ref', (v: unknown) => ({ value: v }))

const { useUpdateMatch } = await import('~/composables/useUpdateMatch')

const U = '11111111-1111-1111-1111-111111111111'
const input = {
  name: '横浜市大会', matchDate: '2026-06-06',
  teamAPlayer1Id: U, teamAPlayer2Id: U.replace(/1/g, '2'),
  teamBPlayer1Id: U.replace(/1/g, '3'), teamBPlayer2Id: U.replace(/1/g, '4'),
  videoSourceType: 'local' as const, videoSourceUrl: 'm1.mp4'
}

beforeEach(() => {
  update.mockClear(); eq.mockClear()
  single.mockResolvedValue({ data: { id: 'm1', name: '横浜市大会', match_date: '2026-06-06' }, error: null })
})

describe('useUpdateMatch', () => {
  it('TC1: 全項目を eq(id) で更新 (group_id 非送信)', async () => {
    const { updateMatch } = useUpdateMatch()
    const r = await updateMatch('m1', input)
    expect(update).toHaveBeenCalledWith(expect.objectContaining({
      name: '横浜市大会', match_date: '2026-06-06', video_source_type: 'local'
    }))
    expect(update.mock.calls[0]?.[0]).not.toHaveProperty('group_id')
    expect(eq).toHaveBeenCalledWith('id', 'm1')
    expect(r.error).toBeNull()
  })

  it('TC2: RLS/通信エラーは ActionResult.error で返し pending を戻す', async () => {
    const err = { message: 'rls_denied' }
    single.mockResolvedValue({ data: null, error: err })
    const { updateMatch, pending } = useUpdateMatch()
    const r = await updateMatch('m1', input)
    expect(r.data).toBeNull()
    expect(r.error).toBe(err)
    expect(pending.value).toBe(false)
  })
})
```

## 注意事項
- `pending` は **必ず try/finally** で false に戻す（useUpdatePlayer.ts 同方針）。
- 本 composable は **Zod 検証を行わない**。編集時の検証も Phase 2 フォーム + `matchFormSchema` の責務。
- `group_id` を update 引数に **含めない**（id 指定 + RLS で自 Group 限定。選手の所属 Group 変更は本単位スコープ外）。
- 全項目編集可（REQ-003）。4 選手・動画ソース・name・match_date のすべてを update 対象にする。
- エラーは `ActionResult.error` に詰めて返す。表示チャネル（toast、EDGE-010）の選択は page 側（ADR-007）。
- camelCase → snake_case のマッピング漏れに注意（TASK-0004 と同マッピング）。
