## タスク概要

Phase 2 の UI（TASK-0008 `MatchFormModal.vue` / TASK-0009 `matches.vue`）が使う **全 UI 文言**を
`i18n/locales/ja.json` / `en.json` に `matches` namespace として追加する。コードに文字列リテラルを
直書きせず、すべて `t('matches.…')` 経由にするための前提タスク（NFR-301 / REQ-404）。

追加対象は一覧見出し・空状態説明文・「試合を追加」CTA・フォームラベル（試合名 / 試合日付 /
team A・team B 選手枠 / 動画ソース種別 youtube・local / URL 入力 / ファイル選択 / 保存 /
キャンセル）・削除確認文言・選手 4 人未満の説明文/導線・各検証エラー文言。検証エラー文言は
`match-form.ts`（TASK-0004）の Zod `message` 値と整合する **既存 `errors` namespace 配下**に置く
（player-management の `errors.invalid_player_name` と同じ規約に合わせる）。

ja / en の **キー構造を完全一致**させる（CI のキー構造一致チェックの対象、NFR-301）。
新規 DB スキーマ・API・エラーコードは作らない。i18n の JSON 追加のみの DIRECT タスク。

### 3. errors namespace への配置判断 🔵
**信頼性**: 🔵 *既存 errors.invalid_player_name 規約 / TASK-0004 match-form.ts message*

`match-form.ts`（TASK-0004）の Zod は `message: 'invalid_match_name'` 等を返す。表示は
`useErrorMessage`（`errorToMessage`）→ `t('errors.<code>')` の既存変換経路を通る想定。
したがって検証エラーキーは `matches` 配下ではなく **既存 `errors` namespace** に置き、
player-management の検証エラー（`invalid_player_name`）と同階層に並べる（命名・配置を既存規約に
合わせ、変換ロジックを再利用する）。キー文字列は Zod `message` の値と完全一致させる。

## 注意事項
- ja / en は**追記のみ**。既存キーの編集・削除・並べ替えをしないこと（CI 差分とキー一致を壊さない）。
- 検証エラーキーは `matches` 配下ではなく **`errors` namespace** に置く（player-management の
  `invalid_player_name` と同階層）。`match-form.ts` の `message` 値と文字列を一致させること（TASK-0004 と整合）。
- `videoSourceOptions` のキーは `VideoSourceType` union（`'youtube' | 'local'`）と**完全一致**させる
  （TASK-0008 が union 値でキーを引くため、表記ゆれ厳禁）。
- 文言の日本語/英語そのものは仕様未確定の妥当推測（🟡）。レビューで文言調整があってもキー構造は変えない。
- JSON のため ESLint の no comma dangle はそのまま適用される。末尾カンマを付けないこと。
