## タスク概要

次のラリーのサーバー情報を返す関数 `computeNextServer` を実装する。`computeRallyStates` と類似のロジックだが、最後のラリーの「次」のサーバー情報を返す点が異なる。ラリー配列が空の場合はセット開始直後の初期サーバー情報を返す。

UI からリアルタイムに「次の得点を入力する前に誰がサーバーか」を表示するために使用される。

**配置先**: `app/utils/rule-engine/compute-next-server.ts`

## 実装詳細

### 関数シグネチャ

```typescript
import type {
  SetConfig,
  SetPlayerPosition,
  Rally,
  PositionOverride,
  NextServerInfo
} from './types'

/**
 * 次のラリーのサーバー情報を返す。
 *
 * ラリー配列が空の場合（セット開始直後）は初期位置に基づく最初のサーバーを返す。
 *
 * @param config - セットの設定
 * @param initialPositions - セット開始時の選手立ち位置
 * @param rallies - これまでのラリー結果の配列
 * @param overrides - PositionOverride の配列
 * @returns 次のラリーのサーバー情報
 */
export function computeNextServer(
  config: SetConfig,
  initialPositions: SetPlayerPosition[],
  rallies: Rally[],
  overrides: PositionOverride[]
): NextServerInfo
```

### ロジック

1. **ラリーが空の場合**:
   - サーブ権: `config.firstServingTeam`
   - スコア: `{ teamA: 0, teamB: 0 }`
   - サーバー位置: `resolveServerPosition(0)` → `'right'`
   - ポジション: 初期ポジションをそのまま使用
   - サーバー/レシーバー: 初期ポジションから特定

2. **ラリーがある場合**:
   - 全ラリーのスコアを累積計算
   - 最後のラリーに基づいてサーブ権チームを決定
   - サーブ権チームのスコアからサーバー位置を決定
   - 「次のラリー番号」でオーバーライドを適用
   - ポジションからサーバー/レシーバーを特定

## 注意事項

- rule-engine は Nuxt/Vue に依存しない純 TypeScript モジュールである（REQ-402）
- `computeRallyStates` と共通のロジックが多いが、目的が異なるため別関数として実装する
  - `computeRallyStates`: 過去の全ラリーの状態を返す
  - `computeNextServer`: 次のラリーのサーバー情報を返す
- セット遷移（前セット勝者が次セットのサーブ権を持つ）は `config.firstServingTeam` に前セット勝者を設定することで対応する（本関数内でセット遷移ロジックを持たない）
- 「次のラリー番号」は `rallies.length > 0 ? rallies[rallies.length - 1].rallyNumber + 1 : 1` で算出する
