## タスク概要

セット内の全ラリーの状態を計算するメイン関数 `computeRallyStates` を実装する。この関数は rule-engine の中核であり、内部ヘルパー関数（`resolveServingTeam`, `resolveServerPosition`, `applyOverrides`）および `computeScore` を統合して、各ラリーごとの完全な状態を算出する。

入力として `SetConfig`、初期ポジション、ラリー配列、オーバーライド配列を受け取り、各ラリーの `RallyState`（サーバー、レシーバー、スコア、ポジション等）を返す。

**配置先**: `app/utils/rule-engine/compute-rally-states.ts`

## 実装詳細

### 関数シグネチャ

```typescript
import type {
  SetConfig,
  SetPlayerPosition,
  Rally,
  PositionOverride,
  RallyState
} from './types'

/**
 * セット内の全ラリーの状態を計算する。
 *
 * @param config - セットの設定（目標ポイント、デュースルール、最初のサーブ権）
 * @param initialPositions - セット開始時の選手立ち位置（ダブルスなら4人分）
 * @param rallies - ラリー結果の配列（全ラリー確定済み）
 * @param overrides - PositionOverride の配列
 * @returns 各ラリーの計算結果（RallyState の配列）
 */
export function computeRallyStates(
  config: SetConfig,
  initialPositions: SetPlayerPosition[],
  rallies: Rally[],
  overrides: PositionOverride[]
): RallyState[]
```

### ロジック（ラリーごとの反復処理）

各ラリー `i` に対して以下を順に計算する:

1. **スコア累積**: `rallies[0..i]` までのラリーからスコアを計算（レットはスキップ）
2. **サーブ権決定**: `resolveServingTeam(config, rallies[0..i-1])` でサーブ権チームを決定
3. **サーバー位置決定**: `resolveServerPosition(servingTeamScore)` でサーバーのコート位置（左/右）を決定
4. **ポジションオーバーライド適用**: `applyOverrides(initialPositions, overrides, rally.rallyNumber)` で実際のポジションを算出
5. **サーバー・レシーバー特定**: ポジションとサーバー位置から、サーバーとレシーバーの選手IDを特定
6. **RallyState 構築**: 上記の情報を `RallyState` オブジェクトにまとめる

## 注意事項

- **最も複雑な関数**: rule-engine の中核であり、統合テストに十分な時間を確保すること
- rule-engine は Nuxt/Vue に依存しない純 TypeScript モジュールである（REQ-402）
- 各内部関数の単体テスト（TASK-0005〜0007）が通っていることを前提とする
- ラリーの順序は `rallyNumber` の昇順で処理する
- スコア計算はラリー「まで」の累積であり、「このラリーの得点を含む」点に注意（`scoreAfter`）
- サーブ権決定は「このラリーより前」のラリーに基づく点に注意
- 空の `rallies` 配列を渡した場合は空配列 `[]` を返す（NextServerInfo を返すのは `computeNextServer` の役割）
