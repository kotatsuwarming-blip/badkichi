## コート図（CourtDiagram）の仕様 🔵

**信頼性**: 🔵 *rule-engine GameState.positions + sets.camera_near_team_at_start + REQ-002*

- **向き**: `camera_near_team` のチームを**手前（下）**、相手を**奥（上）**に描画。MVP はセット開始時に1回確定（REQ-002）。`null` の場合は A を手前の既定とする。🟡
- **配置**: 各チームの half を左右に分割し、`GameState.positions.teamX.left / right` の選手チップを配置。
- **強調**: サーバー＝`◎`（塗り/色）、レシーバー＝枠線 + `→`。`GameState.server` / `receiver` を参照。
- **override 反映**: `applyOverride` 後の `positions` をそのまま描画するため、入替で左右チップが視覚的に入れ替わる（EDGE-008）。
- **左右ミラーの注意**（実装時）: 奥チームはカメラ視点で左右が手前と反転して見える。MVP の描画では「各チームの left/right を素直にラベル表示 + コート図で対応づけ」を基本とし、厳密なミラー補正は実装時に動画と突き合わせて調整（[[project_override_ux]] のプロトタイプと併せて検証）。🟡

## インタラクション / ショートカット 🔵

**信頼性**: 🔵 *ヒアリング2026-06-05 + NFR-201（キーボード操作）*

| 操作 | PC | スマホ | 挙動 |
|---|---|---|---|
| 打った | `Space` / ボタン | 大ボタン | shot を楽観追加 + 痕跡 + カウント +1。未ロードは無効（EDGE-001） |
| 取り消し（統一） | `Backspace` / `↩` | `↩` ボタン | **直近の記録操作を1つ戻す**（REQ-110）。文脈ラベルで対象を明示。戻せる操作が無ければ no-op |
| 得点A / 得点B | ボタン | ボタン | applyRally + 次サーバー表示。誤入力は取り消し→再入力で直す（REQ-110b） |
| レット / スキップ | ボタン | ボタン | REQ-102 / REQ-103 |
| A入替 / B入替 | ボタン | ボタン | applyOverride（一時停止して落ち着いて押す運用、[[project_override_ux]]） |
| 次のセットへ | ボタン（決着時のみ活性） | 同左 | REQ-107 |

- 細かいショートカット（J/K/L 等）は**作らない**（「Space だけで十分かも」を尊重しシンプルに）。🔵
- 「直前修正」は独立ボタンを廃し、統一「取り消し」+ 再入力で代替（REQ-106 の即時修正をこの仕組みで実現）。🔵
- 「打った」の即時フィードバック: 痕跡マーク追加 + カウント更新 + 一瞬のフラッシュ。楽観反映で <16ms（NFR-001）。🔵

## コンポーネント分割（`app/components/recording/`） 🔵

**信頼性**: 🔵 *architecture.md コンポーネント構成 + 上記レイアウト*

```
record.vue（page・CSR・orchestration）
├─ ScoreHeader.vue       スコア/セット番号/サーバー・レシーバー（テキスト）
├─ VideoPane.vue         useVideoPlayer + 痕跡オーバーレイ + 再生コントロール
├─ CourtDiagram.vue      GameState.positions をコート図で可視化
├─ ShotButton.vue        「打った」+ Space バインド + ショット数
```

- `VideoPane` のみ `useVideoPlayer` を直接持ち、`getCurrentTimeMs` を page 経由で session に注入。
- 文言は全て i18n（ja/en、REQ-405）。

## 新挙動: 統一「取り消し」（要件追加 REQ-110） 🔵

**信頼性**: 🔵 *ヒアリング2026-06-05（取り消しはショット取消と同じ仕組み・得点も取消→再入力）*

- `useRecordingSession` に **undo スタック**を持たせる。各記録操作（shot / point / let / skip / override）を push し、各ステップに**直前の `GameState` スナップショット**と DB 参照（行 id）を保持する。
- `undoLast()`（↩ / Backspace）は現在セット内でスタックを1つ pop し、逆操作を行う：
  - **shot**: 最後の shot 行を**物理削除**（`useDeleteShot`）+ メモリから除去。その削除でラリーが空（shot 0・point 未確定）になり遅延生成行なら rally も物理削除（`useDeleteRally`、REQ-110a）。
  - **point / let**: 当該ラリーを進行中に戻す（rally 行を `point_winner=null` / `is_point_confirmed=false` に **update**）+ engine を直前 GameState へ復元。ユーザーは正しい結果を入れ直す。
  - **override**: position_overrides 行を**物理削除**（`useDeleteOverride`）+ engine 状態を復元。
- **物理削除（hard delete）方針**（ユーザー2026-06-05）: undo は soft delete を使わず行を物理削除。分析 SQL で `deleted_at` フィルタ不要。→ data-foundation に DELETE RLS ポリシー追加の additive migration が1本必要（`rallies`/`shots`/`position_overrides`、REQ-406）。
- 楽観 insert がまだ未解決の行を取り消す場合、insert 解決（id 確定）を待ってから削除（delete が insert を追い越さない、REQ-110d）。
- engine は前方関数（applyRally/applyOverride）のみのため、巻き戻しは**保存済み GameState スナップショットの復元**で行う（REQ-106 の再計算機構を共用）。
- スコープは**現在セット内・linear（逆順）**。スタックが空のとき no-op。`shot_number` の再採番方針（歯抜け許容 or 詰め）は実装時に確定。🟡
- これにより「直前修正」専用 UI は不要。得点の誤入力は「取り消し → 再入力」で直す（REQ-110b、REQ-106 の即時修正を実現）。
