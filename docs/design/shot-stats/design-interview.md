# shot-stats 設計ヒアリング記録

**作成日**: 2026-08-03
**ヒアリング実施**: kairo-design step4（要件ヒアリングからの継続セッション）

## ヒアリング目的

要件定義（🔵 100%）を前提に、設計レベルで残っていた見せ方・実装方式の判断を確定する。あわせて既存実装調査（Explore エージェント）の結果として判明したスキーマ差分を報告・設計へ反映した。

## 質問と回答

### Q1: 設計の作業規模・既存実装分析の要否（2026-08-03）

**カテゴリ**: 進め方
**回答**: フル設計。既存実装分析は「必要」（stats 画面のタブ構造・既存 RPC の引数パターン・純関数シグネチャに合わせるため）。

**信頼性への影響**: 実装調査により architecture.md の大半（composable / RPC / チャート規約）を 🔵 で確定。

---

### Q2: 実装調査で判明したスキーマ差分の報告（2026-08-03）

**カテゴリ**: データモデル
**背景**: shot-annotation 実装中に注釈スキーマが進化しており、要件定義の参照（ADR-017 時点の 7 値 / 16 種）と実体がずれていた。

**報告内容（設計はこちらに準拠）**:
- `end_reason` は 6 値（`in`/`out` → `floor` 統合。in/out は `deriveInOut` で導出）
- `shot_type` は 17 値（`unknown` 追加）
- `shots` にソフトデリート（`deleted_at`）と `annotated_timestamp_precision` 追加
- 純関数の実シグネチャ: `decisiveShotIndex(shotCount, endReason, winnerHitLast)` / `deriveOutDirection(land)`

**信頼性への影響**: requirements.md の該当箇所（REQ-005/104 等）を実装準拠に更新。決着分類・決定打の SQL/クライアント導出規則を 🔵 で確定。

---

### Q3: D の「使用割合 × 得点率」の見せ方（2026-08-03）

**カテゴリ**: UI/技術選択
**回答**: **散布図**（x = 使用割合、y = その球種を打ったラリーの得点率、点 = 球種）。

**信頼性への影響**: `StatsShotMixScatter.vue` + ECharts ScatterChart 登録を 🔵 で確定。

---

### Q4: コート図（F ヒートマップ・A 落下点）の描画方式（2026-08-03）

**カテゴリ**: 技術選択
**回答**: **SVG 自作コンポーネント**（`StatsCourtZones.vue`。コートラインの上に 3×3 セルを重ね、A/F で共用）。

**信頼性への影響**: ECharts heatmap 依存を回避。コート図コンポーネント設計を 🔵 で確定。

---

### Q5: stats 画面のタブ構成（2026-08-03）

**カテゴリ**: アーキテクチャ
**背景**: 現状の stats 画面にはタブがない（単一グリッド）。要件は「既存画面に追加タブ + 2 タブ分割（NFR-203）」。
**回答**: **3 タブ構成**（概要 = 既存ダッシュボードをそのまま収容 / ショット分析 / ラリー展開）。グローバルフィルタと動画はタブ横断で共有。

**信頼性への影響**: ページ再編方針を 🔵 で確定。動画ペインの v-show 保持・タブ遅延ロードは設計判断として 🟡。

---

## ヒアリング結果サマリー

### 設計方針の決定事項
- 3 層構成（RPC 集計 → 統合 composable → SFC）と「選手・球種 = クライアント側フィルタ / セット・hand = RPC パラメータ」の grain 設計
- 新規 RPC 5 本（coverage / shot_types / shot_zones / rally_endings / rally_tempo）。J/L は既存 stats_rallies を再利用
- 決定打・in/out の SQL 導出は `derive.ts` と integration テストで突き合わせ（REQ-406）
- D 散布図 / SVG コート図 / 3 タブ構成（Q3〜Q5）

### 残課題（実装フェーズへ）
- ゾーンセルの色スケール・空状態文言（UI 微調整）
- 性能実測（Group 横断の grain 行数, architecture.md の唯一の 🟡）

### Q6: 設計判断 7 件（🟡）の確認（2026-08-04）

**カテゴリ**: アーキテクチャ/データモデル
**背景**: 設計初版の 🟡（動画ペイン v-show 保持 / タブ遅延ロード / フィルタ二段構え / 性能見積り / RPC 行への 4 選手 ID 同梱 / インデックス見送り / ZoneCell.ratio）を平易な説明つきで確認。3 と 5 は追加説明を実施（3 = フィルタごとに即時絞り込みと再問い合わせを使い分ける話、5 = matches の既存列を RPC の返り値にコピーするだけでスキーマ変更ではない、を確認）。

**回答**: 「どちらも OK」で 7 件全て了承。ただし **3 は「実際にどのようなアクセスが多いかで変えた方が良さそう」**との留保 → フィルタの即時側/再取得側の配分はアクセスパターンを見て見直してよい、として記録。性能見積り（4）のみ「実装時に実測で検証」の 🟡 注記を残す。

**信頼性への影響**: 設計 5 ファイルの 🟡 が 1 件（性能見積り）を除き全て 🔵 に。

### 信頼性レベル分布

**Q1〜Q5 後（設計 5 ファイル計）**: 🔵 約 91% / 🟡 約 9% / 🔴 0
**Q6 後・最終**: 🔵 99%（残 🟡 は性能見積り 1 件のみ・実装時実測） / 🔴 0
