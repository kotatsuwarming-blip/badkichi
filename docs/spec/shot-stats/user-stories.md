## エピック1: 決着と配球の分析（探針・注釈依存）

### ストーリー 1.1: どうやって点を取り、失っているかを知る（A: 決着分析） 🔵

**信頼性**: 🔵 *note.md §4-② + ヒアリング2026-08-03（A 採用）*

**私は** チームの分析担当（プレーヤー兼任） **として**
**試合の得点・失点が「エースで取った」のか「相手のミスで貰った」のか、「決められた」のか「自滅した」のかの内訳を見たい**
**そうすることで** 練習で直すべきなのが決定力なのかミスの多さなのかを判断できる

**関連要件**: REQ-005, REQ-006, REQ-007

**詳細シナリオ**:
1. 試合単位 stats 画面の「ショット分析」タブを開く
2. 選手/ペア別の得点・失点内訳（エース/相手ミス/自ミス/被エース）を見る
3. 決定打の球種ランキングで「何で決めているか」を確認する
4. 3×3 コート図で決着落下点の偏り（どこで決まっているか）を見る

**前提条件**:
- 対象試合にクイックパス注釈（end_reason・落下点）が付与されている
- 未注釈分は母数併記・注釈率バッジで明示される（REQ-002/003）

**優先度**: Must Have

### ストーリー 1.2: サーブ選択の成否を知る（C: サーブ種別分析） 🔵

**信頼性**: 🔵 *note.md §4-④ + ヒアリング2026-08-03（C 採用）*

**私は** サーブの組み立てを考えるプレーヤー **として**
**ショートサーブ・ロングサーブ・ドライブサーブそれぞれの得点率をサーバー別に見たい**
**そうすることで** 自分がどのサーブを使うべきか、相手や局面によって変えるべきかを判断できる

**関連要件**: REQ-008

**詳細シナリオ**:
1. 「ショット分析」タブのサーブ分析セクションを開く
2. サーバーを選び、サーブ 3 種の得点率（母数つき）を比較する
3. 右/左サービスポジションで絞り込み、ポジション別の傾向を見る

**優先度**: Must Have

---

### ストーリー 1.3: 配球の傾向とその成否を知る（D: 球種構成比・成果） 🔵

**信頼性**: 🔵 *note.md §4-③ + ヒアリング2026-08-03（D 採用）*

**私は** チームの分析担当 **として**
**各選手の球種構成比と、球種ごとのミス率・決定率（分母 = その球種の総打数）、使用割合と得点率の関係を見たい。対戦相手の選手を選べば相手の配球と弱点も同じチャートで見たい**
**そうすることで** 「スマッシュに頼りすぎ」「カットのミスが多い」「相手はヘアピンをミスしやすい」のような課題・付け入り所を特定できる

**関連要件**: REQ-009, REQ-010

**優先度**: Must Have

---

### ストーリー 1.4: どこから打っているかを知る（F: 配球ヒートマップ） 🔵

**信頼性**: 🔵 *note.md §4-① + ヒアリング2026-08-03（F 採用・3×3・選手視点固定）*

**私は** チームの分析担当 **として**
**選手・球種で絞り込んだ打点のヒートマップ（3×3 ゾーン）を選手視点で見たい**
**そうすることで** ポジショニングの偏りや、特定の球種をどこから打たされているかを把握できる

**関連要件**: REQ-011, REQ-105（選手視点ミラー）, REQ-004（フィルタ）

**前提条件**:
- 打点パス注釈の完了率に依存するため、母数併記が特に重要（NFR-201）

**優先度**: Must Have

---

### ストーリー 1.5: フォア/バックの偏りを知る（G: フォア/バック分析） 🔵

**信頼性**: 🔵 *ヒアリング2026-08-03（G 採用）*

**私は** プレーヤー **として**
**球種別のフォア/バック比率と、フォア/バック別のミス率を見たい**
**そうすることで** バック側の弱点（バックで打たされてミスが多い等）を数字で確認できる

**関連要件**: REQ-012, REQ-102（hand null は未判定扱い）

**前提条件**:
- hand トグル ON で注釈されたショットのみが母数（最も母数が小さい探針であることをバッジで明示）

**優先度**: Must Have

## エピック2: ラリー展開の分析（ライブ記録のみ・注釈不要）

### ストーリー 2.1: 局面ごとの強さを知る（J: 局面別得点率） 🔵

**信頼性**: 🔵 *ヒアリング2026-08-03（J 採用。クラッチ + 序盤/中盤/終盤の統合はユーザ合意）*

**私は** ペア編成を考えるチームの分析担当 **として**
**序盤/中盤/終盤の局面別得点率と、接戦局面（終盤の僅差）での得点率を選手/ペア別に見たい**
**そうすることで** 「立ち上がりが弱い」「終盤の接戦に強い」を根拠にペア編成や試合運びを決められる

**関連要件**: REQ-013, REQ-014

**詳細シナリオ**:
1. stats 画面（試合単位 / Group 横断）で局面別得点率チャートを開く
2. 選手/ペアを選び、序盤/中盤/終盤の得点率を比較する
3. 接戦局面の強調表示で「勝負どころの強さ」を確認する

**優先度**: Must Have

---

### ストーリー 2.2: 速い展開・遅い展開のどちらに強いかを知る（K: 展開スピード分析） 🔵

**信頼性**: 🔵 *ヒアリング2026-08-03（連続値・両 measure 切替はユーザ指定）*

**私は** 戦術を考えるプレーヤー **として**
**ラリーのテンポ（連続値）を得点ラリーと失点ラリーで分布比較したい。ラリー全体の平均テンポと、決まる直前の終盤テンポを切り替えて見たい**
**そうすることで** 「速い展開に持ち込むと勝てる」「終盤に展開が速くなると負けている」といった傾向を掴める

**関連要件**: REQ-015, REQ-016, REQ-106, REQ-107

**前提条件**:
- 押下時刻ベースの近似であることが UI に明示される（REQ-107）

**優先度**: Must Have

---

### ストーリー 2.3: セットの流れと連取・連失を振り返る（L: セット推移チャート） 🔵

**信頼性**: 🔵 *ヒアリング2026-08-03（L 採用。詳細仕様を説明の上で承認）*

**私は** 試合を振り返るプレーヤー **として**
**セットごとの得点差の推移（スコアワーム）と連取/連失区間のハイライトを見て、流れが切れたラリーをタップしてすぐ動画で見返したい**
**そうすることで** 「どこで・なぜ流れを失ったか」を映像とセットで特定できる

**関連要件**: REQ-017, REQ-018, REQ-019, REQ-203

**詳細シナリオ**:
1. 試合単位 stats 画面でセットタブを選ぶ
2. 得点差の階段折れ線で流れを見る（11 点インターバル目印・連取/連失の色帯つき）
3. 連失区間のラリーをタップ → その時点のスコアが表示され、動画が該当ラリーへジャンプ
4. 映像で原因（サーブレシーブの崩れ等）を確認し、探針（エピック1）の統計と突き合わせる

**優先度**: Must Have

## エピック3: 部分注釈でも誤読しない

### ストーリー 3.1: 注釈率を見て統計の信頼度を判断する 🔵

**信頼性**: 🔵 *note.md §3-6 + ヒアリング2026-08-03（バッジ + 母数併記）*

**私は** 統計を見るユーザー **として**
**試合・チャートごとの注釈率バッジと、全チャートの母数（注釈済み n / 全体 N）を見たい**
**そうすることで** 少ないサンプルの統計を過信せず、注釈を足すべき試合が分かる

**関連要件**: REQ-002, REQ-003, NFR-201, REQ-201, REQ-202

**優先度**: Must Have

## ストーリーマップ

```
エピック1: 決着と配球の分析（注釈依存・探針5枚）
├── 1.1 決着分析 A        (🔵 Must Have・クイックパスのみで成立=最速)
├── 1.2 サーブ種別 C      (🔵 Must Have・1打目注釈のみで成立)
├── 1.3 球種構成比・成果 D (🔵 Must Have・種別パス依存)
├── 1.4 配球ヒートマップ F (🔵 Must Have・打点パス依存=最重)
└── 1.5 フォア/バック G    (🔵 Must Have・handパス依存=母数最少)

エピック2: ラリー展開の分析（注釈不要・全既存試合に即適用）
├── 2.1 局面別得点率 J     (🔵 Must Have)
├── 2.2 展開スピード K     (🔵 Must Have)
└── 2.3 セット推移 L       (🔵 Must Have)

エピック3: 部分注釈でも誤読しない
└── 3.1 注釈率バッジ + 母数併記 (🔵 Must Have・全チャート横断)
```

※ 探針 5 枚は ADR-018 の「2〜3枚」を意図的に拡大し**同列（すべて Must Have）**とした（ヒアリング2026-08-03）。ただしデータが埋まる順序は注釈パスに依存するため、実装・リリース順は kairo-design / kairo-tasks で注釈パス依存の軽い順（A→C→D→F/G）を推奨する。🟡
