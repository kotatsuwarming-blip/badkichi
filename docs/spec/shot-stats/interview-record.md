# shot-stats ヒアリング記録

**作成日**: 2026-08-03
**ヒアリング実施**: 2026-07-26 〜 2026-08-03（モバイルで断続的に実施）
**前提資料**: [note.md](note.md)（探針候補・確定事項の引き継ぎノート）

## ヒアリング目的

note.md の論点リスト（§5）を出発点に、探針の選定・表示方針・集計規則の未決部分を確定する。途中でユーザ主導により「分析軸・measure の棚卸しと分類」へ進め方を転換し、注釈依存軸（群1）とライブ記録のみで作れる軸（群2）を分けて選定した。

**背景**: kairo-requirements step2 の必須確認。

**回答**: フル機能開発（5点セット完備）。

**信頼性への影響**: 出力構成が確定（requirements / interview-record / user-stories / acceptance-criteria / note）。

### Q2: 既存コードベースの詳細分析の要否（2026-07-26）

**カテゴリ**: 進め方
**背景**: note.md に集計規則・スキーマ・関連純関数が整理済みのため。

**信頼性への影響**: 以降のヒアリングを「軸の棚卸し → 分類 → 選定」の流れに変更。

### Q3: 探針の初回選定・表示場所・基本/詳細・ゾーン粒度(2026-07-26)

**カテゴリ**: 優先順位 / 既存設計確認
**背景**: note.md §5-1/2/3/6。

**回答**:
- 探針: ①〜④の全候補に関心。「一旦可能性のありそうなものを全て挙げて、見せ方を検討したい」→ 即決せず候補拡張へ
- 表示場所: **既存 stats 画面に追加タブ/セクション**（確定）
- 基本/詳細: **今は全部基本扱い**。課金グルーピングは ADR-019 検討時にまとめて（確定）
- ゾーン粒度: **3×3**（前/中/後 × 左/中/右。保存は座標のままなので後から変更可を前提に）（確定）

**信頼性への影響**: REQ-001 / REQ-301 / REQ-302・ゾーン 3×3 が 🔵 に。

### Q4: 分析軸・measure の棚卸し（2026-08-03）

**カテゴリ**: 未定義部分詳細化
**背景**: ユーザから軸の列挙が提示された（ショット種類 / サーブ・レシーブ位置 / ラリー本数 / ラリーの速さ / ラリー時間 / ラリー間時間 / クラッチ力 / 連続得失点 / 序盤・中盤・終盤 / 誰が打ったか / 打った位置・コース。measure は各軸の集計値と得点率）。

**回答（分類の合意）**: 「注釈が要るか」で 2 群に分類。
- **群1（注釈依存）**: ショット種類・打者・打点/コース（+ システム側で存在する決着様式・hand）
- **群2（ライブ記録のみ）**: サーブ・レシーブ位置（実装済み）・ラリー本数（実装済み）・ラリー時間・速さ・ラリー間時間・クラッチ力・連続得失点・序盤/中盤/終盤

**信頼性への影響**: スコープを「群1 = ADR-018 探針」「群2 = 注釈不要の追加統計」の 2 本立てに整理。

---

### Q5: 群2 の採否（2026-08-03）

**カテゴリ**: 追加要件
**背景**: 群2 は探針の目的（注釈統計の需要検証）とは別枠だが、ユーザは「ライブ記録だけで作れる軸も必要なものは追加していきたい」。

**回答**:
- **J（局面別得点率 = クラッチ力 + 序盤/中盤/終盤の統合）: 採用**
- **連続得失点**: サマリー数値だけでは「しょぼい」→ セット推移チャート（L）として格上げを提案 → 2 回の詳細説明を経て **L 採用**
- **K（展開スピード）**: 採用。ただし「3 段階に分けなくてよく**連続値**でいい。ラリー間で平均するのも良いし、**ラリーが終わる直前の展開の速さ**を見るのが良いかも」→ measure 2 種（平均テンポ / 終盤テンポ）を提案し「**両方（切替トグル）**」で確定
- **ラリー間時間**: 見送り（ノイズ大・解釈難）
- ラリー時間単独・サーブレシーブ位置: 既存機能と重複のため独立チャート化せず

**信頼性への影響**: REQ-013〜REQ-019 を新設（いずれも 🔵）。K の連続値・終盤テンポはユーザ発案。

---

### Q6: 群1 探針の最終選定（2026-08-03）

**カテゴリ**: 優先順位
**背景**: note.md §4 の 4 候補 + 拡張候補（G: F/B 分析、H: 3打目パターン）を見せ方つきで提示。

**回答**: **A（決着分析+落下点）/ C（サーブ種別）/ D（球種構成比・成果）/ F(配球ヒートマップ) / G（フォア/バック）の 5 枚**。H は見送り。

**信頼性への影響**: REQ-005〜REQ-012 が 🔵 に。ADR-018 の「2〜3枚」との矛盾が発生 → Q8 で解消。

### Q8: ADR-018「2〜3枚」との整合（2026-08-03）

**カテゴリ**: 既存設計確認
**背景**: 探針 5 枚は ADR-018 の枠を超える。段階分け（Must/Should/Could）案と枠拡大案を提示。

**回答**: **5 枚同列で枠を拡大**。逸脱を要件書・note に明記する。

**信頼性への影響**: 概要の逸脱明記が 🔵 に。優先度は全探針 Must Have。

### Q10: 🟡（推測項目）の解消ヒアリング（2026-08-03）

**カテゴリ**: 未定義部分詳細化
**背景**: 要件定義初版の 🟡 8 件（推測で置いた仕様）をユーザ確認で 🔵 化するための追加ヒアリング。J・D・K はチャート内容の再説明を挟んで確定した。

**回答**:
- **範囲外座標（EDGE-101）**: クランプ算入（最寄りの外周ゾーンに含める）で確定
- **決着分析の細部（REQ-108 / EDGE-105）**: 決定打未注釈は「未注釈」表示・内訳に算入 / service_fault はサーブミスとしてミス分類 / unknown は「不明」別掲、で確定
- **D の成果定義（REQ-010）**: 当初案（決定打率⇄ミス率の対比のみ）は「イマイチ」→ ユーザ指定で再定義: **ミス率・決定率は分母 = その球種の総打数**。加えて**使用割合 × 球種別得点率の関係**を対比表示。**相手選手のショットも同チャートで分析できる**こと（打者は任意の選手を選択可）
- **J の区分（REQ-014）**: 一度「前半/後半 2 分割」と回答 → チャート再説明の後に**3 分割（序盤 0〜7 / 中盤 8〜14 / 終盤 15〜、接戦 = 終盤かつ 2 点差以内・延長含む）**へ変更して確定
- **K の対象条件（REQ-106）**: 当初案「時刻ありショット 2 本以上」→ ユーザ指定で**「ラリー内の全ショットに打点時刻がある場合のみ対象」**に厳格化（部分欠損は得点率との関連表示のノイズになるため）。終盤テンポ = ラスト 3 打の 2 間隔の平均、時間 0 は除外、で確定
- **レイアウト（NFR-203）**: 「ショット分析（探針 5 枚）」と「ラリー展開（J/K/L）」の **2 タブ分割**で確定

**信頼性への影響**: 🟡 8 件が全て 🔵 に（requirements 52 項目が 🔵 100%）。REQ-010 と REQ-106 は内容自体もユーザ指定で更新。

## ヒアリング結果サマリー

### 確認できた事項

- チャート構成: 探針 5 枚（A/C/D/F/G）+ ライブ系 3 枚（J/K/L）の計 8 枚
- 表示: 既存 stats 画面への追加タブ/セクション、全部基本扱い、3×3 ゾーン、選手視点固定ミラー
- フィルタ: 打者・球種・セット・hand + 既存グローバルフィルタ
- 部分注釈: 注釈率バッジ + 全チャート母数併記

### 追加/変更要件

- **ADR-018 からの逸脱**: 探針を 2〜3 枚 → 5 枚同列に拡大（意図的・記録済み）
- **PRD §3.2 からの逸脱**: テンポ分析（将来フェーズ扱い）を押下時刻ベースの近似で先行実装（K）
- ユーザ発案の measure: 終盤テンポ（ラリーが終わる直前の展開の速さ）

### 残課題（kairo-design へ持ち越し）

- 要件レベルの未決事項はなし（🟡 は Q10 で全て解消）
- 設計判断のみ持ち越し: D の「使用割合 × 得点率」対比の見せ方（散布図 / 並列棒）、タブ内のセクション構成・遅延読み込み、「未注釈」「不明」の表示文言

### 信頼性レベル分布

**ヒアリング前**（note.md のみの時点）: 確定事項は集計規則のみで、チャート選定・表示・フィルタは全て未決（🔴 相当）。

**ヒアリング後・初版**（requirements.md 全 52 項目）:
- 🔵 青信号: 44 件（85%）/ 🟡 黄信号: 8 件（15%）/ 🔴 赤信号: 0 件

**Q10（🟡解消ヒアリング）後・最終**:
- 🔵 青信号: 52 件（100%）
- 🟡 黄信号: 0 件
- 🔴 赤信号: 0 件
