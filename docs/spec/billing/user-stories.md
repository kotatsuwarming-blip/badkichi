# billing ユーザストーリー

**作成日**: 2026-09-26
**関連**: [requirements.md](requirements.md) / [acceptance-criteria.md](acceptance-criteria.md)

## ストーリー1: 代表者としてチーム全員分をまとめて Pro にする

- **である** チームの代表者（owner） **として**
- **私は** 自分 1 人がカードで月額を払うだけでチーム全員を Pro にしたい
- **そうすることで** メンバー一人ひとりに登録や支払いを頼まずに、チーム全体で詳細分析と無制限の試合登録を使える

対応要件: REQ-001 / REQ-002 / REQ-004 / REQ-005 / REQ-012 / REQ-013 / REQ-016 / NFR-201

## ストーリー2: カード情報をアプリに預けずに決済する

- **である** 代表者 **として**
- **私は** 決済・解約・カード変更を Stripe の画面で済ませたい
- **そうすることで** 個人開発アプリにカード情報を入力する不安がなく、領収書や請求履歴も Stripe から確実に受け取れる

対応要件: REQ-012 / REQ-014 / REQ-407 / NFR-104 / NFR-201

## ストーリー3: 今どのプランで、いつまで使えるかを知る

- **である** チームメンバー（owner でない人も含む） **として**
- **私は** 設定画面で現在のプラン、Trial の残り日数、次回の更新日、解約予約の有無を見たい
- **そうすることで** 「あと何日で無料期間が終わるか」「誰に払ってもらうか」を把握してチームで相談できる

対応要件: REQ-008 / REQ-009 / REQ-010 / REQ-011 / REQ-102 / NFR-202

## ストーリー4: 無料のまま試してから決める

- **である** 新しくグループを作った人 **として**
- **私は** カード登録なしで 30 日間 Pro 相当の機能を試したい
- **そうすることで** 自分たちのチームに合うか確かめてから代表者に課金を相談できる

対応要件: REQ-006 / REQ-010 / REQ-101 / REQ-204 / EDGE-106 / EDGE-205

## ストーリー5: 解約しても期末までは使い切る

- **である** 代表者 **として**
- **私は** Customer Portal で解約予約し、支払い済みの期間の終わりまでは Pro のまま使いたい
- **そうすることで** 解約した瞬間に機能が消える不安なく、区切りの良いタイミングで無料プランに戻れる

対応要件: REQ-011 / REQ-109 / EDGE-103 / EDGE-104 / EDGE-204

## ストーリー6: 上限に達したら何をすればよいか分かる

- **である** Free プランのグループの記録係 **として**
- **私は** 試合を追加できなくなったとき、理由と次の一手（代表者にアップグレードを頼む）を画面で知りたい
- **そうすることで** 「保存できない」だけで止まらず、チームで課金の判断に進める

対応要件: REQ-022 / REQ-024 / REQ-113 / NFR-203 / EDGE-202

## ストーリー7: 課金を後から足しても既存データが壊れない

- **である** 既存ユーザー **として**
- **私は** 課金機能の追加でグループ・試合・統計の見え方や操作が変わらないでほしい
- **そうすることで** 機能追加を理由に使い続ける不安がなく、仲間内ローンチ中は制限なしのまま使える

対応要件: REQ-003 / REQ-112 / REQ-204 / REQ-401 / EDGE-201 / EDGE-204 / EDGE-301

## ストーリー8: 運営者として法的義務を満たしつつ運用を最小にする

- **である** アプリ運営者 **として**
- **私は** 特商法表記と利用規約の課金条項を揃え、督促・請求書・再試行を Stripe に任せたい
- **そうすることで** 個人開発の工数で法令要件を満たし、支払い失敗の個別対応をしなくて済む

対応要件: REQ-015 / REQ-020 / REQ-021 / REQ-110 / REQ-404 / REQ-405 / NFR-401 / NFR-402

## ストーリー9: 運営者としてチームと直接契約する

- **である** アプリ運営者 **として**
- **私は** 直接話をつけたチームを、金額をチームごとに決めた Team プランとして契約記録 1 行で登録したい
- **そうすることで** Stripe の手数料や機能差の管理を持ち込まず、契約条件を柔軟に決めながら UI からの自己契約（Pro）とは別の営業ルートを持てる

対応要件: REQ-026 / REQ-027 / REQ-029 / REQ-036 / REQ-037 / REQ-207 / REQ-209 / NFR-304 / NFR-403

## ストーリー10: 運営者として代行入力を手動で回す

- **である** アプリ運営者 **として**
- **私は** Team のグループに自分のダミーアカウントを招待してもらい、通常メンバーとして試合の記録・注釈を入力したい
- **そうすることで** 依頼フォームや枠管理をアプリに作らなくても、契約ごとに柔軟な条件で代行を提供できる

対応要件: REQ-121 / EDGE-405 / NFR-403

## ストーリー11: 開発者として検証環境でプランを自由に行き来する

- **である** 開発者 **として**
- **私は** dev 環境で自分のグループを free / trial / pro に即座に切り替え、課金せずに制限・ロック表示・残り試合数を確認したい
- **そうすることで** Stripe を通さずに UI と DB ガードの挙動を素早く検証でき、決済フロー自体は test mode で別途確認できる

対応要件: REQ-030 / REQ-031 / REQ-032 / REQ-033 / REQ-034 / REQ-035 / EDGE-501〜506

## ストーリー12: 開発者として新機能に課金ゲートを 1 行で足す

- **である** 開発者 **として**
- **私は** 新機能を作るとき `shared/entitlements.ts` に 1 行足して `can(feature)` を呼ぶだけで済ませたい
- **そうすることで** 機能ごとに課金判定を作り込まず、ADR-013 の「3 列メモ」を実装に直結できる

対応要件: REQ-007 / REQ-008 / REQ-410 / NFR-301 / NFR-302
