# serve-start-assist (ラリー確認) ユーザストーリー

**作成日**: 2026-11-01 / **改訂**: 2026-11-23
**関連**: [requirements.md](requirements.md) / [acceptance-criteria.md](acceptance-criteria.md)

## ストーリー1: 候補を確認するだけで記録を終える

- **である** 運営の記録係 **として**
- **私は** 動画を通しで見ずに、提示されるサーブ候補の画像を見て「サーブ」「違う」を押すだけで 1 ゲームの記録を終えたい
- **そうすることで** 1 ゲーム 15 分かかっていたライブ記録を 8 分以内に収め、月 8 時間の代行枠で入力できる試合数を増やせる

対応要件: REQ-001 / REQ-002 / REQ-004 / REQ-005 / NFR-002 / NFR-201

## ストーリー2: 得点者を入れずにスコアが進む

- **である** 記録係 **として**
- **私は** ラリーの終わりを見て得点者を判断する代わりに、次のサーブの画像で「どちらがサーブしているか」を確かめるだけにしたい
- **そうすることで** ラリーの間の時間 (動画の 8 割) を一切見なくてよくなり、判断の種類も 1 つに揃う

対応要件: REQ-003 / REQ-005 / REQ-006 / REQ-109 / REQ-110

## ストーリー3: 抜けたサーブに気づける

- **である** 記録係 **として**
- **私は** 検出が見逃したサーブ (1 ゲームに 3〜4 本) がどこにあるかを、システムに「この区間が怪しい」と教えてほしい
- **そうすることで** 自分で動画を探し回らずに、数十秒の区間だけを見て補える

対応要件: REQ-101 / REQ-102 / REQ-103 / REQ-104 / REQ-111 / NFR-202

## ストーリー4: 連続で抜けても最後に帳尻が合う

- **である** 記録係 **として**
- **私は** 2 本続けて抜けて予測に矛盾が出ないときでも、セットの最終得点を入れれば本数の差で抜けが分かるようにしたい
- **そうすることで** 記録の点数が実際の試合と食い違ったまま保存されることがなくなる

対応要件: REQ-009 / REQ-107 / REQ-111 / EDGE-101

## ストーリー5: 余分な候補を 1 回の操作で捨てる

- **である** 記録係 **として**
- **私は** サーブ前のシャトル渡しや素振りを拾った候補を、画像を見て 1 キーで捨てたい
- **そうすることで** 7 分あたり 6〜14 出る余分な候補に時間を取られない

対応要件: REQ-105 / EDGE-103 / EDGE-203

## ストーリー6: 既存の記録や統計を壊さない

- **である** 既存ユーザー **として**
- **私は** この記録モードで作った試合も、ライブ記録で作った試合と同じように注釈・統計に使えてほしい
- **そうすることで** 入力の方法によってデータの見え方が変わらない

対応要件: REQ-007 / REQ-401 / REQ-403 / REQ-205

## ストーリー8: 確認した結果がモデルを育てる (改訂 2026-11-23)

- **である** `~/dev/badkichi-ai` でサーブ検出とサーバー判定を学習する人 (または自動のループ) **として**
- **私は** 人が確認した候補 (正例)、却下した候補 (負例)、直したサーブ側・左右・時刻を、元の候補とモデルの版つきで書き出したい
- **そうすることで** 人が見ていない候補を正解にしてしまうことなく、次の版の精度を上げられる

対応要件: REQ-001 / REQ-011 (ai-draft-loop REQ-020)

## ストーリー7: 将来は顧客が自分で確認する

- **である** 顧客チームの担当者 **として**
- **私は** 運営が用意した候補を自分で確認して記録を作りたい
- **そうすることで** 運営の入力枠に依存せず、自分のチームの試合を増やせる (BL-044)

対応要件: REQ-404 / NFR-201 / NFR-202 (本単位では運営の利用を先行し、顧客利用は BL-044 で扱う)
