## エピック1: クイックパス（ラリー決着の注釈）

### ストーリー 1.1: 各ラリーの「決まり方」を素早く記録する 🔵

**信頼性**: 🔵 *ADR-017 §3 / §7 + ヒアリング2026-07-17（end_reason 再設計）*

**私は** 分析したいプレーヤー **として**
**記録済み試合の各ラリーについて、決着の種類（イン/アウト/ネット/越えず/身体/サーブフォルト）を短時間で入力したい**
**そうすることで** 得点パターン（どうやって取った/失った点か）の分析ができる

**関連要件**: REQ-004, REQ-005, REQ-006, REQ-102

**詳細シナリオ**:
1. スタジオでクイックパスを開始すると、ラリー1の最終ショット付近（±2秒）がループ再生される
2. end_reason を1タップで選ぶ。in / out なら続けてコート図（ライン外含む）で落下点をタップ
3. 決定打（勝者チームの最後のショット）の種別を1タップで選ぶ
4. 次のラリーへ自動遷移。1試合 10〜15 分で完走できる
5. 導出勝者が記録済み point_winner と矛盾したら警告が出る（保存は可能）

**前提条件**: 当該試合にラリーが記録済み
**優先度**: Must Have

### ストーリー 1.2: 際どい判定を「不明」で流す 🔵

**信頼性**: 🔵 *ADR-017 §7（unknown は正規の選択肢）*

**私は** 注釈する人 **として**
**動画から確信が持てないイン/アウトを無理に決めずに先へ進みたい**
**そうすることで** 迷いによる手が止まらず、ラベルの品質も濁らない

**関連要件**: REQ-004（unknown 選択）
**優先度**: Must Have

## エピック2: 種別パス（全ショットの球種）

### ストーリー 2.1: 流し見しながらキーボードで球種を打ち込む 🔵

**信頼性**: 🔵 *ADR-017 §4（順番マッチング）+ ヒアリング2026-07-13（1周同時入力は不可能→2周）*

**私は** 注釈する人 **として**
**動画を連続再生しながら、打球のたびにキー1つで球種を入力したい。押すタイミングが多少ズレても正しいショットに紐づいてほしい**
**そうすることで** 実プレー時間だけ（約15分/試合）で全ショットの球種が入る

**関連要件**: REQ-007, REQ-008, REQ-109

**詳細シナリオ**:
1. 種別パスを開始すると、ラリー間を自動スキップしながら再生される
2. ラリー内 k 回目のキー押下が k 番目のショットに対応づく（順番マッチング）
3. ラリー境界で自動一時停止。取りこぼしたらそのラリーだけやり直せる
4. 速い打ち合いは再生速度を落とせる（0.5〜1.5 倍可変）
5. 1打目は自動でサーブになり、S/L/D（ショート/ロング/ドライブ）だけ選ぶ

**優先度**: Must Have

---

### ストーリー 2.2: レシーブ局面で迷わない 🔵

**信頼性**: 🔵 *ヒアリング2026-07-13（レシーブ独立・ハイライトはするがキーは固定）*

**私は** 注釈する人 **として**
**スマッシュ等の直後はレシーブ3種（ロング/ドライブ/ショート）が視覚的に強調されてほしい。ただしキー割当は変わらないでほしい**
**そうすることで** 目線の誘導は受けつつ、筋肉記憶で打鍵し続けられる

**関連要件**: REQ-103
**優先度**: Should Have

---

### ストーリー 2.3: フォア/バックを追加コストなしで入れる 🔵

**信頼性**: 🔵 *ヒアリング2026-07-13（修飾キー方式）*

**私は** 深く分析したいプレーヤー **として**
**入れたいときだけ Shift+キー（モバイルは長押し）でバックハンドを記録したい**
**そうすることで** 必須タップを増やさずに利き手前後の分析を将来できる

**関連要件**: REQ-104
**優先度**: Should Have

## エピック3: 打点パス（どこから打ったか）

### ストーリー 3.1: 静止画の紙芝居で打点をタップしていく 🔵

**信頼性**: 🔵 *ADR-017 §4 + ヒアリング2026-07-14（タイムスタンプは押下遅延を含む）*

**私は** 注釈する人 **として**
**ショットごとに打球瞬間の静止画が出て、コート図をタップするだけで次に進んでほしい。押下遅延のズレは最初に一度合わせれば以降は自動補正されてほしい**
**そうすることで** 再生速度に追われることなく、1試合 20〜35 分で全打点が入る

**関連要件**: REQ-009, REQ-010, REQ-011, REQ-014

**詳細シナリオ**:
1. 打点パス開始時、冒頭数ショットでフレームを手動で合わせる → 平均遅延が以降に適用される
2. 各ショットで ±0.5 秒のサムネイル帯（5〜7枚）から正しいフレームを選び、コート図をタップ
3. 確定した打球時刻は annotated_timestamp_ms に保存される（元の押下時刻は保持 = 将来の AI 教師データ）
4. 打者が二択のショットだけ、タップ後に選手チップを1タップ

**前提条件**: ローカル動画（YouTube はストーリー 3.2 の劣化モード）
**優先度**: Must Have

---

### ストーリー 3.2: YouTube 動画でもループ方式で入力できる 🔵

**信頼性**: 🔵 *ADR-017 §4 動画ソース制約 + ヒアリング2026-07-19（YouTube のみで一回やる）*

**私は** YouTube 限定公開で動画を管理しているユーザー **として**
**サムネイル帯が使えなくても、該当区間のスローループ再生を止めて打点を入力したい**
**そうすることで** 動画をアップロードし直さずに注釈を完了できる

**関連要件**: REQ-101
**優先度**: Must Have（検証フェーズの代行は YouTube 前提のため）

## エピック4: 進捗とチーム分担

### ストーリー 4.1: どこまで注釈したか一目で分かり、途中から再開できる 🔵

**信頼性**: 🔵 *ADR-017 §3（進捗は null 有無から導出）*

**私は** 注釈する人 **として**
**モードごとの進捗（例: 種別 60%・打点 0%）と次の未注釈位置が見えて、そこから再開したい**
**そうすることで** 1試合を数回に分けて、あるいはセット単位でチームで分担して進められる

**関連要件**: REQ-003, REQ-013
**優先度**: Must Have

---

### ストーリー 4.2: 代行オペレーターとして他グループの試合を注釈する 🔵

**信頼性**: 🔵 *ADR-018 §2（テスター限定代行）*

**私は** 運営（代行オペレーター） **として**
**招待コードで参加したテスターのグループで、受領した YouTube 動画の試合を記録し、クイックパス＋1セットのフル注釈を効率よく行いたい**
**そうすることで** テスターに本人の試合のショットレベル統計を返せる（仮説Aの検証）

**関連要件**: REQ-101（YouTube モード）, REQ-013（1セットだけの部分注釈）
**備考**: 専用機能は不要（既存の招待コード + 本スタジオで成立）。スタジオの最初のヘビーユーザーは運営自身であり、ドッグフーディングが QA とラベル蓄積を兼ねる
**優先度**: Must Have
