## REQ-014: 座標変換 util（タップ → 正規化座標） 🔵

### Given / When / Then

- **Given**: コート図（ライン外領域込み）の描画サイズとタップ位置
- **When**: 正規化座標へ変換する
- **Then**: コート内は x, y ∈ [0,1]、ライン外は範囲外値（<0 / >1）で返る

### テストケース

- [ ] **TC-014-01**: コート中央のタップ → (0.5, 0.5) 🔵
- [ ] **TC-014-02**: チームA側バックバウンダリー左端 → (0, 0) / チームB側右端 → (1, 1) 🔵
- [ ] **TC-014-B01**: サイドライン外へのタップ → x < 0 または x > 1 の範囲外値で保存（clamp しない） 🔵
- [ ] **TC-014-B02**: 逆変換（正規化座標 → 描画座標）との往復で誤差が1px 未満 🔵 *REQ-014 確定（2026-07-19）に伴う許容誤差*

## REQ-005 / REQ-102 / EDGE-002: out 細分の導出と整合チェック 🔵

### 導出式（確定）

- `side` = x が [0,1] 範囲外 / `back` = y が [0,1] 範囲外 / `both` = 両方範囲外
- 導出勝者: `in` / `body` → 最終接触者のチーム、`out` / `net` / `not_over` → 最終接触者の相手チーム、`service_fault` → サーバーの相手チーム

### テストケース

- [ ] **TC-005-01**: 落下点 (1.1, 0.5) + end_reason=out → out_direction=side を導出 🔵
- [ ] **TC-005-02**: 落下点 (1.1, 1.2) → both（コーナー） 🔵
- [ ] **TC-005-03**: 落下点未入力で out → out_direction のサブ選択を提示、選択値を保存 🔵
- [ ] **TC-102-01**: end_reason=in・最終接触者=チームA・point_winner=B → 矛盾警告が発火（保存は拒否しない） 🔵
- [ ] **TC-102-02**: point_winner 未確定（is_point_confirmed=false）のラリー → 整合チェックはスキップ（EDGE-005） 🔵 *2026-07-19 確定*
- [ ] **TC-002-01**: end_reason=out なのに落下点がコート内 (0.4, 0.5) → ソフト警告（EDGE-002） 🔵 *2026-07-19 確定*

## REQ-007 / EDGE-003: 順番マッチング 🔵

### Given / When / Then

- **Given**: ラリー内のショット列（タイムスタンプ順）とキー入力列
- **When**: k 番目の入力を対応づける
- **Then**: タイミングに依らず k 番目のショットの shot_type が更新される

### テストケース

- [ ] **TC-007-01**: ショット5件に入力5件 → 順に1対1で対応 🔵
- [ ] **TC-007-02**: 入力がショット数を超過（6件目）→ 無視 + 警告状態を返す 🔵
- [ ] **TC-007-03**: ラリーやり直し → 当該ラリーの shot_type がクリアされ再入力可能 🔵
- [ ] **TC-109-01**: 1打目 → shot_type はサーブ系（serve_short / serve_long / serve_drive）以外を受け付けない 🔵
- [ ] **TC-104-01**: hand トグル ON のパス: Shift+キー → hand='backhand'、無印キー → **hand='forehand' が明示保存**される 🔵 *ヒアリング2026-07-24*
- [ ] **TC-104-02**: hand トグル OFF のパス: どのキーでも hand は null のまま（null = 未判定。「フォア」と解釈しない） 🔵 *同上*
