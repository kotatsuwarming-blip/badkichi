# video-upload ユーザストーリー (親への対応表)

**作成日**: 2026-11-24
**関連**: [requirements.md](requirements.md) / 親のストーリー [../video-upload-analysis/user-stories.md](../video-upload-analysis/user-stories.md)

ユーザーストーリーは「動画を上げる → 解析 → 確認」をまたぐので、親 video-upload-analysis に置く。本単位はそのうち次のストーリーを担う。

| 親のストーリー | 本単位が担う部分 | 対応要件 |
|---|---|---|
| 1. 動画を上げるだけで候補が届く | アップロード、メタデータ、校正、`ready` にして解析に渡す | REQ-001 / REQ-003 / REQ-004 / REQ-005 / REQ-007 |
| 2. 動画がどう扱われ、いつ消えるか分かる | 同意の 4 点、保持の理由の表示、削除の記録、利用者の削除要求 | REQ-002 / REQ-008 / REQ-010 / REQ-204 / REQ-401 / REQ-402 |
| 3. 手元に動画を置かなくてよい | 解析専用のアップロード (再生は YouTube) | REQ-001 / REQ-007 |
| 7. 複数試合が入った動画でも使える | 区間の指定を受け取る | REQ-006 |
| 9. 確認を直したら AI がやり直してくれる | 入力が完了するまで原本を保持する (`correction`) | REQ-008 / REQ-103 / REQ-104 / EDGE-101 / EDGE-102 |
| 10. 学習に使うかは自分で選ぶ | 学習同意の保存・取り消し、`learning` の保持 | REQ-009 / REQ-105 / REQ-108 |
| 11. 評価用の試合が勝手に消えない | `eval` の保持、自動削除の除外 | REQ-106 / EDGE-103 / EDGE-104 |
| 12. 保管の費用が見える | プロキシ化、Group ごとの使用量 | REQ-301 / REQ-302 / NFR-301 |
