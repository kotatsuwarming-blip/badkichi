## ヒアリング要旨（2026-09-26）

- プロフィール: 性別 / 身長 / 体重 / 生年月日（年齢自動）/ バドミントン歴（自動で上がる + 編集可）/
  練習頻度 / プレースタイル（キーワード複数選択）。用途は**分析軸と選手間比較**
- メンバー区分: 自チームと対戦相手が同列なのを分けたい。**分析は基本自チーム**
- PR は 1 つずつ分ける。量が多ければ tsumiki に則る

## ユーザ確認結果（2026-09-27）

1. 区分は**新規登録フォームで最初から選択**（既定 member）。既存行は member 初期化 — REQ-001/002
2. 練習頻度 5 段階で確定 — REQ-101
3. プレースタイルは**パワー型を足して 9 種**・複数選択可 — REQ-102

## 設計メモ（kairo-design に向けて）

- 歴の「自動で上がる + 編集可能」は **badminton_since（開始時期）を保存**して表示時導出で両立。
  年齢も birthdate から導出（年齢・歴の直接保存は禁止 — 陳腐化する）
- 統計軸への組み込み（性別別/年代別比較・ミックスの sex 活用等）は**本件のスコープ外**（REQ-402）。
  プロフィールが溜まってから別要件で。SV のゾーン×選手成績や「上げさせる戦術」分析（shot-value
  interview Q5）は sex 列が入ると精度が上がる — 将来の接続先としてメモ
- roster_type は matches の選手 FK に影響しない（表示・並び順のみ）ので PR ① は小さい
- 対戦相手を統計から隠さない理由: shot-stats REQ-009「相手選手も選択可能」が既決
- 実装接点: `app/components/players/`（フォーム・一覧）, `StatsGlobalFilterBar`（選手選択）,
  `supabase/migrations/`（additive 列追加）, i18n ja/en
