## エピック1: 試合単位の戦術分析

### ストーリー 1.1: サービス/レシーブ得点率を見る 🔵

**信頼性**: 🔵 *PRD §F-04 最重要 + US-02 + ヒアリング2026-06-06*

**私は** バドミントンプレーヤー **として**
**1 試合のデータから、サービス時 vs レシーブ時の得点率を選手別に確認したい**
**そうすることで** ペアの組み合わせや戦術の改善に活かせる

**関連要件**: REQ-001, REQ-003, REQ-101

**詳細シナリオ**:
1. record 画面の `[統計を見る →]`、または試合一覧から試合単位ダッシュボードを開く
2. 選手別のサービス時得点率 / レシーブ時得点率がチャートで表示される
3. レット・未確定ラリーは集計から除外され、母数（対象ラリー数）が併記される

**前提条件**:
- 当該試合に確定済みラリーが 1 件以上記録されている

**制約事項**:
- 自 Group の試合のみ（RLS）

**優先度**: Must Have

---

### ストーリー 1.2: チーム → 選手へドリルダウンする 🔵

**信頼性**: 🔵 *ヒアリング2026-06-06（どちらもドリルダウンできるイメージ）*

**私は** 分析担当 **として**
**まずチーム視点の得点率を俯瞰し、気になったら選手視点へ掘り下げたい**
**そうすることで** チーム全体の傾向と個人の貢献の両方を把握できる

**関連要件**: REQ-004

**詳細シナリオ**:
1. チーム視点（A/B）の得点率サマリを見る
2. チームを選択すると、その構成選手の得点率へドリルダウンする

**優先度**: Must Have

---

### ストーリー 1.3: ラリー長と得点率の関係を見る 🔵

**信頼性**: 🔵 *PRD §F-04 次に重要 + US-06*

**私は** チームの分析担当 **として**
**ラリーのショット数（ラリー長）と得点率の関係を確認したい**
**そうすることで** ラリーが長引く場合の傾向を把握できる

**関連要件**: REQ-005, REQ-101

**詳細シナリオ**:
1. ラリー長（shot 本数）を軸に得点率の関係チャートが表示される
2. ショット数 0 のラリーの扱いは明示される（ラリー長 0 区分）

**優先度**: Should Have（PRD 優先度「高」）

---

### ストーリー 1.4: ラリー一覧から動画にジャンプする 🔵

**信頼性**: 🔵 *PRD US-04 + ヒアリング2026-06-06（プレーヤー埋め込み）*

**私は** データ入力者 **として**
**ラリー一覧から該当ラリーの動画再生位置にワンクリックでジャンプしたい**
**そうすることで** 特定のラリーを素早く確認できる

**関連要件**: REQ-006, REQ-007, REQ-102, EDGE-103

**詳細シナリオ**:
1. stats 画面に埋め込まれた動画プレーヤーとラリー一覧テーブルが並ぶ
2. ラリー行をクリックすると、プレーヤーが当該 `video_start_timestamp_ms` へシークし再生する
3. `local` 動画で URL 喪失時は再選択を促す。`video_start_timestamp_ms` が NULL のラリーは非リンク

**前提条件**:
- ラリーに `video_start_timestamp_ms` が記録されている（ジャンプ可能行）

**優先度**: Must Have

## エピック2: Group 横断の選手分析

### ストーリー 2.1: 複数試合を跨いだ選手別累計を見る 🔵

**信頼性**: 🔵 *ヒアリング2026-06-06（選手横断累計を含む）+ PRD US-02（ペア編成最適化）*

**私は** ペア編成を考える人 **として**
**Group の全試合を跨いだ選手別のサービス/レシーブ得点率の累計を見たい**
**そうすることで** 単発の試合ではなく傾向としてペア編成を最適化できる

**関連要件**: REQ-002, REQ-003, REQ-004, REQ-101

**詳細シナリオ**:
1. `/groups/[id]/stats` で Group 横断ダッシュボードを開く
2. 選手別の累計得点率（複数試合合算）がチャートで表示される
3. 個別ラリーを深掘りしたい場合は、該当試合の試合単位ダッシュボードへ遷移する

**制約事項**:
- 横断ビューは動画が試合ごとに異なるため、ラリージャンプは試合単位ダッシュボード経由（REQ-104）

**優先度**: Should Have
