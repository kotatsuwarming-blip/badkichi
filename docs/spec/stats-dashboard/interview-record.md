# stats-dashboard ヒアリング記録

**作成日**: 2026-06-06
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

PRD §F-04（統計ダッシュボード）・確定済み DB スキーマ・上流単位（match-recording / video-playback / rule-engine）の責務境界・ADR-013（収益化）を確認したうえで、stats-dashboard の集計スコープ・可視化方式・指標定義の曖昧点を明確化するためのヒアリングを実施した。

## 質問と回答

### Q1: 集計スコープを MVP でどこまで含めるか

**質問日時**: 2026-06-06
**カテゴリ**: スコープ調整
**背景**: PRD のルートは `/matches/:id/stats`（試合単位）だが、US-02「ペア編成最適化」は複数試合を跨ぐ選手別集計を示唆しており、MVP に含めるか曖昧だった。

**回答**: **試合単位＋選手横断累計**（両方を MVP に含む）

**信頼性への影響**:
- REQ-001（試合単位）に加え REQ-002（Group 横断ダッシュボード）を 🔵 で追加
- 横断集計に伴うジャンプ方式の整理として REQ-104 を追加

---

### Q2: ラリー一覧からの「動画ジャンプ」の実現方式

**質問日時**: 2026-06-06
**カテゴリ**: 未定義部分の詳細化
**背景**: PRD §5.4 では stats 画面とデータ入力画面が別画面。ジャンプを stats 画面内で完結させるか、record 画面へ遷移させるか未定義だった。

**回答**: **stats 画面にプレーヤー埋め込み**（その場でシーク再生）

**信頼性への影響**:
- REQ-007 を 🔵 で確定（stats 画面に video-playback プレーヤーを埋め込み）
- 横断ダッシュボードは動画が試合ごとに異なるため、ジャンプは該当試合の stats 画面へ遷移する設計（REQ-104 🟡）として切り分け

---

### Q3: 選手別「サービス時・レシーブ時得点率」の定義

**質問日時**: 2026-06-06
**カテゴリ**: 未定義部分の詳細化
**背景**: 得点率の母数・分子の定義（個人視点 / チーム視点）と、レット・未確定ラリーの扱いを確定する必要があった。

**回答**: **「どちらもドリルダウンできるようなイメージ」** — チーム視点と選手視点の両方を提供し、ドリルダウンできること。レット・未確定ラリーは除外する方針は承認。

**信頼性への影響**:
- 得点率の算出式（サーブ側/レシーブ側勝率）を採用し、REQ-003 で選手別、REQ-004 でチーム ⇄ 選手ドリルダウンを 🔵 で確定
- REQ-101（レット・未確定の除外）を 🔵 で確定

---

### Q4: ADR-013 の「基本 / 詳細ダッシュボード」の線引き

**質問日時**: 2026-06-06
**カテゴリ**: 既存設計確認（収益化との接点）
**背景**: ADR-013 はダッシュボードを基本（Free）/ 詳細（Pro/Trial）でグルーピングする仕込みを推奨。MVP でどこまで意識するか確認が必要だった。

**回答**: **全て基本扱い**（MVP は全機能を基本扱い。詳細/有料の線引きは実装時まで保留）

**信頼性への影響**:
- 課金ゲートを要件から外し、REQ-301 を「将来グルーピング可能な構造としてよい（MVP はゲートなし・全機能基本扱い）」のオプション要件に格下げ（🔵）

---

## ヒアリング結果サマリー

### 確認できた事項
- 集計スコープ = 試合単位 + Group 横断（選手別累計）の両方
- ラリージャンプ = stats 画面への動画プレーヤー埋め込みで実現
- 得点率 = サーブ/レシーブ側勝率を、チーム ⇄ 選手のドリルダウンで提供。レット・未確定は除外
- MVP は課金ゲートなし・全機能基本扱い（ADR-013 のグルーピングは構造の仕込みのみ）

### Claude 主導で確定した事項（明確なため非ヒアリング）
- ルート規約 `/groups/[id]/matches/[matchId]/stats` ＋ `/groups/[id]/stats`（既存単位と一貫）🔵
- 読み取り専用・スキーマ変更なし（責務境界）🔵
- CSR 限定（ADR-010）🔵
- チャートは vue-echarts（PRD §6 指定）🔵
- 集計ロジックは composable/util に分離し単体テスト可能に（ADR-007/012）🔵

### 残課題（kairo-design で判断）
- 集計の実装場所：クライアント TS 算出 vs 読み取り専用 Supabase RPC / View（NFR-002 🟡）
- ショット数 0 ラリー（EDGE-102）の扱い：ラリー長 0 として含めるか明示区分するか
- composable 分割粒度（試合集計 / 横断集計 / ラリー一覧 / チャート整形）
