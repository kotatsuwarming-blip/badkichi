## エピック 1: 認証フロー

### ストーリー 1.1: Google ログイン (新規ユーザ) 🔵

**信頼性**: 🔵 *PRD §3 + ADR-004 + data-foundation/architecture.md §Auth フロー*

**私は** badkichi の新規ユーザ **として**
**Google アカウントでログインしたい**
**そうすることで** 別途パスワードを覚えずに badkichi を使い始められる

**関連要件**: REQ-001, REQ-002, REQ-101, REQ-104, REQ-203

**詳細シナリオ**:
1. 招待リンクなしで `https://badkichi.example.com/` にアクセス
2. 未認証 middleware により `/login` にリダイレクト
3. 「Google でログイン」ボタンを押す
4. Google OAuth 承認画面で承認
5. `/confirm` でセッション確立 (この間 `<USkeleton>` 表示)
6. Group 未所属判定 → `/onboarding` に遷移

**前提条件**:
- Supabase Auth で Google プロバイダが有効化済 (data-foundation TASK-0001)
- ユーザが Google アカウントを保有

**制約事項**:
- Email/Password 認証は使えない (REQ-402)

**優先度**: Must Have

### ストーリー 1.2: Google ログイン (既存ユーザ、Group 所属済) 🔵

**信頼性**: 🔵 *REQ-001, REQ-002, REQ-103*

**私は** badkichi の既存ユーザ **として**
**再度 Google アカウントでログインしたい**
**そうすることで** 前回中断した試合分析を続けられる

**関連要件**: REQ-001, REQ-002, REQ-103, REQ-104

**詳細シナリオ**:
1. `/login` にアクセス (例: ブックマークから直接)
2. 「Google でログイン」ボタンを押す
3. Google OAuth 承認画面 (既に承認済なら省略表示)
4. `/confirm` でセッション確立
5. Group 所属判定 → `/` (トップ) に遷移
   - URL に `redirect` クエリパラメータがあれば優先

**前提条件**:
- ユーザが過去にログインし Group 所属済

**優先度**: Should Have

### ストーリー 1.3: ログアウト 🟡

**信頼性**: 🟡 *PRD 暗黙要件 (認証あればログアウト必要)*

**私は** ログイン済みユーザ **として**
**ログアウトしたい**
**そうすることで** 共用 PC で他人にデータを見られないようにできる

**関連要件**: REQ-008

**詳細シナリオ**:
1. ヘッダーまたはメニューのユーザアバターをクリック
2. 「ログアウト」を選択
3. `supabase.auth.signOut()` 実行
4. `/login` に遷移

**前提条件**:
- ログイン済

**優先度**: Must Have

## エピック 2: オンボーディング

### ストーリー 2.1: 初回ログイン後の Group 作成 🔵

**信頼性**: 🔵 *PRD §1 + note.md F-AO-03 + data-foundation/api-endpoints.md §create_group_with_owner*

**私は** Group をまだ持たない新規ユーザ **として**
**自分の所属するバドミントンクラブの Group を作成したい**
**そうすることで** クラブのメンバーを招待して試合分析を共有できる

**関連要件**: REQ-003, REQ-004, REQ-102, REQ-109, REQ-401

**詳細シナリオ**:
1. 初回ログイン後 `/onboarding` に到達
2. 「Group を作る」を選択 → `/groups/new` へ
3. Group 名 (例: 「○○バドミントンクラブ」) を入力
4. 「作成」ボタンを押す
5. `create_group_with_owner` RPC が呼ばれ、groups + group_members に同時 INSERT
6. 成功で `/` (トップ) に遷移

**前提条件**:
- ログイン済
- Group 未所属

**制約事項**:
- Group 名は 1〜50 文字 (trim 後)、空白のみ不可
- 1 ユーザー 1 Group のみ (REQ-401)

**優先度**: Must Have

---

### ストーリー 2.2: 招待リンク URL からのログイン → Group 参加 🔵

**信頼性**: 🔵 *note.md F-AO-04 + EDGE-001 + ヒアリング A2*

**私は** クラブ仲間から招待 URL を LINE で受け取った新規ユーザ **として**
**その URL をタップするだけでログインから Group 参加まで完了したい**
**そうすることで** 招待コードをコピペする手間なく仲間入りできる

**関連要件**: REQ-005, REQ-101, REQ-104, REQ-108

**詳細シナリオ**:
1. LINE で受け取った `/join/abc123` URL をタップ
2. 未ログインのため `/login?redirect=/join/abc123` にリダイレクト
3. 「Google でログイン」ボタンを押す
4. Google OAuth 承認 → `/confirm?redirect=/join/abc123` に戻る
5. セッション確立後 `/join/abc123` に遷移
6. `join_group_with_code` RPC が呼ばれ Group 参加
7. `/` (トップ) に遷移

**前提条件**:
- 招待リンクが有効期限内
- ユーザが未ログイン or ログイン済 Group 未所属

**優先度**: Must Have

---

### ストーリー 2.3: ログイン済 + Group 未所属からの招待リンク参加 🔵

**信頼性**: 🔵 *REQ-005 + REQ-102*

**私は** すでにログイン済だが Group 未所属のユーザ **として**
**招待リンクをタップして Group に参加したい**
**そうすることで** スムーズに分析機能を使い始められる

**関連要件**: REQ-005, REQ-102

**詳細シナリオ**:
1. `/onboarding` で「招待リンクから参加」を選択
2. クラブから受け取った URL `/join/abc123` を開く (LINE 経由 or 直接入力)
3. `join_group_with_code` RPC で参加
4. `/` (トップ) に遷移

**前提条件**:
- ログイン済
- Group 未所属
- 招待リンク有効期限内

**優先度**: Must Have

---

### ストーリー 2.4: 招待リンクで参加失敗 (期限切れ) 🔵

**信頼性**: 🔵 *REQ-106 + cross-cutting/error-handling.md §6.3 #3*

**私は** クラブ仲間から 1 ヶ月前に受け取った招待リンクを今日初めて開いたユーザ **として**
**「期限切れ」と分かりやすく表示してほしい**
**そうすることで** 仲間に再発行を依頼すべきと判断できる

**関連要件**: REQ-106

**詳細シナリオ**:
1. `/join/old123` を開く (ログイン済 + Group 未所属)
2. `join_group_with_code` RPC が `invitation_expired` 例外
3. `/join/old123` ページ内 `<UAlert>` で「招待コードの有効期限が切れています」表示
4. ユーザはクラブ仲間に再発行を依頼

**前提条件**:
- 招待リンクの `expires_at < now()`

**優先度**: Should Have

---

### ストーリー 2.5: 招待リンクで参加失敗 (既に他 Group 所属) 🔵

**信頼性**: 🔵 *REQ-105 + REQ-401 + ヒアリング Q2*

**私は** すでに別の Group に所属しているユーザ **として**
**間違って別の Group の招待リンクを開いた場合、現状の所属を保ったまま分かりやすくエラー表示してほしい**

**関連要件**: REQ-105, REQ-401

**詳細シナリオ**:
1. `/join/other-group-code` を開く (ログイン済 + 既に Group X 所属)
2. `join_group_with_code` RPC が `already_in_group` 例外
3. `<UAlert>` で「すでに別の Group に所属しています。MVP では 1 ユーザー = 1 Group のみ対応です」表示
4. 「Group X に戻る」ボタンで `/` に遷移

**前提条件**:
- ログイン済
- 別 Group に所属済

**制約事項**:
- MVP では退会機能がないため、別 Group に移籍することはできない (REQ-404)

**優先度**: Should Have

## エピック 3: Group 管理

### ストーリー 3.1: 招待リンク発行 🔵

**信頼性**: 🔵 *note.md F-AO-05 + data-foundation/api-endpoints.md §generate_invitation_code*

**私は** Group のメンバー (誰でも) **として**
**新規メンバーを招待するための URL を発行したい**
**そうすることで** クラブ LINE に URL を貼って一括で招待できる

**関連要件**: REQ-006, REQ-007, REQ-110, REQ-405, REQ-408

**詳細シナリオ**:
1. `/groups/[id]/settings` を開く
2. 「招待リンクを発行」ボタンを押す
3. `generate_invitation_code` RPC で 8 文字 hex コード生成
4. `${origin}/join/{code}` URL が画面に表示される
5. 「コピー」ボタンでクリップボードコピー
6. `<UToast>` で「コピーしました」表示
7. クラブ LINE に URL を貼り付け共有

**前提条件**:
- ログイン済 + Group メンバー

**制約事項**:
- 招待リンクは 7 日有効 (REQ-405)
- 何人でも同じリンクで参加可能 (multi-use)
- MVP では無効化ボタンなし (REQ-404)

**優先度**: Must Have

---

### ストーリー 3.2: 招待リンク URL をクリップボードコピー 🔵

**信頼性**: 🔵 *REQ-007 + NFR-203*

**私は** Group メンバー **として**
**発行済の招待リンクをワンクリックで LINE に貼り付けられる状態にしたい**

**関連要件**: REQ-007, NFR-203

**詳細シナリオ**:
1. Group 設定画面の招待リンク一覧から該当の URL の横の「コピー」ボタンを押す
2. `navigator.clipboard.writeText()` でコピー
3. `<UToast>` で「コピーしました」を 2 秒表示

**前提条件**:
- 招待リンク発行済
- ブラウザが Clipboard API 対応 (HTTPS 必須)

**優先度**: Must Have

---

### ストーリー 3.3: Group メンバー一覧閲覧 🔵

**信頼性**: 🔵 *REQ-006 + PRD §3.2 (メンバーフラット権限)*

**私は** Group メンバー **として**
**現在 Group に誰が参加しているか確認したい**

**関連要件**: REQ-006

**詳細シナリオ**:
1. `/groups/[id]/settings` を開く
2. 「メンバー」セクションに各メンバーの Google アカウント表示名 + avatar が一覧表示される

**前提条件**:
- ログイン済 + Group メンバー

**優先度**: Should Have
