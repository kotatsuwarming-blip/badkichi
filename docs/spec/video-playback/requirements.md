# video-playback 要件定義書

## 概要

video-playback は、**YouTube 動画（YouTube IFrame Player API）とローカル動画ファイル（HTML5 Video API）を、ソース種別に依らない統一インターフェースで再生・制御する動画プレーヤー抽象ユニット**である。

ADR-002 の分割方針により、F-02（動画再生 + データ入力）から「動画再生」基盤を切り出した独立ユニットであり、依存は持たない（DB・認証・他ユニットに非依存）。録画画面（match-recording）と統計画面（stats-dashboard）の両方から再利用される。本ユニット自身は DB を一切触らず、ブラウザの動画 API を「黒箱」として抽象化し、上位ユニットへ再生制御・現在時刻取得・指定位置ジャンプの手段を提供することに責務を限定する。

データエンジニア的アナロジー: データソース抽象化レイヤー（S3 でも GCS でも同一インターフェースで読む）と同じ発想。再生ソースが YouTube でもローカルでも、上位は同一インターフェースで「現在時刻を取る」「指定位置へ飛ぶ」を呼べる。

## 機能要件（EARS記法）

**【信頼性レベル凡例】**:
- 🔵 **青信号**: PRD・設計文書・ADR・ユーザヒアリングを参考にした確実な要件
- 🟡 **黄信号**: PRD・設計文書・ADR・ユーザヒアリングから妥当な推測による要件
- 🔴 **赤信号**: 上記資料にない推測による要件

### 通常要件

- REQ-001: システムは YouTube 動画（YouTube IFrame Player API）とローカル動画ファイル（HTML5 Video API）を再生できなければならない 🔵 *PRD §F-02 / アーキテクチャ図*
- REQ-002: システムは動画ソース種別（`youtube` / `local`）に依らず、統一インターフェースで再生制御を提供しなければならない 🔵 *PRD 保守性 NFR「動画ストレージの抽象化」/ ADR-002 §F-02 分割*
- REQ-003: システムは再生・一時停止・シーク・再生速度変更の操作を提供しなければならない 🔵 *PRD §F-02「再生コントロール: 一時停止、シーク、速度変更」*
- REQ-004: システムは現在の再生位置を**ミリ秒精度の整数**で取得する手段を提供しなければならない 🔵 *PRD §F-02「打った」ボタン / data-foundation B-14（video_timestamp_ms は ms 単位 integer）*
- REQ-005: システムは指定した**ミリ秒位置へシーク（ジャンプ）**する手段を提供しなければならない 🔵 *PRD US-04 / §F-04 ラリー一覧からのワンクリックジャンプ*
- REQ-006: システムは再生速度を 0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 2.0 倍から選択できなければならない 🔵 *ユーザ決定 2026-06-01（バランス型 6 段階）*
- REQ-007: システムは動画の総再生時間（duration, ms）と再生状態（`unstarted` / `buffering` / `playing` / `paused` / `ended`）を取得できなければならない 🔵 *UI 表示（進捗・ローディング）と境界処理に必須の確定要件（設計決定 2026-06-01）。状態名は YouTube/HTML5 を吸収した統一値*
- REQ-008: システムは再生面に加え、標準的な再生コントロール UI（再生/一時停止・シークバー・現在時刻/総時間・速度選択）を描画して提供しなければならない 🔵 *ユーザヒアリング 2026-06-01（オーバーレイ方式=コントロール+スロット）。REQ-003 の操作を UI として具現化*
- REQ-009: システムは上位ユニットが痕跡（マーカー等）や独自表示を重ねられるよう、タイムライン上および再生面上に**汎用オーバーレイスロット**を提供し、スロットへ `durationMs` / `currentTimeMs` を渡さなければならない 🔵 *ユーザヒアリング 2026-06-01。match-recording の「打った痕跡」表示・stats-dashboard のラリー区切りを依存方向を保ったまま実現するため*

### 条件付き要件

- REQ-101: 動画ソースが `youtube` の場合、システムは `matches.video_source_url`（YouTube URL）から動画 ID を解決して再生しなければならない 🔵 *PRD §F-01/§F-02 / data-foundation schema `video_source_type='youtube'`*
- REQ-102: 動画ソースが `local` の場合、システムはユーザーが選択したローカルファイルを再生しなければならない 🔵 *PRD §F-02「ローカル動画ファイルを選択して再生」*
- REQ-103: ローカル動画でページ再読み込み後に動画参照（オブジェクト URL）が失われている場合、システムはユーザーに**同一ファイルの再選択**を促さなければならない 🔵 *ユーザヒアリング 2026-06-01（方式 A 採用）*
- REQ-104: シーク先が有効範囲外の場合、システムは有効範囲に**クランプ**してシークしなければならない（負値 → 0、duration 超過 → duration） 🔵 *シーク境界の挙動をクランプと確定（設計決定 2026-06-01）*

### 状態要件

- REQ-201: 動画がロード未完了（メタデータ未取得 / バッファ中）の状態にある場合、現在時刻取得は `null` を返し、シーク要求は無効（no-op）として扱わなければならない（NaN・負値を上位へ返してはならない） 🔵 *未ロード時の契約を確定（設計決定 2026-06-01）。UI は `null` の間、記録操作を無効化する*
- REQ-202: 再生中の状態にある場合、システムは現在時刻取得を**ポーリングなしで即時に**返さなければならない（入力ラグ防止） 🔵 *PRD 性能 NFR「動画再生中の入力遅延 100ms 以内」*

### オプション要件

- REQ-301: システムは長時間記録時に、ローカルよりも YouTube 利用を推奨する UX 誘導を表示してもよい 🔵 *ユーザヒアリング 2026-06-01（方式 A の補完）*

### 制約要件

- REQ-401: 動画プレーヤーはブラウザ専用 API（IFrame / HTML5 Video）に依存するため、**クライアントサイド（CSR）でのみ初期化**されなければならない 🔵 *ADR-010 Supabase SSR/CSR 境界の方針に準拠（ブラウザ専用 API は CSR）*
- REQ-402: page / component から動画 API を直接呼ばず、**composable 経由**で利用しなければならない 🔵 *cross-cutting/error-handling 設計原則1 / ADR-007 composable 規約*
- REQ-403: システムは MVP では `youtube` と `local` の 2 種のみ対応し、フレーム単位コマ送り・クラウド動画保存は対象外とする 🔵 *PRD「対象外スコープ」/ ユーザ決定 2026-06-01*
- REQ-404: 録画断絶（`recording_gaps`）の検出・記録は match-recording の責務であり、video-playback は**単一ソースの連続再生**のみを担う 🔵 *ADR-002 Q4 責務分担 / data-foundation `recording_gaps` テーブル定義*
- REQ-405: video-playback は「ショット」「ラリー」などのドメイン概念を一切知ってはならず、オーバーレイスロット（REQ-009）の中身に依存してはならない（依存方向は match-recording → video-playback の一方向を維持） 🔵 *ユーザヒアリング 2026-06-01 / ADR-002 依存関係（循環依存の防止）*
- REQ-406: 「打った」ボタン押下直後の記録確認フィードバック（記録した旨の即時表示）は match-recording の責務であり、video-playback は現在時刻取得（REQ-004）とオーバーレイスロット（REQ-009）の提供に留まる 🔵 *ユーザヒアリング 2026-06-01 / ADR-002 §6 match-recording 責務*

## 非機能要件

### パフォーマンス

- NFR-001: 現在時刻取得（REQ-004）はポーリング不要で同期的に即時返却し、動画再生中の入力（「打った」ボタン押下 → 記録）が 100ms を超える遅延源になってはならない 🔵 *PRD 性能 NFR「ボタン押下から記録完了まで 100ms 以内」*
- NFR-002: シーク・速度変更・再生/一時停止の操作は、知覚可能なフリーズなく即時に反映されなければならない 🔵 *NFR-001（入力ラグ防止）に紐付く確定 UX 要件（設計決定 2026-06-01）*

### セキュリティ

- NFR-101: ローカルファイル参照はブラウザのセキュリティ制約に従い、ページ外・セッション跨ぎで自動再アクセスしてはならない（再アクセスには明示的なユーザー操作を要する） 🔵 *ブラウザ制約 / ユーザヒアリング 2026-06-01*

### ユーザビリティ

- NFR-201: 再生コントロールはキーボードで操作可能でなければならず、Nuxt UI の標準アクセシビリティに準拠しなければならない（スクリーンリーダ向けの作り込みは MVP 対象外） 🔵 *ユーザ決定 2026-06-01（キーボード操作 + Nuxt UI 標準）*
- NFR-202: 動画ロード中・バッファ中はローディング状態を提示しなければならない 🔵 *cross-cutting/error-handling 層4 提示 / UX*

## Edgeケース

### エラー処理

- EDGE-001: YouTube 動画が埋め込み無効 / 削除済 / 非公開の場合、ロード失敗を検知し、ユーザーに別動画の指定を促さなければならない 🔵 *error-handling カテゴリ D「YouTube IFrame ロード失敗」*
- EDGE-002: 無効な YouTube URL（動画 ID 抽出不可）の場合、再生開始前に検証してエラーを提示しなければならない 🔵 *再生前検証を確定要件化（設計決定 2026-06-01）*
- EDGE-003: ローカル動画が未対応コーデック / 破損で再生不可の場合、HTML5 video のエラーイベントを捕捉して提示しなければならない 🔵 *error-handling カテゴリ D「HTML5 video エラー」*
- EDGE-004: ネットワーク不調で YouTube のバッファが進まない場合、REQ-007 の `buffering` 状態を提示し、他操作を阻害してはならない 🔵 *REQ-007 のバッファ中状態で提示と確定（設計決定 2026-06-01）*

### 境界値

- EDGE-101: シーク位置が 0ms ちょうど / duration ちょうど / duration 超過 の各境界で、REQ-104 のクランプに従い正しく動作しなければならない 🔵 *REQ-104 の境界（クランプ確定）*
- EDGE-102: 動画長（duration）が 0 または取得不可の状態で現在時刻取得・シークが呼ばれた場合、REQ-201 の契約（現在時刻 `null` / シーク no-op）に従わなければならない 🔵 *REQ-201 の境界（契約確定）*
