## エピック1: 動画の再生と制御

### ストーリー 1.1: YouTube 動画を URL で再生する 🔵

**信頼性**: 🔵 *PRD US-09 / §F-02*

**私は** データ入力者 **として**
**YouTube 動画 URL を指定して動画を再生したい**
**そうすることで** 動画ダウンロードの手間なく試合を見返せる

**関連要件**: REQ-001, REQ-101
**詳細シナリオ**:
1. 試合に紐付いた YouTube URL から動画 ID が解決される
2. プレーヤーが動画をロードし、再生可能状態になる
3. 再生・一時停止・シーク・速度変更ができる

**優先度**: Must Have

---

### ストーリー 1.2: ローカル動画ファイルを再生する 🔵

**信頼性**: 🔵 *PRD §F-02*

**私は** データ入力者 **として**
**手元のローカル動画ファイルを選択して再生したい**
**そうすることで** YouTube に上げていない試合動画も記録対象にできる

**関連要件**: REQ-001, REQ-102, REQ-103
**詳細シナリオ**:
1. ファイル選択でローカル動画を指定する
2. プレーヤーが再生可能状態になる
3. （再読み込み後に参照が失われた場合）同一ファイルの再選択を促される

**優先度**: Must Have

---

### ストーリー 1.3: 再生速度を変えて見返す 🔵

**信頼性**: 🔵 *PRD §F-02「速度変更」*

**私は** データ入力者 **として**
**再生速度を変更したい（0.5〜2.0 倍）**
**そうすることで** 速いラリーをスロー確認したり、退屈な区間を倍速で飛ばせる

**関連要件**: REQ-003, REQ-006
**優先度**: Must Have

---

## エピック2: 上位ユニットへの時刻インターフェース提供

### ストーリー 2.1: 「打った」瞬間の動画時刻を記録できる（基盤提供） 🔵

**信頼性**: 🔵 *PRD §F-02「打った」ボタン / data-foundation B-14*

**私は** match-recording（上位ユニット） **として**
**現在の再生位置を ms 単位で即座に取得したい**
**そうすることで** ボタン押下時のショットタイミングをラグなく記録できる

**関連要件**: REQ-004, REQ-202, NFR-001
**詳細シナリオ**:
1. ユーザーが「打った」ボタンを押す
2. プレーヤーから現在時刻（ms 整数）を同期的に取得
3. 取得 → 記録完了まで 100ms 以内

**優先度**: Must Have

---

### ストーリー 2.2: ラリー一覧から該当位置へジャンプできる（基盤提供） 🔵

**信頼性**: 🔵 *PRD US-04 / §F-04*

**私は** stats-dashboard（上位ユニット） **として**
**指定した ms 位置へ動画をシークさせたい**
**そうすることで** ラリー一覧クリックで該当ラリーの動画位置に即ジャンプできる

**関連要件**: REQ-005, REQ-104
**優先度**: Must Have

---

## エピック3: エラー時のフィードバック

### ストーリー 3.1: 再生できない動画を知らせてもらう 🔵

**信頼性**: 🔵 *cross-cutting/error-handling カテゴリ D*

**私は** データ入力者 **として**
**埋め込み無効・削除済みの YouTube 動画や、破損したローカル動画を再生しようとしたとき、明確なエラーと次の手（別動画指定）を知りたい**
**そうすることで** 何が悪いのか分からず手が止まることを避けられる

**関連要件**: EDGE-001, EDGE-002, EDGE-003, NFR-202
**優先度**: Should Have
