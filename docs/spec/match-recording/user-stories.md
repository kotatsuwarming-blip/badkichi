## エピック1: セットのセットアップ

### ストーリー 1.1: 試合を選んで録画を開始する 🔵

**信頼性**: 🔵 *PRD §5.4 画面一覧 + REQ-001*

**私は** データ入力者 **として**
**所属 Group の試合を選び、録画画面で動画を再生したい**
**そうすることで** 試合動画を見ながらデータ記録を始められる

**関連要件**: REQ-001, REQ-004, REQ-204

**詳細シナリオ**:
1. `/groups/[id]/matches/[matchId]/record` を開く
2. match の4選手・動画ソースが読み込まれる
3. 動画（YouTube / local）が再生可能になる（local は方式A で再選択）

**前提条件**: Group に所属している / 対象 match が存在する
**優先度**: Must Have

---

### ストーリー 1.2: セット設定と初期立ち位置を入力する 🔵

**信頼性**: 🔵 *PRD §F-03 + sets / set_player_positions 定義 + REQ-002/003*

**私は** データ入力者 **として**
**目標点・デュース・先攻・カメラ手前チームを設定し、4選手の初期立ち位置を入力したい**
**そうすることで** rule-engine が最初のサーバー/レシーバーを推論できる

**関連要件**: REQ-002, REQ-003, REQ-201

**詳細シナリオ**:
1. 目標点（既定21）・デュース有無・上限点（既定30）・先攻チームを設定 → `sets`
2. カメラ手前チームを設定（`camera_near_team_at_start`）
3. 4選手それぞれの team・左右を入力 → `set_player_positions` 4行
4. rule-engine `createInitialState` で初期 GameState を得る

**前提条件**: 録画画面に入っている
**制約事項**: 同一 (team, position) スロットは重複不可（EDGE-002）
**優先度**: Must Have

## エピック2: ラリー記録

### ストーリー 2.1: ショットタイミングを記録する 🔵

**信頼性**: 🔵 *PRD §F-02「打った」 + ヒアリング2026-06-05 + REQ-005*

**私は** データ入力者 **として**
**ラリー中に「打った」を押してショットのタイミングを記録したい**
**そうすることで** ショット数とラリー長を後で分析できる

**関連要件**: REQ-005, REQ-101, NFR-001, NFR-202

**詳細シナリオ**:
1. 再生中に「打った」を押す
2. video-playback から現在 ms を取得し `shots` に記録（100ms 以内）
3. 痕跡がタイムラインのオーバーレイに表示される

**制約事項**: 動画未ロード時は記録不可（EDGE-001）
**優先度**: Must Have

---

### ストーリー 2.2: ラリー結果を入力するとサーバー/レシーバーが自動特定される 🔵

**信頼性**: 🔵 *PRD §F-02/§F-03 + US-03 + rule-engine GameState + REQ-006/007*

**私は** データ入力者 **として**
**ラリー終了時にどちらのチームが得点したかだけを入力したい**
**そうすることで** サーバー/レシーバーが自動特定され、入力の手間が最小になる

**関連要件**: REQ-006, REQ-007, REQ-008, REQ-410, NFR-002

**詳細シナリオ**:
1. 「チームA得点」または「チームB得点」を押す
2. rule-engine `applyRally` がサーバー/レシーバー・サーバー位置・スコアを算出
3. 結果を `rallies` に denormalize 保存（serving_team / server_position / server_player_id / receiver_player_id）
4. 現在スコア・次サーバー/レシーバーをリアルタイム表示（100ms 以内）

**優先度**: Must Have

---

### ストーリー 2.3: 得点者不明時にスキップし後から確定する 🔵

**信頼性**: 🔵 *PRD US-05 + rallies is_point_confirmed + REQ-103/104*

**私は** データ入力者 **として**
**得点者が判断できないラリーを一旦スキップし、次のサーブを見てから確定したい**
**そうすることで** 正確なデータを入力できる

**関連要件**: REQ-103, REQ-104

**詳細シナリオ**:
1. 「スキップ」を押す → `point_winner=NULL` / `is_point_confirmed=false` で保留
2. 次のサーブを確認して得点者を確定
3. `is_point_confirmed=true` とし rule-engine に渡してサーバー/レシーバーを確定保存

**制約事項**: 未確定ラリーは engine に渡せず推論保留（EDGE-003）
**優先度**: Must Have

---

### ストーリー 2.4: レットを記録する 🔵

**信頼性**: 🔵 *PRD §F-02 + US-08 + rule-engine REQ-006 + REQ-102*

**私は** データ入力者 **として**
**やり直し（レット）を記録したい**
**そうすることで** 正確なスコア計算が維持される

**関連要件**: REQ-102

**詳細シナリオ**:
1. 「レット」を押す → `is_let=true` / `point_winner=NULL`
2. ラリー番号は採番されるがスコアは不変（EDGE-010）

**優先度**: Should Have

---

## エピック3: 修正と入れ替わり

### ストーリー 3.1: 直前ラリーの得点を修正する 🔵

**信頼性**: 🔵 *PRD §F-03 + US-07 + ヒアリング2026-06-05 + [[project_rally_correction]] + REQ-106*

**私は** データ入力者 **として**
**直前ラリーの数え間違いをその場で修正したい**
**そうすることで** 以降の推論が正しく継続される

**関連要件**: REQ-106

**詳細シナリオ**:
1. 直前ラリーの得点者/レット種別を修正
2. rule-engine がそれ以降のサーバー/レシーバー・スコアを再計算
3. `rallies` を再保存

**制約事項**: 修正対象は直前ラリーのみ（履歴からの任意編集は MVP 外）
**優先度**: Should Have

---

### ストーリー 3.2: 左右の入れ替わりを記録する 🔵

**信頼性**: 🔵 *PRD §F-02 + rule-engine REQ-104/105 + position_overrides + REQ-105*

**私は** データ入力者 **として**
**選手が左右を間違えた（入れ替わった）ことを記録し、戻った時点で戻ったと入力したい**
**そうすることで** 実際のポジションに基づいた推論が継続される

**関連要件**: REQ-105

**詳細シナリオ**:
1. 入れ替わりに気づいたら override を押す → `override_type='swapped'` を `position_overrides` に記録
2. rule-engine `applyOverride` で当該チームの左右をトグル
3. 戻ったら再度 override → `override_type='restored'`（2回連続で元に戻る、EDGE-008）

**制約事項**: 再生しながらの同時操作が難しいため、ラリー開始後でも入力可能とする（NFR-203、要プロトタイプ）
**優先度**: Should Have

## エピック4: セット・試合の進行

### ストーリー 4.1: セット勝者を検知して次セットへ進む 🔵

**信頼性**: 🔵 *ヒアリング2026-06-05 + rule-engine REQ-007/009 + REQ-010/107*

**私は** データ入力者 **として**
**セットが決着したら検知し、自分の操作で次セットを開始したい**
**そうすることで** セット境界を確認しながら記録を続けられる

**関連要件**: REQ-010, REQ-107, REQ-203

**詳細シナリオ**:
1. rule-engine `determineSetWinner` が勝者を検知 → `sets.winner` 更新
2. 「次のセットへ」導線を提示（自動遷移しない）
3. 次セットの設定・立ち位置を入力（先攻＝前セット勝者を既定提示）

**優先度**: Must Have

---

### ストーリー 4.2: 試合勝者を判定して終了する 🟡

**信頼性**: 🟡 *rule-engine REQ-008（試合勝者判定）から妥当な推測。先取数ルールは kairo-design*

**私は** データ入力者 **として**
**先取セット数に達したら試合勝者として表示したい**
**そうすることで** 試合の記録を完了できる

**関連要件**: REQ-011, EDGE-011

**詳細シナリオ**:
1. 先取セット数（3セットマッチで2セット先取等）に達したら試合勝者を判定・表示
2. 試合終了後の新規セット追加を抑止（EDGE-011）

**優先度**: Should Have
**備考**: 先取数の具体ルールは kairo-design で確定
