# ai-draft-loop ヒアリング記録

本単位の要件は、新規のヒアリングではなく ADR-020 の決定過程（2026-11-13 〜 23 のセッション）から抜き出した。
一次情報は ADR-020 本文と `docs/research/loop-engineering/survey.md`。

## 2026-11-13: 方針の転換

- 作者判断: 記録の全項目を AI の下書きにし、人は訂正だけ行う。精度が低くても先に出す。訂正から正解を得て学習するループを自動化する。
- 当初案: shots の項目ごとに draft / confirmed / corrected の 3 状態を持つ。「未変更 = 正解」としない。
- 確認画面の条件: ラリー単位の全却下、1 キーでの確定、訂正 1 ショット 5 秒以内。満たせない項目は下書きを出さない。

## 2026-11-23: 調査による改訂

- Label Studio の「予測は読み取り専用、人の注釈は元予測を参照する別の行」を採り、二層スキーマ（`ai_predictions` / `human_resolutions`）に変更。確認も訂正も所要時間（`lead_time_ms`）も残る。
- 所要時間の合計が「1 試合あたりの作業時間」（BL-020）になるので、計測機能を別に作らない。
- 作者の質問「入力時間にはショット種別や打刻・場所も入る。シャトル追跡が要るのでは」→ 追跡が無いと困るのは球種だけ。球種は利用者が直せるがシャトル座標は直せないので、訂正で育つものから出す。着手は球種の訂正率で判断。
- 作者の質問「DVC は評価の仕組みか」→ DVC はデータの版管理。評価は自前の評価器、記録は MLflow。評価セットを増やすときは**試合単位で分ける**（5 試合に 1 を評価専用）。→ REQ-019 〜 021。
- 作者の指摘「全項目 AI 入力には動画を badkichi 側に記録する機能が要る」→ 別単位 video-intake（VID-0 〜 4）としてキューに登録。本単位は動画の受け取りを含まない。
- 作者の判断「課金は一旦置き、AI 化とループを進める」→ 本単位がキューの先頭。

## 本単位で補完した点（🟡）

- 試合ごとの下書き状態（REQ-009）、低確信度の強調（REQ-014）、未確認の注意表示（REQ-024）、無操作の閾値（REQ-017）、`eval_holdout` の自動付与（REQ-019）は、ADR の方針から運用上必要と判断して足した。値は設計と運用で確定する。
