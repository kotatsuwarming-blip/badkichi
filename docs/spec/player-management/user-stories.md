## エピック1: 選手ロスター管理

### ストーリー 1.1: 選手一覧を見る 🔵

**信頼性**: 🔵 *players_select RLS + ADR-006*

**私は** Group に所属するメンバー **として**
**自分のチームの選手一覧を見たい**
**そうすることで** 試合記録時に誰がいるかを把握できる

**関連要件**: REQ-001, REQ-202, REQ-402

**詳細シナリオ**:
1. 認証済み・Group 所属済みユーザーが選手管理画面を開く
2. 所属 Group の未削除選手が一覧表示される（name / handedness）
3. 選手が 0 人なら空状態と「選手を追加」導線が表示される

**前提条件**:
- ログイン済みかつ Group 所属済み（未所属なら middleware が /onboarding へ誘導）

**優先度**: Must Have

---

### ストーリー 1.2: 選手を追加する 🔵

**信頼性**: 🔵 *players_insert RLS + players CHECK 制約*

**私は** Group メンバー **として**
**新しい選手を名前（と利き手）で登録したい**
**そうすることで** 新メンバーを試合記録の対象にできる

**関連要件**: REQ-002, REQ-101, REQ-102, REQ-401, REQ-403

**詳細シナリオ**:
1. 「選手を追加」を押す
2. name（必須）を入力、handedness（right/left/unknown）を選択（任意・既定unknown）
3. 保存すると composable 経由で players へ insert され、一覧に追加される
4. 同名の選手が既にいても登録は成功する

**制約事項**:
- name は trim 後 1〜50 字（境界外はエラー表示）
- supabase 直叩き禁止、composable 経由

**優先度**: Must Have

---

### ストーリー 1.3: 選手情報を編集する 🔵

**信頼性**: 🔵 *players_update RLS*

**私は** Group メンバー **として**
**既存選手の名前や利き手を直したい**
**そうすることで** 入力ミスや利き手情報を後から修正できる

**関連要件**: REQ-003, REQ-101, REQ-401, REQ-403

**詳細シナリオ**:
1. 一覧から選手を選び編集する
2. name / handedness を変更して保存
3. composable 経由で update され、一覧に反映される

**優先度**: Must Have

---

### ストーリー 1.4: 選手を削除する 🔵

**信頼性**: 🔵 *no DELETE policy → soft delete + ヒアリング2026-06-01*

**私は** Group メンバー **として**
**使わなくなった選手をロスターから消したい**
**そうすることで** 一覧を現役メンバーだけに保てる

**関連要件**: REQ-004, REQ-103, REQ-104, REQ-402

**詳細シナリオ**:
1. 一覧から選手の削除を実行する
2. 確認ダイアログなしで `deleted_at` が設定される（ソフト削除）
3. 一覧から消えるが、その選手が出場した過去の試合記録は維持される

**制約事項**:
- 物理削除は行わない（DB 仕様）
- 試合参照があっても削除可（履歴は player.id 経由で保持）

**優先度**: Must Have
