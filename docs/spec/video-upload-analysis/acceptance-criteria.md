# video-upload-analysis 受け入れ基準

**作成日**: 2026-11-01
**関連**: [requirements.md](requirements.md) / [user-stories.md](user-stories.md)

テスト ID は `TC-{REQ 番号}-{連番}` とし、E は Edge ケース由来を表す。
試料は戸塚ミックスの動画 (1280×720 30 fps、44 分) と、南区の動画 (縦向き・横から、検出が成立しない例)。

## 1. アップロードと同意

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-002-01 | 試合あり | 同意のチェックを入れずにアップロードを開始 | 開始できない | REQ-002 |
| TC-002-02 | 同上 | 同意して開始 | 同意の日時と内容 (解析・削除方針) が記録される | REQ-002 |
| TC-003-01 | 1 GB の動画 | アップロード | 進捗 (割合・転送量) が表示され、完了する | REQ-003 |
| TC-101-01 | アップロード途中 | タブを閉じて開き直し、同じファイルを選ぶ | 続きから再開し完了する | REQ-101 |
| TC-001-E01 | 動画以外のファイル | 選択 | 拒否され理由が出る | EDGE-001 |
| TC-407-01 | 上限を超える大きさ・長さ | 選択 | 拒否され上限が表示される | REQ-407 |
| TC-104-01 | ジョブ実行中 | 2 本目をアップロード | 受け付けない | REQ-104 |
| TC-201-01 | 動画分析数が上限 | アップロードを開く | 受け付けず、上限とプランの案内 | REQ-201 |
| TC-002-E01 | 前のジョブ完了済み・原本保管中 | 2 回目のアップロード | 前の原本が削除されてから受け付け、新しいジョブができる | EDGE-002 |

## 2. 校正と区間

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-009-01 | 試合に校正あり | アップロード完了 | 校正の入力なしにジョブが始まる | REQ-009 |
| TC-009-02 | 校正なし | アップロード完了 | ジョブは待機のまま、静止画の上で 4 隅をタップする画面が出る | REQ-009 / REQ-202 |
| TC-009-03 | 同上 | 4 隅を入力 | ジョブが始まり、ワーカーの入力に 4 隅の座標が入る | REQ-006 / REQ-009 |
| TC-106-01 | 2 試合入りの動画 | 区間 10:00〜55:00 を指定 | ワーカーは区間だけ処理し、候補の時刻は動画先頭からの秒数 | REQ-106 |
| TC-009-E01 | 手前 2 隅が画面外 | 4 隅を入力 | 画面外の点を「画面外」として扱い、校正が成立する | EDGE-003 |

## 3. ジョブと結果

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-004-01 | アップロード完了・校正あり | 自動 | `analysis_jobs` に待機のジョブが 1 件できる | REQ-004 |
| TC-005-01 | ジョブ実行中 | 試合画面を開く | 状態「実行中」と進捗 (処理済み分 / 全体) が出る。30 秒以内に更新される | REQ-005 / REQ-203 / NFR-003 |
| TC-006-01 | 戸塚の動画 | ジョブ完了 | 候補ファイル (形式 version 1) が保存され、serve-start-assist で開ける | REQ-006 / REQ-007 |
| TC-006-02 | 同上 | 候補ファイルを確認 | 選手名・ID を含まず、`duration_ms` と `camera_near_team` 非依存のスロット表記 | REQ-403 |
| TC-008-01 | ジョブ完了 | billing の分析数を確認 | 1 本加算されている | REQ-008 |
| TC-008-02 | ジョブ失敗 | 同上 | 加算されていない | REQ-008 / EDGE-203 |
| TC-102-01 | ジョブ失敗 (内部エラー) | 画面を見る | 失敗の種類と、再実行の操作が出る | REQ-102 / NFR-202 |
| TC-102-02 | 失敗から 3 日後 | 再実行 | 原本の再アップロードなしに新しいジョブが始まる | REQ-102 |
| TC-107-01 | 南区の動画 (横から・床置き) | ジョブ完了 | 「完了 (候補 0 件)」と撮影条件の案内が出る | REQ-107 / EDGE-101 |
| TC-109-01 | 上限を超えて走るジョブ | 自動 | 時間切れで失敗になり、ワーカーが停止する | REQ-109 |
| TC-010-01 | 60 fps・1080p の動画 | ジョブ完了 | 候補の時刻が元の動画の秒数で返る | REQ-010 / EDGE-104 |
| TC-010-02 | 縦向きの動画 | ジョブ完了 | 回転して処理され、エラーにならない | REQ-010 |
| TC-105-01 | 候補あり・記録前 | 再実行 | 候補が置き換わる | REQ-105 |
| TC-201-E01 | ワーカー異常終了 | 運営画面 | 「実行中」のまま残ったジョブを手で失敗にできる | EDGE-201 / NFR-302 |

## 4. 原本の削除と保護

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-103-01 | 保管なし (既定) | ジョブ成功 | 原本が削除され、削除の日時・理由が記録される | REQ-103 / REQ-402 |
| TC-103-02 | 保管あり (30 日) | ジョブ成功 → 30 日後 | 30 日後の定期ジョブで削除される | REQ-103 / NFR-303 |
| TC-102-E01 | ジョブ失敗 | 7 日後 | 定期ジョブで削除される | REQ-402 |
| TC-108-01 | 保管中 | 利用者が削除を要求 | 直ちに削除され記録される | REQ-108 |
| TC-204-01 | 原本削除済み | serve-start-assist を開く | Storage 再生の選択肢が出ない | REQ-204 |
| TC-401-01 | 他 Group の利用者 | 原本・候補・台帳に API でアクセス | いずれも取得・更新できない | REQ-401 / NFR-101 |
| TC-401-02 | 署名 URL | 有効期限後にアクセス | 取得できない。URL がログに残っていない | NFR-102 |
| TC-403-01 | ワーカーの実行環境 | DB・Storage への権限を確認 | 対象ジョブの動画の取得と候補の書き込み以外ができない | REQ-403 |
| TC-202-E01 | 保管中に Group を削除 | 自動 | 原本と候補が削除される | EDGE-202 |
