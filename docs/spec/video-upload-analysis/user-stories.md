# video-upload-analysis ユーザストーリー

**作成日**: 2026-11-01 / **改訂**: 2026-11-23
**関連**: [requirements.md](requirements.md) / [acceptance-criteria.md](acceptance-criteria.md)

## ストーリー1: 動画を上げるだけで候補が届く

- **である** 顧客チームの記録担当 **として**
- **私は** YouTube に上げたのと同じ動画ファイルをアプリにアップロードして、サーブ候補を作ってもらいたい
- **そうすることで** 運営者に動画を渡して待つことなく、自分のチームの試合を自分のペースで記録に進められる

対応要件: REQ-001 / REQ-003 / REQ-004 / REQ-005 / REQ-007

## ストーリー2: 動画がどう扱われるか分かる

- **である** 選手 (映っている本人) とチームの管理者 **として**
- **私は** 動画が何のためにサーバーに送られ、いつ消えるのかを、送る前に知って同意したい
- **そうすることで** 肖像や個人の映像が勝手に保存・利用される不安なく使える

対応要件: REQ-002 (同意の 4 点) / REQ-103 / REQ-108 / REQ-401 / REQ-402 / REQ-301

## ストーリー8: 同じ動画からショット層の下書きも届く (改訂 2026-11-23)

- **である** 記録担当 **として**
- **私は** ラリー確認が終わった試合について、同じアップロード済み動画から打刻・打者・球種・打点の下書きも作ってもらいたい
- **そうすることで** 動画を上げ直すことなく、注釈の確認モード (ai-draft-loop) に進める

対応要件: REQ-006 / REQ-007 (ai-draft-loop REQ-006〜008、Issue #102)

## ストーリー3: 手元に動画を置かなくてよい

- **である** 記録担当 **として**
- **私は** 記録のときは YouTube で再生し、動画ファイルを PC に置き続けたくない
- **そうすることで** 容量の大きいファイルの管理や「同じファイルを選び直す」手間から解放される

対応要件: REQ-001 / REQ-103 (serve-start-assist REQ-113 と対)

## ストーリー4: 失敗しても次に何をすればいいか分かる

- **である** 記録担当 **として**
- **私は** 解析が失敗したり候補が出なかったりしたとき、原因と自分にできること (撮り直し、校正のやり直し、再実行) を知りたい
- **そうすることで** 運営に問い合わせずに自分で先に進める

対応要件: REQ-102 / REQ-107 / NFR-202 / EDGE-101

## ストーリー5: 運営者がジョブの状態を把握できる

- **である** 運営者 **として**
- **私は** 全チームの解析ジョブの状態・失敗率・処理時間・費用を一覧したい
- **そうすることで** 失敗の傾向を早く掴み、GPU の費用とプランの値付けを合わせられる

対応要件: REQ-304 / NFR-302 / NFR-303

## ストーリー6: 分析数がプランに結びつく

- **である** 運営者 **として**
- **私は** 解析 1 本を billing の「動画分析数」として数えたい
- **そうすることで** 上限つきのプランが成立し、解析の費用を回収できる

対応要件: REQ-008 / REQ-201 / EDGE-203

## ストーリー7: 複数試合が入った動画でも使える

- **である** 記録担当 **として**
- **私は** 1 本の動画に 2 試合入っているとき、試合ごとの区間を指定して解析したい
- **そうすることで** 動画を切り分けて上げ直す手間なく、試合ごとの候補を得られる

対応要件: REQ-106 / EDGE-105
