# video-upload-analysis ユーザストーリー (機能群全体)

**作成日**: 2026-11-01 / **改訂**: 2026-11-23、2026-11-24 (親子に分割。ストーリーは親に置き、子は対応表を持つ)
**関連**: [requirements.md](requirements.md) / 子: [video-upload](../video-upload/user-stories.md)、[video-analysis-job](../video-analysis-job/user-stories.md)

「対応要件」は子の単位の REQ を `単位:REQ` で示す。VU = video-upload、VAJ = video-analysis-job。

## ストーリー1: 動画を上げるだけで候補が届く

- **である** 顧客チームの記録担当 **として**
- **私は** YouTube に上げたのと同じ動画ファイルをアプリにアップロードして、サーブ候補を作ってもらいたい
- **そうすることで** 運営者に動画を渡して待つことなく、自分のチームの試合を自分のペースで記録に進められる

対応要件: VU:REQ-001 / 003 / 004 / 005 / 007、VAJ:REQ-001 / 002 / 004 / 005

## ストーリー2: 動画がどう扱われ、いつ消えるか分かる

- **である** 選手 (映っている本人) とチームの管理者 **として**
- **私は** 動画が何のためにサーバーに送られ、いまなぜ残っていて、いつ消えるのかを、送る前と保管中に知りたい
- **そうすることで** 肖像や個人の映像が勝手に保存・利用される不安なく使える

対応要件: VU:REQ-002 (同意の 4 点) / 008 / 010 / 204 / 401 / 402

## ストーリー3: 手元に動画を置かなくてよい

- **である** 記録担当 **として**
- **私は** 記録のときは YouTube で再生し、動画ファイルを PC に置き続けたくない
- **そうすることで** 容量の大きいファイルの管理や「同じファイルを選び直す」手間から解放される

対応要件: VU:REQ-001 / 007 (serve-start-assist REQ-113 と対)

## ストーリー4: 失敗しても次に何をすればいいか分かる

- **である** 記録担当 **として**
- **私は** 解析が失敗したり候補が出なかったりしたとき、原因と自分にできること (撮り直し、校正のやり直し、再実行) を知りたい
- **そうすることで** 運営に問い合わせずに自分で先に進める

対応要件: VAJ:REQ-101 / 105 / 203 / NFR-201 / EDGE-101

## ストーリー5: 運営者がジョブの状態を把握できる

- **である** 運営者 **として**
- **私は** 全チームの解析ジョブの状態・失敗率・処理時間・費用を一覧したい
- **そうすることで** 失敗の傾向を早く掴み、GPU の費用とプランの値付けを合わせられる

対応要件: VAJ:REQ-303 / NFR-302

## ストーリー6: 分析数がプランに結びつく

- **である** 運営者 **として**
- **私は** 解析 1 本を billing の「動画分析数」として数えたい
- **そうすることで** 上限つきのプランが成立し、解析の費用を回収できる (課金は保留中、計測だけ)

対応要件: VAJ:REQ-006 / 201 / EDGE-202

## ストーリー7: 複数試合が入った動画でも使える

- **である** 記録担当 **として**
- **私は** 1 本の動画に 2 試合入っているとき、試合ごとの区間を指定して解析したい
- **そうすることで** 動画を切り分けて上げ直す手間なく、試合ごとの候補を得られる

対応要件: VU:REQ-006、VAJ:REQ-104 / EDGE-105

## ストーリー8: 同じ動画からショット層の下書きも届く (2026-11-23)

- **である** 記録担当 **として**
- **私は** ラリー確認が終わった試合について、同じアップロード済み動画から打刻・打者・球種・打点の下書きも作ってもらいたい
- **そうすることで** 動画を上げ直すことなく、注釈の確認モード (ai-draft-loop) に進める

対応要件: VAJ:REQ-004 / 005 / 103 (ai-draft-loop REQ-006〜008、Issue #102)

## ストーリー9: 確認を直したら AI がやり直してくれる (2026-11-24)

- **である** 記録担当 **として**
- **私は** ラリーの開始・終了を直したら、その区間の打刻や球種を AI に推論し直してもらいたい。確認を途中で止めても、再開したときに同じことができてほしい
- **そうすることで** 入力が終わるまで、AI の下書きを頼りに進められる

対応要件: VU:REQ-008 (`correction`) / 103 / 104 / EDGE-101 / EDGE-102、VAJ:REQ-107

## ストーリー10: 学習に使うかは自分で選ぶ (2026-11-24)

- **である** チームの管理者 **として**
- **私は** 自分たちの動画を AI の学習に提供するかどうかを別に選び、あとで取り消したい
- **そうすることで** 解析は使いたいが学習には出したくない、という選択ができる

対応要件: VU:REQ-009 / 105 / 108

## ストーリー11: 評価用の試合が勝手に消えない (2026-11-24)

- **である** 運営者 **として**
- **私は** 評価専用に指定した試合の原本が自動削除から守られてほしい
- **そうすることで** モデルの精度を測る基準 (固定評価セット) が製品側の削除で壊れない

対応要件: VU:REQ-106 / EDGE-103 / EDGE-104

## ストーリー12: 保管の費用が見える (2026-11-24)

- **である** 運営者 **として**
- **私は** Group ごとの Storage 使用量と、動画が残っている理由の内訳を見たい
- **そうすることで** 保管の費用を把握し、プロキシ化や上限期間の値を決められる

対応要件: VU:REQ-301 / 302 / NFR-301
