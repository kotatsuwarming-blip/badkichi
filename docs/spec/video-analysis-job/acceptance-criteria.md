# video-analysis-job 受け入れ基準

**作成日**: 2026-11-24 (親 video-upload-analysis から分割)
**関連**: [requirements.md](requirements.md) / [../video-upload-analysis/user-stories.md](../video-upload-analysis/user-stories.md)

テスト ID は `TC-{REQ 番号}-{連番}` とし、E は Edge ケース由来を表す。
試料は戸塚ミックスの動画 (1280×720 30 fps、44 分) と、南区の動画 (縦向き・横から、検出が成立しない例)。

## 1. ジョブの作成と進捗

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-001-01 | video-upload で `ready` | 自動 | `analysis_jobs` に待機のジョブが 1 件できる (動画、要求した出力、契約の版を含む) | REQ-001 |
| TC-002-01 | ジョブ実行中 | 試合画面を開く | 状態「実行中」と進捗 (処理済み分 / 全体) が出る。30 秒以内に更新される | REQ-002 / REQ-202 / NFR-002 |
| TC-002-02 | ジョブ完了 | 試合画面を開く | ラリー確認へ進む導線が出る | REQ-002 |
| TC-102-01 | ジョブ実行中 | 同じ動画で再実行 | 受け付けない | REQ-102 |
| TC-201-01 | billing 導入後、動画分析数が上限 | ジョブを作ろうとする | 受け付けず、上限とプランの案内 | REQ-201 |
| TC-NFR-202-01 | ジョブ作成 | 画面を見る | 推定の解析時間が表示される | NFR-202 |

## 2. ワーカー契約と出力

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-003-01 | 校正・区間ありの `ready` 動画 | ジョブ開始 | ワーカーの入力に署名 URL、4 隅、区間、fps と向き、要求する出力が入る | REQ-003 |
| TC-004-01 | 戸塚の動画 | ジョブ完了 | 候補ファイル (形式 version 1) が保存され、serve-start-assist で開ける | REQ-004 / REQ-005 |
| TC-004-03 | 戸塚の動画 | ジョブ完了 → 原本を削除 | 骨格・シャトル座標・コート射影・音の立ち上がりの特徴量が抽出モデルの版つきで残り、人の確認・訂正と試合 ID で結べる | REQ-004 |
| TC-004-02 | 下書き JSON に対応したワーカー | ジョブ完了 | 下書き JSON が ai-draft-loop の取り込み経路に渡り、確定済みのラリーだけ現在の値に反映される | REQ-004 / REQ-005 |
| TC-004-03 | 同上 | 候補ファイルを確認 | 選手名・ID を含まず、`camera_near_team` 非依存のスロット表記 | REQ-401 |
| TC-007-01 | 60 fps・1080p の動画 | ジョブ完了 | 候補の時刻が元の動画の秒数で返る | REQ-007 / EDGE-104 |
| TC-007-02 | 縦向きの動画 | ジョブ完了 | 回転して処理され、エラーにならない | REQ-007 |
| TC-104-01 | 区間 10:00〜55:00 | ジョブ完了 | 区間だけ処理され、候補の時刻は動画先頭からの秒数 | REQ-104 |
| TC-008-01 | ジョブ成功 / 失敗 | 自動 | 原本は削除されない (video-upload の保持の理由はそのまま) | REQ-008 |
| TC-006-01 | ジョブ完了 | 分析数を確認 | 1 本加算されている | REQ-006 |
| TC-006-02 | ジョブ失敗 | 同上 | 加算されていない | REQ-006 / EDGE-202 |
| TC-304-01 | プロキシ採用時 | ジョブ完了 | プロキシが video-upload に渡る | REQ-304 |

## 3. 失敗と再実行

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-101-01 | ジョブ失敗 (内部エラー) | 画面を見る | 失敗の種類と、再実行の操作が出る | REQ-101 / NFR-201 |
| TC-101-02 | 失敗、原本あり | 再実行 | 再アップロードなしに新しいジョブが始まる | REQ-101 |
| TC-203-01 | 失敗、原本削除済み | 再実行 | 受け付けず、再アップロードの案内 | REQ-203 |
| TC-103-01 | 候補あり・記録前 | 再実行 | 候補が置き換わる | REQ-103 |
| TC-103-02 | 候補あり・確定済みラリーあり | 再実行 | 確定済みの値は上書きされない | REQ-103 |
| TC-105-01 | 南区の動画 (横から・床置き) | ジョブ完了 | 「完了 (候補 0 件)」と撮影条件の案内が出る | REQ-105 / EDGE-101 |
| TC-106-01 | 上限を超えて走るジョブ | 自動 | 時間切れで失敗になり、ワーカーが停止する | REQ-106 |
| TC-107-01 | ラリー区間を訂正済み | 部分再推論を要求 | 区間だけのジョブが起き、該当ラリーの下書きだけ差し替わる | REQ-107 |
| TC-201-E01 | ワーカー異常終了 | 運営画面 | 「実行中」のまま残ったジョブを手で失敗にできる | EDGE-201 / NFR-302 |
| TC-203-E01 | 実行中に原本が削除された | 自動 | ワーカーは完了まで進み、出力が保存される | EDGE-203 |
| TC-NFR-301-01 | 契約のバージョンを上げたワーカー | 旧バージョンの本体 | 失敗 (契約の不一致) として記録し、運営者に知らせる | NFR-301 / EDGE-204 |

## 4. 保護と非機能

| ID | 前提 | 操作 | 期待結果 | 要件 |
|---|---|---|---|---|
| TC-401-01 | ワーカーの実行環境 | DB・Storage への権限を確認 | 対象ジョブの動画の取得と出力の書き込み以外ができない | REQ-401 / NFR-102 |
| TC-NFR-101-01 | 他 Group の利用者 | 候補・下書き・台帳に API でアクセス | いずれも取得・更新できない | NFR-101 |
| TC-403-01 | 使用モデルの一覧 | ライセンスが商用可能なもので構成されている (YOLO11 は代替またはライセンス購入) | REQ-403 |
| TC-NFR-001-01 | 戸塚 44 分の動画を解析 | 2 時間以内に完了 (待機を除く) | NFR-001 |
| TC-303-01 | 運営者 | ジョブ一覧を開く | 処理時間・GPU 時間・推定費用が見える。利用者には見えない | REQ-303 / NFR-302 |
