# video-analysis-job ユーザストーリー (親への対応表)

**作成日**: 2026-11-24
**関連**: [requirements.md](requirements.md) / 親のストーリー [../video-upload-analysis/user-stories.md](../video-upload-analysis/user-stories.md)

ユーザーストーリーは「動画を上げる → 解析 → 確認」をまたぐので、親 video-upload-analysis に置く。本単位はそのうち次のストーリーを担う。

| 親のストーリー | 本単位が担う部分 | 対応要件 |
|---|---|---|
| 1. 動画を上げるだけで候補が届く | `ready` でジョブを起こし、候補ファイルを保存してラリー確認に渡す | REQ-001 / REQ-002 / REQ-004 / REQ-005 |
| 4. 失敗しても次に何をすればいいか分かる | 失敗の分類、再実行、候補 0 件の案内 | REQ-101 / REQ-105 / REQ-203 / NFR-201 |
| 5. 運営者がジョブの状態を把握できる | 台帳の一覧、費用の記録、手で失敗にする | REQ-303 / NFR-302 |
| 6. 分析数がプランに結びつく | 完了を 1 本として計測 (上限の強制は billing 後) | REQ-006 / REQ-201 / EDGE-202 |
| 7. 複数試合が入った動画でも使える | 区間だけを解析し、時刻は動画先頭から | REQ-104 / EDGE-105 |
| 8. 同じ動画からショット層の下書きも届く | 下書き JSON を同じジョブの出力として ai-draft-loop に渡す | REQ-004 / REQ-005 / REQ-103 |
| 9. 確認を直したら AI がやり直してくれる | 訂正した区間だけの部分再推論 | REQ-107 |
