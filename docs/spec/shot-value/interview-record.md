# shot-value ヒアリング記録

**期間**: 2026-08-16 〜 2026-09-16（設計対話。すべて同一セッションの継続）
**起点**: 川島氏の指摘「強みと課題はショット種別で見たい」（usability-test-01, 2026-06-16）を受け、
ユーザが「ショットの有効性を示す値」の設計を発案。「テニスにフォア/バックの有効性数値があった気がする。
既存のものがあるなら使いたい」。

## Q1: 既存指標はあるか（2026-08-16〜08-23）

**調査結果**:
- テニス: **Tennis Abstract (Match Charting Project) の FHP/BHP**（Forehand/Backhand Potency）。
  ウィナー +1 / お膳立て +0.5 / 自ミス −1 を 100 本あたりに正規化。トラッキング不要で
  「誰が・何を・どう終わったか」だけで計算でき、badkichi の注釈データと同型。
- バドミントン: 球種別 winner/error 分類は学術研究の定番だが、**単一数値の普及指標は存在しない**。
  研究側には shot influence（Wang et al., ACM TIST 2022 / ShuttleScorer, ShuttleSet 系）が
  あるが学習ベースかつシングルス前提 → 将来枠。
- **決定**: FHP/BHP の採点構造を翻案する（v1）。学習ベースは v3 として見送り。

## Q2: ミス誘発の重みと最低本数（2026-08-19）

**質問**: 誘発 +1 か +0.5 か / 表示の最低 n はいくつか → **ユーザ回答: どちらも「もう少し考えたい」**
（サーブ 3 種を含めることのみ確定）。

**再提案と合意**:
- 誘発の重みは判断保留のまま進められるよう、**RPC はエース/誘発を別カウントで返し、重みはクライアント定数**にする
- 最低 n の固定閾値はやめ、**95% 信頼区間のヒゲ**で「まだ読めない」を可視化。極端な少数（n<5）のみ薄表示

## Q3: 最後の2本しか採点されないのは良くない（2026-08-28）

**ユーザ指摘**: 「もっと全てのショットを入れたいが、データは得点したかくらいしかなく、
途中に追い込めているかがないのがきつい」

**回答と展開**:
- 実データには全ショットの球種・打者・座標・時刻があると整理
- 案1: 決着から遡る配点（BHP のお膳立て項の拡張）
- 案2: 押し込み率 = 相手の次球が守備的な球種かで「追い込み」を測る
- 案3: 学習ベース shot influence（将来）
- いったん「決定力 + 押し込み率」の 2 本立てを提案

## Q4: レシーブにも良い球がある（2026-08-28）

**ユーザ指摘**: スマッシュ→ショートレシーブ→相手が甘いロブ→決めた、ならショートレシーブが良かった。

**確認**: 提案方式は全ショットが評価対象（押し込み判定は「相手の次球」基準）であり、
遡り配点でも決めの 1 本前のレシーブに配点される。両方式がこの例を正しく拾うことを検算。

## Q5: ロブ＝苦しいは思い込み → 球種攻守分類の廃止（2026-08-28〜09-02）

**ユーザ指摘**: ミックスでは女子後衛に打たせるため**わざとロブを上げさせる/上げる**のが一般戦術。
ダブルスでも遅いスマッシュの選手を後ろに下げさせる。「ロブ＝守勢」の決めつけは誤る。

**決定**:
- **球種の攻守分類に基づく押し込み率は不採用**（球種の意味が戦術で反転するため原理的に誤る）
- ラリー途中の貢献は**遡り配点に一本化**（結末だけから配点、球種の決めつけなし）
- 「上げさせる戦術」の分析は**ゾーン×選手成績**（どこから打つと危険/無害か）で直接測る方向へ

## Q6: 表示の要望（2026-09-02）

- ゾーンは **3×3 で選べて、複数同時選択もできること**
- **相手ポジション軸（ミックス）はスコープ外**と明示
- ドリルダウンの表示イメージが湧かない。「ショットの内訳だけでなくポイントがあった方がいい」

## Q7: 遡りの減衰と「混ざる」問題（2026-09-14 直前）

**ユーザ**: 「1つ前が半分になるのは減りすぎ」「ゾーン合算だと攻守の文脈が混ざるが、
その方が『後ろが弱い』に早く届く。迷っている」

**合意**:
- 減衰は定数化し初期値を緩める（**b1=0.7, b2=0.5**、同チーム 2 本前まで）。実データで較正
- 混ざる問題は「計算はゾーン×球種の細かさで 1 回、表示は合算 → ドリルダウン」で両取り
- 負け側にも対称の遡り（−b1/−b2）を配る

## Q8: 積み上げ棒の説明と 5 色の確定（2026-09-16）

動くモック（sv-drilldown-mock.html）を提示 → 「積み上げ棒の意味が分かりづらい」→
スマッシュ 20 本の具体例で 5 役割（決め/誘発/布石/自ミス/許した）の採点→積み上げの意味を説明。
**ユーザ: 5 色でいったん OK**（2 色 + 開いて内訳への簡略化は不採用のまま保留）。

## Q9: 画面統合と重みの位置づけ確認（2026-09-16）

- **ユーザ**: 「この表示があればゾーン合算 SV（独立チャート）は不要。球種別 SV はあってもいい」
  → 未選択時 = コート全体の球種別 SV となるため **1 画面に統合**（独立チャートなし）で確定
- **ユーザ**: 「0.7 と 0.5 は適当に決めているか?」→ **暫定の仮置きと明示的に合意**。
  構造（近いほど濃く配点）とテニスの前例のみが根拠。実データを見て順位の安定性と試合感覚で較正
