## エピック1: サーバー / レシーバー自動推論

### ストーリー 1.1: ラリー結果からサーバーを推論する 🔵

**信頼性**: 🔵 *PRD F-03・US-03*

**私は** データ入力者 **として**
**ポイント結果（チームA/B得点 or レット）だけを入力すれば、次のサーバーとレシーバーが自動特定されてほしい**
**そうすることで** 入力の手間を最小限にでき、動画の視聴に集中できる

**関連要件**: REQ-001, REQ-002, REQ-003

**詳細シナリオ**:
1. セット開始時に各選手の初期立ち位置が設定されている
2. ラリーが終わるたびに得点結果を入力する
3. rule-engine が次のサーバー・レシーバーを即座に算出し、UIに表示する

**前提条件**:
- セット開始時の 4 人の初期立ち位置（左右）が設定済み
- 全ラリーに得点者 or レットが確定済み

**優先度**: Must Have

---

### ストーリー 1.2: 立ち位置（左右）を自動決定する 🔵

**信頼性**: 🔵 *PRD F-03「サーバーの立ち位置はチームの得点で決定」*

**私は** データ入力者 **として**
**各ラリーのサーバーがコートの左右どちら側にいるかを自動で知りたい**
**そうすることで** 動画と照合して入力の正確性を確認できる

**関連要件**: REQ-003

**詳細シナリオ**:
1. サービングチームの得点が偶数 → サーバーは右コート
2. サービングチームの得点が奇数 → サーバーは左コート
3. レシーバー側のペアも同様に得点の偶奇で位置が決まる

**優先度**: Must Have

---

## エピック2: スコア管理とレット処理

### ストーリー 2.1: スコアを自動計算する 🔵

**信頼性**: 🔵 *PRD F-03 から直接導出*

**私は** データ入力者 **として**
**ラリー結果を入力するたびにスコアが自動更新されてほしい**
**そうすることで** 手動でスコアを数える必要がない

**関連要件**: REQ-005, REQ-006

**詳細シナリオ**:
1. チームAが得点 → チームAのスコアが +1
2. チームBが得点 → チームBのスコアが +1
3. レットの場合 → スコアは変化しない

**優先度**: Must Have

---

### ストーリー 2.2: レットを正しく処理する 🔵

**信頼性**: 🔵 *PRD F-03「レットはラリー番号を振るがスコアに影響しない」*

**私は** データ入力者 **として**
**レット（やり直し）を記録しても、スコアやサーブ権に影響しないでほしい**
**そうすることで** 正確なスコア計算が維持される

**関連要件**: REQ-006

**詳細シナリオ**:
1. ラリー #5 で「レット」を記録
2. スコアは変化せず、サーバーも前のラリーと同じまま
3. 次のラリー #6 は #5 の前と同じ状態から開始

**優先度**: Must Have

## エピック3: 勝敗判定

### ストーリー 3.1: セット勝者を判定する 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-04-10 + BWF ルール*

**私は** データ入力者 **として**
**セットの目標ポイントに到達した時点で勝者が自動判定されてほしい**
**そうすることで** セット終了のタイミングを見逃さない

**関連要件**: REQ-007, REQ-101, REQ-102, REQ-103

**詳細シナリオ**:
1. 目標ポイント 21 点、デュースルール cap30 の場合:
   - 21-19 → 先に 21 点に到達したチームが勝利
   - 20-20（デュース突入）→ 2 点差がつくまで続行
   - 29-29 → 次の得点でセット勝者が確定（30-29 で勝利）
2. デュースなしルールの場合:
   - 21-20 → 先に 21 点に到達したチームが勝利（延長なし）

**優先度**: Must Have

---

### ストーリー 3.2: 試合勝者を判定する 🟡

**信頼性**: 🟡 *ユーザヒアリング「勝敗判定を含める」+ PRD の 3 セットマッチ前提から推測*

**私は** データ入力者 **として**
**先に 2 セット取ったチームが試合の勝者として自動判定されてほしい**
**そうすることで** 3 セット目が必要かどうかを自動で判断できる

**関連要件**: REQ-008

**詳細シナリオ**:
1. チームAがセット 1, 2 を連取 → チームA勝利（セット 3 不要）
2. 1-1 の場合 → セット 3 に進む
3. セット 3 で勝ったチームが試合勝者

**優先度**: Must Have

**備考**: 3 セットマッチ以外のフォーマット（5 セットマッチ等）は MVP では対象外。将来の拡張時にセット数をパラメータ化する可能性あり。

## エピック4: PositionOverride（左右入れ替わり対応）

### ストーリー 4.1: 左右入れ替わりミスを反映する 🔵

**信頼性**: 🔵 *PRD F-03「PositionOverride が入力された場合、実際の立ち位置を現状として採用」*

**私は** データ入力者 **として**
**選手が間違った位置に立っていることを記録したら、以降の推論がその実際の位置に基づいて継続されてほしい**
**そうすることで** 動画の実際の状況と rule-engine の推論が一致する

**関連要件**: REQ-104, REQ-105

**詳細シナリオ**:
1. ラリー終了後、得点を入力する
2. rule-engine が次のサーバー / レシーバーと位置を計算し、UIに表示する
3. 動画と見比べて、チームA のペアが表示と逆の位置に立っていると気付く
4. 「チームA 入れ替わり」ボタンを押す
5. rule-engine がチームA の左右を反転して再計算、表示が更新される
6. 以降のラリーは反転状態を基準に推論が継続される
7. 後のラリーで元に戻った場合、再度「チームA 入れ替わり」を押す（トグル）

**前提条件**:
- 通常の左右入れ替わり（得点による）は rule-engine が自動計算済み
- PositionOverride は人為的ミス（表示と実際の不一致）のみ
- `swapped` / `restored` の区別はなく、毎回トグル（反転）

**優先度**: Must Have

## エピック5: セット遷移

### ストーリー 5.1: 新セットのサーバーを自動決定する 🔵

**信頼性**: 🔵 *ユーザヒアリング 2026-04-10「前セットの勝者」*

**私は** データ入力者 **として**
**新しいセットが始まった時に、前セットの勝者が自動的にサーブ権を持つようになってほしい**
**そうすることで** セット間のサーブ権遷移を手動で設定する必要がない

**関連要件**: REQ-009

**詳細シナリオ**:
1. セット 1 をチームB が勝利
2. セット 2 開始時、チームB がサーブ権を持つ
3. セット 2 の初期立ち位置に基づいてサーバーが決定される

**前提条件**:
- 新セットの初期立ち位置（SetPlayerPosition）は別途入力される

**優先度**: Must Have
