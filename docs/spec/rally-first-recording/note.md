# rally-first-recording コンテキストノート

**作成日**: 2026-11-01
**バックログ**: BL-027「記録の軽量化と打点の 1 パス化」（[docs/backlog/product-backlog.md](../../backlog/product-backlog.md)）
**根拠資料**: [docs/research/input-automation/analysis.md](../../research/input-automation/analysis.md) §1（入力時間の実測）/ §2（時間がかかっている理由）/ §3-1 A（ユーザー案 2026-10-11）

## 目的

1 試合の入力時間を縮める。現状は 42 分の試合で 186〜204 分（動画の 4.4〜4.8 倍）かかり、その内訳は
打刻 40 分 / 決まり方 14 分 / 種別 84 分 / 打点 48〜66 分（計算値）。

時間がかかる理由（analysis.md §2）:

- 同じショットを 3 回訪ねている（打刻・種別・打点）。
- 訪ねるたびにスロー再生のループを見る（1 周 3.3 秒が 1 ショットの下限になる）。
- 打刻が見てから押すため 0.2〜0.5 秒遅れ、ループの窓を狭められない。
- 実プレー時間は動画の 20% なのに、打刻は動画を通して見る。

## 方式（ユーザー案 2026-10-11、2026-11-01 に 3 段構成で再確認）

| 段 | 入れるもの | 再生 | 見る範囲 | 画面 |
|---|---|---|---|---|
| 1. ラリー記録 | ラリーの開始と終了、得点者（レット / スキップ含む）、左右入替・コートチェンジの訂正だけ。ショットは押さない | 1.5〜2 倍速 | 動画全体 | record（ラリー記録モード） |
| 2. 打点パス（流し） | ラリー区間だけを低速で**流し**、打球の瞬間にコート図をタップ。タップの時刻が打刻（`video_timestamp_ms`）、位置が打点（`hit_x` / `hit_y`）。ループ再生はしない | 0.5 倍速（速い打ち合いは 0.25） | ラリー中のみ（段 1 の区間） | annotate（新モード） |
| 3. 種別パス | ショット種別と打者（個人）。既存の種別パスをそのまま使う | 既存どおり | 既存どおり | annotate（既存） |

決まり方（クイックパス）は既存どおり。ショットが無いラリーではループの基準を段 1 の終了時刻にする。

見積（42 分の試合、720 打、analysis.md §3-1）: 段 1 が 21〜28 分、段 2 が 25〜45 分。現状の 40 + 48〜66 分に対して 15〜60 分（8〜30%）の短縮。
段 2 のタップは反応の遅れが小さいので、段 3 のループ窓を狭めて種別パスも短くできる余地がある（本単位では見積も変更もしない）。

## 設計の要点（既存実装への載せ方）

### 1. 段 1 はセット単位の「記録方式」として record 画面に載せる

- `sets.recording_mode text NOT NULL DEFAULT 'shot' CHECK IN ('shot', 'rally')` を追加（additive migration）。
- セット設定フォームで記録方式を選ぶ（既定 = 従来の `shot`）。`rally` のときは「打った」ボタンの代わりに
  「ラリー開始」ボタンを出し、得点 / レット / スキップのボタンがそのままラリー終了になる。
- ADR-017 §3「ライブ記録 UI は聖域」との関係: 従来モードのコアループ（打った → 100ms 以内に記録）には触らない。
  ラリー記録モードは**別コンポーネント**（例: `RallyModeControls.vue`）で、スコア表示・コート図・履歴・取り消し・
  左右入替・コートチェンジ・rule-engine 連携は既存の composable（`useRecordingSession`）を流用する。
- 時刻の保存先: 開始 = 既存の `rallies.video_start_timestamp_ms`（現状は 1 打目の時刻を入れている列を、
  ラリー記録モードでは開始ボタンの時刻に使う）、終了 = 新列 `rallies.video_end_timestamp_ms`。
- ショット 0 件のラリーが**正常な状態**になる。現状の「ショットが 0 件ならラリー行を消す」undo の規則
  （`useRecordingSession` REQ-110）はラリー記録モードでは使わない。

### 2. 段 2 はアノテーションスタジオの新モード

- 対象は `recording_mode = 'rally'` のセットのラリー（ショット 0 件、またはやり直し）。従来の打点パスは `shot` モード用に残す。
- 再生: ラリー区間 [開始 − 前余白, 終了 + 後余白] を選んだ速度で 1 回流す。区間の終わりで自動停止し、次のラリーへ進める。
- タップ: 既存の `CourtDiagramInput.vue`（正規化座標、ライン外は範囲外値）を使う。タップごとに
  `shots` を 1 行作る（`shot_number` = 連番、`video_timestamp_ms` = タップ時の再生位置、`hit_x` / `hit_y`、
  `input_source = 'manual'`、`annotation_source = 'human'`）。
- 打者: shot-annotation REQ-012 のプレフィルと同じ。1 打目 = `server_player_id`、2 打目 = `receiver_player_id`、
  3 打目以降は打順の偶奇でチームのみ確定し、個人は段 3（種別パス）で入れる。シングルスは候補 1 人なので個人まで確定する。
- 速度: 0.5 を既定とし、0.25 を追加（`PlaybackRate` に 0.25 を足す。YouTube IFrame API / HTML5 video ともに 0.25 を受け付ける）。
  キーを押している間だけ 0.25 に落とす操作も提供する（速い打ち合い対応、analysis.md §3-1 注意点）。
- 訂正: Backspace で直前のタップを取り消し（ショット行の削除）。ラリー単位の「やり直し」で区間を頭から流し直す
  （そのラリーのショットを全部消して再入力）。
- BL-021（動画直接タップ + 4 隅校正）との関係: 本単位はコート図タップで成立させ、BL-021 が入ればタップ面を
  動画に差し替えられる構造にする（タップ → 正規化座標の変換を 1 箇所に閉じる）。**BL-021 への依存は外す**
  （バックログの依存欄を更新する）。

### 3. 既存パスへの影響

- クイックパス: ループの基準（アンカー）を「最終ショットの時刻 → 無ければ `video_end_timestamp_ms` → 無ければ
  `video_start_timestamp_ms`」の順にする（現状は最終ショット → 開始時刻）。終了時刻を基準にする場合は決着イベントが
  基準より**前**にあるので、窓は前側を長く取る。
- 種別パス: 変更なし。段 2 が作ったショット行をそのまま巡回する（1 打目サーブ自動確定、打者二択）。
- 進捗（`useAnnotationProgress` / `AnnotationRallyList`）: ショット 0 件のラリーを「打点パス（流し）未着手」として数える。
  現状は `shots.length > 0 && every(hitX !== null)` なので、0 件は未完了扱いになり整合する。
- 統計: 本単位では集計 SQL を変えない。ショット 0 件のラリーが混在する試合の統計は、ショットに依存しない
  指標（得点率・決まり方）は正しく、ショットに依存する指標（ラリー長・ショット統計）は段 2 が終わるまで欠ける。
  ラリー長 0 の扱い（除外か 0 として数えるか）は kairo-design で SQL を確認して決める。

### 4. DB 変更（additive のみ、CI 経由で適用）

| 対象 | 変更 |
|---|---|
| `sets` | `recording_mode text NOT NULL DEFAULT 'shot' CHECK (recording_mode IN ('shot', 'rally'))` |
| `rallies` | `video_end_timestamp_ms integer NULL` |

既存行は `recording_mode = 'shot'`、`video_end_timestamp_ms = NULL` のまま。既存の挙動は変わらない。
